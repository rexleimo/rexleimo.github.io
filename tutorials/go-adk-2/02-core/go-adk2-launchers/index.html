launcher 全家桶：console / web / full / prod / universal / agentengine 该选哪个

ADK Go v2.4.0 的运行期入口全解：Launcher 与 SubLauncher 接口、Config.Validate、universal 的默认子启动器规则、full 与 prod 的组合差异、web 的 api/webui/a2a/pubsub/eventarc 关键字、authn/authz 默认裸奔与 h2c，附选型决策表和排错清单。

September 26, 2026 · 4 min · 822 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 cmd/launcher/（launcher.go、universal/universal.go、full/full.go、prod/prod.go、web/web.go、console/console.go）。

launcher 是 2.x 应用唯一的运行期入口，但它的组合关系官方文档没写清楚，导致大量人在生产里跑着 full（带 Dev UI、带 console、默认不鉴权）。这一篇把接口、组合、默认值和选型一次钉死。

接口：两个方法就够描述一个 launcher#

// cmd/launcher/launcher.go
type Launcher interface {
	// Execute parses command-line arguments and runs the launcher.
	Execute(ctx context.Context, config *Config, args []string) error
	// CommandLineSyntax returns a string describing the command-line flags and arguments.
	CommandLineSyntax() string
}

type SubLauncher interface {
	// Keyword returns the command-line keyword that activates this sub-launcher.
	Keyword() string
	// Parse parses the arguments for the sub-launcher. It should return any unparsed arguments.
	Parse(args []string) ([]string, error)
	// CommandLineSyntax returns a string describing the command-line flags and arguments.
	CommandLineSyntax() string
	// SimpleDescription provides a brief, one-line description of the sub-launcher's function.
	SimpleDescription() string
	// Run executes the sub-launcher's main logic.
	Run(ctx context.Context, config *Config) error
}

（web 自己另有一套更宽的子启动器接口，多了 SetupSubrouters 用于往路由器上挂路由、以及包装 handler —— 那是 web 层的扩展点，不是 launcher.SubLauncher 的一部分。）

universal 是组合器：

// NewLauncher returns a new universal launcher.
// The first element on launcher list will be the default one if there are no arguments specified
func NewLauncher(sublaunchers ...launcher.SubLauncher) launcher.Launcher

这条默认规则必须记住：full 的第一个子启动器是 console，所以

go run .            # ≡ go run . console
go run . web api    # 显式挑 web，再挑它的子启动器 api

web 自己也是个 universal 式的容器，Keyword() 决定命令行里的名字（api、webui、a2a、pubsub、eventarc、agentengine）。它的 CommandLineSyntax() 会把「可用子启动器列表 + 每个的语法」全部打出来——这是你唯一需要记住的东西：

l := full.NewLauncher()
if err := l.Execute(ctx, cfg, os.Args[1:]); err != nil {
	log.Fatalf("run failed: %v\n\n%s", err, l.CommandLineSyntax())   // ← 别省这半句
}

组合关系（源码原文）#

// cmd/launcher/full/full.go
func NewLauncher() launcher.Launcher {
	return universal.NewLauncher(
		console.NewLauncher(),
		web.NewLauncher(
			webui.NewLauncher(),
			a2a.NewLauncher(),
			pubsub.NewLauncher(),
			eventarc.NewLauncher(),
			api.NewLauncher(),
		),
	)
}

// cmd/launcher/prod/prod.go
// Package prod provides easy way to play with ADK with all available options without
// development support (no console, no ADK Web UI) including only production
// options like the REST API and A2A support.
func NewLauncher() launcher.Launcher {
	return universal.NewLauncher(
		web.NewLauncher(api.NewLauncher(), a2a.NewLauncher()),
	)
}

自定义面（生产只要 REST API，不要 A2A，也不要任何 UI）是 2.x 里最该养成的一习惯：

import (
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/universal"
	"google.golang.org/adk/v2/cmd/launcher/web"
	"google.golang.org/adk/v2/cmd/launcher/web/api"
)

l := universal.NewLauncher(web.NewLauncher(api.NewLauncher()))   // 只挂 api

launcher.Config：能力开关全在这一张表上#

type Config struct {
	SessionService   session.Service
	ArtifactService  artifact.Service
	MemoryService    memory.Service
	AgentLoader      agent.Loader
	A2AOptions       []a2asrv.RequestHandlerOption
	PluginConfig     runner.PluginConfig
	TelemetryOptions []telemetry.Option
	Authenticator    authn.Authenticator   // nil → authn.NewNoop()
	Authorizer       authz.Authorizer      // nil → authz.NewNoop()
	Compaction       *compaction.Config    // nil → 关闭；进程级
}

Config.Validate() 的注释是：“Validate reports a Config that cannot work, before anything starts serving.” 也就是说，装配错误应当在 Execute 之前炸，而不是服务起来后第一个请求才发现。CI 冒烟阶段建议显式调一次：

cfg := &launcher.Config{AgentLoader: agent.NewSingleLoader(root), SessionService: ss}
if err := cfg.Validate(); err != nil {
	log.Fatalf("bad launcher config: %v", err)
}

默认裸奔：Authenticator / Authorizer#

Config 注释明确：Authenticator 非 nil 时，对除 /health、/version 之外的所有 restapi 端点做认证，无有效凭据回 401，通过认证后调用者身份挂在 ctx 上。默认 nil = authn.NewNoop()。

可选 provider（server/authn 目录）：

文件用途
header.go信任反向代理传来的身份头（配合网关/LB 收敛入口）
iap.goGoogle IAP（Identity-Aware Proxy）token 校验
custom.go自定义 scheme（API key、bearer…）
noop.goauthn.NewNoop()

授权侧 server/authz 只有两种：NewNoop() 与 NewStrict()；strict 提供 CanActAsUser(ctx, userID) error——校验「调用者能否代表这个 userID」。

这为什么关键：ADK 的 REST 会话 API 是按 app/user/session 三级寻址的。没有 authz.NewStrict()，任何拿到 URL 的人都能用别人的 userID 读写会话历史。用 full 上生产 + Noop 授权，等于把会话数据库暴露到公网。

Compaction 的进程级约束#

注释原文（浓缩）：

  • 滑窗压缩按常数因子缩减 prompt，只有尾保留（EventRetentionSize）真正约束增长；若两次滑窗压缩之间累积的事件数没超过尾保留容量，该机制就空转；
  • 这是进程级设置：一个 launcher 通过 agent loader 服务多个应用时，它们全都用同一份配置、同一个 Summarizer 实例（也就是同一个模型）；
  • 不同应用需要不同压缩策略、或不能共享 summarizer，就必须分开跑进程。

还有个隐含约束在 runner 侧：不指定 Summarizer 时 runner 会装一个 compaction.LLMSummarizer，用 root agent 的模型——那就要求 root 必须是 LLM agent；并且这个「你没要求但它会发生」的调用带了默认超时（defaultSummarizerTimeout），因为压缩跑在 run loop 里，供应商不响应会把这一轮一直挂着。

运行期行为：两个容易忽略的细节#

① console 是带信号处理的。 源码：ctx, cancel := signal.NotifyContext(ctx, os.Interrupt)，并且它跑的就是路径 B 那个迭代器：

for event, err := range r.Run(ctx, userID, sess.ID(), userMsg, agent.RunConfig{StreamingMode: streamingMode}) {
	if err != nil { /* A compaction failure is not this turn's failure. */ }
}

两个含义：Ctrl-C 在 console 下是优雅结束本轮；以及压缩失败不算本轮失败——这是官方定的语义，你自己包 runner 时最好保持一致。

② web launcher 从 v2.2.0 起启用 h2c（HTTP/2 cleartext，PR #826）。反代/负载均衡上要做对应配置，否则会出现「本地 HTTP/2 正常、网关后掉到 HTTP/1.1」的行为差异；SSE/流式端点在中间层还要记得关掉响应缓冲。

常见问题

ADK Go 2.x 有哪些 launcher？

cmd/launcher 下六类：console、web（含 api/webui/a2a/agentengine/triggers 子启动器）、full、prod、universal、agentengine。full 与 prod 都是 universal 的组合预设。

full.NewLauncher() 到底组合了什么？

源码原文：universal.NewLauncher(console.NewLauncher(), web.NewLauncher(webui.NewLauncher(), a2a.NewLauncher(), pubsub.NewLauncher(), eventarc.NewLauncher(), api.NewLauncher()))。

不带参数直接运行会进哪个模式？

universal.NewLauncher 的注释写明：列表里第一个子启动器是无参数时的默认。full 的第一个是 console，所以 go run . 等价于 go run . console。

生产环境该用哪个 launcher？

prod.NewLauncher() = universal(web(api, a2a))：只有 REST API 与 A2A，不含 console 与 ADK Web UI。开发/演示用 full。

launcher 默认会做鉴权吗？

不会。Config.Authenticator 为 nil 时是 authn.NewNoop()，Authorizer 为 nil 时是 authz.NewNoop()，除 /health 与 /version 外的端点等于裸奔，必须显式装 provider。

adkgo 和 launcher 是什么关系？

没有关系。adkgo 只做部署（deploy cloudrun / deploy agentengine）；console/web/api 这些运行期子命令来自你 main.go 里选择的 launcher。
