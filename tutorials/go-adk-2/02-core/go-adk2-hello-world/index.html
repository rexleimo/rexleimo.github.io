Hello World 的三条路径与模型接入：launcher、runner、workflowagent

ADK Go v2.4.0 起手式：用 launcher 一行跑起来、用 runner 直接拿事件流（iter.Seq2）、用 workflowagent 走图；逐字段讲清 llmagent.Config（Instruction 模板、GlobalInstruction、OutputSchema 注入、Mode 默认值随位置变化）与模型层 gemini/openaimodel/apigee 的差别。

September 26, 2026 · 4 min · 774 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0 · 源码 agent/llmagent/llmagent.go、runner/runner.go、cmd/launcher/*。

同一个 Agent 有三种跑法，各自的用途完全不同。1.x 时代大家只会用 launcher，结果写测试和做批处理时到处绕路。这一篇把三条路和 llmagent.Config 的全部字段一次讲完——这张字段表你会在后面每个模块反复回来查。

路径 A：launcher（开发/演示/联调，一行起服务）#

package main

import (
	"context"
	"log"
	"os"

	"google.golang.org/genai"

	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/agent/llmagent"
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/full"
	"google.golang.org/adk/v2/model/gemini"
	"google.golang.org/adk/v2/tool"
	"google.golang.org/adk/v2/tool/geminitool"
)

func main() {
	ctx := context.Background()

	model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
		APIKey: os.Getenv("GOOGLE_API_KEY"),
	})
	if err != nil {
		log.Fatalf("failed to create model: %v", err)
	}

	a, err := llmagent.New(llmagent.Config{
		Name:        "weather_time_agent",
		Model:       model,
		Description: "Agent to answer questions about the time and weather in a city.",
		Instruction: "Your SOLE purpose is to answer questions about the current time and weather in a specific city.",
		Tools:       []tool.Tool{geminitool.GoogleSearch{}},
	})
	if err != nil {
		log.Fatalf("failed to create agent: %v", err)
	}

	l := full.NewLauncher()
	if err := l.Execute(ctx, &launcher.Config{
		AgentLoader: agent.NewSingleLoader(a),
	}, os.Args[1:]); err != nil {
		log.Fatalf("run failed: %v\n\n%s", err, l.CommandLineSyntax())
	}
}

go run . console

要点：错误分支里把 l.CommandLineSyntax() 打出来——它会告诉你当前 launcher 支持哪些子命令。官方样例全部这么写，别省。

路径 B：runner（测试/批处理/自建服务）#

不用 launcher，直接驱动 Agent 拿事件流：

ss := session.InMemoryService()        // 内存会话；另有 session/database 与 session/vertexai

r, err := runner.New(runner.Config{
	AppName:           "weather-agent",
	Agent:             a,
	SessionService:    ss,
	AutoCreateSession: true,
})
if err != nil {
	log.Fatal(err)
}

msg := &genai.Content{
	Role:  "user",
	Parts: []*genai.Part{{Text: "上海现在天气如何？"}},
}

for ev, err := range r.Run(ctx, "user-1", "sess-1", msg, agent.RunConfig{}) {
	if err != nil {
		log.Printf("event error: %v", err)
		break
	}
	// ev.Author / ev.Partial / ev.Actions.StateDelta ...
	fmt.Println("author:", ev.Author, "partial:", ev.Partial)
}

上面这段我实际编译跑通（runner.New + session.InMemoryService() + iter.Seq2 循环）。两个补充：

  • runner.New 会在构造时就报错：cfg.Agent == nil → “root agent is required”；cfg.SessionService == nil → “session service is required”。装配错误不会留到第一个请求才爆。
  • 想要“三个服务全内存”的省事写法，v2.1.0 加了便捷构造函数：runner.NewInMemory(appName, agent)，内部就是 session.InMemoryService() + artifact.InMemoryService() + memory.InMemoryService()。测试里用它最短。

签名（源码原文）：

func (r *Runner) Run(ctx context.Context, userID, sessionID string,
	msg *genai.Content, cfg agent.RunConfig, opts ...RunOption) iter.Seq2[*session.Event, error]

三个值得注意的设计：

  1. 返回 iter.Seq2[*session.Event, error]（Go 1.23+ 的 range-over-func 迭代器）。所以 for ev, err := range 是正统写法，不用自己建 channel。好处是：break 就是取消，不用清理订阅。
  2. opts ...RunOption 目前有两个：WithStateDelta(map[string]any)（本轮预置 state）、WithYieldUserMessage()（先把用户消息事件 yield 出来再接 Agent 事件，源码注释说对齐 adk-python 的 yield_user_message，当前仅 node 路径生效）。
  3. RunLive(ctx, userID, sessionID, cfg agent.LiveRunConfig, opts...) (agent.LiveSession, iter.Seq2[*session.Event, error], error) —— 双向流式（语音/实时）走这个入口，模块 7 细讲。

什么时候必须用 runner：单元测试、离线批量评测、你自己的 gRPC/HTTP 服务里嵌 Agent。生产装配时也别手搓 runner——它有个 Compaction 字段的默认解析逻辑（下一节），用 launcher 更省事。

路径 C：workflowagent（起手就是图）#

greet := workflow.NewFunctionNode("greet",
	func(ctx agent.Context, name string) (string, error) {
		return "Hello, " + name + "!", nil
	}, workflow.NodeConfig{})

root, err := workflowagent.New(workflowagent.Config{
	Name:        "hello_graph",
	Description: "minimal graph agent",
	Edges:       workflow.Chain(workflow.Start, greet),
})

新应用我反而推荐从这条起步：它的上下文签名（func(agent.Context, In) (Out, error)）会逼你从一开始就按统一上下文思考，而不是先写 transfer 再回头改。完整拓扑见模块 5 。

llmagent.Config 逐字段（v2.4.0 源码核对）#

身份与结构#

字段语义坑
Name非空、在 Agent 树内唯一不能叫 "user"（那是终端用户输入的保留名）
DescriptionLLM 用它决定是否把任务委派给这个 Agent一行足够；写得含糊，委派就乱
SubAgents []agent.Agent可委派的子 AgentADK 会自动把 parent 指回本 Agent 以支持 transfer，别自己再设一遍父子
GlobalInstruction整棵树的统一指令只有 root 上的这一份生效
OutputKey把本 Agent 的输出写进 state 的某个 key用来在 Agent 之间传值、或在工具里取回上游结论

指令：三种写法，别混用#

Instruction: "当前用户是 {user_name}，所在地 {location?}。请引用 {artifact.resume}。"

规则（源码注释）：

  • {key_name} 由 ADK 在运行时用 session state 和 context 解析；
  • 名字必须匹配 ^[a-zA-Z_][a-zA-Z0-9_]*$，否则当字面量处理；
  • 变量/artifact 不存在时会报错；加 ?（{var?}）变成可选；
  • {artifact.key_name} 插入该 artifact 的文本内容；
  • 不想要模板语义 → 用 InstructionProvider（它两者都设时优先于 Instruction，且不做 {} 替换；要注入 state 变量得自己用 util/instructionutil.InjectSessionState）。

GlobalInstructionProvider 同理优先于 GlobalInstruction。

模型与生成参数#

Model:                 model,      // model.LLM 接口
GenerateContentConfig: &genai.GenerateContentConfig{
	Temperature:   new(float32(0.2)),      // Go 1.26 的 new(expr) 直接给可选指针字段赋值
	SafetySettings: ...,
},

GenerateContentConfig 不是所有字段都能用——源码明写：tools 必须走 Tools/Toolsets，不要塞这里。另外 Temperature *float32 这类可选字段在 Go 1.26+ 可以用 new(0.2) 形式省掉 helper（理由见模块 0 第 3 篇 ）。

六个回调槽位（顺序语义很重要）#

槽位何时触发非 nil 返回值的后果
BeforeAgentCallbacksAgent 开跑前，按序短路：跳过 Agent 本次 run 和其余回调，用其 content/error 造新事件
AfterAgentCallbacksAgent 完成后，按序用其 content/error 造新事件，跳过其余回调
BeforeModelCallbacks每次 LLM 调用前，按序跳过真实 LLM 调用，用返回的 response/error —— 官方点名可以实现缓存
AfterModelCallbacksLLM 返回后替换真实响应；适合记 metrics、后处理
OnModelErrorCallbacks模型报错时错误处理/降级
BeforeToolCallbacks / AfterToolCallbacks工具调用前后，按序返回结果即跳过真实工具执行
OnToolErrorCallbacks工具报错时错误处理

BeforeModelCallbacks 返回缓存响应用来省 token 是很实用的组合：命中缓存时不产生任何模型调用。想接自建语义缓存就挂这里（模块 10 有一个最小实现）。

结构化输入输出#

InputSchema:  &genai.Schema{Type: genai.TypeObject, Properties: map[string]*genai.Schema{...}, Required: []string{...}}
OutputSchema: &genai.Schema{Type: genai.TypeObject, ...}
  • InputSchema：当这个 Agent 被当成工具调用时的入参约束；
  • OutputSchema：设置后框架透明注入一个 set_model_response 工具，让模型在产出结构化输出的同时仍然能调其它工具（函数工具、RAG、agent transfer）。实现见 internal/llminternal/outputschema_processor.go；
  • 上游留了 TODO：这里可能从 genai.Schema 换成 jsonschema——别把这个类型写死进你的抽象层。

Mode：默认值随位置变化（2.x 最容易踩的一条）#

源码注释原文：

Default value is ModeChat as a sub-agent, ModeSingleTurn as a node in a workflow.

ModeUnset     // 不显式设置时的零值
ModeChat       Mode = "chat"
ModeTask       Mode = "task"
ModeSingleTurn Mode = "single_turn"

含义差很多：同一个 Agent，挂在 SubAgents 下默认能和用户对话；塞进图节点里默认不能对话。 想让图里的 LLM 节点能问用户，必须显式 Mode: llmagent.ModeChat（或 ModeTask）。

与之配套的还有 IncludeContents（源码注释：不设时，作为 single_turn 图节点的 Agent 只看得到当前轮；显式设置才能在图里保留历史）和 DisallowTransferToParent / DisallowTransferToPeers。

这三条一起构成了 2.x 多 Agent 的「对话可见性」模型，模块 6 会整篇讲。

模型层选型（2.x 树里三个适配器）#

包存在性用法
model/gemini1.x/2.x 都有gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{APIKey: …})；走 Vertex 时用 GOOGLE_GENAI_USE_VERTEXAI=true + ADC
model/openaimodel仅 2.xOpenAI 兼容端点（自建网关/中转）。v2.4.0 修了「可选 function call output ID」的兼容问题
model/apigee两条线都有Apigee AI 网关

统一约束是 model.LLM 接口 —— 所以你可以自己写一个 wrapper 做超时/重试/降级。官方 examples/workflow/complex/resilient_model.go 就是一个示范：把共享模型包一层 resilientModel，对每次调用加 timeout、限重试次数、失败时 fail-open 到 fallback 模型。这个模式我在模块 5 第 4 篇 展开。

另外 v2.1.0 引入了按名字的模型注册表（Register / NewLLM）：配置里写模型名字符串，运行期解析成实现，便于换模型不改代码。

常见问题

ADK Go 2.x 最小的 Hello World 长什么样？

gemini.NewModel(ctx,name,cfg) 造模型，llmagent.New(llmagent.Config{...}) 造 Agent，full.NewLauncher().Execute(ctx, &launcher.Config{AgentLoader: agent.NewSingleLoader(a)}, os.Args[1:]) 跑起来，然后 go run . console。

不想用 launcher 怎么直接拿事件流？

用 runner 包：runner.New(runner.Config{AppName, Agent, SessionService}) 得到 *Runner，再 for ev, err := range r.Run(ctx, userID, sessionID, msg, runCfg) —— Run 返回 iter.Seq2[*session.Event, error]。

llmagent.Config.Mode 的默认值是什么？

取决于位置：作为 sub-agent 时默认 ModeChat，作为 workflow（图）节点时默认 ModeSingleTurn。官方注释明确写了这条差异。

Instruction 里的 {变量} 怎么解析？

ADK 运行时用 session state 与 context 替换 {key_name}，名字需匹配 ^[a-zA-Z_][a-zA-Z0-9_]*$；不存在会报错，加问号 {var?} 变成可选；{artifact.key_name} 插入该 artifact 的文本内容。若不想模板化，改用 InstructionProvider。

设置 OutputSchema 会发生什么？

框架会透明注入一个 set_model_response 工具，让模型在产出结构化输出的同时仍能调用其它工具（函数工具、RAG、agent transfer 等）。

ADK Go 2.x 支持 OpenAI 模型吗？

支持，model/openaimodel 是 2.x 独有的包（v1.7.0 树里没有）；另外 model/apigee 也在两条线里都有。
