模块 6：多 Agent 新范式

1.x 的多 Agent 是「树 + transfer」；2.x 把它拆成两条正交的线：结构交给图（模块 5），交互交给模式（Mode）。

事实边界

  • 包路径 agent/workflowagents/{sequentialagent,parallelagent,loopagent} 在 v1.7.0 里已经存在，而且 v2.4.0 依旧不走图引擎——源码里就是三个普通循环（Sequential/Loop 是 for subAgent := range ctx.Agent().SubAgents()，Parallel 是 errgroup + 重建子 ctx）。所以不要假设它们获得了路由、fan-in 屏障、HITL 恢复、重试这些图能力；需要就自己包成 workflow.NewAgentNode(seq, cfg)。

  • 三者 Config 只有 AgentConfig agent.Config（LoopAgent 额外 MaxIterations uint），且 AgentConfig.Run != nil 直接报错。

  • 只有 Sequential 实现 RunLive（Parallel/Loop 无）。

  • Loop 退出：MaxIterations 耗尽或任一子事件 Actions.Escalate；0 = 不限。

  • Parallel 自动给子 agent 分 branch（<父>.<子>）→ 默认兄弟互不可见；早停会 cancel 但等 teardown 跑完。

  • llmagent.Config.Mode 是 2.x 的交互开关。定义在 internal/llminternal，type Mode = llminternal.Mode：

    ModeUnset      = llminternal.ModeUnset       // 未显式设置
ModeChat       Mode = "chat"                 // 经 transfer_to_agent 可达
ModeTask       Mode = "task"                 // 会与人多轮澄清
ModeSingleTurn Mode = "single_turn"          // 不问人，干完直接交结果

  • 官方 collaboration 样例的三模式对照：root 协调者用 chat；single_turn 子 Agent 不与用户对话、干完自动带结果返回；task 子 Agent 允许问澄清问题、自动交还结构化结果。

  • InputSchema / OutputSchema（*genai.Schema）配合 ModeTask 使用。官方 testdata 里有 TestDelegation_07_ChatToTaskValidationRetry（schema 校验失败后重试）、TestDelegation_06_ChatToTaskHITLResume（task 子 Agent 里暂停等人）、TestDelegation_09_ChatPeerTransferAcrossSiblings（同辈之间转交）——这三个用例基本就是本模块的目录。

  • DisallowTransferToParent 控制是否允许向父级转交；SubAgents []agent.Agent 挂子 Agent。
