ADK Go 2.x 安装与验证：go get /v2、adkgo CLI、跑通第一个 Agent

从零装好 ADK Go v2.4.0：Go 1.27.1 工具链、go get google.golang.org/adk/v2、凭据配置（Gemini API Key / Vertex ADC）、adkgo 部署 CLI 与 launcher 运行方式，附完整验证清单与失败排查表。

September 26, 2026 · 4 min · 690 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0 · Go 1.27.1（下限 1.26.6）· 2026-09-26

这一篇只做一件事：把环境装对，并且让你能自证装对了。所有版本号的来由见模块 0 第 3 篇 ，这里不重复论证。

第 0 步：确认工具链#

go version
# go version go1.27.1 darwin/arm64   ← 需要 ≥ 1.26.6

go env GOTOOLCHAIN GOPROXY

低于 1.26.6 的话先解决它，否则下一步立刻撞墙：

go: google.golang.org/adk/v2@v2.4.0 requires go >= 1.26.6 (running go 1.25.6; GOTOOLCHAIN=local)

第 1 步：新建模块并拉依赖#

mkdir myagent && cd myagent
go mod init myagent
go get go@1.27.1                              # 抬 go 指令，见下面的坑
go get google.golang.org/adk/v2@v2.4.0        # 正式依赖，锁版本

这里有个必踩的坑：Go 1.26 起 go mod init 故意把 go 指令写成「当前工具链次版本减一」，所以你会得到 go 1.26.0 —— 低于 ADK 要求的 1.26.6。所以 go get go@1.27.1 那一步不是可选的。

期望的 go.mod：

module myagent

go 1.27.1

require (
	google.golang.org/adk/v2 v2.4.0
	google.golang.org/genai v1.x.x   // 由 go get 解析
)

自证版本（不要去找 adkgo version，它不存在）：

go list -m google.golang.org/adk/v2                     # google.golang.org/adk/v2 v2.4.0
go list -m -f '{{.Path}} {{.Version}} needs go {{.GoVersion}}' google.golang.org/adk/v2

第 2 步：凭据#

两条路线，选一条。

路线 A：Gemini API Key（最快）

export GOOGLE_API_KEY="your-key"

路线 B：Vertex AI（企业/合规场景）

gcloud auth application-default login
export GOOGLE_GENAI_USE_VERTEXAI=true
export GOOGLE_CLOUD_PROJECT="your-project"
export GOOGLE_CLOUD_LOCATION="your-region"     # 例如 us-central1

这两组变量名取自官方 examples/workflow/README.md（v2.4.0 原文），不是我编的。

关于 .env#

ADK Go 的官方样例统一用 os.Getenv 取值，没有内置 .env 加载器。想要 .env 体验，自己选一种：

// 方案 1：显式加载（推荐，行为清楚）
import "github.com/joho/godotenv"

func main() {
	if err := godotenv.Load(); err != nil && !os.IsNotExist(err) {
		log.Printf("no .env loaded: %v", err)   // 别 panic：CI 里通常没有 .env
	}
	// ...
}

# 方案 2：不进代码，交给环境
direnv allow                 # 或 systemd unit 里 EnvironmentFile=/etc/myagent/env

绝对不要把 .env 提交上去。.gitignore 第一行就写：

.env
.env.*
!.env.example

配一份 .env.example（只有键名没有值）进仓库，新人 copy 一份就能跑。

第 3 步：能编译的最小 Agent#

// main.go
package main

import (
	"context"
	"log"
	"os"

	"google.golang.org/genai"

	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/agent/llmagent"
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/full"
	"google.golang.org/adk/v2/model/gemini"
	"google.golang.org/adk/v2/tool"
	"google.golang.org/adk/v2/tool/geminitool"
)

func main() {
	ctx := context.Background()

	model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
		APIKey: os.Getenv("GOOGLE_API_KEY"),
	})
	if err != nil {
		log.Fatalf("failed to create model: %v", err)
	}

	a, err := llmagent.New(llmagent.Config{
		Name:        "weather_time_agent",
		Model:       model,
		Description: "Agent to answer questions about the time and weather in a city.",
		Instruction: "Your SOLE purpose is to answer questions about the current time and weather in a specific city. You MUST refuse to answer any questions unrelated to time or weather.",
		Tools:       []tool.Tool{geminitool.GoogleSearch{}},
	})
	if err != nil {
		log.Fatalf("failed to create agent: %v", err)
	}

	l := full.NewLauncher()
	if err := l.Execute(ctx, &launcher.Config{
		AgentLoader: agent.NewSingleLoader(a),
	}, os.Args[1:]); err != nil {
		log.Fatalf("run failed: %v\n\n%s", err, l.CommandLineSyntax())
	}
}

对照 1.x，这段代码有三处必须不一样：

  1. 每个 import 都带 /v2；
  2. gemini.NewModel(ctx, ...) 第一个参数是 ctx（这条其实是 v1.0 就改的，但旧专栏写的是无 ctx 版本）；
  3. l.Execute(ctx, config, os.Args[1:]) 也是 ctx 版签名。

cmd/launcher/full 的组合（源码）是 universal.NewLauncher(console.NewLauncher(), web.NewLauncher(webui, a2a, pubsub, eventarc, api))，所以下面这些子命令它都支持。

第 4 步：跑起来#

go build ./... && go vet ./...     # 先过静态检查
go run . console                   # 控制台模式

进 console 后随便问一句 What's the weather in Shanghai?，看到回答就说明整条链路（模型、工具、launcher、会话）通了。

不知道有哪些子命令时，让它自己告诉你：

go run . --help
# 或故意不带参数运行，Execute 会返回错误并把 l.CommandLineSyntax() 打出来

网页形态（Dev UI / API / A2A）：

go run . web api webui

别搞混：adkgo 不是运行命令#

go install google.golang.org/adk/v2/cmd/adkgo@latest
adkgo --help

装完你会发现 adkgo 只有 deploy 一个子命令树（deploy cloudrun / deploy agentengine）——它是部署 CLI，不负责跑 Agent。跑 Agent 用的是你自己 main.go 编译出的二进制 + launcher 子命令。旧专栏把 adk version / ./adk 当运行入口，那是 v0.x 时代的遗留，现在全线失效。

第 5 步：验证清单（全绿再进下一篇）#

go list -m google.golang.org/adk/v2        # 期望 v2.4.0
go version                                 # 期望 ≥ go1.26.6
grep -c 'google.golang.org/adk/v2' go.mod  # ≥1
go build ./... && go vet ./...             # 无输出
go run . console                           # 手输一句，看到回复就算通

# 生产构建留痕（把二进制里内嵌的依赖版本存进发布记录）
go install ./...
go version -m "$(go env GOPATH)/bin/myagent" | grep 'adk/v2'

失败排查表#

现象原因处理
requires go >= 1.26.6工具链低 / go 指令低升 Go；go get go@1.27.1；CI 换 golang:1.27.1 镜像
卡在 golang.org/toolchain@... 下载自建代理没同步 toolchain 路径换 GOPROXY，或 GOTOOLCHAIN 指向本地已有工具链
unresolved import "google.golang.org/adk/..."只改了 go.mod 没改 import按迁移篇 第 3 步批量重写
module .../adk/v2: version "@latest" invalid把 /v2 和 @latest 拼错位置正确形态是 google.golang.org/adk/v2@v2.4.0
400/403 API key not valid变量没导出 / 用了 .env 但代码没加载echo $GOOGLE_API_KEY 核对；见「关于 .env」
Vertex 路线报 no credentialsADC 未登录或 project/location 没设gcloud auth application-default print-access-token 自检
找不到 adk 命令2.x 叫 adkgo重装 .../cmd/adkgo@latest，并把 $(go env GOPATH)/bin 加进 PATH
首次 go build 很慢ADK v2 依赖树大（GCP SDK、OTel、grpc）正常；CI 上给 GOMODCACHE 加缓存

常见问题

ADK Go 2.x 怎么安装？

在项目里执行 go get google.golang.org/adk/v2@v2.4.0；生产环境锁具体版本号，不要用 @latest。

adkgo 是什么，怎么装？

go install google.golang.org/adk/v2/cmd/adkgo@latest 装的是部署 CLI（adkgo deploy cloudrun / agentengine），它不用于运行 Agent，运行期子命令来自你 main.go 里的 launcher。

为什么 go install google.golang.org/adk/cmd/adk@latest 失败？

因为 2.x 树里没有 cmd/adk 包，CLI 已改名 cmd/adkgo；且 adkgo 没有 version 子命令，查版本请用 go list -m google.golang.org/adk/v2。

运行 Agent 前必须配置什么？

Gemini 路线设 GOOGLE_API_KEY；Vertex AI 路线设 GOOGLE_GENAI_USE_VERTEXAI=true、GOOGLE_CLOUD_PROJECT、GOOGLE_CLOUD_LOCATION 并完成 gcloud auth application-default login。

ADK Go 会自动读 .env 吗？

不会。官方样例统一用 os.Getenv 取值，没有内置 .env 加载器；需要 .env 就自己引入 godotenv 或用 direnv / systemd Environment。

第一个 Agent 怎么跑起来？

go run . console 进控制台；go run . --help 或让程序在报错时打印 l.CommandLineSyntax() 看当前 launcher 支持哪些子命令。
