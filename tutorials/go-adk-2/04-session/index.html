模块 4：会话、事件与上下文压缩

事件是 ADK 的原子。2.x 在这条线上有两处硬变化：造事件必须交 ctx（session.NewEvent(ctx, invocationID)），以及上下文压缩进了框架（session/compaction，2.x 独有包）。

事实边界

  • v1.7.0 的签名是 session.NewEvent(invocationID string) *Event，另有一个临时的 NewEventWithContext(ctx, invocationID)；v2 只保留 NewEvent(ctx, invocationID)。
  • 事件 ID / 时间戳改由 platform 包提供：platform.WithTimeProvider / platform.WithUUIDProvider（第三个接缝是 WithTaskRunner + RunTasks）。session.NewEvent 的注释原文：“This lets callers such as workflow engines produce deterministic, replay-safe events”。
  • 没有 session/event.go：Event、EventActions、RequestInput、NodeInfo、EventCompaction 全在 session/session.go；Service 接口在 session/service.go。
  • EventActions.Compaction 是框架独占：从工具/回调里设无效，调用方 actions 被复制到事件时会被清掉。
  • launcher.Config.Compaction 的官方注释明确：滑窗按常数因子缩减 prompt，只有尾保留真正约束增长；且该设置是进程级，同一 launcher 下所有应用共享同一个 Summarizer 实例与模型。
  • 会话服务：内存版是 session.InMemoryService()（session 包里的函数，没有 session/inmemory 这个包），持久化版是 session/database（GORM 路线，v2.4.0 新增 NewSessionServiceFromDB 构造器）与 session/vertexai。测试还可以用 runner.NewInMemory(appName, agent) 一次把 session/artifact/memory 三个服务全接内存。
  • 状态前缀只有三个：session.KeyPrefixApp / KeyPrefixUser / KeyPrefixTemp（裸键 = 会话级）。Go 版没有 _shared: 前缀，那是 adk-python 的概念，写文章时不要串。
  • 指令模板占位符由 internal/llminternal/instruction_processor.go 解析：{key}、{key?}、{user:key}、{artifact.file}；非法名字原样保留。InstructionProvider 不做模板替换，需要自己调 util/instructionutil.InjectSessionState。
  • google.golang.org/adk/v2 v2.4.0 要求 google.golang.org/genai v1.70.0，该版本 Content.Parts 是 []*genai.Part（不是 []genai.Part）；二进制载荷在 Part.InlineData *genai.Blob{Data, MIMEType}。
