跨语言互操作：`remoteagent.NewA2A` 的默认拒绝策略与两套 metadata 命名空间

ADK Go v2.4.0 的 agent/remoteagent/v2 与 server/adka2a 元数据契约：adk_ 前缀与 a2a: 前缀的双向命名空间、九个被搬运的 action 字段、AllowTransferToAgent 默认 false 的安全理由（远端对等体不得重定向本地编排）、agent card 来源的 origin 校验与 ErrUntrustedCardInterface、aggregatePartial 如何把对端 partial 分片重组成非 partial 事件、artifact 文本折叠规则、RemoteTaskCleanupCallback 默认 5 秒 cancel RPC，以及与 adk-python 互通时的已知缺口。

September 26, 2026 · 9 min · 1833 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 agent/remoteagent/v2/{a2a_agent.go,a2a_agent_run_processor.go,client.go,utils.go}、server/adka2a/v2/{metadata.go,parts.go}。

一、一个远端 agent 就是一个本地 agent.Agent#

import "google.golang.org/adk/v2/agent/remoteagent"

peer, err := remoteagent.NewA2A(remoteagent.A2AConfig{
	Name:                  "translation_agent",
	Description:           "把中文翻成任意目标语言",
	AgentCardProvider:     remoteagent.NewAgentCardProvider("https://translate.example.com"),
})
if err != nil { /* … */ }

root, _ := llmagent.New(llmagent.Config{
	Model: m, Name: "orchestrator",
	SubAgents: []agent.Agent{peer},   // 和本地 sub agent 用法完全一致
})

func NewA2A(cfg A2AConfig) (agent.Agent, error) —— 返回的就是 agent.Agent，所以远端 agent 可以出现在任何接受 agent 的位置：SubAgents、workflow.NewAgentNode、SequentialAgent 的成员。

⚠️ 这也意味着模型可以自主把任务转交给远端 agent（见模块 6 第 2 篇）。一旦这个 agent 上外网，“模型决定调用谁"就变成了"模型决定把哪些数据发出去”。生产里建议用图节点固定它（谁调、传什么都在代码里），或者至少给它加一层 BeforeRequestCallbacks 做出口审查。

两种 card 来源#

// AgentCard is a static agent card. Either AgentCard or AgentCardProvider must be set.
AgentCard *a2a.AgentCard
// AgentCardProvider resolves an agent card on each agent invocation.
// Use [NewAgentCardProvider] to create a provider from a URL or file path.
AgentCardProvider AgentCardProvider
  • NewAgentCardProvider(source, opts...) 会先 classifyCardSource 判断是 URL 还是文件路径：URL 走 agentcard.DefaultResolver.Resolve，文件走 os.ReadFile + json.Unmarshal。
  • provider 是"每次调用都解析"（注释：on each agent invocation），所以 card 里的地址能随部署滚动更新。生产上如果 card 内容稳定，缓存一下更省时间。
  • 文件模式跳过 origin 校验，注释说明理由：“a card read from a local file did not come off the network here, and its target is left to the caller.” —— 本地文件你已经有控制权了，所以别再指望库来保护你。

二、A2AConfig 全字段（按用途分组）#

type A2AConfig struct {
	Name        string
	Description string
	AgentCard           *a2a.AgentCard
	AgentCardProvider   AgentCardProvider
	BeforeAgentCallbacks  []agent.BeforeAgentCallback
	BeforeRequestCallbacks []BeforeA2ARequestCallback
	Converter             A2AEventConverter
	AfterRequestCallbacks []AfterA2ARequestCallback
	AfterAgentCallbacks   []agent.AfterAgentCallback
	AllowTransferToAgent  bool
	A2APartConverter      adka2a.A2APartConverter
	GenAIPartConverter    adka2a.GenAIPartConverter
	ClientProvider        A2AClientProvider
	MessageSendConfig     *a2a.SendMessageConfig
	RemoteTaskCleanupCallback A2ARemoteTaskCleanupCallback
}

三层回调，语义各不相同（这是本模块最容易混的地方）：

层回调注释要点
agent 层BeforeAgentCallbacks / AfterAgentCallbacks与普通 agent 回调同义：返回非 nil content 就跳过 agent 运行
请求层BeforeRequestCallbacks“in the order they are provided until there’s a callback that returns a non-nil result or error. Then the actual request is skipped” → 可以拿来做缓存（直接返回缓存响应）
请求层AfterRequestCallbacks“the actual remote agent event is replaced with the returned result/error” → 记响应、统计 token、预处理的理想位置
转换层Convertera2a.Event → session.Event，不给就用默认的 adka2a.ToSessionEvent（错误会被转成带 error payload 的事件）

BeforeRequestCallbacks 那个"短路即跳过请求"的写法，是 v2.4.0 里少见的明确支持用回调实现缓存的地方。

三、AllowTransferToAgent：默认拒绝的控制流#

注释写得非常直白，值得整段读：

// AllowTransferToAgent controls whether a transfer_to_agent value set by
// the remote A2A peer in its response metadata is honored by the local
// orchestrator.
//
// TransferToAgent drives which agent runs next within the caller's own
// configured multi-agent tree, so accepting it from a remote peer lets
// that peer redirect the local orchestrator's control flow. This
// defaults to false (the peer-supplied value is redacted) so that
// connecting to an agent you do not fully trust is safe by default. Set
// this to true only for closed, trusted deployments that rely on the
// remote peer being able to select the next local agent.
//
// This is applied uniformly after conversion, whether the default
// converter or a custom Converter is used.
AllowTransferToAgent bool

实现（NewA2A 内部）：

// See toEventActions: TransferToAgent is restored here, after
// conversion, only when the caller has opted in via
// AllowTransferToAgent.
if err == nil && event != nil && a2aEvent != nil && cfg.AllowTransferToAgent {
	if transferToAgent, ok := adka2a.TransferToAgentFromMeta(a2aEvent.Meta()); ok {
		event.Actions.TransferToAgent = transferToAgent
	}
}

三条推论：

  1. 默认转换器会把 TransferToAgent 抹掉（toEventActions 阶段不带出来），开启时是在转换之后重新贴回。
  2. “applied uniformly after conversion” —— 你写自定义 Converter 也绕不过这条策略，因为它是转换后统一施加的。这是个真正可靠的安全边界，不是靠转换器自觉。
  3. 打开它的唯一正当理由是"封闭可信部署里，对端确实需要选我本地的下一个 agent"。公网/合作方一律别开。

四、agent card 的 origin 校验：防开放重定向移动信任锚#

NewAgentCardProvider 在 URL 分支上强制校验（文件分支不校验）：

card, err := agentcard.DefaultResolver.Resolve(ctx, source, opts...)
// …
if err := validateCardInterfaceOrigins(card, source); err != nil { return nil, err }

策略原文（注释）：

Every interface the card declares is checked, not only whichever one a
given transport negotiation would select, since any of them could end up
being used. Each must be https, or http on a loopback host (the shape
local-development tooling emits, and a host an attacker who does not
already control this machine cannot redirect a fetch to), and must share
the origin of the configured agent card source -- not necessarily the
origin the fetch actually landed on, if the resolver followed a redirect.
Pinning to the configured source rather than the final URL is
intentional: pinning to wherever a fetch actually lands would let an open
redirect move the trust anchor.

拆成四条规则：

规则内容理由
全量检查card 里每个 SupportedInterfaces 都校验，不是只校验最终会被选中的那个任何一个都可能被用上
scheme必须 https，或 loopback host 上的 httploopback 是本地开发工具的输出形态，而且"不能已经把这台机器交出去的攻击者没法把 fetch 重定向到 loopback"
同 origin必须与你配置的 card source 同 origin而不是 fetch 实际落地的那个 URL
钉配置源故意钉 source，不钉 final URL“pinning to wherever a fetch actually lands would let an open redirect move the trust anchor”

origin 比较也做了归一化（这段是实现细节里的讲究）：

// Comparing url.URL.Host directly, as an earlier version of this check did, treats
// "https://Agent.Example.com" as a different origin from "https://agent.example.com",
// and "https://agent.example.com:443" as different from "https://agent.example.com"
// -- rejecting same-origin cards that spell the port explicitly or the host in a
// different case, even though DNS hostnames are case-insensitive and both name the
// same origin.
func urlOrigin(u *url.URL) (scheme, host, port string)   // host 大小写折叠，缺省端口按 scheme 补全
var defaultPorts = map[string]string{"http": "80", "https": "443"}

并且注释明说这套归一化是与 adk-python 的 _url_origin / _DEFAULT_PORTS 对齐的——跨语言互操作里，两侧的校验严格程度必须一致，否则一边能连一边不能连。

失败错误是 ErrUntrustedCardInterface（errors.Is 可判），带上下文：interface URL %q must use https, or http on a loopback host / does not share the origin of the configured agent card source (%q)。

部署提示：如果你的 card 通过 CDN/网关发布，supportedInterfaces[].url 与 card 的 source 必须同源，否则进程连不上远端。常见踩法是 card 里写了内网地址 http://10.0.0.5:8080/a2a —— 非 loopback + 非 https，直接拒。

五、两套 metadata 命名空间#

ADK 与 A2A 各有自己的 metadata，互转时靠前缀区分归属：

// ToA2AMetaKey adds a prefix used to differentiate ADK-related values stored in Metadata of an A2A event.
func ToA2AMetaKey(key string) string { return "adk_" + key }
// ToADKMetaKey adds a prefix used to differentiate A2A-related values stored in custom metadata of an ADK session event.
func ToADKMetaKey(key string) string { return "a2a:" + key }

被搬运的 action 字段（server/adka2a/v2/metadata.go）：

ADK 侧字段A2A metadata key
Actions.Escalateadk_escalate
Actions.TransferToAgentadk_transfer_to_agent
（错误码）adk_error_code
（是否错误消息）adk_is_error_message
（partial 标志）adk_partial
citationsadk_citation_metadata
groundingadk_grounding_metadata
usageadk_usage_metadata
（自定义）adk_custom_metadata

反向：A2A 特有的值落到 ADK 事件的自定义 metadata 里时带 a2a: 前缀。

两个实用推论：

  1. 跨语言调试时抓包看到 adk_*，说明这是 ADK 语义载荷，不是标准 A2A 字段。第三方（非 ADK）A2A 客户端不会读它们——所以 escalate、transfer_to_agent、partial 这些能力只在 ADK 对等体之间有效。
  2. 反向兼容：你要接非 ADK 的 A2A 服务，就不要依赖这些 key，只按标准 A2A 语义（task/artifact/status message）交互。

adk_partial 的读取方式很特别#

func IsPartialFlagSet(meta map[string]any) bool {
	if meta == nil { return false }
	_, isSet := meta[metadataPartialKey].(bool)
	return isSet
}

只判断 key 存在且是 bool，不看值。因为 Partial: false 在 ADK 侧是零值、不会被序列化出来（addMeta 对 data == nil 直接 return）。所以：

adk_partial 出现就等于"这是 partial"，别去读它的布尔值。

六、aggregatePartial：把对端分片重组成非 partial 事件#

远端流式返回的是 A2A artifact 分片，客户端负责重组（a2a_agent_run_processor.go）：

func (p *a2aAgentRunProcessor) aggregatePartial(ctx agent.InvocationContext, a2aEvent a2a.Event, event *session.Event) []*session.Event

分支表（按代码顺序）：

输入行为
meta 里有 adk_partial原样透传，注释：“ADK partial events should be aggregated by ADK and emitted as a non-partial artifact update. That’s why we skip them regardless of the actual isPartial value. This is the legacy OutputMode.”
TaskStatusUpdateEvent 且状态 Terminal()先把所有缓冲的 artifact 聚合成非 partial 事件依次发出，再发终态事件
*a2a.Task（快照）清空聚合状态（“published a snapshot which should have all the data we potentially aggregated. Reset the aggregation so that it is not published twice."），只发这一个事件
非 TaskArtifactUpdateEvent（即 status update）不聚合，透传
Append == false重置该 artifact 的聚合；若同时 LastChunk 则强制 event.Partial = false 后发出（“non-append event which is the last chunk must already be non-partial”)
Append == true, LastChunk == false累积，透传当前事件
Append == true, LastChunk == true先发当前（partial）事件，紧接着补发一个合成的非 partial 聚合事件

对模块 7 第 9.2 节的正面解答：A2A 客户端已经做了分片重组，所以 Go↔Go 的 A2A 链路不会因为对端流式而天然踩"流以 partial 结束"的坑——除非对端用的是 legacy OutputMode 且没发 LastChunk/terminal。

文本折叠规则#

if part.Text != "" { // collapse small text-block parts to bigger text blocks
	if len(agg.parts) > 0 {
		lastPart := agg.parts[len(agg.parts)-1]
		// check if last part is a text block of the same 'Thought' type
		if lastPart.Text != "" && lastPart.Thought == part.Thought {
			lastPart.Text += part.Text
			continue
		}
	}
	agg.parts = append(agg.parts, &genai.Part{Text: part.Text, Thought: part.Thought})
} else {
	agg.parts = append(agg.parts, part)
}

三条要点：

  1. 只有 Text != "" 的 part 会被折叠（流式 token 是常态），其他类型原样 append。
  2. Thought 标志不同的文本不会合并 —— 思考段和正文段不会被粘成一段。
  3. ⚠️ part.Text == "" 的 part（比如空文本、只有 functionCall 的 part）走 else 分支原样保留，不参与折叠。

这就是"聚合事件数 ≠ A2A 帧数"的原因。统计 token 或计事件数时，用聚合后的 part 数量，别用帧数。

合成事件会重跑回调#

NewA2A 的发射循环里有一段非常细的正确性处理：

for _, toEmit := range processor.aggregatePartial(ctx, a2aEvent, event) {
	// aggregatePartial may synthesize a brand-new non-partial event from buffered
	// partial chunks (the reassembled artifact). That event has not passed through
	// the after-callbacks, so run them here. The pass-through `event` already ran
	// callbacks above; skip it (same pointer) to avoid invoking callbacks on it twice.
	if toEmit != event {
		if cbResp, cbErr := processor.runAfterA2ARequestCallbacks(ctx, toEmit, nil); …
	}
}

用指针相等判断"是不是已经跑过回调的那个事件”。对你的启示：

  • AfterRequestCallbacks 在一次 A2A 帧之后可能被调用多次（原事件 + 合成事件）。做统计/计费时按 event.ID 去重，否则 token 会重复计数。
  • 回调里别写"每次调用自增一次"的假设。

七、远端任务清理：默认 5 秒 cancel RPC#

// RemoteTaskCleanupCallback is called if Run exited before a terminal event was received
// from the remote A2A server. If Run exited due to an error including context cancellation
// it will be passed as cause.
// The context passed to this callback is the original context, but with Err() removed by
// context.WithoutCancel.
// If no callback is provided the default behavior is to make a cancel RPC request with 5
// second timeout.
type A2ARemoteTaskCleanupCallback func(ctx context.Context, card *a2a.AgentCard, client A2AClient, taskInfo a2a.TaskInfo, cause error)

四条：

  1. 触发条件：本地 Run 在收到终态事件之前退出了（含 ctx 取消、报错、上游提前 break）。不做清理会让远端任务继续跑并计费。
  2. 默认行为是发 cancel RPC，超时 5 秒。5 秒这个值写死在注释里，没暴露成参数——要更长就自己实现回调。
  3. ctx 是 context.WithoutCancel(原ctx)（去掉 Err()）。这样回调才能在"因为取消而退出"的情况下继续发 RPC。
  4. ⚠️ 因此回调里不能用 ctx 判断是否被取消（ctx.Err() 永远是 nil）——取消原因只能读 cause 参数。

服务端对称的那条清理回调（ExecutorConfig.A2AExecutionCleanupCallback，额外带 subAgentCards）见第 1 篇第四节 。

八、与 adk-python 互通：三个已知缺口#

这一节是真实联调时最容易浪费时间的地方，全部来自源码注释。

① 哪些东西会跨过边界（服务端视角）#

server/adka2a/v2/metadata.go 里 toInvocationMeta / toEventMeta 定义了这个集合（完整代码见第 1 篇第 5.5 节 ）：

userID, sessionID := "A2A_USER_"+reqCtx.ContextID, reqCtx.ContextID
方向内容
进入你的 agent（对端→你）消息 parts（文本/文件/数据）、ContextID（→ sessionID）、TaskID、对端 metadata、a2a-go 附带的认证身份
你发出（你→对端）事件正文（artifacts / status message）、adk_app_name、adk_user_id、adk_session_id、adk_invocation_id、adk_author、adk_branch、citations/grounding/usage、custom_metadata、error_code、actions（adk_escalate / adk_transfer_to_agent）

三个安全相关的结论：

  1. adk_branch 会把你的内部 agent 层级结构透露给对端（模块 6 里 branch 是 <父>.<子> 形式）。不想露就不要用会写 branch 的并行/图拓扑，或者用自定义 GenAIPartConverter/AfterEventCallback 剔理 metadata。
  2. adk_custom_metadata 把整个 event.CustomMetadata 携出——而 CustomMetadata 是可以被 callback / tool 随便写人的地方。不要把内部提示词、用户敏感字段、内部 ID 写进 CustomMetadata 后就暴露 A2A 服务，它会原样到对端。
  3. session 作域完全由对端的 ContextID 决定。一个恶意/错配的客户端只要在 ContextID 上碰运气，就能读写它“已存在”会话的历史（因为这些 session 真的在你的库里）。所以 A2A 表面必须接入认证（见 config.A2AOptions / 模块 10 第 1 篇），单靠 A2A_USER_ 前缀不是访问控制。

② 长运行 function call 必须靠扩展 metadata 才不被丢#

server/adka2a/v2/extension.go（完整解读在第 1 篇第五节）：

A client that does not find the key may assume artifacts hold the whole response.
An ADK Python client does exactly that, and consequently misses the long-running
function call of an input-required task, synthesizing a
mock_function_call_for_required_user_input in its place.
See https://github.com/google/adk-go/issues/913.

症状：Go 侧发起 input-required，Python 侧回包里出现一个叫 mock_function_call_for_required_user_input 的假函数调用，你真实的那个 adk_request_input 不见了，HITL 链路对不上。

根因：Python 客户端只读 artifacts，而 ADK Go 把长运行 function call 放在 status message 里。

判据：检查响应的 task.metadata / status update metadata 里有没有 https://google.github.io/adk-docs/a2a/a2a-extension/。这也是为什么这个 key 走 metadata 而不是标准扩展头 X-A2A-Extensions（Python 不读那个头），以及为什么光在 agent card 里声明不算数（card 描述请求之前的 agent，客户端读响应的依据来自响应本身）。

③ 部分流不能在对端中途终止#

模块 7 讲过：base_flow 遇到"以 Partial=true 结束"的流会丢弃整个 invocation。而源码注释直接点名 A2A：

This commonly happens when an agent receives a partial event
from a streaming A2A peer and then the stream ends, e.g. due to an error.

跨语言 + 流式组合下，对端异常断流会让本地这一轮历史消失，但 session.Service 里前面几轮已经落盘的部分还在。做重试时要按"这一轮没发生过"来设计，别假设历史完整。

④ 双侧校验强度必须一致#

第四节的 origin 归一化专门对齐了 Python 的 _url_origin。含义：如果 Go 侧连不上而 Python 侧能连，先检查 card 里 URL 的大小写/端口写法——这是校验实现不一致的历史症状，v2.4.0 已经对齐，遇到就说明两侧版本不同步。

九、一份跨语言接入清单#

peer, err := remoteagent.NewA2A(remoteagent.A2AConfig{
	Name: "peer", Description: "…",
	AgentCardProvider: remoteagent.NewAgentCardProvider(cardURL),
	// AllowTransferToAgent: false,   // 明确不开：不要把控制权交给远端
	BeforeRequestCallbacks: []remoteagent.BeforeA2ARequestCallback{egressAudit},  // 出口审查 + 可选缓存
	AfterRequestCallbacks:  []remoteagent.AfterA2ARequestCallback{metricsByName},   // 注意会多次触发
	RemoteTaskCleanupCallback: cancelWithLongerTimeout,
})
if err != nil {
	if errors.Is(err, remoteagent.ErrUntrustedCardInterface) { /* card 地址不合规，别当成网络故障 */ }
}
  • card 的 supportedInterfaces[].url 与 card source 同 origin，且是 https（或 loopback http）
  • 明确决定 AllowTransferToAgent，公网场景保持 false
  • 出口有审查：对端请求内容、invocation_id、branch、author 都会随 metadata 过边界（见第 1 篇第 5.5 节）
  • AfterRequestCallbacks 按"可能多次调用"实现（用 event.ID 去重）
  • 事件数/token 统计基于聚合后的 part，不用 A2A 帧数
  • 清理回调里用 cause 判断退出原因（ctx 已被 WithoutCancel）
  • 与 Python 互通时验证 adk_* metadata 与扩展 key 都在，特别是 input-required 的长运行调用
  • 跨语言流式有异常断流的兜底（本地这一轮可能整轮丢弃）

小结#

模块 9 的两篇是一套协议的正反两面：

  • 服务端（第 1 篇 ）：Executor 把 ADK 事件投影成 A2A 的七步映射，OutputMode 决定 artifact 粒度，ADKExtensionURI 保证内容分散这件事被客户端知道。
  • 客户端（本篇）：remoteagent.NewA2A 把远端投影成本地 agent，同时默认拒绝远端对本地控制流的干预、强制校验 card 的可信 origin、重组分片、清理未完成任务。

到这里，全系列的功能面（模型/工具/会话/图/多 agent/流式/部署/A2A）已经全部走完。最后一章模块 10：生产化 把注册表、鉴权、插件、可观测性拼成一个完整的上线形态。

常见问题

怎么把别的语言的 ADK agent 当本地 agent 用？

remoteagent.NewA2A(remoteagent.A2AConfig{Name, Description, AgentCardProvider: remoteagent.NewAgentCardProvider(cardURL)}) 返回一个普通 agent.Agent，直接塞进 SubAgents 或图节点即可。

远端 agent 能让我的编排转到别的本地 agent 吗？

默认不能。AllowTransferToAgent 默认 false，对端在响应 metadata 里塞的 transfer_to_agent 会被丢掉（redacted）。这是刻意的安全默认：接受它等于让不信任的对端控制你自己的 agent 树走向。

agent card 能被重定向劫持吗？

有防护。fetch 回来的 card 里每个 SupportedInterfaces.URL 必须是 https（或 loopback 上的 http），且必须与你配置的 card source 同 origin。不满足就返回 ErrUntrustedCardInterface。钉的是配置的 source 而不是实际落地的 URL，否则一个开放重定向就能移动信任锚。

对端流式输出的分片怎么处理？

客户端的 aggregatePartial 会按 artifact 缓冲分片，在 terminal 状态或 LastChunk 时合成一个非 partial 事件补发。所以你看到的事件可能比 A2A 帧数少，而且合成事件会重跑 after-request 回调。

远端任务没跑完就退出了会泄漏吗？

默认行为是发一个 5 秒超时的 cancel RPC。要自定义（比如记审计）就给 RemoteTaskCleanupCallback；注意它拿到的 ctx 是原 ctx 去掉 Err()（context.WithoutCancel），所以取消原因要读 cause 参数。

ADK 双方怎么区分哪些 metadata 是自己人的？

两套前缀。ADK 语义写进 A2A metadata 时加 adk_（ToA2AMetaKey），A2A 特有的值存回 ADK 事件自定义 metadata 时加 a2a:（ToADKMetaKey）。
