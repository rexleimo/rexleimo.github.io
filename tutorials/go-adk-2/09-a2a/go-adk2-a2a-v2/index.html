A2A v2 服务端：Executor 的九条事件映射规则，和那张会自动生成的 Agent Card

ADK Go v2.4.0 的 server/adka2a/v2：Executor 把 session.Event 翻译成 a2a.Event 的完整规则（Submitted → Working → ArtifactUpdate{Append:true} → 空 LastChunk → Completed/Failed/InputRequired）、OutputArtifactPerRun 与 OutputArtifactPerEvent 两种产出模式、RunnerProvider 与 plugin 安装的耦合要求、四个回调各自的触发条件、ADKExtensionURI 为什么是 metadata 而不是 Extensions.Activate、BuildAgentSkills 怎么从 agent 树推技能，以及 web launcher 的 a2a 子启动器生成的双协议 agent card。

September 26, 2026 · 8 min · 1692 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 server/adka2a/v2/{executor.go,agent_card.go,extension.go,input_required.go,doc.go,conversions.go}、cmd/launcher/web/a2a/a2a.go，依赖 github.com/a2aproject/a2a-go/v2。

一、包定位：只做一件事#

server/adka2a/v2/doc.go 的包注释：

Package adka2a allows exposing ADK agents via A2A.

NewExecutor returns an a2a-go AgentExecutor. To serve it over HTTP, wrap it
with a2a-go's request handler and transport-specific HTTP handler, such as
[a2asrv.NewHandler] and [a2asrv.NewJSONRPCHandler].

分层很清楚：adka2a 只负责 ADK 事件 → A2A 事件的翻译；HTTP/JSON-RPC 传输由 a2a-go 官方库提供。所以：

executor := adka2a.NewExecutor(adka2a.ExecutorConfig{
	RunnerConfig: runner.Config{AppName: agentName, Agent: root, SessionService: sessSvc},
})
reqHandler := a2asrv.NewHandler(executor, a2aOptions...)   // a2aOptions 来自 launcher.Config.A2AOptions
jsonrpc    := a2asrv.NewJSONRPCHandler(reqHandler)

Executor 满足接口这一条是编译期保证的（源码里就有 var _ a2asrv.AgentExecutor = (*Executor)(nil)），入口：

func (e *Executor) Execute(ctx context.Context, execCtx *a2asrv.ExecutorContext) iter.Seq2[a2a.Event, error]

又是 iter.Seq2——A2A 流式和 ADK 内部事件流用的是同一套迭代器范式，不需要 channel。

二、事件映射契约（九条，来自类型注释原文）#

Executor invokes an ADK agent and translates session.Events to a2a.Events
according to the following rules:
 - If the input doesn't reference any a2a.Task, produce a Task with TaskStateSubmitted state.
 - Right before runner.Runner invocation, produce TaskStatusUpdateEvent with TaskStateWorking.
 - For every session.Event produce a TaskArtifactUpdateEvent{Append=true} with transformed parts.
 - After the last session.Event is processed produce an empty TaskArtifactUpdateEvent{Append=true}
   with LastChunk=true, if at least one artifact update was produced during the run.
 - If there was an LLMResponse with non-zero error code, produce a TaskStatusUpdateEvent with
   TaskStateFailed. Else if there was an LLMResponse with long-running tool invocation, produce a
   TaskStatusUpdateEvent with TaskStateInputRequired. Else produce a TaskStatusUpdateEvent with
   TaskStateCompleted.

排成时间线（这是排查跨语言问题的唯一地图）：

#A2A 事件状态/标志触发时机
1TaskSubmitted输入没引用任何已有 task 时
2TaskStatusUpdateEventWorking紧挨在 runner.Run 之前
3TaskArtifactUpdateEventAppend=true每个 session.Event 一条（含转换后的 parts）
4TaskArtifactUpdateEventAppend=true, LastChunk=true（空 body）最后一条事件处理完之后，且本轮至少产出过一个 artifact
5TaskStatusUpdateEventFailed有 LLMResponse 的 error code 非零
6TaskStatusUpdateEventInputRequired有 LLMResponse 带长运行工具调用
7TaskStatusUpdateEventCompleted以上都不成立

三条必须由映射规则推出的结论：

  1. InputRequired 判定用的是"长运行工具调用"，不是 Event.RequestedInput。也就是模块 5 的 HITL（adk_request_input）与模块 3 的工具确认（adk_request_confirmation）在 A2A 侧统一表现为"有个长运行工具还没回"——因为 NewRequestInputEvent 确实会写 ev.LongRunningToolIDs = []string{req.InterruptID}（模块 5 第 5 篇第④步）。两套暂停协议在 A2A 边界收敛成一条。
  2. 规则 3 是"每个 session.Event" → 结合模块 7 的流式：partial 事件也会各出一条 artifact update（Append=true 天然做增量）。
  3. 收尾的 LastChunk 是"空事件"，只在产出过 artifact 时才有。客户端不能把"收到 LastChunk"当"一定有内容"。

三、OutputMode：一个 artifact 还是多个#

const (
	// OutputArtifactPerRun produces a single artifact per runner.Runner.Run.
	OutputArtifactPerRun OutputMode = "artifact-per-run"
	// OutputArtifactPerEvent produces an artifact per non-partial session.Event.
	// While agent is emitting events an artifact is build incrementally (parts are append to it).
	// The next partial event replaces accumulated contents and seals the artifact, meaning
	// the next event from this agent will create a new artifact.
	OutputArtifactPerEvent OutputMode = "artifact-per-event"
)
默认 artifact-per-runartifact-per-event
artifact 数整轮 1 个每个非 partial 事件 1 个
增量方式parts 持续 appendappend 到当前 artifact；遇到 partial 事件则用累积内容替换并 seal
语义“这轮的回答”“每个 agent 各说了什么”
适合单 agent、只要最终答复多 agent 协作、图工作流要保留阶段边界

⚠️ per-event 那句 “The next partial event replaces accumulated contents and seals the artifact” 有个反直觉后果：partial 事件是"封条"而不是"追加"。流式跑图时你会看到"每次开始新片段就切一个 artifact"，数量可能远多于 agent 数。别按 artifact 数推断 agent 数。

四、ExecutorConfig：九个字段各自能干什么#

type ExecutorConfig struct {
	RunnerConfig              runner.Config      // 默认 provider 用它调 runner.New；设了 RunnerProvider 就被忽略
	RunnerProvider            RunnerProvider     // 控制 runner 怎么建（每请求一个）
	RunConfig                 agent.RunConfig    // 传给 runner.Run 的配置
	BeforeExecuteCallback     BeforeExecuteCallback
	AfterEventCallback        AfterEventCallback
	AfterExecuteCallback      AfterExecuteCallback
	A2APartConverter          A2APartConverter   // A2A part → genai.Part
	GenAIPartConverter        GenAIPartConverter // genai.Part → A2A part
	OutputMode                OutputMode         // 默认 artifact-per-run
	A2AExecutionCleanupCallback A2AExecutionCleanupCallback
}

RunnerProvider：唯一的强约束#

type Runner interface {
	Run(ctx context.Context, userID, sessionID string, msg *genai.Content, cfg agent.RunConfig) iter.Seq2[*session.Event, error]
}
type RunnerProvider func(ctx context.Context, reqCtx *a2asrv.ExecutorContext, plugin *plugin.Plugin) (RunnerConfig, Runner, error)

注释里那句是硬要求：“The provided plugin must be installed in the returned Runner for callbacks taking ExecutorContext to work correctly.”

也就是说：自定义 RunnerProvider 时必须把传进来的 plugin 装进你的 Runner（runner.Config.PluginConfig），否则 AfterEventCallback / AfterExecuteCallback / A2AExecutionCleanupCallback 拿不到 ExecutorContext——不报错，只是上下文为空。这是最容易静默失效的一个坑。

RunnerConfig（provider 要回传的那个小结构）里也只有三样：AppName（同时用于 session key 和 A2A 事件 metadata）、Agent（根 agent）。

注意 Runner 接口的 Run 签名没有 opts ...RunOption —— 自定义 provider 用不了 runner.WithStateDelta / WithYieldUserMessage（模块 4 提过）。要在 A2A 表面注入 state delta，得走 BeforeExecuteCallback 改 ctx 或自己扩展。

四个回调的触发条件（注释精确说明）#

type BeforeExecuteCallback   func(ctx context.Context, reqCtx *a2asrv.ExecutorContext) (context.Context, error)
type AfterEventCallback      func(ctx ExecutorContext, event *session.Event, processed *a2a.TaskArtifactUpdateEvent) error
type AfterExecuteCallback    func(ctx ExecutorContext, finalEvent *a2a.TaskStatusUpdateEvent, err error) error
type A2AExecutionCleanupCallback func(ctx context.Context, reqCtx *a2asrv.ExecutorContext, subAgentCards []*a2a.AgentCard, result a2a.SendMessageResult, cause error)
回调时机能做什么注意事项
BeforeExecuteCallback执行开始前加工 ctx，或返回 error 直接阻止执行返回值会替换 ctx，可用来注入租户信息
AfterEventCallback单个事件成功转换后给事件补 metadata；返回 error 中止执行注释明确：ADK 自身错误与事件处理错误不走这个回调（那些会变成 TaskStateFailed），要拦那种错误得用 AfterExecuteCallback
AfterExecuteCallback执行落成 completed/failed 之后补 metadata、记日志拿到的是终态事件 + err，这里是审计点
A2AExecutionCleanupCallback执行或取消结束（含失败）后清理不提供时默认行为是"把失败原因记日志"；参数里带 subAgentCards，说明它也是子 agent 资源回收点

AfterEventCallback 收的是转换后的 *a2a.TaskArtifactUpdateEvent，改它不会影响 ADK 侧的 session.Event（后者只是作为第二参数供参考）。

自定义 part 转换器#

// Implementations should generally remember to leverage adka2a.ToGenAiPart for default conversions
// nil returns are considered intentionally dropped parts.
type A2APartConverter func(ctx context.Context, a2aEvent a2a.Event, part *a2a.Part) (*genai.Part, error)
type GenAIPartConverter func(ctx context.Context, adkEvent *session.Event, part *genai.Part) (*a2a.Part, error)

nil 返回 = 有意丢弃这个 part，不是错误。 想加自定义类型（比如把内部 widget part 转成 A2A data part）就在这里做，其余分支记得回落 ToGenAiPart/ToA2APart，否则会把你不想改的类型也吞掉。

五、ADKExtensionURI：一个 metadata key 修复的跨语言事故#

这是我在 v2.4.0 里读到的最有价值的一段注释，逐句拆：

// ADKExtensionURI identifies the ADK A2A integration extension.
//
// [Executor] writes it as a metadata key on every task and task status update
// it emits. The key tells a client that the payload follows ADK conventions:
// content is spread across task artifacts and the status message, with
// long-running function calls carried by the latter.
//
// A client that does not find the key may assume artifacts hold the whole
// response. An ADK Python client does exactly that, and consequently misses the
// long-running function call of an input-required task, synthesizing a
// mock_function_call_for_required_user_input in its place. See
// https://github.com/google/adk-go/issues/913.
//
// The key is metadata rather than an [a2asrv.Extensions.Activate] call because
// activation is reported through the X-A2A-Extensions response header, which an
// ADK Python client does not read. Declaring the extension in an
// [a2a.AgentCard] is not a substitute either: the card describes an agent
// before a request, and clients pick how to read a response from the response
// itself.
const ADKExtensionURI = "https://google.github.io/adk-docs/a2a/a2a-extension/"

四层信息量：

  1. ADK 的响应内容天然是分散的：正文在 artifacts，长运行工具调用在 status message。标准 A2A 客户端默认"artifacts 就是全部"，于是丢掉 input-required 需要的那个 function call，退化成 mock_function_call_for_required_user_input（issue #913）。
  2. 这个 key 就是那条"要读 status message"的暗号，写在每个 Task 和 TaskStatusUpdateEvent 的 metadata 上。
  3. 为什么不用标准扩展协商（Extensions.Activate）：因为激活结果通过 X-A2A-Extensions 响应头回传，而 adk-python 客户端不读那个头。
  4. 为什么光在 agent card 里声明也不够：card 描述的是"请求之前的 agent"，而客户端决定怎么解读响应是靠响应本身。

实现上还有个精确性要求：

// Only tasks and task status updates qualify: a2a merges status update metadata
// into the task, while artifact update metadata is merged into the artifact.
func addADKExtensionMeta(event a2a.Event) {
	switch v := event.(type) {
	case *a2a.Task:                 v.Metadata = metaWithADKExtension(v.Metadata)
	case *a2a.TaskStatusUpdateEvent: v.Metadata = metaWithADKExtension(v.Metadata)
	}
}

只有这两种事件的 metadata 会被写到客户端读得到的地方（a2a 会把 status update 的 metadata 合并进 task；artifact update 的 metadata 只会进 artifact）。所以你自己写转换层时，别指望 artifact 上的 metadata 能被通用客户端看到。

Execute 的第一行动作就是 yield = withADKExtensionMeta(yield)——包住下游 yield，所以任何出口事件都带上它。

agent card 侧也同步声明了它（见下一节），两边都有，但客户端真读的是响应里的那个。

五点五、身份映射：ContextID 就是 sessionID#

server/adka2a/v2/metadata.go 的 toInvocationMeta 定义了 A2A 请求如何映射到 ADK 的 (user, session)：

userID, sessionID := "A2A_USER_"+reqCtx.ContextID, reqCtx.ContextID

// a2a sdk attaches authn info to the call context, use it when provided
if callCtx, ok := a2asrv.CallContextFrom(ctx); ok {
	if callCtx.User != nil && callCtx.User.Name != "" {
		userID = callCtx.User.Name
	}
}

meta := map[string]any{
	ToA2AMetaKey("app_name"):   config.AppName,
	ToA2AMetaKey("user_id"):    userID,
	ToA2AMetaKey("session_id"): sessionID,
}

四条：

  1. sessionID = 对端的 ContextID —— 会话连续性完全由客户端掌控。同一个 ContextID 就是同一个会话（模块 4 的多轮记忆因此自动成立）。
  2. userID 默认是 "A2A_USER_" + ContextID 拼出来的，不是真实用户。它只是一个隔离前缀，不是身份。
  3. 有认证时以认证主体覆盖：a2a-go 会把 authn 信息挂在 CallContext 上，callCtx.User.Name 非空就用它。所以 userID 能否相信，取决于你有没有配 A2A 认证（launcher.Config.A2AOptions）。
  4. 这三个值（app_name / user_id / session_id）会作为 adk_* metadata 回写到每个事件上 —— 跨语言抓包时凭它们定位会话。

toEventMeta 还会附加（均为非空才写）：

for k, v := range map[string]string{
	"invocation_id": event.InvocationID,
	"author":        event.Author,
	"branch":        event.Branch,
} { if v != "" { result[ToA2AMetaKey(k)] = v } }
// 另加：citations / grounding / usage / custom_metadata / error_code

⚠️ branch 与 custom_metadata 会过河，这是最容易漏的两个数据出口，安全含义见第 2 篇第九节 。

六、launcher 自动生成的 agent card#

cmd/launcher/web/a2a 的 SetupSubrouters 里直接构造（这就是你线上 /agent-card.json 的内容）：

rootAgent := config.AgentLoader.RootAgent()
agentCard := &a2acore.AgentCard{
	Name:               rootAgent.Name(),
	Description:        rootAgent.Description(),
	DefaultInputModes:  []string{"text/plain"},
	DefaultOutputModes: []string{"text/plain"},
	SupportedInterfaces: []*a2acore.AgentInterface{
		{URL: publicURL,      ProtocolBinding: a2acore.TransportProtocolJSONRPC, ProtocolVersion: a2acore.Version},
		{URL: publicCompatURL, ProtocolBinding: a2acore.TransportProtocolJSONRPC, ProtocolVersion: a2av0.Version},
	},
	Version:        "2.0.0",
	Skills:         adka2a.BuildAgentSkills(rootAgent),
	Capabilities: a2acore.AgentCapabilities{
		Streaming: true,
		Extensions: []a2acore.AgentExtension{{
			URI: adka2a.ADKExtensionURI,
			Description: "Content is spread across task artifacts and the status message, which carries long-running function calls.",
		}},
	},
}

六条要点：

  1. 双接口，双协议版本：一份是当前 A2A 版本（a2acore.Version），一份是 v0 兼容（a2av0.Version），分别挂 apiPath 与 compatAPIPath：

    router.Handle(apiPath,        a2asrv.NewJSONRPCHandler(reqHandler))
router.Handle(compatAPIPath,  a2av0.NewJSONRPCHandler(reqHandler))
router.Handle(a2asrv.WellKnownAgentCardPath, a2asrv.NewAgentCardHandler(compatProducer))

    同一个 executor 服务两个协议版本，老客户端也能连。

  2. Version: "2.0.0" 是硬编的字符串（card 里的版本，不是模块版本）。

  3. 输入输出模式默认只有 text/plain —— 想让对端发图片/音频给你，要么改 card（自己写 producer），要么清楚这层声明会影响对端的发送选择。

  4. Streaming: true。

  5. Skills 由 BuildAgentSkills(rootAgent) 从 agent 树推导：

    func BuildAgentSkills(agent agent.Agent) []a2a.AgentSkill {
    return slices.Concat(buildPrimarySkills(agent), buildSubAgentSkills(agent))
}

    主 agent + 子 agent 各出一批技能，所以你的 agent 层次结构会通过 agent card 泄露给外部（含各层 Description）。对外暴露前先看一眼 card 长什么样。

  6. 顺带一个细节：描述文本会做人称改写（"You are" → "I am"、"your" → "my"），因为 agent 的 Description 是按"对模型下指令"的口吻写的，card 要按"自我介绍"的口吻给外部看。

七、启动即校验：compaction dry-run#

a2a 子启动器第一件事是拒绝不可服务的压缩配置：

// Refuse a compaction config this surface cannot serve, before it serves
// anything. A config can pass its own shape check and still be unservable,
// the plainest case being no Summarizer over a root agent with no model to
// default to, and without this the process starts healthy and then fails
// every request. The other surfaces do the same dry run.
if err := compactionvalidate.AgainstRootAgent(config.Compaction, config.AgentLoader.RootAgent(), runner.Config{…}); err != nil {
	return err
}

“能过自身形状检查 ≠ 能为这个 agent 服务”——最典型的坏配置：Config.Validate() 通过（形状合法）但你没给 Summarizer，而根 agent 也没有可回落的默认模型。这条 dry-run 让进程启动就失败，而不是"起来健康、每个请求都炸"。

模块 8 讲过触发器有同样的校验（AgainstAgents）——四个表面（web/api/a2a/triggers）都做 dry-run，这是 ADK Go v2.4.0 的一致性设计，你自己的入口也应该照做。

八、HandleInputRequired：把对端的回答路由回函数调用#

// HandleInputRequired checks if the input message contains responses to all function calls
// … If a non-nil event is returned the invoking code needs to use the event as the result
// of the execution
func HandleInputRequired(reqCtx *a2asrv.ExecutorContext, content *genai.Content) (*a2a.TaskStatusUpdateEvent, error)

注释里还有一条会影响你事件流的细节：

If a part was incorporated into the final task status update the original event
is modified to not include it,

被吸收进 status message 的 part 会从原事件里被删掉（避免同一内容在 artifact 和 status message 里出现两次）。所以调试时"ADK 侧有、A2A 侧 artifact 里没有"不一定是 bug，可能是这里被挪走了。

“必须回所有 function call 的响应” 这条对客户端很重要：一次 input-required 里若有两个待决调用（比如工具确认 + 业务输入），只回一个会被判为未满足。模块 5 的"一次激活最多一个 RequestedInput“在这里帮了你，但工具确认和输入请求是两套，仍可能同时存在。

九、上手与验证#

# 起服务
go run ./myagent web api a2a

# 看 card（路径来自 a2asrv.WellKnownAgentCardPath）
curl -s localhost:8080/api/.well-known/agent-card.json | jq '.name, .version, .capabilities, (.supportedInterfaces|length), (.skills|length)'

# 两个调用端点（都在 -path_prefix 下，默认 /api）
#   POST /api/a2a/v1/invoke   ← apiPath，当前 A2A 协议版本
#   POST /api/a2a/invoke      ← compatAPIPath，v0 兼容

源码里就是两个常量：

const apiPath = "/a2a/v1/invoke"
const compatAPIPath = "/a2a/invoke"

再看响应 metadata 里有没有扩展 key（第五节）：

curl -s ... | jq '.result.status.message.parts'
curl -s ... | jq '.result.metadata'

看到 "https://google.github.io/adk-docs/a2a/a2a-extension/" 出现在 task / status 的 metadata 里，才说明对端有机会正确读取长运行 function call。

自检清单#

  • 明确选了 OutputMode，并按它解释 artifact 数量
  • 自定义 RunnerProvider 时把传入的 plugin 装进了 Runner
  • 拦截"ADK 自身错误"用 AfterExecuteCallback，不是 AfterEventCallback
  • 自定义 part 转换器回落了 ToGenAiPart/ToA2APart，且知道 nil = 丢弃
  • 确认客户端会读 task metadata 里的 ADKExtensionURI（否则 input-required 会退化成 mock 调用）
  • 对外暴露前检查 agent card：BuildAgentSkills 会把子 agent 结构公开
  • 输入输出模式与实际需求匹配（默认只有 text/plain）
  • 启动路径保留 compaction dry-run，失败就别起服务
  • 一次 input-required 回答所有待决 function call

常见问题

ADK Go 怎么把 agent 暴露成 A2A 服务？

两条路。省事的是 web launcher 加 a2a 关键字（go run ./myagent web api a2a），它自动建 executor + agent card + JSONRPC handler；要自定义就 adka2a.NewExecutor(adka2a.ExecutorConfig{RunnerConfig: runner.Config{…}}) 再自己套 a2asrv.NewHandler / NewJSONRPCHandler。

一次 agent 运行在 A2A 侧会看到几个事件？

默认（artifact-per-run）：一个 Submitted 的 Task、一个 Working 的 TaskStatusUpdateEvent、每个 session.Event 一个 TaskArtifactUpdateEvent{Append:true}、若产出过 artifact 再补一个空的 LastChunk=true，最后按情况给 Completed / Failed / InputRequired。

OutputArtifactPerEvent 和 OutputArtifactPerRun 怎么选？

默认 per-run（整个运行一个 artifact）。per-event 是每个非 partial 的 session.Event 出一个 artifact，遇到 partial 事件就把已累积内容替换掉并 seal——多 agent 协作时用它区分"谁说的"。

为什么我的 A2A 客户端拿不到长运行工具调用？

看 task metadata 里有没有 ADKExtensionURI 这个 key。它说明内容分散在 artifacts 与 status message 两处；没有这个 key 的客户端（例如当前 adk-python）会假定 artifacts 就是全部响应，从而错过 input-required 的长运行 function call。

A2A 表面能开上下文压缩吗？

能配，但启动时会做 dry-run 校验：compactionvalidate.AgainstRootAgent 不通过就直接拒绝启动。原因是一个能过自身形状检查的配置仍然可能不可服务（最常见是没 Summarizer 且根 agent 没有默认模型）。

agent card 里的 skills 要手写吗？

launcher 路径下不用，它调 adka2a.BuildAgentSkills(rootAgent) 从 agent 树推导（自身 + 子 agent）。手写 card 时才需要自己填。
