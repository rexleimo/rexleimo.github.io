路由与条件执行：Default 的真实语义、静默死路，和一条被去重的边

ADK Go v2.4.0 的条件执行：Route 接口如何读 event.Routes、StringRoute/IntRoute/BoolRoute/MultiRoute/Default 五种匹配的精确规则、findSuccessors 的四条调度语义（无条件边不抑制 Default、Default 在无具体路由命中时触发、全部落空且无 Default 时静默死路、同目标去重）、每激活一条路由事件的硬约束（ErrMultipleRoutingEvents/ErrMultipleOutputs/ErrMultipleTerminalOutputs）、FunctionNode 返回 *session.Event 才能自带路由这条隐式行为，以及扇出时的 branch 推导。

September 26, 2026 · 4 min · 657 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 workflow/{workflow.go,scheduler.go,function_node.go,validation.go}。

路由是图引擎里唯一能把执行权交给数据的机制，也是文档最少、语义最容易被猜错的一块。所有规则都来自一个函数 findSuccessors 的注释——我把它拆成可执行的条目。

机制：事件携带字符串，边消费字符串#

// Route 接口只有一个方法
type Route interface {
	Matches(event *session.Event) bool
}

// 匹配实现：线性扫 event.Routes 做字符串相等
func matchRoute(routeValue string, event *session.Event) bool {
	for _, v := range event.Routes {
		if v == routeValue { return true }
	}
	return false
}

所以节点负责"我是哪条路"，边负责"哪条路去哪个节点"。两侧都是纯数据，没有表达式语言。

节点侧只有一行：

func classify(ctx agent.Context, in string) (*session.Event, error) {
	ev := session.NewEvent(ctx, ctx.InvocationID())
	ev.Output = in
	if urgentRe(in) {
		ev.Routes = []string{"urgent"}
	} else {
		ev.Routes = []string{"normal"}
	}
	return ev, nil
}

五种 Route，精确规则#

类型比较方式写法示例
StringRoute原样字符串StringRoute("urgent")
IntRoutefmt.Sprint(r)，按十进制字符串比IntRoute(2) ↔ Routes: ["2"]
BoolRoute"true"/"false" 字符串形式BoolRoute(true) ↔ Routes: ["true"]
MultiRoute[T comparable]列表里任一值命中即命中（同样 fmt.Sprint）MultiRoute[string]{"a","b"}
DefaultMatches 恒为 false，由 scheduler 特殊识别{From: c, To: fallback, Route: workflow.Default}

两个坑：

  1. IntRoute/BoolRoute 是字符串比较。事件里写 "02" 配 IntRoute(2) 不匹配（fmt.Sprint(2) == "2"）。跨语言录制的事件回放时尤其要注意（模块 9 会碰到）。
  2. MultiRoute[T] 的 T 是 comparable，混用不同类型会各自 fmt.Sprint，MultiRoute[any]{1, "1"} 会匹配同一个值两次。别这么写。

findSuccessors 的四条规则#

注释原文逐条拆开：

① Edges with no Route always fire (and do not suppress Default).
② Edges with a concrete Route fire only if Route.Matches(event) is true.
③ Duplicate To targets are deduplicated (same target node may not be
   queued twice for one parent activation).
④ The Default edge fires when no concrete Route matched. An unconditional
   edge does not count as a "match" for this purpose, so a graph with one
   unconditional edge and one Default edge fans out to both targets.

再加一条最反直觉的：

⑤ If every outgoing edge has a concrete Route and none matched, and no
   Default is present, the workflow silently dead-ends at this node.
   The absence of a matching route is treated as a deliberate decision
   not to continue, not an error.

第 ④ 条画重点：Default 只被"具体路由是否命中"控制，无条件边不参与这个判定。所以：

{From: a, To: b},                              // 无条件：总是跑
{From: a, To: c, Route: workflow.Default},     // 没有具体路由命中时跑
// 结果：a 完成后 b 和 c 都会跑（扇出！）

想让 Default 成为"唯一的兜底"，就必须给同节点的其他所有出边都加具体路由（第 ⑤ 条那种"全部有条件"的形态）。

第 ③ 条是 ErrDuplicateEdge 的另一面：(From,To) 相同在建图时就被拒，所以"同一目标多个条件"只能靠 MultiRoute 表达（校验注释直接给了这个指引）；而运行时即便出现两个不同来源指到同一目标、又被同一激活命中，也会被去重成一次。

第 ⑤ 条是生产事故高发区：所有边都有条件、一个都没命中 → 不报错，静静结束。图"没跑完"和"跑完了但提前结束"在事件流上看不出区别。防御办法只有一条：每个出度 >0 的节点，要么留一条无条件边，要么留一条 Default。

三条"一次激活只能有一个"的硬约束#

ErrMultipleOutputs        // 一条激活只能有一个事件带 Output
ErrMultipleRoutingEvents  // 一条激活只能有一个事件带 Routes
ErrMultipleTerminalOutputs// 多个终结节点都出了 output → 工作流 output 有歧义

三个都定义在 scheduler.go（注意：不在 errors.go，找的时候别只翻 errors.go）。

handleEvent 里的实现细节值得知道：

if it.ev.Routes != nil {
	nr.setRoutingEvent(it.ev, it.nodeName)   // 已存在则报 ErrMultipleRoutingEvents
}

判的是 != nil，不是 len(...) > 0。所以 ev.Routes = []string{}（空切片但非 nil）会被当作"这条激活的路由事件"，再发第二条就报错——想要"没有路由决策"就别碰这个字段，保持 nil。

还有一条：Routes: []string{} 会让 Default 不触发（因为已经有路由事件且 Matches 都失败）。上面 matchRoute 扫空切片必然 false，concreteMatched 取决于边上是否有具体路由……空切片 + 具体路由边 = 全落空 = 第 ⑤ 条静默死路。这是我见过最难查的一类图 bug，写进自检清单。

子孙事件的归属也在这段逻辑里：NodeInfo.Path != 当前节点名 的事件是动态节点转发的子事件，它们的 Output/Routes 归子节点，不进气父节点的累加器。例外只有 RequestedInput——子的暂停会解开父的执行，父必须转成 NodeWaiting，否则 Resume 的 InterruptID 对不上。

让 FunctionNode 能自带路由#

FunctionNode.Run 的返回类型分派（源码顺序）：

if ev, ok := output.(*session.Event); ok { yield(ev, nil); return }   // ← 直接转发，Routes 保留
if c, ok := output.(*genai.Content); ok { event.Content = c }
else if c, ok := output.(genai.Content); ok { event.Content = &c }
else { event.Output = output }

注释点明了设计意图：“This ensures that a custom FunctionNode can explicitly route its output (via event.Routes) to select conditional successors.”

于是三种返回类型有三种语义：

返回类型落到事件哪里能设 Routes 吗
*session.Event原样 yield✅ 唯一途径
*genai.Content / genai.Contentevent.Content❌
其他任何值event.Output❌

⚠️ 代价：返回 *session.Event 时下游的 input 就是整个事件（Output 得自己塞进 ev.Output，否则后继拿不到值）。所以"只是想给个 output"就别用事件返回；“要路由"才用。

流式/多事件节点（NewEmittingFunctionNode）同理：自己 emit 带 Routes 的事件，最后返回的 OUT 会成为 output——注意别 emit 两条带 Routes 的，直接撞 ErrMultipleRoutingEvents。

扇出时的 branch 怎么算#

路由决定"谁跑”，branch 决定"他们互相能看见什么"。findSuccessors 尾部三条规则：

  • 单后继：直接继承父 branch，不加东西；
  • 扇出到 >1 后继：每个非 Join 后继打上 <parentBranch>.<successorName>@1；
  • JoinNode 后继：自己算——取所有已完成前驱 branch 的公共点前缀（commonBranchPrefix）。

这里的 @1 是固定 run id（注释解释：静态调度器不做同名片段的自动计数；循环回同一节点时子 branch 保持稳定）。

为什么这很重要：分支上挂着 LLM agent 时，branch 决定它能在 prompt 历史里看到谁（模块 4 第 2 篇）。扇出后兄弟分支互不可见是默认行为，不是配置出来的——反过来，如果你希望两个并行分支共享上下文，就得避免触发扇出的 sub-branch 分裂（比如改成串行，或都挂在同一无条件链上）。

让 LLM 来选路（下一篇详述）#

图引擎只提供 Routes 这个数据面。“谁决定 routes"是你的节点实现的——三种常见做法：

// ① 规则：函数节点里 if/switch（本例）
// ② schema 分类：agent 节点带 OutputSchema，节点函数按输出字段填 Routes
// ③ LLM 直接选：让 agent 输出一个枚举，再由一层 FunctionNode 翻译成 Routes

第 ②③ 种涉及 AgentNode 的输出投射和协作式 agent 的 transfer 语义，见模块 6：多 Agent 新范式 。

自检清单#

  • 每个出度 >0 的节点：有 Default 边或有至少一条无条件边（防第 ⑤ 条静默死路）
  • 同节点没有两条 (From,To) 相同的边（ErrDuplicateEdge）
  • 一次激活只发一条带 Routes 的事件，且不需要路由时保持 nil
  • IntRoute/BoolRoute 对应的 Routes 值是 fmt.Sprint 形式（"2" 而非 "02"）
  • 用 *session.Event 返回时，同时设置了 ev.Output
  • 有条件路由进 JoinNode 吗？——不该有（第 2 篇的屏障语义）

常见问题

ADK Go 图工作流怎么做条件分支？

节点在发出的事件上写 ev.Routes = []string{"urgent"}，边上写 Route: workflow.StringRoute("urgent")。scheduler 拿事件的 Routes 逐条比对边上的 Route。

workflow.Default 是怎么匹配的？

它的 Matches 永远返回 false——Default 不走 Matches。scheduler 单独识别 edge.Route == Default，只有在"没有任何具体路由命中"时才触发它。

无条件边会挡住 Default 吗？

不会。注释明说：无条件边总是触发，且不算作"match"。所以一条无条件边 + 一条 Default 边 = 扇出到两个目标。

所有路由都没命中会怎样？

静默死路（前提是没有 Default）。注释："The absence of a matching route is treated as a deliberate decision not to continue, not an error." 这是设计，不是 bug——所以要给兜底边。

同一个节点能发多条带路由的事件吗？

不能。ErrMultipleRoutingEvents；同理一条激活只能有一个 output（ErrMultipleOutputs），多个终结节点出 output 会报 ErrMultipleTerminalOutputs。

为什么我的 FunctionNode 设了 Routes 不生效？

要让路由生效必须返回 *session.Event（自己写 ev.Routes/ev.Output）——FunctionNode 检测到返回类型是 *session.Event 就直接 yield 它。返回普通值时框架会自己造事件，路由没地方写。
