节点类型全解：Node 接口九个方法、六种内置节点，和 NodeConfig 的三态指针

ADK Go v2.4.0 图引擎的节点层：workflow.Node 九个方法的调用时机、BaseNode 与自定义节点、FunctionNode 家族四种构造器（含 FromState 的 state 参数绑定与 node_input 逃生口）、EmittingFunctionFn、AgentNode/ToolNode/JoinNode/WorkflowNode/ParallelWorker 各自的构造器与语义，以及 NodeConfig 七个字段（ParallelWorker/RerunOnResume/WaitForOutput/RetryConfig/Timeout/EmitsOwnSpan）为什么用指针。

September 26, 2026 · 4 min · 782 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 workflow/{workflow.go,base_node.go,config.go,function_node.go,agent_node.go,tool_node.go,join_node.go,parallel_worker.go,workflow_node.go,dynamic_node.go}。

模块 1 我说过：在 Go 里工作流图就是一等 Agent。这一篇讲最小执行单元——节点。

Node 接口：九个方法，两个校验钩子#

type Node interface {
	Name() string
	Description() string
	Config() NodeConfig
	InputSchema() *jsonschema.Resolved        // nil = 无 schema，不校验输入
	OutputSchema() *jsonschema.Resolved       // nil = 不校验输出
	ValidateInput(input any) (any, error)     // 每次激活、Run 之前
	ValidateOutput(output any) (any, error)   // 每个带非 nil output 的事件、转发之前
	Run(ctx agent.Context, input any) iter.Seq2[*session.Event, error]
}

注意几件事：

  1. schema 类型是 *jsonschema.Resolved（github.com/google/jsonschema-go/jsonschema），不是 genai.Schema。构造器收的是 *jsonschema.Schema，内部 Resolve(nil) 后才存。这也是模块 3 里那条"两套 schema 类型"的延续。
  2. ValidateInput 的返回值可能是被转换过的（注释：“might be coerced/parsed/transformed”）。也就是说校验器有权把 map[string]any 反序列化成你的强类型——别在 Run 里再转一遍，直接用节点给的类型。
  3. Run 返回 iter.Seq2[*session.Event, error]，不是 channel。所以节点体内是"边算边 yield"，取消靠 yield 返回 false。

BaseNode 把前七个方法全实现好了：

type MyNode struct{ workflow.BaseNode }

func NewMyNode(name string) *MyNode {
	return &MyNode{BaseNode: workflow.NewBaseNode(name, "my node", workflow.NodeConfig{})}
}
// 带 schema 版（注意：这里收的是已 Resolve 的 *jsonschema.Resolved，而且不返回 error）：
//   resolved, err := (&jsonschema.Schema{Type: "object"}).Resolve(nil)
//   workflow.NewBaseNodeWithSchemas(name, desc, cfg, resolved, nil)

func (n *MyNode) Run(ctx agent.Context, input any) iter.Seq2[*session.Event, error] {
	return func(yield func(*session.Event, error) bool) {
		ev := session.NewEvent(ctx, ctx.InvocationID())
		ev.Output = strings.ToUpper(input.(string))
		if !yield(ev, nil) {
			return
		}
	}
}

接口注释原话：“Custom nodes typically embed BaseNode … and supply only Run.”

⚠️ 一个不一致点（实测才发现）：NewBaseNode 与 NewBaseNodeWithSchemas 都不返回 error，后者入参是已解析的 *jsonschema.Resolved；而 NewFunctionNodeWithSchema / NewAgentNodeWithSchemas / NewToolNodeWithSchemas 这类构造器收的是未解析的 *jsonschema.Schema 并返回 error（因为内部要 Resolve）。同一个包里两种风格，自定义节点要自己先 Resolve。

FunctionNode 家族：四种构造器#

// ① 最常用：泛型入出参，schema 自动推断
wf := workflow.NewFunctionNode("normalize",
	func(ctx agent.Context, in string) (string, error) { return strings.TrimSpace(in), nil },
	workflow.NodeConfig{})

// ② 显式 schema（返回 error，因为要 Resolve）
n2, err := workflow.NewFunctionNodeWithSchema[In, Out]("parse", fn, inputSchema, outputSchema, cfg)

// ③ Emitting 版：能自己 yield 中间事件（进度、流式片段）
n3 := workflow.NewEmittingFunctionNode("report",
	func(ctx agent.Context, in In, emit func(*session.Event) error) (Out, error) {
		for _, step := range steps {
			if err := emit(progressEvent(step)); err != nil { return zero, err }
		}
		return Out{...}, nil
	}, cfg)
n4, err := workflow.NewEmittingFunctionNodeWithSchema[In, Out](...)

// ④ 从 state 取参数（Params 必须是 struct）
n5, err := workflow.NewFunctionNodeFromState[Params, Out]("render",
	func(ctx agent.InvocationContext, p Params) (Out, error) { ... }, cfg)

EmittingFunctionFn 的类型别名：

type EmittingFunctionFn[IN, OUT any] = func(ctx agent.Context, in IN, emit func(*session.Event) error) (OUT, error)

④ 是最容易被忽略也最有用的一种——注释里的三条规则：

type Params struct {
	UserQuery string              // 默认按字段名去 state 取 "UserQuery"
	Tone      string `state:"tone"`   // 显式改键
	Input     MyIn  `state:"node_input"` // 或者字段名叫 NodeInput：拿原始上游输出
}
  • 字段名默认就是 state key（state:"my_key" 覆盖）；
  • state:"node_input" 是逃生口：既想要 state 又想要上游输出时用这个标记；
  • Params 不是 struct 会直接返回 error（“params must be a struct type”）。

配套的 StateFieldNames() []string 让引擎能做静态校验——Node 接口旁边那个 StateParamsAware 接口就是它的实现标志，WithStateSchema 声明的字段和节点实际消费的字段对不上时，启动即报错而不是运行时静默取不到。

AgentNode / ToolNode：把 agent 和 tool 变成节点#

// AgentNode：四个构造器
n, err := workflow.NewAgentNode(a, cfg)                                        // 无 schema
n, err = workflow.NewAgentNodeWithSchemas(a, inputSchema, outputSchema, cfg)   // 显式
n, err = workflow.NewAgentNodeTyped[In, Out](a, cfg)                           // 泛型推断
// 私有版 newAgentNodeWithSchemasTyped 是"泛型 + 显式覆盖"的组合入口

// ToolNode：多一个 NewNamedToolNode（给节点自定义名字）
n, err = workflow.NewToolNode(myTool, cfg)
n, err = workflow.NewToolNodeWithSchemas(myTool, inS, outS, cfg)
n, err = workflow.NewToolNodeTyped[In, Out](myTool, cfg)
n, err = workflow.NewNamedToolNode("step3", myTool, cfg)

ToolNode 要求工具实现内部 runnableTool（Run(agent.Context, any) (map[string]any, error)）——functiontool 满足，自定义 tool.Tool 不一定满足。这是"图里编排工具"和"agent 里挂工具"的一个真实差异。

AgentNode 内部有一批值得知道的语义（源码函数名即为证）：synthesizeAgentOutput（agent 只说话没设 output 时，用模型文本合成节点输出）、isOwnAgentEvent（区分"这个 agent 自己的事件"和子孙 agent 的事件）、nodeInputToContent（把节点输入转成 genai.Content 喂给 agent）。这三条合起来的意思是：AgentNode 允许"文本即输出"，BaseNode.modelText / projectTextOntoSchema 也走同一条路（把模型文本按 schema 投射成结构体）。

JoinNode：fan-in 屏障#

join := workflow.NewJoinNode("merge")
// 带 schema：workflow.NewJoinNodeWithSchema("merge", resolved)

契约（注释原文归纳）：

  • 只被激活一次，在图边上声明的每一个前驱都完成之后；
  • 输入是 map[string]any，key 是前驱节点名，value 是它们的 output；
  • 自己的 output 就是这个 map 原样发出。

⚠️ 两条最容易踩的：

  1. 所有入边都喂屏障，所以给 JoinNode 加条件路由是配置错误——屏障会等所有声明的前驱，而被路由跳过的前驱永远不会触发，图就卡住了。
  2. NewJoinNodeWithSchema 的 schema 是逐个前驱的输出校验，不是校验那个合并 map；前驱 output 为 nil 时跳过校验并保留 nil。

ParallelWorker：列表逐项并发#

pw, err := workflow.NewParallelWorker("bulk", workerNode, 8, workflow.NodeConfig{ParallelWorker: true})

签名 NewParallelWorker(name string, wrapped Node, maxConcurrency int, cfg NodeConfig)。它把 wrapped 对输入列表的每一项并发跑一遍，maxConcurrency 在这里是节点级参数（和 WithMaxConcurrency 的图级上限是两个不同旋钮），最终收集成单个聚合输出事件。

FunctionNode 也有对应的 NodeConfig.ParallelWorker 开关，注释说明其行为：“runs the node concurrently for each item of a list-typed input. The engine collects per-item outputs and emits a single aggregate output event.”

WorkflowNode：子图当节点#

sub, err := workflow.NewWorkflowNode("sub", subEdges)   // 注意：没有 opts 参数
n, err := workflow.NewWorkflowNode("sub", edges)

子工作流的名字不能和父工作流相同——ErrSubWorkflowNameCollision（“sub-workflow name collision”）在建图时（validateSubWorkflowNames）就会挡掉。原因见第 2 篇：名字是 RunState 的持久化命名空间。

NodeConfig：七个字段，两个三态指针#

type NodeConfig struct {
	ParallelWorker  bool
	RerunOnResume   *bool          // 三态
	WaitForOutput   *bool          // 三态
	RetryConfig     *RetryConfig   // nil = 不重试
	Timeout         time.Duration  // 0 = 只受父调用 deadline 约束
	EmitsOwnSpan    bool
}

注释点明了指针的理由：“pointer-typed fields are tri-state so node implementations can distinguish ‘user explicitly opted out’ (&false) from ‘user did not configure’ (nil)"。三态语义：

字段&true&falsenil
RerunOnResume重入模式（节点从头再跑）交棒模式（答复给后继当输入）引擎当前按 handoff 处理
WaitForOutput子节点无 output 时让父 parked 重跑正常完成引擎默认（多数节点 = false）

WaitForOutput 的存在理由注释写得很具体：RunNode 派发的子节点跑完却没设 output 时，与其让父节点"用零值假完成”，不如 park 住重跑——多轮子 agent 需要这个。目前只在 RunNode（动态子调度器）路径生效。

EmitsOwnSpan 是遥测细节：节点自己已经开了 span（比如 LlmAgent 节点会发 invoke_agent）时置 true，scheduler 就不再套一层 invoke_node，以保持和 adk-python 一致的 span 树。

Timeout 用 context.WithTimeout 包在每次激活上——注意粒度是"激活"而不是"整个节点生命周期"，配了重试时每次尝试都有独立预算（第 4 篇讲重试时展开）。

常见问题

ADK Go 2.x 自定义一个图节点要实现什么？

workflow.Node 接口共 9 个方法。实践中嵌入 workflow.BaseNode（用 NewBaseNode 构造），只写 Run 就够了——Name/Description/Config/InputSchema/OutputSchema/ValidateInput/ValidateOutput 全都有默认实现。

Node.InputSchema() 返回 nil 会怎样？

不校验。接口注释原文：返回 nil 表示没有 schema、不做输入校验。OutputSchema 同理。

ValidateInput 和 ValidateOutput 什么时候被调？

ValidateInput 由 scheduler 在每次激活 Run 之前调；ValidateOutput 在每个 yield 出的事件带非 nil output 时调，转发给消费者之前。两者都可以返回"被强制转换过的值"。

为什么 NodeConfig 的 RerunOnResume/WaitForOutput 是 *bool？

三态：&true 显式开、&false 显式关、nil "用户没配"。config.go 注释点明这区分了"明确退出"和"没配置"两种语义，引擎据此用默认值（nil → handoff 模式）。

FunctionNode 想拿会话状态而不是上游输出怎么办？

用 workflow.NewFunctionNodeFromState[Params, OUT]：Params 必须是 struct，字段默认按 Go 字段名去 state 取，可用 `state:"my_key"` 改，`state:"node_input"`（或字段名 NodeInput）拿原始上游输出。

JoinNode 和 ParallelWorker 各干什么？

JoinNode 是 fan-in 屏障（等所有前驱完成，输出 map[前驱名]输出）；ParallelWorker 把一个节点对列表逐项并发跑，收集成单个聚合输出事件。前者是"等"，后者是"散"。
