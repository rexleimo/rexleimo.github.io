模块 5：图工作流引擎

这是 ADK Go 2.0 的头号特性，也是本专栏相对旧专栏最大的增量。workflow 与 agent/workflowagent 两个包只存在于 2.x（v1.7.0 树里没有）。

一句话定位：图不是「工作流引擎」，图是一种 Agent。 workflowagent 实现了 agent.Agent，所以它可以出现在别人的 SubAgents 里，也能被 launcher 当根 Agent 直接服务。

API 清单（v2.4.0 已实机编译核实）

// 构造节点
workflow.NewFunctionNode(name, fn, workflow.NodeConfig{})                    // → *FunctionNode，无 error
workflow.NewFunctionNodeWithSchema[In, Out](name, fn, inS, outS, cfg)        // → (*FunctionNode, error)
workflow.NewEmittingFunctionNode[In, Out](name, fn, cfg)                     // fn 多一个 emit func(*session.Event) error
workflow.NewFunctionNodeFromState[Params, Out](name, fn, cfg)               // Params 必须是 struct
workflow.NewAgentNode / NewAgentNodeTyped / NewAgentNodeWithSchemas
workflow.NewToolNode / NewNamedToolNode / NewToolNodeTyped / NewToolNodeWithSchemas
workflow.NewJoinNode(name)                                                   // 无 error
workflow.NewJoinNodeWithSchema(name, resolved)                               // 收 *jsonschema.Resolved
workflow.NewWorkflowNode(name, edges)                                        // 子图，无 opts
workflow.NewParallelWorker(name, wrapped, maxConcurrency, cfg)
workflow.NewDynamicNode[In, Out](name, fn, cfg)                              // → Node

// 连边
workflow.Chain(start, a, b)                       // <2 个节点时返回 nil
workflow.Concat(chain1, workflow.Edge{…})         // 只认 Edge / []Edge，其他类型静默忽略
workflow.NewEdgeBuilder().Add(…).AddRoute(…).AddFanOut(…).AddFanIn(…).AddRoutes(…).Build()
workflow.Start                                    // 哨兵节点，Name() == "START"，Run 不 yield

// 组装成 Agent（恢复自动）
workflowagent.New(workflowagent.Config{Name:…, Description:…, SubAgents:…, Edges: edges})

NodeConfig 字段（全部可选）：ParallelWorker bool、RerunOnResume *bool、WaitForOutput *bool、RetryConfig *RetryConfig、Timeout time.Duration、EmitsOwnSpan bool。

本模块关键约束（均已核对源码）

  1. RetryConfig 一律从 workflow.DefaultRetryConfig() 拿副本再改——结构体字面量未设字段是零值（RetryConfig{MaxAttempts: 5} = 立刻重试 5 次）。默认：5 次 / 1s / 60s / 2x / full jitter，且 defaultShouldRetry 不重试 ErrInputValidation。
  2. Timeout 默认 0，作只受父 invocation deadline 约束；粒度是单次激活。
  3. JoinNode 不允许条件入边（屏障等所有声明前驱，被路由跳过的永远不来）。
  4. 同节点两条 (From,To) 相同的边被拒（ErrDuplicateEdge，不看 Route）；多条件同目标用 MultiRoute。
  5. 所有路由都没命中且无 Default → 静默死路，不是错误。每个出度>0 的节点要么留无条件边、要么留 Default（注意无条件边不抑制 Default）。
  6. 一次激活：最多一个带 Output 的事件、最多一个带 Routes 的事件（判的是 != nil）、最多一个 RequestedInput。
  7. WithMaxConcurrency 不管 RunNode 派发的动态子节点（会死锁）。
  8. 图 name 是 RunState 的持久化命名空间：空名 = 关闭恢复；目前没有图指纹校验，改图结构直接发布会静默吃坏旧 RunState。
  9. workflowagent.Config 只有 6 个字段，内部就是 workflow.New(name, edges)——没有 MaxConcurrency / StateSchema 入口；agent 实例可并发服务多会话（RunState 在 session.State 里）。
  10. HITL 暂停走 adk_request_input 这个 FunctionCall（与其他 runtime 共享的 wire format）；工具确认走 adk_request_confirmation。InterruptID 必须每次运行唯一，否则 Dev UI 不再弹框。

⚠️ 两个高频坑（源码注释原话）：

  1. RetryConfig 请用 workflow.DefaultRetryConfig() 拿副本再改字段。用 struct literal 构造时未设字段是零值不是默认值，零值等价于「不重试、不退避、不加抖动」。默认策略：MaxAttempts 5、InitialDelay 1s、MaxDelay 60s、BackoffFactor 2.0、Jitter 1.0，且 defaultShouldRetry 不重试 ErrInputValidation。
  2. Timeout 为 0（默认）时节点只受父 invocation context 的 deadline 约束。不设就是「不单独限时」，一个卡住的外部调用能拖死整个 fan-in。
