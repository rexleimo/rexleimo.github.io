MCP Toolset：Transport/Endpoint/Auth 三种接法与断线自愈

ADK Go v2.4.0 的 tool/mcptoolset 全解：mcptoolset.New(Config) 的 7 个字段与互斥规则、内存内 MCP server 做测试、Endpoint 快捷构造 streamable HTTP、auth.CredentialProvider 与 OAuthHandler 抢 Authorization 头的坑、connectionRefresher 的重试语义，以及工具集裁剪与确认策略。

September 26, 2026 · 3 min · 593 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 tool/mcptoolset/{set.go,client.go,tool.go}、auth/，样例 examples/mcp/main.go。

MCP 是 2.x 里最省事的扩展点：外部工具不用写一行胶水，一个 toolset 就接进来。但 mcptoolset.Config 只有 7 个字段，其中三个（Transport/Endpoint/Auth）有互斥规则，写错了不会编译报错、只会在第一次调用时炸。这一篇把这些规则钉死。

三种接法#

① 内存内 server（测试与自研工具复用）#

官方 examples/mcp/main.go 的第一种模式——同一个进程里跑一个 MCP server：

import "github.com/modelcontextprotocol/go-sdk/mcp"

type Input struct {
	City string `json:"city" jsonschema:"city name"`
}
type Output struct {
	WeatherSummary string `json:"weather_summary" jsonschema:"weather summary in the given city"`
}

func GetWeather(ctx context.Context, req *mcp.CallToolRequest, input Input) (*mcp.CallToolResult, Output, error) {
	return nil, Output{WeatherSummary: fmt.Sprintf("Today in %q is sunny\n", input.City)}, nil
}

func localMCPTransport(ctx context.Context) mcp.Transport {
	clientTransport, serverTransport := mcp.NewInMemoryTransports()

	server := mcp.NewServer(&mcp.Implementation{Name: "weather_server", Version: "v1.0.0"}, nil)
	mcp.AddTool(server, &mcp.Tool{Name: "get_weather", Description: "returns weather in the given city"}, GetWeather)
	if _, err := server.Connect(ctx, serverTransport, nil); err != nil {
		log.Fatal(err)
	}
	return clientTransport
}

这条路的价值不在生产，在测试：工具逻辑用 MCP 协议形态写，Agent 侧只依赖 tool.Toolset，两边都能单独跑。

② 自己造 transport（需要 OAuth、自定义 HTTP client）#

ts := oauth2.StaticTokenSource(&oauth2.Token{AccessToken: os.Getenv("GITHUB_PAT")})

mcpToolSet, err := mcptoolset.New(mcptoolset.Config{
	Transport: &mcp.StreamableClientTransport{
		Endpoint:   "https://api.githubcopilot.com/mcp/",
		HTTPClient: oauth2.NewClient(ctx, ts),
	},
})

③ 只给 Endpoint（最省事，ADK 帮你建 transport）#

mcpToolSet, err := mcptoolset.New(mcptoolset.Config{
	Endpoint: "https://api.githubcopilot.com/mcp/",
	Auth:     myCredentialProvider,      // 见下文
})

Endpoint 的语义（源码注释）：“when set and Transport is nil, builds a streamable HTTP transport (mcp.StreamableClientTransport) targeting this URL. Ignored when Transport is set.”

所以 Transport 和 Endpoint 同时给 = Endpoint 静默失效。这是最容易踩的一条。

mcptoolset.Config 全字段#

字段类型规则
Client*mcp.Client可选自定义 client，nil 用默认
Transportmcp.Transport给了就用你的
Endpointstring仅当 Transport == nil 生效
Authauth.CredentialProvider只能配 streamable HTTP；与 stdio 同用是配置错误
ToolFiltertool.PredicateDeprecated → 用 tool.FilterToolset
RequireConfirmationbool整个 toolset 的工具都要人工确认
RequireConfirmationProvidertool.ConfirmationProvider动态判断，优先级高于上面那个 flag

Auth 与 OAuthHandler 会抢同一个头#

源码注释里这段是明确警告：

Don’t also set OAuthHandler on a supplied *mcp.StreamableClientTransport: Auth is applied last and overwrites the Authorization header, so the two would fight over the same request.

机制：authHTTPClient(base, provider) 用一个 context-aware RoundTripper 在每个出站请求最后盖 Authorization。所以：

  • 要 ADK 托管凭据 → 用 Config.Auth，别在 transport 上设 OAuthHandler；
  • 要 MCP SDK 自己那套 OAuth → 设 OAuthHandler，别用 Auth。

auth 包是 2.x 独有的新包（v1.7.0 树里没有），它同时服务 MCP 出站凭据和 server/authn 入站认证，是 2.x 统一凭据层的起点。

断线自愈：connectionRefresher#

mcptoolset 不直接用 *mcp.ClientSession，而是包一层：

type connectionRefresher struct { client *mcp.Client; transport mcp.Transport }

func (c *connectionRefresher) CallTool(ctx, params) (*mcp.CallToolResult, error)
func (c *connectionRefresher) ListTools(ctx) ([]*mcp.Tool, error)
func withRetry[T any](ctx, c, fn func(*mcp.ClientSession) (T, error)) (T, bool, error)
func shouldRefreshConnection(err error) bool

含义有三层，值得逐条记住：

  1. ListTools 每次都可能重新拉取，所以 MCP server 热更新工具列表能被感知（这也是 toolset 比静态工具列表贵的原因——每次构造请求都要列工具）。
  2. 只有被判定为「连接类错误」才重建 session 再重试（shouldRefreshConnection）。业务错误不会被重试——不会把你的 CallTool 重复执行一遍。
  3. 重试对任意返回类型生效（withRetry[T any]），所以工具调用的幂等性仍然由你负责：如果 server 端在超时前已经执行成功、只是回包断了，重建连接后的重试会二次执行。写操作类 MCP 工具要带幂等键。

接进 Agent#

a, err := llmagent.New(llmagent.Config{
	Name:        "helper_agent",
	Model:       model,
	Description: "Helper agent.",
	Instruction: "You are a helpful assistant that helps users with various tasks.",
	Toolsets: []tool.Toolset{
		mcpToolSet,
	},
})

注意用的是 Toolsets（复数字段），和 Tools 并列。Tools 放单个工具、Toolsets 放成组工具，两者可以同时给。

裁剪 + 确认的组合写法：

// 只放行两个工具，并且其中一个要人工确认
filtered := tool.FilterToolset(mcpToolSet, tool.AllowedToolsPredicate([]string{"get_weather", "create_issue"}))

confirmed := tool.WithConfirmation(filtered,
	false, // 不整体开
	func(toolName string, toolInput any) bool {
		return toolName == "create_issue"   // 只有写操作要确认
	})

tool.WithConfirmation(ts Toolset, requireConfirmation bool, provider ConfirmationProvider) Toolset 是toolset 层的通用包装器，任何 toolset 都能套，不只是 MCP。

生命周期：谁负责关连接#

mcptoolset.New 只建对象，连接是惰性的（第一次 Tools()/CallTool 时建立，断了由 refresher 重建）。这意味着：

  • 启动阶段不会因为 MCP server 不可达而失败——故障会推迟到第一个工具调用。CI 里要显式打一次 ts.Tools(ctx) 做探活。
  • Config 里没有 Close，tool.Toolset 接口也没有关闭方法。stdio 型 server 的子进程生命周期跟着 *mcp.Client/transport 走，你要长期跑多个 MCP server 时，自己持有 *mcp.Client 并通过 Config.Client 注入，这样关闭权在你手里。

现象原因处理

401 / Authorization 头内容不对Auth 与 OAuthHandler 同时设，互相覆盖二选一
Auth 配 stdio command 报错源码定义为配置错误换 HTTP transport，或自己包 client
工具列表为空但没报错server 可达但 ListTools 返回空/被 FilterToolset 全滤掉先裸调 ts.Tools(ctx) 打印名字
第一次调用很慢，之后正常惰性建连 + 首次 ListTools启动时探活一次
写操作被重复执行连接类错误重试叠加非幂等工具工具侧加幂等键
模型总是选错 MCP 工具server 端 Description 太含糊 + 工具太多FilterToolset 裁剪，改 server 描述

常见问题

ADK Go 2.x 怎么接 MCP server？

mcptoolset.New(mcptoolset.Config{Transport: …}) 或 Config{Endpoint: "https://…"}，得到 tool.Toolset，塞进 llmagent.Config.Toolsets。

Transport 和 Endpoint 同时给会怎样？

Endpoint 只在 Transport 为 nil 时生效（源码：when set and Transport is nil, builds a streamable HTTP transport）。Transport 已设时 Endpoint 被忽略。

Config.Auth 有什么用？

auth.CredentialProvider 通过 context-aware RoundTripper 给每个出站 HTTP 请求注入凭据，只能配 streamable HTTP transport；配 stdio 是配置错误。

能同时用 Auth 和自己 transport 上的 OAuthHandler 吗？

不能。源码明写 Auth 最后应用、会覆盖 Authorization 头，两者会抢同一个请求。二选一。

MCP 连接断了怎么办？

mcptoolset 内部用 connectionRefresher 包一层：CallTool/ListTools 失败且判定为连接类错误时自动重建 session 再重试（withRetry）。你不需要自己重连。

怎么只暴露 MCP server 的一部分工具？

用 tool.FilterToolset(ts, tool.StringPredicate(names))。mcptoolset.Config.ToolFilter 已 Deprecated。
