SkillToolset：把 SKILL.md 目录变成 Agent 能按需加载的能力

ADK Go v2.4.0 的 tool/skilltoolset 全解：skill.Source 五个方法与哨兵错误、NewFileSystemSource(fs.FS)、两种预载（WithCompletePreloadSource / WithFrontmatterPreloadSource）与 reload 闭包、NewMergedSource 合并多源、SKILL.md frontmatter 规范（含 allowed-tools 两种写法）、自动注入的三个工具 list_skills/load_skill/load_skill_resource 与 ProcessRequest 的 XML 清单注入。

September 26, 2026 · 4 min · 748 words · 梦兽编程 -  |  English

验证版本： google.golang.org/adk/v2 v2.4.0，源码 tool/skilltoolset/{toolset.go,skill/*.go}、tool/skilltoolset/internal/skilltool/，样例 examples/skills/。

这是 2.x 里最被低估的一个包。它解决的问题很具体：你有一堆领域流程（报价口径、周报模板、合规检查步骤），塞进 Instruction 会撑爆 prompt 且互相干扰，但模型又必须知道它们存在。

SkillToolset 的答案是两段式加载：只有 frontmatter（名字+描述）常驻 prompt，正文和资源由模型自己按需调工具取。

目录结构（官方默认指令里明确定义的）#

skills/
└── weather/
    ├── SKILL.md          # 必需：frontmatter + 指令正文
    ├── references/       # 可选：补充文档，如 weather_us.json
    ├── assets/           # 可选：模板、脚本等资源
    └── scripts/          # 可选：可执行脚本（bash 跑）

SKILL.md 实例（上游 examples/skills/skills/weather/SKILL.md 原文）：

---
name: weather
description: A skill to check weather in different countries.
---
# Weather Skill

This skill provides weather information for different countries.

## Instructions
1. When asked about weather in a specific country, check if there is a resource file for that country in the `references/` directory.
2. The resource file will be named `weather_<country_code>.json`. Supports `us` and `pl`.
3. Report the weather for the country to the user.

frontmatter 字段（skill.Frontmatter，注释指向 https://agentskills.io/specification#frontmatter）：

type Frontmatter struct {
	Name          string            `yaml:"name"`
	Description   string            `yaml:"description"`
	License       string            `yaml:"license,omitempty"`
	Compatibility string            `yaml:"compatibility,omitempty"`
	Metadata      map[string]string `yaml:"metadata,omitempty"`
	AllowedTools  []string          `yaml:"allowed-tools,omitempty"`
}

allowed-tools 有两种合法写法：规范里的标量字符串（allowed-tools: "Bash, Read"）和早期 ADK Go 接受的 YAML 序列。内部用 allowedToolsYAML 自定义 UnmarshalYAML 同时吃两种，再 splitAllowedTools 拆分——你手写的 skill 源实现也要兼容这点，否则跨工具生态的 SKILL.md 会解析失败。

注意：Description 是唯一进入常驻 prompt 的信息，它决定模型会不会去 load_skill。写成「A skill to check weather in different countries」这种可判定的一句话，别写「weather stuff」。

最小接入#

source := skill.NewFileSystemSource(os.DirFS("./skills"))

skillToolset, err := skilltoolset.New(ctx, skilltoolset.Config{Source: source})
if err != nil {
	log.Fatalf("Failed to create skill toolset: %v", err)
}

a, err := llmagent.New(llmagent.Config{
	Name:        "skills_agent",
	Model:       model,
	Description: "Agent to demonstrate using skills.",
	Instruction: "You are a helpful assistant.",
	Toolsets:    []tool.Toolset{skillToolset},
})

Config 只有三个字段：

type Config struct {
	Source            skill.Source   // 必填，nil 直接报错 "skill source must be provided"
	Name              string         // 默认 "SkillToolset"
	SystemInstruction string         // 默认见下
}

New 的签名带 ctx：func New(ctx context.Context, cfg Config) (*SkillToolset, error)——因为构造时就要枚举 skill（ListSkills 工具需要清单），磁盘上有非法 SKILL.md 会在启动时炸，这是好事。

它给了模型哪三个工具#

工具名作用关键入参
list_skills列出可用技能（frontmatter 级）—
load_skill读某个技能的完整指令正文name
load_skill_resource读技能目录里的文件（references/*、assets/*、scripts/*）skill_name、路径

默认系统指令（源码里的 defaultSkillSystemInstruction，我按原文摘录要点）：

You can use specialized 'skills' to help you with complex tasks. You MUST use the skill tools to interact with these skills.

1. If a skill seems relevant to the current user query, you MUST use the `load_skill` tool with `name="<SKILL_NAME>"` to read its full instructions before proceeding.
2. Once you have read the instructions, follow them exactly as documented before replying to the user. …
3. The `load_skill_resource` tool is for viewing files within a skill's directory … Do NOT use other tools to access these files.

三条都是硬约束措辞（MUST / Do NOT），别轻易覆盖 SystemInstruction——第 3 条尤其重要，它防止模型用 shell 去绕过技能目录。真要自定义，只在末尾追加，不要替换。

prompt 里到底进了什么#

func (ts *SkillToolset) ProcessRequest(ctx agent.Context, req *model.LLMRequest) error {
	skills, err := ts.source.ListFrontmatters(ctx)
	if err != nil { return err }
	if len(skills) == 0 { return nil }
	utils.AppendInstructions(req, ts.systemInstruction, skilltool.SkillsToXML(skills))
	return nil
}

三个信息：

  1. 每次模型请求都会执行——所以 ListFrontmatters 的开销是每轮都付一次，这是下面要预载的根本原因。
  2. 注入的是 frontmatter 的 XML 清单（SkillsToXML），不是正文。成本 ≈ 每个技能一行 name+description。
  3. len(skills) == 0 时完全跳过注入——技能目录为空时不会白烧 token。

性能：两种预载 + 热更新#

裸 fileSystemSource 每次都读盘（ListFrontmatters 要遍历目录解析每个 SKILL.md）。技能多起来后每轮请求都付这个钱，所以 skill 包提供两个装饰源：

// 全量预载：frontmatter + 正文 + 资源都进内存
source, reload, err := skill.WithCompletePreloadSource(ctx, source)

// 只预载 frontmatter：清单常驻，正文/资源仍按需读盘
source, reload, err := skill.WithFrontmatterPreloadSource(ctx, source)

签名：func With…PreloadSource(ctx context.Context, source Source) (Source, func(context.Context) error, error)

  • 第二个返回值是 reload 闭包——挂到文件监听或管理接口上就能热更新技能而不重启进程；
  • 内部是 sync.RWMutex + map[string]*completePreloadSkillData（资源用 map 建索引做快速查找），并发读安全；
  • 官方 examples/skills/main.go 用的正是全量预载。

选哪个：技能正文很小（几 KB）→ 全量预载；正文/资源很大或数量多 → 只预载 frontmatter，让 load_skill 按需读盘。

多来源合并#

src := skill.NewMergedSource(
	skill.NewFileSystemSource(os.DirFS("./skills")),        // 团队共享
	skill.NewFileSystemSource(os.DirFS("./skills-local")),  // 本仓库私有
)

NewMergedSource(sources ...Source) Source。注意冲突语义：Source 接口要求实现方在重复时返回 ErrDuplicateSkill——同名技能在不同源里是错误，不是覆盖。想覆盖就把被覆盖的那个改名，或自己实现一个带优先级的 Source。

自己实现 Source#

Source 只有五个方法，接数据库/对象存储/CMS 都不难：

type Source interface {
	ListFrontmatters(ctx context.Context) ([]*Frontmatter, error)
	ListResources(ctx context.Context, name, subpath string) ([]string, error)
	LoadFrontmatter(ctx context.Context, name string) (*Frontmatter, error)
	LoadInstructions(ctx context.Context, name string) (string, error)
	LoadResource(ctx context.Context, name, resourcePath string) (io.ReadCloser, error)
}

接口注释里的两条硬要求：必须并发安全、必须返回包内定义的哨兵错误：

ErrInvalidSkillName, ErrInvalidFrontmatter, ErrSkillNotFound,
ErrDuplicateSkill, ErrInvalidResourcePath, ErrResourceNotFound

为什么强调哨兵错误：工具层据此把「技能不存在」翻译成给模型的可行动反馈（让它换名字重试），而不是一个 500。你返回 fmt.Errorf("no such skill") 就丢掉了这个能力。

另外 LoadResource 返回 io.ReadCloser，注释明确由调用方负责 Close——你的实现不要提前关，也不要缓存复用一个已关的 reader。

现成的解析/校验/组装工具（自己做导入导出、CI 校验时直接复用）：

fm, body, err := skill.ParseBytes(content)   // frontmatter + 剩余 markdown
fm, err       := skill.Parse(bufio.NewReader(f))
err           := skill.Validate(fm)
data          := skill.Build(fm, markdown)   // 反向组装

Validate 会挡住名字非法/缺描述的技能——在 CI 里对每个 SKILL.md 跑一遍 Validate，比等到线上启动失败便宜得多。

安全边界（必须自己划）#

scripts/ 是「可执行脚本」，默认指令鼓励模型走 load_skill_resource 读文件。ADK 本身不做沙箱，所以：

  • 技能目录只放可信内容。从外部拉来的 SKILL.md 直接进 skills 目录 = 把 prompt injection 变成可执行路径；
  • 真要跑 scripts/，在工具层加确认——正好接上一篇的 HITL ：把执行脚本的函数工具设 RequireConfirmation: true；
  • 用 allowed-tools 收窄该技能能碰的工具面；
  • 生产环境建议把 Source 指向只读、带版本的存储（镜像里的目录、或带 checksum 的对象存储），别挂可写卷。

测试#

func TestSkillSurface(t *testing.T) {
	src, _, err := skill.WithCompletePreloadSource(ctx, skill.NewFileSystemSource(os.DirFS("./testdata/skills")))
	if err != nil {
		t.Fatal(err)
	}
	fms, err := src.ListFrontmatters(ctx)
	if err != nil {
		t.Fatal(err)
	}
	for _, fm := range fms {
		if err := skill.Validate(fm); err != nil {
			t.Errorf("skill %q invalid: %v", fm.Name, err)
		}
	}
}

不依赖模型的确定性断言：清单能列出来、每个 frontmatter 合法、LoadInstructions 非空、ListResources 能找到 references/ 里的文件。模型会不会用技能是另一回事，那部分放到评测集里跑（模块 10）。

本模块收尾#

四篇连起来是 2.x 的工具面全景：函数工具（自己写逻辑）→ MCP（接外部工具生态）→ 确认（管住危险动作）→ 技能（按需加载知识）。它们共用同一个上下文对象 agent.Context，也共用同一个成本问题：声明会进 prompt，能裁就裁。

下一步进模块 4：会话、事件与上下文压缩 ——把 state、artifact、compaction 讲清楚，那是控制 token 成本的主战场。

常见问题

ADK Go 2.x 的 skill 是什么？

一个文件夹：必需 SKILL.md（YAML frontmatter + markdown 指令），可选 references/、assets/、scripts/。Agent 通过工具按需读取，而不是全部塞进 prompt。

怎么接进来？

source := skill.NewFileSystemSource(os.DirFS("./skills"))，再 skilltoolset.New(ctx, skilltoolset.Config{Source: source})，把返回的 *SkillToolset 放进 llmagent.Config.Toolsets。

它会给我哪些工具？

三个：list_skills、load_skill、load_skill_resource。SkillToolset.New 内部构造，不用自己写。

skill 清单会不会每次请求都塞进 prompt？

会。SkillToolset 实现 ProcessRequest，每次模型请求前把系统指令 + 所有 skill 的 frontmatter（XML 形式）追加进去；skill 列表为空时跳过。所以正文不进去，只有 name/description 进去。

改了 skills 目录要重启吗？

取决于源。裸 NewFileSystemSource 每次读盘，改完即生效；套了预载源则读缓存，用返回的 reload 闭包热更新。

allowed-tools 有什么用？

SKILL.md frontmatter 里的字段（规范来自 agentskills.io），声明该技能允许使用的工具；ADK 同时接受标量字符串和 YAML 序列两种写法。
