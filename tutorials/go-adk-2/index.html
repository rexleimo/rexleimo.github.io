Go ADK 2.0 实战完全指南

本专栏基线：google.golang.org/adk/v2 v2.4.0，Go 1.26.6+（实操 go1.27.1）。

这不是 Go ADK 实战完全指南 的修订版，而是一个从零重写的 2.x 专栏。 旧专栏基于 v0.2.0，那个版本的安装命令、模块路径、API 签名在 2.x 下一行都编译不过。

为什么必须另开一版

ADK Go 在 2026-06-30 发布了 2.0.0，这是一个真正的大版本，不是改个号：

维度1.x（含我们旧专栏的 v0.2.0）2.x（本专栏）
模块路径google.golang.org/adkgoogle.golang.org/adk/**v2**
Go 门槛go.mod go 1.24.4 / 1.25.0go.mod go 1.26.6
CLIcmd/adk（adk version）cmd/adkgo（adkgo，adk version 已不存在）
上下文ToolContext + CallbackContext 分裂统一 agent.Context
事件session.NewEvent(invocationID)session.NewEvent(ctx, invocationID)
编排Sequential / Parallel / Loop 三种固定 workflow agent图工作流引擎：节点/边/路由/fan-out-fan-in/并发调度器
人机协同只有 toolconfirmation（工具级确认）引擎级 HITL：RequestInput 暂停、ResumeOrRequestInput 重入
多 Agent树状 sub-agent + transfercollaboration 模式：chat / task / single_turn，子 Agent 自动交还控制权
可测试性手写 mock，接口一变就崩agent.StrictContextMock + platform 时间/UUID provider

一句话：1.x 教你「怎么把 Agent 跑起来」，2.x 教你「怎么把编排逻辑写成图」。

这个专栏解决什么

官方 README-v2.md 只列了 breaking changes 和迁移点，不告诉你工程上该怎么用。本专栏补的是这段：

  • 一个 fan-out/fan-in 的调研工作流，JoinNode 的超时与部分失败怎么处理？
  • RequestInput 暂停后，Session 落在数据库里，进程重启怎么恢复？
  • 动态图 NewDynamicNode 和静态图怎么选，边界在哪？
  • llmagent.Config{Mode: ModeTask} 配 InputSchema/OutputSchema，schema 校验失败会怎样回退？
  • 1.x 的 Sequential/Parallel/Loop 迁到 workflowagents/* 时，行为差异在哪？
  • 统一 agent.Context 之后，回调和工具共享同一套上下文，副作用边界怎么划？

这些只有把 v2 的源码和 examples 读过一遍的人才答得上来。这个专栏就是把它系统化。

适合谁读

  • 写过 1.x ADK Go：直接看模块 0 的迁移地图，然后跳到 05-workflow 补新范式。
  • 第一次接触 ADK：从模块 1 开始按顺序读，2.x 反而比 1.x 更好教——图引擎的心智模型是完整的。
  • 有 Go 基础（能写 HTTP 服务，懂 goroutine/channel），用过 LLM API（Gemini/OpenAI 任一）。

不适合： Go 零基础；只想跑 demo 不打算上线；不接受升级到 Go 1.26.6+ 工具链的团队（那部分人请继续看旧专栏 ，它保持原样服务 1.x）。

版本承诺

  • 本专栏只在 v2.x 范围内更新；补丁版本（v2.5、v2.6…）的变化以「增补篇」形式追加，不悄悄改旧文。
  • 每篇开头标注验证版本。凡是与上游 v2.4.0 源码树不符的说法，都算 bug，欢迎在评论区指出来。
  • 正文里的 Go 片段均实际编译验证：在 google.golang.org/adk/v2 v2.4.0 + Go 1.26.8 下 go build 通过，包括 launcher / runner / llmagent.Config 字段 / 图引擎节点与边 / 路由 / JoinNode / 动态图 / HITL / StrictContextMock mock 写法。（标明「官方样例原文」的块除外，那本来就是上游代码。）
  • 上游 1.x 仍在维护（v1.7.0，2026-09-14），因此本专栏不预测 1.x 的未来，也不劝你留在 1.x。
