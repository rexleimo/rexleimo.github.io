给你自己的 agent 加 Herdr 支持：三类上报、--seq 单调性、resume 命令的四条硬约束与不碰正常会话的测试法

不需要给 Herdr 提 PR，也不需要等它发版：从你自己的代码里调 herdr pane report-agent / report-agent-session / release-agent 就能让 agent 成为 Herdr 的一等公民。本文讲清四个 HERDR_* 环境变量、三类上报的职责边界、--source 为什么不能以 herdr: 开头、--seq 为什么必须跨会话跨重启单调递增（时间戳是推荐实现）、resume 命令的四条硬约束（PATH 上的普通命令名、无撇号与控制字符、64 参数与 8 KiB 上限、source 必须先持有 pane 否则 resume_not_accepted）、两个错误码 invalid_resume_argv 与 resume_not_accepted、退出时 release 与「一两秒安全网」的区别、以及用一个独立命名会话测试恢复而不碰正常会话的三步法。

September 30, 2026 · 6 min · 1211 words · 梦兽编程 -  |  English

验证版本： herdr 0.9.2（stable channel）· 本机实测 macOS / Apple silicon · 2026-09-30 ⚠️ 本篇的代码示例没有在本机的活动 pane 上执行过：pane report-agent 会改写目标 pane 的 agent 身份与状态，而本机那个 pane 正在跑一个真实任务。第九节解释为什么这本身就是条纪律。

前两篇讲的是「用 Herdr 支持的 agent」。这一篇讲反过来的方向：

如果你在做一个 coding agent，你可以从你自己的代码里让它成为 Herdr 里的一等公民。 你不需要给 Herdr 提 pull request，也不需要等 Herdr 发版。

官方还给了一个很实在的理由：

Herdr 为那些厂商不提供集成的 agent 维护集成。 如果你维护你自己的 agent，自己拥有这个集成意味着你可以按你自己的发版节奏修它。

也就是说：等 Herdr 帮你适配，你的修复窗口就是它的发版周期；自己上报，就是你自己的。

先给结论：

一共就三类上报：状态、resume 命令、退出时释放。 全部通过 $HERDR_BIN_PATH 这个二进制发出，只在 HERDR_ENV=1 时发。 最容易做错的两件事：--seq 没有跨重启单调递增（上报被静默丢弃）， 和忘了先持有 pane 就发 resume 命令（拿回 resume_not_accepted）。

一、上报之后用户得到什么#

官方列的四条收益：

  • 你 agent 的名字和 idle / working / blocked 状态，出现在侧边栏和 herdr agent list 里
  • 它完成或需要一个决定时的通知
  • herdr agent wait 以及其他等 agent 状态的自动化
  • Herdr server 重启之后，在同一个 pane 里拿回同一个会话

第三条和第四条是最有价值的：它们让你的 agent 可以被脚本编排、可以活过重启。 （herdr agent wait 属于模块 4「编程化控制」的范围，本专栏后续批次展开。）

二、四个环境变量#

Herdr pane 里的每一个进程都继承这些环境变量：

变量含义
HERDR_ENV在 Herdr 里为 1
HERDR_PANE_ID你的 agent 运行所在的那个 pane
HERDR_BIN_PATH拥有这个 pane 的那个 Herdr 二进制
HERDR_SOCKET_PATHHerdr 的 API socket

以及那条必须遵守的纪律：

只在 HERDR_ENV=1 且其他变量都已设置时上报。 在 Herdr 之外，你的集成应该什么都不做。

本机实测（这个 session 就跑在 Herdr pane 里）：

$ echo "$HERDR_ENV  $HERDR_PANE_ID"
1  w3:p2

为什么用 $HERDR_BIN_PATH 而不是 herdr：因为拥有这个 pane 的那个二进制 才是正确的对话对象——用户的 PATH 上可能有另一个版本的 herdr， 或者压根没有（比如 Herdr 是通过远程 bridge 提供的）。

三、第 1 类上报：状态#

"$HERDR_BIN_PATH" pane report-agent "$HERDR_PANE_ID" \
  --source my-agent \
  --agent my-agent \
  --state working \
  --seq 1

四个参数的规则#

--state：什么时候报什么

状态时机
working一个回合开始时
idle你的 agent 准备好接受输入时
blocked它需要用户决定某件事时（加 --message 解释这个 block）

--agent：用户看到的名字

用你自己 agent 的名字，不要用 Herdr 已经支持的某个 agent 的名字。

--source：标识你的集成

保持它稳定且唯一。不要以 herdr: 开头，因为 Herdr 自己的集成用那个前缀。

（这和集成那篇 里 custom:indexer、user:claude-title 这些示例是同一套约定：用命名空间前缀，别撞 herdr:。）

--seq：可选但强烈推荐

它必须随着你 source 的每一次上报而增加，包括跨 session 和跨你的 agent 重启。 时间戳是个好选择。 Herdr 会忽略序号不高于它上次接受的那些值的报告， 所以迟到或乱序的报告无法覆盖更新的状态。

这是整个协议里最容易做错的一条。 用「进程内自增计数器」的实现会在这里翻车： agent 重启后计数器归零 → 所有上报的 seq 都低于 Herdr 记住的值 → 全部被静默忽略， 而且不会报错。

推荐实现（单调、跨重启、无需持久化）：

# 毫秒时间戳作为 seq
seq_now() { python3 -c 'import time; print(int(time.time()*1000))'; }
# 或者：date +%s%3N（GNU date）／ perl -MTime::HiRes -e 'printf("%d\n", Time::HiRes::time()*1000)'

四、第 2 类上报：resume 命令#

把恢复当前会话的命令放在 -- 之后，并且 带上那个 session 需要的选项，比如模型或权限模式，这样恢复出来的会话行为一致：

"$HERDR_BIN_PATH" pane report-agent "$HERDR_PANE_ID" \
  --source my-agent \
  --agent my-agent \
  --state idle \
  --seq 2 \
  --agent-session-id "$SESSION_ID" \
  -- my-agent --resume "$SESSION_ID" --model my-model

发送时机#

你可以把这个命令附在任何一次状态报告上， 或者在只有 session 变化时用 pane report-agent-session 发送。 每当你的 agent 切换 session，都要重新上报它。

Herdr 恢复时做什么#

Herdr server 重启之后，Herdr 在同一个目录里打开那个 pane，并在那里运行那个命令。

四条硬约束#

#约束
1第一个词是用户 PATH 上的一个普通命令名，例如 my-agent，不是一个路径
2没有任何参数包含撇号（apostrophe）或控制字符
3最多 64 个参数，总共 8 KiB
4你的 source 必须先持有那个 pane —— 所以在命令之前或同时用 report-agent 发一次状态报告；否则 Herdr 回答 resume_not_accepted

第 4 条最容易踩：你不能「只发 resume 命令」。必须先（或同时）有一次状态上报把 pane 归给你的 source。

两个错误码#

错误触发条件后果
invalid_resume_argv违反前三条规则Herdr 拒绝该命令并且不应用那次报告
resume_not_accepted违反第四条（source 没先持有 pane）命令不被接受

用户侧的开关#

用户可以用 [session] resume_agents_on_restore = false 关掉 resume。

（这就是会话状态那篇 里的路径 4 开关—— 它同时管官方集成和自报 agent。）

⚠️ 版本门槛#

resume 命令需要 Herdr 0.10.0 或更新。更旧的版本会忽略它们， 所以状态报告和 release 在那里仍然工作。

本机是 0.9.2（stable channel），所以按这条说明， 自报 agent 的 resume 命令在当前 stable 上会被忽略，而状态和 release 正常工作。

这里要和官方集成区分开：集成那篇 里 18 个官方集成的「最低集成版本」表是另一条路径（由 Herdr 自己维护的集成上报 session 引用）， session-state 页明确说它默认开启。 本节这条 0.10.0 门槛针对的是「第三方 agent 自己用 -- 上报 resume 命令」这条路。 做集成之前，先在目标版本上实测一次恢复，别只看文档。

渐进策略：先只做状态上报（0.9.x 就能用、收益已经很大）， resume 命令照发（新版本自动生效，旧版本忽略、无害），等 0.10.0 落地再验证恢复链路。

五、第 3 类上报：退出时释放#

"$HERDR_BIN_PATH" pane release-agent "$HERDR_PANE_ID" \
  --source my-agent \
  --agent my-agent \
  --seq 3

释放会立刻从那个 pane 清除你的 agent 的名字、状态和 resume 命令。

两条使用规则：

  1. 只在用户真的退出时 release
  2. 如果你的 agent 在同一个进程里用另一个 session 替换了一个 session， 报新 session，而不是 release

忘了 release 会怎样：安全网#

如果你的 agent 没有 release 就退出了，Herdr 会在 pane 回到它的空闲 shell 提示符之后注意到， 并清除那个 agent 和它的 resume 命令。这通常需要一两秒。 它是一个安全网，不是 release 的替代品。

为什么不能依赖它：那一两秒里，侧边栏显示的是一个已经不存在的 agent， herdr agent wait 可能等在一个死掉的目标上，通知也可能发错。 在自动化编排里，这一两秒足够让脚本做出错误决定。

六、别挡住你的 agent：三条工程纪律#

  • 别让 Herdr 拖慢你的 agent。 在后台发送报告，或者用一个短超时，并且忽略失败。
  • 只发送最新的状态。 如果在一次报告在途时有几个变化排队，丢掉旧的那些。
  • resume 命令需要 Herdr 0.10.0 或更新。 更旧的版本忽略它们， 所以状态报告和 release 在那里继续工作。

前两条翻译成实现要求：

要求做法
不阻塞主循环上报放到后台线程/子进程，或者加短超时（例如 200–500 ms）后放弃
失败不影响 agent吞掉错误，最多记一条 debug 日志。绝不因为上报失败而让 agent 退出或卡住
只发最新一个「脏标志 + 当前状态」的合并模型，而不是一个无界队列

这三条本质上是在说：Herdr 集成必须是「可有可无」的。 一个因为 Herdr socket 不可用就崩掉的 agent，比一个没有集成的 agent 更糟。

七、想直接走 socket#

HERDR_BIN_PATH 加 CLI 是可移植的选择，包括在 Windows 上。 如果你的 agent 需要直接 IPC，发送等价的 pane.report_agent、pane.report_agent_session 和 pane.release_agent 请求 （见 Socket API 的 agent-state-reporting 一节 外部链接 ）。 resume 命令放在 resume_argv 数组里。

选择建议：

方式什么时候用
CLI（$HERDR_BIN_PATH）默认选它。跨平台（含 Windows）、无协议耦合、进程级隔离
socket（HERDR_SOCKET_PATH）高频上报、需要在一个连接里做多件事、或者你的 agent 已经是事件驱动架构

注意 socket 路径是 $HERDR_SOCKET_PATH，不要自己拼 ~/.config/herdr/herdr.sock—— 命名会话和远程 bridge 下那个路径是错的。

八、验证你的集成#

基本自检#

在 Herdr pane 里启动你的 agent，然后检查 Herdr 看到了什么：

herdr pane get "$HERDR_PANE_ID"
herdr agent list

配合状态那篇 的解释器，完整三件套是：

herdr pane get "$HERDR_PANE_ID"     # 这个 pane 现在的 agent / state / metadata
herdr agent list                    # 它在不在列表里、状态对不对
herdr agent explain <target>        # 状态是怎么判出来的（上报会短路读屏）

测恢复，但不碰你的正常会话#

为了在不动你正常会话的前提下测试恢复，用一个独立的命名会话：

  1. 启动 herdr --session my-agent-test，然后在一个 pane 里跑你的 agent
  2. 用 herdr session stop my-agent-test 停掉那个会话
  3. 再启动一次 herdr --session my-agent-test。 那个 pane 应该运行你的 resume 命令，并且你的 agent 应该再次上报

这个三步法是官方给的，值得原样抄进你的 CI 或手动检查清单。 关键点：命名会话有自己独立的 server、socket 和运行时状态 （见会话状态那篇 ）， 所以 session stop 只会杀掉测试会话，不会动你正在干活的那个。

一个真实世界的参照实现#

Prime Agent 内置的 Herdr reporter 外部链接 是一个真实世界的集成。 它只在 Herdr 内部激活，把 agent 事件映射到 working、idle 和 blocked， 跨 session 保持它的报告顺序，并且在退出时释放 pane。

这四条正好对应本文的四节：激活条件、状态映射、--seq 单调性、release。 照着它检查自己的实现，比读文档快。

只想改显示、不想改状态#

要在不改变你 agent 状态的前提下改变它的呈现方式，比如一个标题或自定义状态文字， 见 Custom status labels 外部链接 。

也就是用 herdr pane report-metadata（--title / --display-agent / --token summary= / --state-label / --ttl-ms），不要用 report-agent 去抢语义状态的权威。

九、一个可运行的最小 reporter（示例，未在本机活动 pane 上执行）#

#!/usr/bin/env bash
# my-agent-herdr.sh —— 最小可用的 Herdr reporter
# 用法：在你的 agent 里 source 它，或作为子进程包装器
set -uo pipefail

# ① 激活条件：不在 Herdr 里就完全静默
[[ "${HERDR_ENV:-}" == "1" ]] || return 0 2>/dev/null || exit 0
: "${HERDR_PANE_ID:?}" "${HERDR_BIN_PATH:?}"

SOURCE="my-agent"          # 稳定、唯一、不以 herdr: 开头
AGENT="My Agent"           # 用户看到的名字，不要撞已支持的 agent 名

# ② seq：毫秒时间戳，天然跨 session 跨重启单调递增
_seq() { python3 -c 'import time; print(int(time.time()*1000))'; }

# ③ 不阻塞、不抛错：短超时 + 吞掉失败
_report() {  # _report <state> [message]
  local state="$1" msg="${2:-}"
  local args=(pane report-agent "$HERDR_PANE_ID"
              --source "$SOURCE" --agent "$AGENT"
              --state "$state" --seq "$(_seq)")
  [[ -n "$msg" ]] && args+=(--message "$msg")
  timeout 0.4 "$HERDR_BIN_PATH" "${args[@]}" >/dev/null 2>&1 || true
}

herdr_working() { _report working; }
herdr_idle()    { _report idle; }
herdr_blocked() { _report blocked "$1"; }

# ④ resume 命令：必须先有一次状态上报持有 pane（所以先 _report）
herdr_set_session() {  # herdr_set_session <session-id> [model]
  local sid="$1" model="${2:-default}"
  _report idle
  timeout 0.4 "$HERDR_BIN_PATH" pane report-agent "$HERDR_PANE_ID" \
    --source "$SOURCE" --agent "$AGENT" --state idle --seq "$(_seq)" \
    --agent-session-id "$sid" \
    -- my-agent --resume "$sid" --model "$model" >/dev/null 2>&1 || true
}

# ⑤ 只在用户真的退出时调用；同进程换 session 时用 herdr_set_session
herdr_release() {
  timeout 0.4 "$HERDR_BIN_PATH" pane release-agent "$HERDR_PANE_ID" \
    --source "$SOURCE" --agent "$AGENT" --seq "$(_seq)" >/dev/null 2>&1 || true
}
trap herdr_release EXIT INT TERM

这段脚本刻意把前面每一节的规则都实现了一遍： ①激活条件 ②时间戳 seq ③短超时 + 吞错 ④先发状态再发 resume ⑤退出释放 + trap。

为什么我没在本机跑它：pane report-agent 会改写目标 pane 的 agent 身份和状态。 本机唯一的活动 pane（w3:p2）正在跑一个真实任务， 往它上面报一个 --agent "My Agent" 会污染侧边栏、通知和 herdr agent wait 的语义。 要试就用第八节那个独立命名会话（herdr --session my-agent-test）—— 这不只是本篇的注意事项，这就是官方推荐的测试方式。

十、避坑指南#

  1. --seq 用时间戳，别用进程内计数器。 重启归零 = 所有上报被静默忽略，且不报错。
  2. --source 不要以 herdr: 开头。 那是 Herdr 自己集成的前缀。
  3. --agent 不要撞已支持的 agent 名。 用户会在侧边栏看到两个「claude」。
  4. 不能只发 resume 命令。 source 必须先持有 pane，否则 resume_not_accepted。
  5. resume 命令的第一个词不能是路径。 必须是 PATH 上的普通命令名。
  6. resume 参数里不能有撇号和控制字符，上限 64 个参数 / 8 KiB。 违反就是 invalid_resume_argv，而且那次报告整个不被应用。
  7. --agent-session-id 和 -- 后面的命令要一致。 报的是 id A、命令 resume 的是 id B， 恢复出来就是另一个会话。
  8. 切换 session 要重报 resume 命令。 否则 server 重启后恢复的是旧会话。
  9. 同一进程内换 session ≠ 退出。 报新 session，不要 release。
  10. 别依赖「一两秒安全网」。 它存在，但那段时间侧边栏显示的是一个已经不存在的 agent。
  11. 上报必须不阻塞、可失败。 短超时 + 吞错。Herdr 挂了你的 agent 也得照常工作。
  12. 只发最新状态，丢掉排队的旧变化。 无界队列会让状态延迟到「已经过期」。
  13. resume 命令有版本门槛（0.10.0+）。 在目标版本上实测恢复，别只看文档。
  14. 测试用独立命名会话。 herdr --session my-agent-test → session stop → 再启动， 三步验证恢复链路，且不影响你正在用的会话。
  15. 别自己拼 socket 路径。 用 $HERDR_SOCKET_PATH；命名会话和远程 bridge 下固定路径是错的。
  16. 想改显示别用 report-agent。 用 report-metadata（--title / --display-agent / --state-label / --token / --ttl-ms），它不接管语义状态的权威。

常见问题

给自己的 agent 加 Herdr 支持需要改 Herdr 吗？

不需要。官方原文：你不需要给 Herdr 提 pull request，也不需要等 Herdr 发版。整个过程就是从你的代码里调几次 Herdr 的 CLI 或 socket。用户随后能在侧边栏和 herdr agent list 里看到你 agent 的名字和 idle/working/blocked 状态、在它完成或需要决定时收到通知、用 herdr agent wait 等它、并且在 Herdr server 重启后在同一个 pane 里拿回同一个会话。

我的 agent 怎么知道自己在 Herdr 里？

检查四个环境变量：HERDR_ENV（在 Herdr 里为 1）、HERDR_PANE_ID（你的 agent 所在的 pane）、HERDR_BIN_PATH（拥有这个 pane 的 Herdr 二进制）、HERDR_SOCKET_PATH（Herdr 的 API socket）。官方要求只在 HERDR_ENV=1 且其他变量都已设置时才上报；在 Herdr 之外，你的集成应该什么都不做。

--source 和 --agent 有什么区别？

--agent 是用户看到的名字，用你自己 agent 的名字，不要用 Herdr 已经支持的某个 agent 的名字。--source 标识你的集成，要保持稳定且唯一，并且不要以 herdr: 开头，因为 Herdr 自己的集成用那个前缀。同一个 source 的每次上报都必须带更高的 --seq。

--seq 为什么必须跨会话跨重启递增？

因为 Herdr 会忽略序号不高于它上次接受值的那些报告，这样迟到或乱序的报告就无法覆盖更新的状态。官方推荐用时间戳，它天然满足「跨 session 和跨你的 agent 重启都要递增」。如果 seq 回退，你的上报会被静默丢弃。

resume 命令有哪些限制？

四条：第一个词必须是用户 PATH 上的普通命令名（例如 my-agent，不是路径）；任何参数都不能包含撇号或控制字符；最多 64 个参数、总共 8 KiB；你的 source 必须先持有那个 pane，所以要在命令之前或同时用 report-agent 发一次状态报告，否则 Herdr 回答 resume_not_accepted。违反前三条 Herdr 用 invalid_resume_argv 拒绝并且不应用那次报告。另外文档标注 resume 命令需要 Herdr 0.10.0 或更新，更旧版本会忽略它们。

怎么测试恢复而不搞乱我正在用的会话？

用一个独立的命名会话。三步：先 herdr --session my-agent-test 然后在里面一个 pane 跑你的 agent；用 herdr session stop my-agent-test 停掉那个会话；再 herdr --session my-agent-test 启动一次。那个 pane 应该运行你的 resume 命令，并且你的 agent 应该再次上报。
