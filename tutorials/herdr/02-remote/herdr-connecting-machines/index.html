Herdr 连接机器：Local 与保存的 SSH 机器同窗、跨机器 agent 视图与独立重连

把本地工作和远程 agent 放进同一个 Herdr 窗口：herdr machine add 的交互式发现流程与命名规则、一个 profile 只对应一个远程 session、client/server 兼容性协商与审批式安装、跨机器切换时谁推流谁只更新状态、prefix+w 跨机器导航、连接丢失时的变暗缓存语义、Reconnecting / Attention(!auth、!error) / 文件错误三种连接状态、SSH 认证恢复（machine status、machine reconnect、ControlPersist 600）、以及最容易踩的 ID 作用域陷阱——w1:p1 在两台机器上都可能存在，远程自动化必须带 --machine 前缀。

September 29, 2026 · 6 min · 1201 words · 梦兽编程 -  |  English

验证版本： herdr 0.9.2（stable channel）· 本机实测 macOS / Apple silicon · 2026-09-29 本机 herdr machine list 实测输出：No saved SSH machines.（干净环境，正好用来讲默认行为）

前面两篇讲的都是一台机器。但真实的 agent 工作流往往是：笔记本上跑两个 agent， 一台 Linux 构建机上跑三个，可能还有一台 GPU 机器。

Herdr 对这件事的答案不是「开三个终端窗口」，而是：

保存一次 SSH 机器，然后在同一个 Herdr 窗口里切换它的 workspace 和 Local，不用另开 client。 agent 列表包含已连接的机器，所以你能看到工作在哪台机器上跑、哪个 agent 在等回答。

先给结论：

三件事必须先记住。 ①每台机器有自己的 server——断一台不影响其他，这是设计而不是运气。 ②一个 profile 只对应一个远程 session，不是「那台机器上的全部会话」。 ③ID 是按 server 作用域的——w1:p1 在两台机器上可能都存在。 所以远程自动化必须带 --machine 前缀，否则你会把命令发到错误的机器上。

一、连接之前：先把 SSH 打通#

前提：你对远程机器有正常的 SSH 访问权限。先验证：

ssh workbox

workbox 可以是你 SSH config 里的一个 host，也可以直接用目标形式 ssh://you@server:2222。

平台支持矩阵（多机器连接）：

本地 client远程 server
Linux / macOS / WindowsLinux 或 macOS，x86_64 或 aarch64
Linux / macOS / WindowsWindows，仅 x86_64

还有两条安装行为的区别，很重要：

  • 交互式安装可以在确认后安装或更新完整的远程包
  • 后台重连只做发现（discover installed packages），不会安装任何东西

二、herdr machine add：一个 profile 是怎么诞生的#

必须在交互式终端里跑，这样 Herdr 才能在安装或替换任何东西之前问你：

herdr machine add workbox

会话发现流程（官方原文口径）#

在交互式终端里，Herdr 会发现运行中的会话：

情况Herdr 的行为
只有一个运行中的会话自动选中它
有多个让你用 Up/Down + Enter 选；Esc 或 Ctrl+C 取消
查询成功但没有运行中的会话使用 default
找不到 Herdr 安装提议为 default 安装
已安装的二进制无法报告它的会话报错；此时用 --remote-session <name> 显式指定

跳过发现、直接指定会话：

herdr machine add workbox --remote-session agents

非交互命令一律用 default，除非你给了 --remote-session。

命名规则#

场景侧边栏显示
machine add workbox（default session）workbox（去掉 user@ 前缀的 SSH host）
加 --label "Build machine"Build machine
加 --remote-session agents 但没 --labelworkbox/agents
默认名已被占用machine add 要求你传 --label

一个 machine profile 只针对一个远程 session，它不会把宿主机上的每个 session 合并起来。 想在同一台机器上看两个 session，就 add 两次、给两个不同的 --label。

兼容性协商与审批式安装#

这一段是 Herdr 做得比较克制的地方，值得逐条看：

  • Herdr 同时检查已安装的二进制和运行中的 server
  • 它会在保存 profile 之前先启动请求的后台 server
  • 兼容的 client 和 server 版本不必一致（协商，不是要求相同）
  • 缺失或不兼容的安装走审批式（approval-based）安装流程
  • 当运行中的 server 需要被替换时，安装流程会先问才停它和它的 pane 进程， 然后启动兼容的 server。默认答案是 No。
  • 如果安装和替换都需要，一次确认覆盖两者
  • machine add 不使用实验性的 live handoff
  • 取消或安装失败 → profile 不保存

Windows server 上还有一步：安装流程会检查 SSH 用户拥有的 Herdr 进程所用的可执行文件， 并在复用前验证它们的能力——所以即使 SSH 的 PATH 指向一个更旧的安装， 一个兼容的运行中 build 仍然可以被使用。

加完之后#

herdr

打开 UI。如果本地 client 已经开着：

  • 新加的、已启用的机器通常一秒内出现，并在后台连接，不改变你当前的选择
  • 正在进行中的机器切换会先完成，然后才应用 profile 变更
  • 远程 server 在安装流程退出后继续运行

三、在机器之间切换#

鼠标#

在侧边栏里选一台机器，或选它下面的某个 workspace。

关键语义：

被选中的机器接收你的 pane 输入和终端尺寸，并提供可见的终端内容与图形。 其他已连接的机器继续更新它们的 workspace 信息、agent 状态和通知，但不推流 pane 屏幕。

这就是为什么「一个窗口看四台机器」在带宽上是可行的——只有一个画面在流动。

折叠箭头：点任何机器旁边的箭头可以折叠/展开它的 workspace 列表， 而不会切走你当前的 workspace。这台机器正在重连时也一样能用。

键盘：prefix+w#

按 prefix+w，然后用 workspace 导航键（默认 Up/Down）跨已连接机器按侧边栏顺序高亮 workspace：

键行为
Enter激活高亮的 workspace
Esc 或前缀键取消，不切换
—紧凑和展开的侧边栏都会揭示高亮行，包括在折叠的机器下面
—桌面端在两端回绕；移动端切换器停在第一个或最后一个 workspace
—断开的机器被跳过

一条容易出事的操作纪律（官方专门写了）：

当你在另一台机器上高亮一个 workspace 时，先按 Enter 再用其他键盘动作。 这能防止 pane / tab / workspace / 自定义命令快捷键误作用到当前机器上。

点击会取消远程桌面的键盘预览。展开的侧边栏会尊重每台机器自己折叠的 worktree 分组。

Local 的特殊地位#

  • Local 在启动时立即打开，不等 SSH 连接
  • 选中 Local 也会取消一次未完成的远程切换，不等远程机器回复
  • 如果 Local 自己在重连，你的选择会在它就绪后恢复
  • Local 只有在它的新屏幕和终端设置就绪后才接受输入
  • 一台卡住的机器无法拖住另一台机器的输入

最后这条是多机器场景里最重要的可用性保证。

顺带：多个 Herdr client 可以独立查看同一个 server 上的不同 tab； 共享 tab 的尺寸问题见核心概念 的 client-server 一节。

连接丢失时你看到的是什么#

当连接丢失时，最后的 workspace 和 agent 状态仍然可见，但是变暗（dimmed）的。 那是缓存信息，不是活状态。 在拿到新连接和匹配的屏幕之前， 对这些缓存 pane 的输入和导航保持禁用。 重连永远不会从你正在使用的机器那里夺走选择权。

「变暗」这个视觉信号值得刻意记一下：暗 = 你以为的状态，不是真实状态。

四、重命名、禁用、移除#

先从列表里读 profile ID，不要从 label 或 hostname 推导：

herdr machine list
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id>

脚本里给 machine list 加 --json。

本机实测（还没有任何保存的机器）：

$ herdr machine list
No saved SSH machines.

$ herdr machine status
No saved SSH machines.

$ herdr machine --help
Manage saved SSH machines

Commands:
  list       List saved SSH machines
  status     Check saved machines without prompting for authentication
  reconnect  Authenticate a saved machine in this terminal and verify connectivity
  add        Prepare the remote Herdr server and save an SSH machine
  rename / remove / enable / disable ...

注意 status 的官方描述：Check saved machines without prompting for authentication ——不弹认证提示，所以它适合放进脚本和巡检。

三种操作的语义差别：

操作profile远程 server / agent
rename改显示 label，不重连不受影响
disable保留，以后还能用只把这台机器从 client 断开，远程会话和 agent 继续跑，即使宿主机不可达
remove遗忘同上

还有两条边界行为：

  • 移除或禁用你正在查看的那台机器 → 你会被送回 Local。
  • 如果 Local 也不可用，Herdr 会显示这一点并重试它的连接，而不是去选另一台远程机器。 有了已启用的保存机器，即使 Local 失败或重启，client 仍然可以保持可用。

五、三种连接状态，分别该怎么处理#

状态含义你该做什么
Reconnecting网络中断、休眠、SSH 失败后自动重试通常什么都不用做
Attention目标需要一个动作：认证、host-key 批准、或兼容的 server点徽章看错误和它给你的 CLI 命令
Saved-machine file error目录文件不可读或无效什么都不用做：当前连接不受影响，Herdr 会提示并自动重试读取

Reconnecting 的重试策略（细节很重要）#

  • 重复失败会增加延迟，最多到两分钟
  • 短暂的成功连接不会重置这个延迟
  • 一个连接必须保持健康一分钟，下一次中断才能得到快速重试
  • SSH 连接会被检查应用层活动，静默时主动探测——所以一条坏掉的连接不会无限期显示 Online
  • Local 检测原生连接关闭或失败，而不是用远程健康探测

Attention 的两个徽章#

  • ! auth = 认证失败
  • ! error = 其他问题
  • 点徽章 → 显示最新错误 + 相关的 CLI 命令
  • 它永远不会弹出凭据对话框（never opens a credential popup）
  • 折叠的侧边栏里两者都显示为 !
  • 机器行的其余部分保持正常的展开/折叠行为
  • 未知或变更过的 host key 会一直保持 Attention（host-key 检查行为不变）
  • 其他机器仍然可用

后台连接的硬边界（这条最容易被误解）#

后台连接永远不会回答提示，也不会安装、更新、重启或 hand off 一个 server。

所以对于非认证类的 Attention，你要在交互式终端里跑 Herdr 提示的那个独立安装命令：

herdr --remote workbox

用你 profile 的 target；如果添加时选了命名 session，这里也要带上 --session <name>。 跟着提示走完，已打开的 client 会自动重试。

两条纪律：

  1. machine reconnect 不安装也不更新 Herdr（它只做认证和连通性验证）
  2. 不要仅仅因为 server 版本和 client 不同就去停一个运行中的 server

认证失败时#

先检查普通 SSH。 对于带口令保护的密钥， 在启动 Herdr 的非交互后台连接之前先 ssh-add 把它加载进 ssh-agent。

Git 认证与 SSH 签名（远程 pane 里）#

在 SSH config 里为受信任的 host 打开：

ForwardAgent yes

Herdr 不会替你开启转发。 之后的行为：

  • 当一个 session 带着 agent 启动时，更新后的 Linux 和 macOS server 会给 pane 一个 稳定的 agent 地址，所以已有的和新建的 pane 都能在 --remote 或保存机器重连之后使用被转发的 agent
  • 一个正常工作的继承 agent 或更早的连接，优先级高于后来的 client 和临时的安装检查； 如果它消失了，另一个活的 attachment 可以提供 agent
  • ⚠️ 这需要更新远程 server，不只是更新本地 client
  • 没有 agent 启动的 Local session 会保持 SSH_AUTH_SOCK 不动
  • 在 server 更新之前创建的 pane，或在 agent 第一次被提供给 session 之前创建的 pane， 保留它们原来的环境，需要重建一次才能继承稳定地址
  • 更旧的兼容 server 和没有 agent 转发的连接仍然可以正常 attach

六、SSH 认证恢复机制#

这一节的机制比较绕，但理解它能省掉很多「为什么又要我认证」的困惑。

在 Linux 和 macOS client 上、且 remote.manage_ssh_config = true 时：

Herdr 在 machine add、侧边栏和 saved-machine API 命令之间共享一个已批准的 OpenSSH 连接。

配套的三条命令与概念：

命令 / 概念说明
herdr machine status [<label-or-id>] [--json]新鲜的、非交互的检查
Reachable 的含义远程 Herdr server 现在可用，不代表每个开着的 TUI 都已连接
herdr machine reconnect <label-or-id>在终端里完成原生 SSH 认证并验证保存的机器；不安装也不更新 Herdr

恢复的时间线：

  • 已打开的 client 会在 30 秒内重新检查失败的连接，不需要重启
  • 共享连接使用 ControlPersist 600（10 分钟空闲） —— ⚠️ 这不是 MFA 的有效期。活连接可以保持打开， 但公司策略、SSH server 或网络可能更早结束它们
  • Local Windows 的恢复尚不支持
  • 对于非托管的 SSH 连接，认证仍然是你的责任： 单独跑 ssh 本身不会给 Herdr 授权，除非它用的是共享的 ControlPath
  • host-key 检查行为不变：未知或变更过的 host key 仍然是 Attention

后台空闲清理#

当双方安装都支持 bridge idle cleanup 时，到 Linux 和 macOS 的保存机器连接 在一分钟双向无流量之后会关闭它的远程 bridge：

  • 睡眠计入这个期限，在宿主机唤醒时检查
  • 安静的健康连接会交换健康检查；看着连续输出并不需要打字
  • 清理会保留远程 Herdr server、会话和 pane 进程
  • 更旧的安装在没有这个可选清理的情况下仍然兼容

七、设置、ID 作用域与自动化#

UI 用的是谁的设置#

UI 默认使用 client 本地的主题、侧边栏设置和键位。 被选中 server 通告的自定义命令和插件仍然在那台 server 上运行。 Herdr 不会把本地的命令插件、配置、可执行文件或密钥复制到 SSH 宿主机上。 缺失的远程命令会显式失败（fail visibly）。

改完 client 设置后用 UI 的 reload config 动作。

侧边栏 agent 行：存在多台机器时，默认的 agent 行会显示一个 machine token。 已有的自定义行会被保留——想在你的布局里要这个标签，就显式加上 machine。 侧边栏行布局 外部链接 还支持给 machine 标签配条件颜色。

ID 作用域：本篇最大的坑#

Workspace、tab、pane ID 和 agent 名字都是按单个 server 作用域的。 两台机器可能都包含 w1:p1，或者都有一个叫 reviewer 的 agent。

以及一条反直觉的行为：

在 UI 里选中一台机器，不会重定向已经在一个 pane 里运行的 CLI 命令—— 它们仍然使用那个 pane 继承的 session 和 socket。

所以远程自动化的正确姿势：

# 1. 先列出远程机器上的 agent
herdr --machine <label-or-id> agent list

# 2. 之后控制那些远程 ID 时，带上同样的前缀
herdr --machine <label-or-id> pane send --pane w1:p1 ...
  • CLI 直接使用保存 profile 的 SSH target 和 session，它不需要一个开着的 TUI
  • 不带 --machine 时，已有的 session/socket 路由完全不变

（支持哪些命令、更新要求、远程路径规则见 CLI 参考的 saved SSH machines 一节 外部链接 。）

八、保存了什么、没保存什么#

profile 里只有：一个不透明 ID、label、SSH target、显式的远程 session、enabled 状态。

Herdr 不在目录里存密码、私钥、agent ticket 或 SSH control socket。认证留在 OpenSSH 那里。

另外单独记住的缓存：每台机器的远程 OS 和解析出的可执行文件路径， 这样重复的 --machine 命令可以跳过发现。

  • 已有的 profile 会在首次使用时学到缺失的信息
  • 这个缓存是可选的：缺失、无效或不可写的缓存文件不会阻止命令工作
  • 命令仍然检查活的 server 兼容性
  • 如果缓存的可执行文件缺失、或不再支持 API 转发，Herdr 在初始的只读检查中重新发现它
  • ⚠️ 它绝不会自动重复一个可能已经改变远程状态的命令（这条设计非常值得点赞）

版本与能力协商#

  • client 和 server 协商兼容性，而不是要求版本一致
  • 保存机器的连接额外需要 server 的 surface_interest 和 health_check 能力 —— 没有这些能力的旧 server 会显示 Attention，直到被显式更新，即使独立 attach 是能用的
  • 其他缺失的 server 方法只禁用它们对应的动作
  • 更新一个兼容的 client 不会替换运行中的远程 server，也不会停它的 agent —— 需要新的 server 端行为时，显式更新那台 server
  • 正常替换会先问才停 server 和它的 pane 进程
  • live handoff 是实验性的、opt-in 的：对于独立安装流程中需要被替换的受支持 server， 你可以显式给 herdr --remote 加 --handoff； 正常连接或修认证都不需要它

九、避坑指南#

  1. 先 ssh workbox 确认能通再 machine add。 认证问题在这一步暴露，比在 Herdr 里猜快十倍。
  2. 带口令的密钥要先 ssh-add。 后台连接不会弹提示，它会直接失败成 ! auth。
  3. machine add 要在交互式终端里跑。 后台连接永远不回答提示、不安装、不更新、不重启、不 hand off。
  4. 一台机器一个 session。 想在一台宿主机上看两个 session，add 两次、给两个 --label。
  5. 远程自动化必须带 --machine。 否则 w1:p1 可能指到你本地那台机器上——ID 是每 server 作用域的。
  6. UI 里选机器 ≠ 重定向 CLI。 已在 pane 里跑的命令用的是那个 pane 继承的 session/socket。
  7. 看到 ! auth 别去点侧边栏重试。 在终端里跑 herdr machine reconnect <label-or-id>； 非认证类的 Attention 跑 Herdr 提示的那条 herdr --remote <target>。
  8. 不要为了「版本对齐」去停远程 server。 版本不必一致；停了会结束所有 pane 进程。
  9. 变暗的行是缓存。 别照着它做判断，等重连完成。
  10. ControlPersist 600 不等于 MFA 有效期。 公司策略可能更早掐掉连接，那是正常的。
  11. ForwardAgent yes Herdr 不会替你开。 而且 server 更新之前创建的 pane 要重建一次才能继承稳定 agent 地址。
  12. 移除机器不会停远程 agent。 这是特性；但反过来也意味着你以为清干净了其实还在跑—— 真要停得去那台机器上 herdr server stop。

常见问题

一台机器断线会影响其他机器吗？

不会。每台机器保留自己的 Herdr server、会话和运行中的进程，对一台机器的连接丢失不会断开其他机器。重连也永远不会夺走你正在使用的那台机器的选择权。

herdr machine add 一个 profile 覆盖宿主机上所有会话吗？

不覆盖。一个 machine profile 只针对一个远程 session。不加 --remote-session 时，交互式终端里 Herdr 会发现运行中的会话：只有一个就自动选，多个就用 Up/Down + Enter 选，Esc 或 Ctrl+C 取消；查询成功但没有运行中的会话就用 default；找不到 Herdr 安装则提议为 default 安装。

保存的机器名字是怎么来的？

默认显示为 default session 的名字，即去掉 user@ 前缀的 SSH host，例如 workbox。加 --label "Build machine" 可以自定义。如果指定了 --remote-session agents 又没给 --label，会显示成 workbox/agents。默认名被占用时 machine add 会要求你传 --label。

切换机器时其他机器还在更新吗？

在。被选中的机器接收你的 pane 输入和终端尺寸，并提供可见的终端内容与图形；其他已连接的机器继续更新它们的 workspace 信息、agent 状态和通知，但不推流 pane 屏幕。

连接断了以后侧边栏显示的是什么？

最后一次的 workspace 和 agent 状态仍然可见但是变暗的。那是缓存信息不是活状态。在拿到新连接和匹配的屏幕之前，对这些缓存 pane 的输入和导航保持禁用。

远程自动化命令为什么要加 --machine？

因为 workspace / tab / pane ID 和 agent 名字是按单个 server 作用域的，两台机器可能都有 w1:p1 或都叫 reviewer。在 UI 里选中一台机器不会重定向已在某个 pane 里运行的 CLI 命令——它们仍用那个 pane 继承的 session 和 socket。要控制远程 ID，先 herdr --machine <label-or-id> agent list，之后所有命令都带同样的 --machine 前缀。
