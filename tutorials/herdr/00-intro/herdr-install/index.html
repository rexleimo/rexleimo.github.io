Herdr 安装与验证：三平台五渠道，以及怎么自证装对了

在 macOS / Linux / Windows 上装好 herdr 0.9.2：直装脚本、Homebrew、mise、Nix、手动下载五条渠道的真实命令与各自的升级方式；stable 与 preview 两个 channel 怎么切、为什么 Windows 老 preview 装机会切不回来；herdr status 每个字段怎么读；以及装完之后 ~/.local/bin、~/.config/herdr、~/.local/state/herdr 里到底多了什么。附失败排查表。

September 29, 2026 · 6 min · 1151 words · 梦兽编程 -  | 

验证版本： herdr 0.9.2（stable channel，2026-09-29 发布）· 本机实测 macOS / Apple silicon · 2026-09-29

这一篇只做一件事：把 Herdr 装对，并且让你能自证装对了。

先给结论，因为它决定了你后面所有的升级动作：

有五条安装渠道，但只有「官方脚本直装」这一条能用 herdr update 升级。 Homebrew / mise / Nix 装的一律走各自的包管理器，混着用会出现 client 是新版、server 还是旧版的错配。 选渠道之前先想清楚你打算怎么升级。

二、macOS / Linux：官方脚本直装#

curl -fsSL https://herdr.dev/install.sh | sh
herdr

installer 会下载你平台的 release 二进制并放到 PATH 上。新的直装默认走 stable channel。

本机实测装完的落点：

$ which herdr
/Users/rex/.local/bin/herdr

$ ls -la ~/.local/bin/herdr
-rwxr-xr-x  1 rex  staff  22194464 Sep 29 22:56 /Users/rex/.local/bin/herdr

约 22 MB 的单个静态二进制，没有额外运行时依赖（Rust 写的，见上一篇 ）。

三、Windows：两种装法，第二种是给企业环境的#

标准 PowerShell 装法：

powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"

如果端点安全（EDR）拦掉了这条「无文件」命令——这在公司机器上非常常见——改用命令提示符落地成文件再跑：

curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd

Windows 上还有两个容易踩的细节，都来自官方 install 文档：

  1. PATH 指向的是「当前版本的带号目录」，installer 同时维护 current 和 stable bin 两个兼容别名， 这样升级时不需要覆盖正在运行的 herdr.exe（Windows 不允许覆盖运行中的可执行文件，这个设计是绕开它的）。
  2. ZIP 里的东西不能拆开用。 herdr-windows-x86_64.zip 里除了 herdr.exe 还有它的 app-local ConPTY 运行时，必须整目录放在一起，只拷 herdr.exe 会跑不起来。

另：Windows 的老 preview 安装会一直留在 preview，直到你显式 herdr channel set stable 切回来。

四、包管理器三条路#

Homebrew#

brew install herdr

mise#

mise use -g herdr

坑：如果 mise 报 herdr not found in mise tool registry，说明你的 mise 版本早于 Herdr 进 registry。 先升级 mise 再重试；实在不想升级，官方给的临时兜底是：

mise use -g github:herdrdev/herdr

Nix（从源码构建）#

nix run     github:herdrdev/herdr/v0.x.y
nix build   github:herdrdev/herdr/v0.x.y
nix profile install github:herdrdev/herdr/v0.x.y

把 v0.x.y 换成最新的 release tag。省略 tag 就是跟 master，官方建议常规安装用 release tag。

flake 还提供开发 shell：

nix develop github:herdrdev/herdr

升级方式取决于你怎么装的：

nix profile list                      # 找到 Herdr 那一条
nix profile upgrade <index-or-name>     # profile 安装
nix flake update herdr                  # 如果是你自己 flake 的 input

五、手动下载#

从 GitHub Releases 外部链接 取对应资产：

系统资产名
Linux x86_64herdr-linux-x86_64
Linux aarch64herdr-linux-aarch64
macOS Intelherdr-macos-x86_64
macOS Apple siliconherdr-macos-aarch64
Windows x86_64herdr-windows-x86_64.zip

Linux / macOS 上要自己加执行权限并放进 PATH：

chmod +x herdr-linux-x86_64
mv herdr-linux-x86_64 ~/.local/bin/herdr

Windows ARM64 没有原生资产——跑的是 x86_64 构建 + Windows 模拟。

六、验证：三步，全绿才算装好#

第 1 步：版本#

$ herdr --version
herdr 0.9.2

如果 shell 说找不到 herdr，重启终端，或者检查安装目录在不在 PATH 上。

第 2 步：能起来#

cd 你的项目目录
herdr

Herdr 会自动启动或接上本地默认后台会话，并且在没有任何 workspace 时自动开一个。 你不需要管 socket。首次运行会走一遍 onboarding 流程。

第 3 步：herdr status 逐字段读#

这是本机实测输出，一条没改：

$ herdr status
client:
  version: 0.9.2
  channel: stable
  protocol: 22
  endpoint_protocol_generation: 1

server:
  status: running
  version: 0.9.2
  endpoint_compatible: yes
  private_protocol: 22
  private_protocol_compatible: yes
  socket: /Users/rex/.config/herdr/herdr.sock

update:
  restart_needed: no
  server_binary_stale: no
字段该是什么不是的话意味着什么
server.statusrunningserver 没起来（或者被 herdr server stop 停了）
client.version == server.version一致client 新、server 旧：升级后 server 还没重启，见下面第七节
server.endpoint_compatibleyes协议不兼容，新 server 端动作在旧 server 上不可用
private_protocol / private_protocol_compatible两侧同号 + yes同上，私有协议错配
update.restart_neededno有更新装好了但需要重启 server 才生效
update.server_binary_staleno磁盘上的 server 二进制已经过期

也可以只看一半：herdr status server / herdr status client。本机实测 herdr status server：

status: running
version: 0.9.2
endpoint_compatible: yes
private_protocol: 22
private_protocol_compatible: yes
socket: /Users/rex/.config/herdr/herdr.sock

顺手记两条自检命令#

$ herdr channel show
stable

$ herdr config check
config: ok

config check 会校验 config.toml 并打印诊断，改完配置先跑它，比启动一次快得多。

七、升级：herdr update 的真实语义#

这一节是最容易出事故的地方，因为它不像普通 CLI 升级那样「装完就是新的」。

默认行为（官方 install 文档原文口径）：

  • 装上新二进制，但保留 endpoint-generation-1 的 server 和它们的 pane 进程继续运行
  • 你再跑一次 herdr，用新 client 接上去
  • 纯 client 侧的改动立刻生效
  • 新的 server 侧动作在那个 server 被更新并重启之前一直不可用——此时 client 会显示一条提示，而不是断开
  • 早于 endpoint generation 1 的 server 需要最后一次 stop

升级结束时，herdr update 会列出：

  1. 仍在旧版本上运行的 server，附带重启它的命令
  2. 你保存的 SSH 机器——它们各自跑自己的 Herdr，需要你在每台上分别执行 herdr update

实验性的 live handoff#

herdr update --handoff

对支持的运行中会话做实验性的实时交接。当新旧两个 server 都支持 agent-status transfer 时， live handoff 会保留 hook 上报的 agent 状态，直到下一次上报到来。 已知副作用：从旧 server 交接过来时，一个正在运行的 agent 可能短暂显示为 idle。

注意：live handoff 不适用于 Homebrew / mise / Nix 的包管理器升级。那些安装方式是： 用包管理器升级 → 再跑一次 herdr 用新 client 接上 → 兼容的旧 server 继续跑 → 等你确实需要新版本的 server 侧改动时，再用 herdr server stop 或 herdr session stop <name> 重启它。

八、channel：stable 还是 preview#

herdr channel set preview    # 切到 preview（从 master 出的 GitHub prerelease）
herdr channel set stable     # 切回 stable
herdr channel show           # 查看当前 channel

对直装来说，切 channel 会立刻检查该 channel 并安装它的最新二进制。如果那次更新失败， 再跑一次 herdr update 从已配置的 channel 重试。

事实基线（GitHub Releases 实测，2026-09-29）：

  • v0.9.2 发布于 2026-09-29，v0.9.1 发布于 2026-09-16 —— stable 大约两周一版
  • preview 是 preview-2026-09-29-9dc3a1df2b56 这种带日期和 commit 的 prerelease，几乎每天一个

我的建议：日常和生产留在 stable。preview 的价值是「下个 stable 之前就想拿到某个修复」， 代价是官方明说的「可能回退」。Windows 上更是如此——官方直接写 stable 是 Windows 常规使用的推荐 channel。

还有个 Windows 边角情况：如果老的 preview 构建拒绝 herdr channel set stable， 先在 preview 上跑一次 herdr update，再重试切 channel。

九、装完之后，磁盘上多了什么（本机实测）#

这部分文档里分散在几页，我一次列全，排障时非常有用：

~/.local/bin/herdr                     # 二进制（22 MB）

~/.config/herdr/
├── config.toml                        # 配置；本机实测内容只有一行 onboarding = false
├── herdr.sock                         # 主 socket（server）
├── herdr-client.sock                  # client socket
├── herdr.sock.agent                   # 符号链接 → launchd 的 SSH agent 监听端
├── session.json                       # 会话持久化状态（本机 version 3，workspaces=1）
├── session-snapshots/                 # 恢复用快照，文件名带时间戳
├── herdr-server.log                   # server 日志（结构化，带 event/subsystem/outcome 字段）
├── herdr-client.log                   # client 日志
└── .plugins.lock                      # 插件锁文件

~/.local/state/herdr/
└── agent-detection/                   # agent 检测的运行时状态

三点值得单独说：

  1. herdr.sock.agent 是个符号链接，本机指向 /var/run/com.apple.launchd.06viBMHaY4/Listeners——也就是说 Herdr 会把 SSH agent 的 socket 接进 pane（环境变量 SSH_AUTH_SOCK 在 pane 里就指向它）。这解释了为什么在 Herdr 里 ssh 到 远程机器不需要重新解锁密钥。命名会话的日志在 ~/.config/herdr/sessions/<name>/ 下。
  2. session.json 是人类可读的 JSON，里面就是 workspace / tab / pane 的树和它们的 cwd。 想知道「Herdr 到底记住了什么」，直接读它最快。
  3. 日志是结构化的，长这样（本机 server 日志原文，路径已截断）：
INFO herdr::persist::writer: preserved session recovery copy event="persist.backup" subsystem="persist" outcome="ok" path=.../session.json
INFO herdr::logging: session saved event="persist.save" subsystem="persist" outcome="ok" path=.../session.json workspaces=1
INFO herdr::logging: tab focused event="tab.focus" subsystem="tab" outcome="ok" workspace_id="w3" tab_id="w3:t1"

每条都有 event / subsystem / outcome，用 grep 'outcome="err"' 就能捞出所有失败。 想调日志级别：HERDR_LOG=herdr=debug。

pane 里能看到的环境变量（本机实测）#

在一个 Herdr pane 里 env | grep -i herdr：

HERDR_ENV=1
HERDR_PANE_ID=w3:p2
HERDR_TAB_ID=w3:t2
HERDR_WORKSPACE_ID=w3
HERDR_SOCKET_PATH=/Users/rex/.config/herdr/herdr.sock
HERDR_STARTUP_CWD=/Users/rex
HERDR_BIN_PATH=/Users/rex/.local/bin/herdr
TERM_PROGRAM=herdr
SSH_AUTH_SOCK=/Users/rex/.config/herdr/herdr.sock.agent

官方文档列出的可设置变量是这些（读的用途居多）：

变量用途
HERDR_CONFIG_PATH覆盖配置文件路径
HERDR_SESSION为 CLI 命令选择命名会话
HERDR_SOCKET_PATH低层 socket 路径覆盖
HERDR_PROCESS_DETECTIONLinux 进程检测策略：native（默认）或 opt-in 的 child-groups
HERDR_ENV在 Herdr 管理的 pane 进程里为 1
HERDR_PANE_ID / HERDR_TAB_ID / HERDR_WORKSPACE_ID当前 pane 进程的公开 id
HERDR_LOG日志过滤器，例如 HERDR_LOG=herdr=debug
HERDR_DISABLE_SOUND即使开了声音通知也禁止播放

HERDR_STARTUP_CWD 和 HERDR_BIN_PATH 本机也存在，但不在这张官方表格里—— 写脚本时可以用，但要知道它们目前没有文档承诺。

HERDR_ENV=1 是最有用的一个：它是「我已经在 Herdr 里了」的判据。 官方 agent guide 明确要求 AI 助手先检查它，因为 Herdr 在设计上阻止嵌套启动—— 在 pane 里再跑 herdr 是不会给你第二层的。

常见问题

Herdr 怎么安装？

macOS / Linux 执行 curl -fsSL https://herdr.dev/install.sh | sh；Windows 在 PowerShell 里执行 powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"。也可以 brew install herdr、mise use -g herdr、nix profile install github:herdrdev/herdr/<tag>，或从 GitHub Releases 手动下载二进制。

装完怎么验证？

三步：herdr --version 应输出 herdr 0.9.2；herdr 能启动或接上默认会话；herdr status 里 server.status 是 running、client 与 server 的 version 一致、endpoint_compatible 是 yes。

herdr update 什么时候不能用？

只有用官方 installer 直装的才用 herdr update。Homebrew、mise、Nix 装的必须用各自的包管理器升级，否则会出现 client 新版、server 旧版的错配。

stable 和 preview 有什么区别？

直装默认 stable。preview 是从 master 出的 GitHub prerelease（几乎每天一个），修得快但官方明确说可能回退（can regress）。切换用 herdr channel set preview / set stable，切 channel 会立刻装该 channel 的最新二进制。包管理器安装不走 preview channel。

配置文件在哪？没有会怎样？

Linux/macOS 在 ~/.config/herdr/config.toml，Windows 在 %APPDATA%\herdr\config.toml。没有配置文件也能正常跑（本机实测 config.toml 只有一行 onboarding = false）。看全部默认值用 herdr --default-config，校验用 herdr config check。

Windows 上安装被企业安全软件拦了怎么办？

官方的无文件 PowerShell 命令（irm | iex）常被端点安全拦截。改用命令提示符：curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd。
