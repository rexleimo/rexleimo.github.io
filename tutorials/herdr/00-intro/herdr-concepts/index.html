Herdr 核心概念：session / workspace / tab / pane / agent / mode

把 Herdr 的六层模型一次讲清：session 是后台 server 命名空间、workspace 是项目级容器、tab 是布局、pane 是真实终端、agent 是被识别出来的进程（五种状态与「每个 client 各自记 seen」的语义）、mode 是 terminal/prefix/navigate 三种输入去向。附本机 session.json 与 herdr agent list 的真实对照，以及「什么时候该开新 pane / tab / workspace / session」的粒度决策表。

September 29, 2026 · 6 min · 1215 words · 梦兽编程 -  |  English

验证版本： herdr 0.9.2（stable channel）· 本机实测 macOS / Apple silicon · 2026-09-29

这一篇把六层模型一次讲清。之所以要专门写一篇，是因为从 tmux 迁过来的人几乎都会在 session 和 workspace 这两层上搞混——tmux 的 session 既是隔离边界又是项目容器， 而 Herdr 把这两件事拆开了。

先给结论：

一个 repo（或一个任务、一次排查）= 一个 workspace。 大多数人都只需要默认 session。 命名 session 是「完全独立的运行时命名空间」，它换来的是独立 socket 和独立持久化状态， 代价是你得自己记住哪个 session 里有什么。

一、Session：后台 server 的命名空间#

session 是持久化的 Herdr server 命名空间。直接跑 herdr 就是接上默认 session。

命名 session 是完全独立的运行时命名空间：

herdr session list
herdr session attach work
herdr session attach side-project

官方给的选择标准很明确：

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

**先用 workspace。**只有当你需要完全独立的 pane、socket 和持久化运行时状态时，才用命名 session。

翻译成实际场景：

你的需求该用什么
同时开三个项目，想在侧边栏一眼看到哪个在等我三个 workspace（同一个默认 session）
工作项目和私人项目要彻底隔离，连 socket 都不共享两个命名 session
一台机器上给不同团队/不同用户跑互不干扰的 agent 群命名 session
只是想给某个长任务一个干净环境一个 workspace + 一个专用 tab 通常就够

日志和状态的落点也跟着 session 走：默认 session 在 ~/.config/herdr/， 命名 session 在 ~/.config/herdr/sessions/<name>/ 里（官方 agent guide 口径）。

二、Workspace：项目级容器#

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

workspace 是顶层项目容器，官方建议一个 repo、一个任务、或一次排查 = 一个 workspace。

它拥有 tab 和 pane，而且有一个关键行为：

Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

侧边栏的状态是从它内部的 agent 汇总上来的，所以你能看出哪个项目需要你关注。

这就是「一个 repo 一个 workspace」这条建议的技术理由——汇总的粒度就是 workspace。 如果你把八个项目塞进一个 workspace，侧边栏只会告诉你「这坨东西里有人在等你」， 不会告诉你是哪个项目。

本机实测，herdr workspace list 的真实输出：

{"id":"cli:workspace:list","result":{"type":"workspace_list","workspaces":[
  {"active_tab_id":"w3:t1","agent_status":"working","focused":true,
   "label":"rex-videos","number":1,"pane_count":3,"tab_count":3,
   "workspace_id":"w3"}]}}

注意 agent_status: "working" 是汇总值，label 取的是目录名 rex-videos （workspace 的 custom_name 为 null 时的行为），number 是给你在 UI 上按编号跳转用的。

三、Tab：workspace 内的一个布局#

tab 是 workspace 内部的布局单位。官方给的用法是按视图分：agents、logs、server、review。

有一条容易被忽略但很重要的性质：

Tabs are addressable from the CLI and socket API.

tab 是可以被 CLI 和 socket API 寻址的。这意味着你可以写脚本「往 logs tab 里开个 pane 跑测试」， 而不必担心抢走用户当前正在看的那个 tab 的焦点。这是模块 4「编程化控制」的基础。

本机的 tab id 形如 w3:t1、w3:t2、w3:t4——<workspace>:t<编号>。 注意编号不连续（t3 不在了），因为 tab 关掉后编号不回收； public_tab_numbers 记录的是当前有效编号集合。

四、Pane：一个真实终端#

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

pane 是真实终端：Herdr 渲染它的输出、把输入送回进程、并且在 client detach 之后保留它。

能力清单（官方 concepts 页原文口径）：

  • 可以向右或向下分割
  • 可以手动重命名
  • 可以被 CLI 读取（herdr pane read）
  • 可以被送入输入（herdr pane send-keys）
  • 可以被关闭

pane id 形如 w3:p1、w3:p2、w3:p4——<workspace>:p<编号>，同样是关了不回收。

五、Agent：Herdr 唯一真正新增的那一层#

前四层，tmux 都有对应物（session/window/pane，加一个 server）。 agent 是 Herdr 新增的语义层，也是它存在的理由。

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

检测有三个来源：前台进程、屏幕清单（screen manifest）、可选集成。 前两个是零配置的，第三个需要装东西（见模块 3 ）。

五种状态#

状态准确含义
blockedagent 需要输入、批准或一个决定
workingagent 正在跑
doneagent 跑完了，而你还没看过
idleagent 已结束或在等待，并且已经被看过了
unknownHerdr 无法自信分类

这里有个非常反直觉的设计，务必看懂#

官方原文：

Each client tracks which completions it has displayed. Viewing a completion in one client does not clear another client’s Done badge. CLI/API statuses use the server’s seen state, so they need not match a particular client’s badge; both idle and done mean ready for input.

拆成三条：

  1. 「看过没有」是每个 client 各自记的，不是全局的。你在笔记本上看过了某个完成， 不会清掉你手机上那个 client 的 Done 角标。
  2. CLI / API 返回的是 server 侧的 seen 状态，所以它不必和你屏幕上某个 client 的角标一致。 这不是 bug，别再对着 herdr agent list 和侧边栏较劲了。
  3. done 和 idle 的实质是一样的：都表示「可以接受输入了」。差别只在「你看过了没有」。

如果你要写自动化（模块 4 的内容），这条决定的判据是：关心「能不能喂下一条指令」就用 done + idle 一起判；关心「有没有需要人看的新结果」才用 done。

本机实测：三层 id 是怎么对上的#

{"agent":"pi","agent_status":"working",
 "cwd":"/Users/rex/codes/rex-hugo","foreground_cwd":"/Users/rex/codes/rex-hugo",
 "focused":false,"pane_id":"w3:p2","revision":1,"state_change_seq":38,
 "tab_id":"w3:t2","terminal_id":"term_65ca0990363e22",
 "terminal_title":"π - rex-hugo","terminal_title_stripped":"π - rex-hugo",
 "workspace_id":"w3"}
字段说明
agent识别出的 agent 名（这里是 pi）
agent_status五态之一
cwd / foreground_cwdpane 的工作目录 / 前台进程的工作目录（两者可能不同，比如 pane 里 cd 到别处再启动 agent）
pane_id / tab_id / workspace_id三层容器 id，正好是上面讲的 w3:p2 / w3:t2 / w3
terminal_id终端实例 id，pane 重建会变
terminal_title / _stripped终端标题原文 / 去掉控制序列后的版本
revision该 agent 记录的修订号
state_change_seq状态变更序号（做「等状态变化」的自动化时靠它，比轮询字符串可靠）
focused是否是当前焦点

想知道某个 pane 为什么被判成这个状态，用 herdr agent explain <target> --json—— 它会把检测器的判断依据摊开给你看。这是排障的第一手段，别去猜。

六、Client 与 Server：谁拥有什么#

By default, Herdr runs as a background server plus one or more attached clients. The server owns panes and process state. The client is the terminal UI attached to that server.

server 拥有 pane 和进程状态；client 只是接上去的终端 UI。

多 client 时的尺寸归属规则（这条官方写得很细，因为最容易踩）：

  • 只有一个 client：所有 tab 跟随它的尺寸，和以前一样
  • 多个 client：每个 client 可以看自己的 workspace 和 tab；不同的 tab 跟随各自的 client
  • 多个 client 看同一个 tab：最后一个 focus / select / interact 的那个 client 决定该 tab 的 pane 尺寸

所以「我用手机接上去，桌面上的布局突然被挤扁了」是这个规则的正常结果—— 手机成了最后交互的 client。

两个必须分清的动作：

# detach：client 走了，server 和 agent 全都在
ctrl+b 然后 q

# 真的结束会话、停掉所有 pane
herdr server stop

七、Mode：按键到底去哪儿#

Herdr 有三种模式，理解它们就等于理解了「为什么我的快捷键没反应」：

模式按键去向怎么进
terminal mode送进当前焦点 pane（也就是给里面跑的程序）默认状态
prefix mode等一个 Herdr 动作键，然后回到 terminal mode按前缀键（默认 ctrl+b）
navigate mode常驻的工作区导航面由绑定进入（例如 prefix+w）

前缀键的按法要特别注意：按下 ctrl+b，松开，再按动作键。不是三个键同时按。

几个最常用的动作键（官方 quick-start 表）：

动作键
向右分割prefix+v
向下分割prefix+minus
新建 tabprefix+c
下一个 / 上一个 tabprefix+n / prefix+p
工作区导航prefix+w
新建 workspaceprefix+shift+n
detach clientprefix+q
列出当前全部生效绑定prefix+?
进 copy mode（键盘复制）prefix+[

prefix+? 是最值得记的一个——它是活的，显示的是当前真正生效的绑定， 包括你自己改过的。忘了键位就按它，不要去翻文档。

八、鼠标优先：键盘是可选层#

官方 concepts 页把这一条写成了独立小节，可见它是设计意图而不只是便利功能：

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

具体手势（quick-start 页）：

  • 点击窗格 / tab / workspace / agent 来聚焦
  • 拖动分割边框改大小
  • 右键出上下文菜单，里面有分割窗格、新建 tab
  • 拖选文字即复制到剪贴板，不需要 ctrl+c
  • 双击选中一个 token；第二下按住拖动可按整词扩展选区
  • Ctrl + 点击打开 pane 里的链接（支持 OSC 8 超链接和 http(s)://， 包括首尾在可视区外被折行的链接）。macOS 上鼠标捕获开启时用 Ctrl-click 走 Herdr 处理的链接； Cmd-click 只在终端原生旁路下可用（例如 Shift-Cmd-click，或者 ui.mouse_capture = false）

不想让 Herdr 抢鼠标：

[ui]
mouse_capture = false

还有个进阶开关 ui.right_click_passthrough_modifier：设了它之后， 「该修饰键 + 右键」会把右键的按下/保持/拖动透传给 pane 里支持鼠标上报的程序 （比如某些 TUI agent 自己的右键菜单）。想让普通右键直接给某个 pane 程序， 就在它的菜单里选 Send right-clicks to pane，或者在里面执行：

herdr pane input --current --right-click pane

之后右键 pane 的边框可以重新打开 Herdr 自己的菜单。

九、把四层容器落到磁盘上：本机 session.json#

概念讲完，看它持久化成什么样。本机 ~/.config/herdr/session.json 的真实内容（缩进整理过，值未改）：

{"version": 3, "workspaces": [{
  "id": "w3", "custom_name": null,
  "identity_cwd": "/Users/rex/codes/rex-videos",
  "public_pane_numbers": {"1": 1, "2": 2, "4": 4},
  "next_public_pane_number": 5,
  "public_tab_numbers": [1, 2, 4],
  "next_public_tab_number": 5,
  "tabs": [
    {"custom_name": null, "layout": {"Pane": 1},
     "panes": {"1": {"cwd": "/Users/rex/codes/rex-videos"}},
     "zoomed": false, "focused": 1, "root_pane": 1},
    {"custom_name": null, "layout": {"Pane": 2},
     "panes": {"2": {"cwd": "/Users/rex/codes/rex-hugo"}},
     "zoomed": false, "focused": 2, "root_pane": 2},
    {"custom_name": null, "layout": {"Pane": 4},
     "panes": {"4": {"cwd": "/Users/rex/codes/rex-hugo"}},
     "zoomed": false, "focused": 4, "root_pane": 4}],
  "active_tab": 2}],
 "active": 0, "selected": 0,
 "sidebar_width": null, "sidebar_section_split": null,
 "collapsed_space_keys": []}

对着这份 JSON 复查一遍概念，会记得非常牢：

  • version: 3 是状态格式版本，不是 Herdr 版本
  • workspace w3 的 identity_cwd 是 rex-videos —— workspace 的身份绑在目录上， label 也是从这里来的
  • public_tab_numbers 是 [1,2,4]，next_public_tab_number 是 5 —— 印证了编号不回收（3 号 tab 被关过）
  • layout 这里都是 {"Pane": n}，也就是单个 pane 没有分割；分割之后这个字段会变成树形结构
  • 每个 pane 只存了 cwd —— 进程本身不在这里，它在 server 内存里，PTY 由 server 持有
  • zoomed / focused / active_tab 是 UI 状态，也被持久化了

所以「Herdr 记住了什么」这个问题的准确答案是：它记住的是布局、身份和 cwd， 以及（通过快照与 agent 集成）恢复所需的信息；活着的进程归 server 管。 这两件事的边界，正是模块 1 第 3 篇「五条状态路径」要讲的东西。

十、粒度决策表：到底该开新的什么#

这张表是我实际用了一段时间之后总结的，官方文档没有：

情况开新的什么理由
同一个项目的另一个长任务（另一个 agent）新 pane（同 tab 或新 tab）侧边栏汇总在 workspace 层，同项目就该在同一个 workspace 里
想把「agent 群」和「日志/服务」分开看新 tabtab 是布局单位，且可被 CLI 寻址，适合脚本往里塞东西
换了一个 repo / 换了一件不相干的事新 workspace汇总粒度就是 workspace，混在一起侧边栏就失去意义
要跑一次性的危险实验，怕污染主环境新 workspace，必要时新 tab关掉 workspace 比清 pane 干净
工作和私人要彻底隔离（连 socket 都不共享）命名 sessionsession 是运行时命名空间，隔离级别最高
要给不同团队/用户在同一台机器上跑 agent 群命名 session独立持久化状态与日志目录（sessions/<name>/）
只是想看一眼某个 agent 的终端直接 attach 到那个 agent不必切布局；见 herdr agent attach

十一、避坑指南#

  1. 别在 pane 里再跑 herdr。 先 echo $HERDR_ENV，为 1 说明你已经在了； Herdr 在设计上阻止嵌套启动。pane 里还有 HERDR_PANE_ID / HERDR_TAB_ID / HERDR_WORKSPACE_ID / HERDR_SOCKET_PATH 可以直接读到自己的身份，写脚本时非常有用。
  2. 别把八个项目塞进一个 workspace。 侧边栏的汇总粒度是 workspace， 塞在一起就等于放弃了 Herdr 最值钱的那个能力。
  3. done 和 idle 不是「完成 vs 空闲」的对立。 两者都表示可以接受输入， 区别只是「你看过了没有」，而且 seen 是每个 client 各记一份。 拿 CLI 输出去对屏幕角标对不上是正常的。
  4. detach 不等于 stop。 prefix+q 或关窗口之后 server 和 agent 都还在； 想真停只有 herdr server stop。反过来，发现 agent 不见了先查 server 是否被停或机器是否重启过。
  5. 多 client 看同一个 tab 时，尺寸归最后交互的那个。 手机接上去会把桌面布局挤变形， 这不是渲染 bug。要避免就别让两个 client 看同一个 tab。
  6. 别默认「一个 session 走天下」然后又在里面疯狂开 workspace。 session 层的隔离是要付代价的（你得自己记住哪个 session 有什么、日志分散在 sessions/<name>/）。绝大多数人只需要默认 session + 多 workspace。

下一步#

概念齐了，接下来是「每天怎么用」。模块 1 日常操作 会按 先鼠标、后键盘、再彻底搞懂状态的顺序讲：

  • 鼠标优先工作流：从建 workspace 到跑第一个 agent，全程不碰键位
  • 键盘控制：前缀键、五个必学键、copy mode，以及一套官方推荐的 prefix-free 方案
  • 会话状态五条路径：detach、快照恢复、pane 历史回放、agent 原生 resume、live handoff—— 这一篇会回答「关掉窗口/断 SSH/升级/重启之后，我的 agent 到底还在不在」

如果你更关心 agent 那一层，也可以直接跳模块 3 Agent 集成 。

常见问题

Herdr 的 session 和 workspace 有什么区别？

session 是后台 server 的命名空间，决定 socket、持久化状态和运行时的隔离边界；workspace 是 session 内的项目级容器，拥有 tab 和 pane，侧边栏按 workspace 汇总 agent 状态。官方建议先用 workspace，只有需要完全隔离的 pane、socket 和持久化状态时才用命名 session。

Herdr 的 agent 状态有哪几种？

blocked（需要你输入/批准/决策）、working（正在跑）、done（跑完了但你还没看）、idle（跑完或等待中，且已经被看过）、unknown（无法自信分类）。idle 和 done 都表示「可以接受输入了」，区别只在有没有被看过。

为什么 CLI 查到的 agent 状态和我屏幕上的角标不一样？

每个 client 各自记录自己展示过哪些完成。在一个 client 里看过某个完成，不会清掉另一个 client 的 Done 角标。CLI 和 API 用的是 server 的 seen 状态，所以不必和某个特定 client 的角标一致。

多个终端窗口同时接一个 Herdr 会怎样？

允许。只有一个 client 时所有 tab 跟随它的尺寸；多个 client 时各自可以看不同的 workspace 和 tab，各 tab 跟随各自的 client；当多个 client 看同一个 tab 时，最后一个 focus/select/interact 的 client 决定该 tab 的 pane 尺寸。

prefix mode 是什么？前缀键是哪个？

三种模式：terminal mode 把按键送进当前 pane；prefix mode 在前缀键之后等一个 Herdr 动作键；navigate mode 是常驻的工作区导航面。前缀键默认 ctrl+b，按法是先按 ctrl+b、松开、再按动作键，例如 c 新建 tab、w 打开工作区导航、q detach。prefix+? 列出当前全部生效绑定。

怎么判断我现在是不是已经在 Herdr 里？

看环境变量 HERDR_ENV，值为 1 就是。同 pane 里还有 HERDR_PANE_ID、HERDR_TAB_ID、HERDR_WORKSPACE_ID、HERDR_SOCKET_PATH 可直接读到自己的身份。Herdr 在设计上阻止嵌套启动，所以在 pane 里再跑 herdr 不会给你第二层。
