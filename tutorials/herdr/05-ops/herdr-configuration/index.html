Herdr 配置精读：208 个键分在 14 段，以及「reload 了但没变」到底意味着什么

把 Herdr 的 208 个配置键按「谁拥有它、什么时候生效」重新组织，而不是按名字背：配置文件位置与 Windows 差异、herdr --default-config 的 377 行怎么用、herdr config check 与 server reload-config 的真实输出、reload config 能热生效什么不能热生效什么（pane 默认值、worktree、集成、自定义命令归 server，主题、侧边栏、复制行为归 client）、headless_cols/headless_rows 为什么在无人连接时才是关键、terminal 三件套（default_shell、shell_mode、new_cwd）的真实取舍、keys.prefix 与直连键的区别、以及 experimental.allow_nested 这个键就是模块 4 里那道嵌套闸门的开关。附 14 段配置键数速查表与实验性键的风险分级。基线 herdr 0.9.2。

September 30, 2026 · 5 min · 983 words · 梦兽编程 -  |  English

Herdr 的配置项有 208 个。照着名字背显然是浪费——但按名字分类也不对，因为真正决定你配置会不会生效的，是「谁拥有这个设置」。

同一份 config.toml，主题改完 reload 立刻生效，pane 默认 shell 改完要新开 pane，kitty 图形开关改完要重启 server。这不是 bug，是这些设置分属不同进程的不同职责。

这一篇按「谁拥有 / 什么时候生效」重组这 208 个键，并把实验性键按风险分级，让你知道自己每次 true 在换什么。

基线：herdr 0.9.2 stable · macOS · 键数与默认值来自本机缓存的 config-reference.json（14 段），herdr -V / config check / reload-config 输出均为本机实测。

结论前置#

Herdr 的配置分三档生效：client 热生效、server reload 生效、startup-only 必须重启。 判断某个设置改完没反应，先问它归 client 还是 server，再问它是不是 startup-only——这两个问题能解决绝大多数「我明明改了」。 另外，「关闭一个坑」和「打开它」经常各有代价（光标锚点、IME 光标、嵌套启动都是），配置描述里的取舍句比默认值更值得读。

一、208 个键在哪、配置文件在哪#

位置#

Linux / macOS:  ~/.config/herdr/config.toml
Windows:         %APPDATA%\herdr\config.toml

herdr --help 会显示你机器上解析出来的路径。herdr status 里的 socket: 字段指向同一个根目录（本机实测 /Users/rex/.config/herdr/herdr.sock）。

从默认配置开始#

herdr --default-config          # 打印完整默认配置，本机实测 377 行
herdr --default-config > ~/.config/herdr/config.toml   # 从零开始配

也可以只查一个键的正确名字和取值：

herdr --default-config | grep -n 'headless_cols\|allow_nested'

本机实测默认配置里这些键都是注释状态（# allow_nested = false 之类），所以「键名写错了」不会报错——reload 成功，但设置没生效。排查设置不生效时，先确认键名拼写。

校验与生效#

herdr config check              # 校验配置
herdr server reload-config      # 让运行中的 server 重新读取

本机实测两个命令的输出：

$ herdr config check
config: ok

$ herdr server reload-config
{"id":"cli:server:reload-config","result":{"diagnostics":[],"status":"applied","type":"config_reload"}}

diagnostics 是空数组就说明这次 reload 没有产生诊断。配置值非法时，文档说 Herdr 会回落到安全默认值并显示启动警告——所以「配错了但没人告诉你」在热生效路径上是可能的，这一行 config check 值得每次改完都跑。

一个观察：theme 61 个键、keys 63 个键，两段占了三成。也就是说你实际会改的绝大多数键都在「外观」和「键位」里；控制面（server/session/terminal）加起来不到 10 个。

三、三档生效：谁拥有这个设置#

这是本篇的核心。文档原话把边界划得很清楚：

主题、侧边栏布局、复制行为等呈现设置来自 client 的本地配置，包括你查看某台 SSH 机器时。 pane 默认值、worktree、集成和自定义命令属于 pane 实际运行的那个 server。 UI 里的 reload config 会同时重载 client 本地设置和所选 server 的配置。

据此可以整理出三档：

档典型键改完怎么生效
client 热生效theme.*、ui.*（侧边栏、复制、toast、sound）、keys.*（本地键位）reload config 即可
server reload 生效terminal.*、worktrees.*、session.*、remote.*、advanced.*server reload-config
startup-only，必须重启experimental.kitty_graphics（文档：改完要重启 server 或重连 client）、session.startup_per_agent_delay_ms（文档：重启 server 生效）、ui.sidebar_start_collapsed（文档：下次启动生效）重启对应会话

所以「我改了主题但没变」和「我改了默认 shell 但新 pane 还是老 shell」是两种不同的现象，前者该查 client 是否真的收到 reload，后者是正常的——已有 pane 保留当前 shell，直到被重建。

键位的一个例外#

本地键位 reload 会生效，但如果你用 --remote-keybindings server，那用的是所选 server 的键位。也就是「改哪份键位」取决于你用哪种键位模式。

四、server 段：headless 尺寸，与你的 CI#

[server]
headless_cols = 160
headless_rows = 50

这两个键只在没有客户端连接时起作用（本机默认配置里它们是注释状态，即 120×40）。完整规则：

客户端状态行为
0 个所有布局和新 pane 用配置的虚拟尺寸
1 个所有 tab 跟着它
多个每个被查看的 tab 跟着最近 focus/select/interact 它的那个 client
从 2 变 1立刻全部回到剩下的那个的尺寸
从 1 变 0已有 pane 的 PTY 保留最后尺寸；新布局用配置回退值

最后一行是重点：一旦连接过，所有 client 断开之后，PTY 尺寸会停在最后那次的值——只有全新创建的 pane 才用 headless 回退值。

这对你在 CI 里跑 Herdr 很关键：如果你先用 TUI 连过、然后断开，再跑脚本量布局，得到的尺寸和纯 headless 不一样。要么全程不连、要么连之前先设好。

五、terminal 段：三个常被误解的键#

default_shell#

[terminal]
default_shell = "nu"

这是可执行文件名或路径，不是 shell 命令行——写 "nu --login" 是无效的。留空时回落到 $SHELL，Unix 再回落到 /bin/sh；Windows 上 pwsh.exe 在 PATH 就用它，否则用内置的 powershell.exe。已有 pane 保留当前 shell 直到重建。

shell_mode#

[terminal]
shell_mode = "auto"   # 默认

三档：auto / login / non_login。

auto 的含义在 macOS 上最有用：它用登录 shell 起新 pane，于是 /usr/libexec/path_helper、Homebrew 的 shell 初始化这类「只在登录 shell 里跑」的 PATH 设置会生效。 其他平台保持原来的非登录行为。

如果你遇到过「新 pane 里找不到 brew 装的命令」，shell_mode = "login" 就是解药。

new_cwd#

[terminal]
new_cwd = "follow"   # 默认
值行为
follow继承源 pane 或 workspace 的 cwd（默认）。没有源 workspace 时用 $HOME
home永远 $HOME
currentHerdr 进程所在目录
固定路径如 "~/Projects"

无论怎么设，CLI 或 socket API 显式传的 --cwd 仍然优先（模块 4 第 1 篇实测过 --cwd /tmp 会被规范化成 /private/tmp）。

kitty_graphics#

默认 true。文档有一句值得记：「外部 socket pane-overlay API 不再可用」——所以老教程里那套「外部 socket 叠加图片」的做法在 0.9.2 已经不工作了。要关掉就设 false，并且重启 server 或重连 client。

六、keys 段：prefix 与直连键#

keys.prefix = "ctrl+b"

默认 prefix 是 ctrl+b。键位字符串有两种含义，这个区别是配置错误最常见的来源：

写法含义
prefix+n先按配置好的 prefix，再按 n
ctrl+alt+n直连快捷键，不经过 prefix 模式

模块 1 第 2 篇专门讲过键位，这里只补配置视角的一点：keys 段有 63 个键，是最大的两段之一，且 prefix 本身可以写成数组来同时接受多个前缀键（例如 "f12"）。

直连键位如果毫无反应，问题通常不在这里——那是排障篇 第一节的排查顺序（OS 层 / 终端层 / Herdr 层）。

七、update 与 manifest_check：检测规则的更新是另一条通道#

[update]
channel = "stable"
version_check = true
manifest_check = true

manifest_check 控制的是agent 检测清单的后台更新（模块 3 讲过的那批规则）。关掉它，检测就只用二进制内置清单。

模块 4 第 2 篇实测过 server.agent_manifests 的返回：22 个 agent、21 个来自 remote、1 个 bundled，每个清单有日期式版本号（2026.09.23.1 这种）。所以：

  • 「Herdr 版本旧」不等于「检测规则旧」——清单独立更新、不需要重启
  • 排查「检测行为变了」时，看的是清单版本，不是 herdr -V

channel 在 Windows 上有额外含义：stable 的 Windows 安装默认 stable，已有的 preview 安装会留在 preview，直到你显式 herdr channel set stable。

八、experimental 段：读 description 再开#

7 个实验性键，风险从低到高：

键默认取舍
switch_ascii_input_source_in_prefixfalseprefix 模式下临时切到 ASCII 输入源，让 prefix 命令不被 IME 吃掉。Windows 只支持韩文 IME，其他语言会保持不变
reveal_hidden_cursor_for_cjk_imefalse把聚焦 pane 的光标锚点暴露给外层终端，即使 pane 请求了 ?25l（隐藏光标）。代价：隐藏光标但不画替代物的应用（vim 普通模式）会多出一个可见硬件光标
cjk_ime_cursor_shapesteady_block上一个键渲染的光标形状
cjk_ime_agents[]把上一个键限制到指定 agent（空 = 任何聚焦 pane）。未知名字被忽略；如果列表里全是未知名字，则 reveal 不生效
pane_historyfalse把 pane 屏幕历史持久化到 session-history.json
allow_nestedfalse模块 4 第 1 篇那道嵌套保护闸门的开关
kitty_graphicsunset已废弃的兼容键；新键是 terminal.kitty_graphics，两者都设时新键优先

allow_nested 与模块 4 的连接#

模块 4 第 1 篇实测过在 Herdr pane 里启动嵌套 Herdr 会被拒：

error: nested herdr is disabled by default.
see configuration if you want to enable it.

报错里那句「see configuration」指的就是这个键。本机默认配置里它是注释状态（默认 false）。

在你真的需要它之前，先读一下这条新闻的代价：agent 在 pane 里能启动新 Herdr，等于给了 agent 自我复制会话的能力。如果只是为了测试某段启动逻辑，用模块 4 第 1 篇的命名会话方案（--session <name> + 独立 socket）就够了，不需要放开这个闸门。

九、worktrees 与 remote：两个单键#

[worktrees]
directory = "~/.herdr/worktrees"   # 默认

[remote]
manage_ssh_config = true           # 默认

worktrees.directory 决定 checkout 的根，Herdr 在 <directory>/<repo>/<branch-slug> 下创建。想要「同级目录」效果就指向 ~/Projects/herdr-worktrees。

remote.manage_ssh_config 打开时，herdr --remote 会写一份私有的临时 SSH 配置：先包含你的用户级和系统级 SSH 配置，再补上兜底的 ServerAliveInterval / ServerAliveCountMax（你自己的设置优先）。Linux 和 macOS 还用一个私有的 per-attach OpenSSH 控制套接字来复用第一次认证的连接；Windows OpenSSH 不支持这个复用。设 false 就走原生 ssh，不加任何 Herdr 生成的东西。

模块 2 讲过 SSH 认证的排查，这里补一句配置视角：复用的存在意味着「第一次认证成功之后不需要再提示」，如果你在远程 setup 时反复被要求输入口令，很可能就是这条复用路径没生效。

十、session 段：agent 恢复的两个键#

[session]
resume_agents_on_restore = true
startup_per_agent_delay_ms = 100

resume_agents_on_restore 打开时，恢复 Herdr session 会把支持的 agent pane 恢复到它们各自的原生会话。模块 1 第 3 篇讲过 session 状态，这一键就是「agent 的对话也一起恢复」的那个开关。

startup_per_agent_delay_ms 是自动恢复时 agent 之间的间隔（第一个 agent 不延迟，0 表示关闭间隔）。文档明确：不影响手动启动和显式终端 attach，且需要重启 server 生效。 大量 agent 同时恢复会互相抢 CPU/CPU 亲和性时，调这个。

十一、避坑指南#

  1. 「改了没生效」先分 client / server。主题侧边栏归 client；pane 默认值、worktree、集成归 server。
  2. startup-only 设置 reload 无效，包括 terminal.kitty_graphics、session.startup_per_agent_delay_ms、ui.sidebar_start_collapsed。
  3. 改完先跑 herdr config check。热生效路径上非法值会静默回落，reload 的 diagnostics 数组是唯一信号。
  4. 默认配置里大量键是注释状态，键名拼错不会报错。herdr --default-config | grep 查准确名字。
  5. headless 尺寸只在 0 个 client 时是新布局的规则；client 断开后已有 PTY 保留最后尺寸。
  6. default_shell 写可执行名不是命令行。"nu --login" 无效。
  7. 新 pane 找不到 brew 的命令 → shell_mode = "login"。auto 在 macOS 上已经等价于 login。
  8. --cwd 永远优先于 new_cwd，而且 macOS 上会被规范化成真实路径（/tmp → /private/tmp）。
  9. terminal.kitty_graphics 取代了旧的外部 socket 叠加 API，老教程那段做法已经失效。
  10. manifest_check = false 会让检测规则退回内置版本，排查检测行为差异时先确认这个开关。
  11. cjk_ime_agents 全是未知名字时，reveal 不生效——不是 bug，是「没有有效目标」的直接后果。
  12. allow_nested 默认 false 是在防 agent 自我复制会话。能不用不开；测试启动逻辑用命名会话。

常见问题

改了 config.toml 之后要怎么生效？

herdr server reload-config。本机实测它的返回是 status=applied 带一个 diagnostics 数组：改成这样 {"id":"cli:server:reload-config","result":{"diagnostics":[],"status":"applied","type":"config_reload"}}，diagnostics 为空就是没有诊断。但要注意 reload 只热生效大部分 UI 设置，startup-only 的设置仍然需要重启。

为什么 reload 了但设置没变？

因为配置分属两端。文档说得很明确：主题、侧边栏布局、复制行为等呈现设置来自 client 的本地配置（包括你查看某台 SSH 机器时）；pane 默认值、worktree、集成、自定义命令属于 pane 实际运行的那个 server。所以改错了文件热生效不了是常态。另外还有一批 startup-only 设置，reload 对它们无效，必须重启对应会话。

herdr --default-config 要怎么用？

它打印完整默认配置，本机实测 377 行。想从零开始配就 herdr --default-config > ~/.config/herdr/config.toml。它的另一个用处是「查一个键的正确名字和取值」——比如你从博客抄了一个键名但 reload 没报错也没生效，很可能是名字写错了而在默认配置里它被注释掉了。

实验性配置键能不能开？

看键名和取舍说明。experimental.allow_nested 就是模块 4 第 1 篇那道嵌套保护闸门的开关，默认 false。experimental.reveal_hidden_cursor_for_cjk_ime 的描述里明确写了取舍：开启后对于隐藏光标但不绘制替代物的应用会出现额外的可见硬件光标。这类键改了可能随版本变化语义，先读它的 description 再开。

无头运行（没有客户端连接）时 Herdr 的终端尺寸是什么？

server 用 120×40 的虚拟终端给布局和新建 pane 用，这可以用 [server] 下的 headless_cols 和 headless_rows 改（本机默认配置里两行都是注释状态）。有一个已连接 client 时所有 tab 跟着它的尺寸；多个 client 时每个被看的 tab 跟着最近交互它的那个；所有但一个 client 断开时立即回到剩下那个的尺寸；全部断开时已有 pane 的 PTY 保留最后尺寸、新布局用配置的回退值。
