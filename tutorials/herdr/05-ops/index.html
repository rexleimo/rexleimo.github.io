模块 5：排障与调优

前四个模块讲的是功能：它是什么、怎么用、怎么被代码控制。这个模块讲出问题时怎么办和怎么把它调成你要的样子。

这两个话题看起来琐碎，但它们决定了一个工具你能不能长期依赖：一个功能再好用，故障判断顺序不清楚、配置改了不知道为什么不生效，你还是会在第二次踩坑时把它卸掉。

这一模块三篇的写法都遵循一个原则：先给判断依据，再给处置，最后说清代价。因为排障里最贵的动作往往不是错的命令，而是不知道它会不会杀掉正在跑的进程。

基线：herdr 0.9.2 stable · 文档源 pinned v0.9.2 实测：日志路径与结构、config check、reload-config 返回、launchctl managername、默认配置 377 行、208 个配置键 / 14 段

前置要求

  • 已完成模块 0 ，herdr status 能看到 server running
  • 第 1、3 篇按需读；第 2 篇建议对照自己的 ~/.config/herdr/config.toml
  • 第 3 篇即使你不用 Windows 也值得读——它解释了很多「Unix 上正常但别处不正常」的原因

学习目标

完成本模块后，你能回答：

  • 一个异常该往哪查：外层终端、操作系统、还是 Herdr，以及为什么这个顺序不能反
  • 为什么 herdr server stop 会结束所有 pane 进程，命名会话该用什么命令代替
  • 双发按键、IME 候选窗错位、Option 方向键冒字符，分别归谁修
  • 为什么「注销后 SSH/DNS 失效」不能靠重新登录或 live handoff 修好
  • 改完 config.toml 没反应：怎么判断是键名写错、归错进程、还是 startup-only
  • 哪个实验性开关就是你在模块 4 里遇到的那道嵌套保护
  • Windows 上哪些能力可以用、哪些是 partial、哪些明确不支持，以及 partial 里最影响日常的是哪两项

一句话结论

排障先分「谁持有问题」，调优先分「谁拥有这个设置」。 前者决定你去改终端、改 OS 还是改 Herdr；后者决定你 reload 一下还是要重启会话。 而两者共同的代价意识是同一件事：server stop 会结束 pane 进程，动手前先确认里面有没有正在跑的东西。

这个模块的三个反直觉点

  1. launchctl managername 返回 Background 不代表 Keychain 有问题（本机实测就是这个值）——它是自动启动 server 的正常状态，很多人跳过这步直接白重启一次。
  2. 重新登录修不好注销后 SSH/DNS 失效的 server，而 live handoff 修不了它（因为 handoff 保留的正是那个坏掉的上下文）。这需要完整重启。
  3. Kitty 在 Herdr 之外按键正常、里面不正常是真实现象：kitty 的自动 zsh 集成只给它自己启动的 shell 装绑定，不给多路复用器创建的 shell 装。
