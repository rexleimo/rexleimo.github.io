模块 4：编程化控制

模块 0–3 讲的是人在 Herdr 里怎么工作。这个模块讲的是另一半：代码怎么把 Herdr 当接口用。

这是 Herdr 和 tmux / zellij 拉开差距的另一处——它不只是「有个 CLI」，而是整个 UI 背后就是一个 socket API，CLI 是它的薄封装，插件是它的固化形式。你要做的只是决定从哪一层进去。

这一模块四篇，全部在隔离命名会话里实测完成，包括一个真实探针插件的完整生命周期。

基线：herdr 0.9.2 stable · macOS · 文档源 pinned v0.9.2 实测规模：18 个 CLI 顶层动词、102 个 socket 方法、27 个可订阅事件、22 份 agent 检测清单、14 个注入插件的环境变量

前置要求

  • 已完成模块 0 ，herdr status 能看到 server running
  • 会读 JSON、能写一点 shell 或 Python（第 2、3 篇要发 socket 帧）
  • 第 3 篇建议先读模块 3 第 1 篇 ：状态语义是编排的前提
  • 第 4 篇需要会写 TOML，并且手边有一个能跑的脚本

学习目标

完成本模块后，你能回答：

  • CLI 的 18 个动词和 socket 的 102 个方法是什么关系，哪些能力只有 socket 有
  • 为什么 herdr xxx | jq 在失败时会骗你，以及退出码 1 和 2 分别该做什么
  • --session、HERDR_SOCKET_PATH、HERDR_SESSION 的优先顺序，以及为什么 HERDR_CONFIG_PATH 不能当隔离手段用
  • 在一个 Herdr pane 里启动第二个 Herdr 会被拒两次，两次的原因分别是什么、怎么绕
  • agent target 到底能写什么（实测四行矩阵），以及为什么 agent get claude 会失败
  • 为什么「我刚才报了 working」不等于「它现在是 working」
  • 为什么 socket 上不能复用连接发第二个请求，以及订阅为什么可以
  • events.subscribe 和 events.wait 为什么用两套事件命名，以及后者在 0.9.2 实际支持几种
  • 插件 link 成功但事件钩子永不触发，最可能是什么原因
  • 插件的 config 目录和 state 目录为什么不在同一棵树下

一句话结论

Herdr 的控制面是一层 NDJSON socket API，CLI 是它的封装，插件是它的固化。 三层共享同一个控制面，但只有 socket 那层是完整接口。 而这三层共同的工程含义是：接受 ≠ 生效——命令 rc=0 不代表状态被保住，manifest link 成功不代表清单干净，订阅发出去不代表订阅生效。每一步都要读回来看。

实测方法说明

这个模块的所有结论都来自隔离会话，方法本身也值得记一下：

  1. 用带真实窗口大小的 pty 起一个命名会话（第 1 篇第四节有可运行代码）
  2. 所有写操作都带 --session <name>，物理上走另一个 socket
  3. 测完 herdr session stop <name>，不用 server stop
  4. 涉及全局注册表的实验（插件），测完立刻 plugin unlink 并验证 plugins.json 回到 []

第 3 篇还额外记录了一次我自己的测量错误及其被推翻的过程——那部分不是装饰，它是这一模块最实用的内容之一。
