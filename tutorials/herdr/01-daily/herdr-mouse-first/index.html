Herdr 鼠标优先工作流：从建 workspace 到跑第一个 agent，全程不碰键位

Herdr 是鼠标原生的：点击窗格/标签/工作区聚焦、拖动分割线改大小、右键菜单分割与新建、拖选即复制、双击选词、Ctrl+点击开链接。本文按官方 quick-start 的真实顺序走完第一个 workspace 与第一个 agent，标出哪些事鼠标就能做、哪些事必须上键盘（只有一个真的值得学：prefix+g 的 goto picker），并给出本机 herdr 0.9.2 的 workspace list / agent list 实测输出。

September 29, 2026 · 4 min · 770 words · 梦兽编程 -  |  English

验证版本： herdr 0.9.2（stable channel）· 本机实测 macOS / Apple silicon · 2026-09-29

官方文档在 quick-start 和 concepts 两页里都写了同一句话：

No keybindings are required to use Herdr.

这不是客套。Herdr 是鼠标原生（mouse-native）的，键盘是可选层。 所以这一篇全程用鼠标走完第一个 workspace 和第一个 agent，最后只告诉你一个真的值得学的键位。

先给结论：

前 30 分钟别碰键盘。 鼠标能覆盖建 workspace、分割、切换、复制、开链接、重命名这些全部日常动作。 唯一值得早期就学的是 prefix+g（goto picker）——因为当你有 8 个 agent 时， 它是唯一能按状态过滤的入口，鼠标点侧边栏做不到这件事。

第 1 步：进项目目录，跑 herdr#

cd ~/codes/your-project
herdr

就这两行。官方文档特别强调了两件事：

  • 它会自动启动或接上默认后台会话，你不需要管理 socket
  • 会话里一个 workspace 都没有时，Herdr 自动开一个

首次运行会走一遍 onboarding 流程（选完之后它会往 config.toml 里写 onboarding = false—— 本机实测这个文件里就只有这一行）。

注意：如果你已经在一个 Herdr pane 里（echo $HERDR_ENV 输出 1）， 不要再跑 herdr。Herdr 在设计上阻止嵌套启动。

第 2 步：认一下界面#

进去之后你会看到三块东西：

区域是什么怎么用鼠标操作
侧边栏workspace 列表，每个 workspace 下面按 tab/pane 列出 agent 与终端，带状态点击 workspace 切换；点击 agent 行直接跳到那个 pane
主区域当前 tab 的 pane 布局点击 pane 聚焦；拖动分割边框改大小；右键出菜单
状态栏当前模式、主前缀键等只读；prefix+? 能展开完整帮助

侧边栏的宽度可以在配置里调（sidebar_width），也可以直接拖。 本机的 session.json 里 sidebar_width 是 null，意思是「用默认值」。

关于 workspace 的粒度，官方建议是一个 repo / 一个任务 / 一次排查 = 一个 workspace， 理由在核心概念 里讲过：侧边栏的状态汇总是按 workspace 做的。 把八个项目塞进一个 workspace，你就放弃了 Herdr 最值钱的那个能力。

第 3 步：鼠标手势全表#

这一节建议直接当速查表用。全部来自官方 quick-start / concepts 两页：

手势作用
点击 pane / tab / workspace / agent聚焦
拖动分割边框调整 pane 大小
右键上下文菜单，里面有分割窗格和新建 tab
拖选文字松开即复制到剪贴板，不需要 ctrl+c
双击选中一个 token
双击后第二下按住拖动按整词扩展选区
Ctrl + 点击打开 pane 里的链接（OSC 8 超链接、http://、https://）
Ctrl + 悬停把链接的可见段加下划线
鼠标滚轮 / 点滚动条槽 / 拖滑块在 goto picker 列表溢出时滚动，且不会误跳到某个目标

几个需要展开说的细节：

折行的链接也能点#

Ctrl-click 支持开头或结尾在可视区外的折行链接——这个细节在长 URL 的日志里非常实用。 悬停高亮会在三种情况下清除：指针移开、pane 内容变化、或 Herdr 收到 Ctrl 释放事件。 官方补了一句：有些终端只在鼠标移动时才上报修饰键变化，所以「按住 Ctrl 但高亮没出现」 可能是终端的问题，不是 Herdr 的。

macOS 上的 Ctrl vs Cmd#

这条是 mac 用户最容易困惑的：

  • 鼠标捕获开启时（默认），Herdr 处理的 pane 链接走 Ctrl-click
  • Cmd-click 只在终端原生旁路下可用，比如 Shift-Cmd-click，或者你把捕获关掉：
[ui]
mouse_capture = false

关掉捕获之后，Herdr 就不抢鼠标了——所有鼠标事件直接给终端和 pane 里的程序。 代价是你失去了上面那张表里的全部鼠标操作。这是个二选一的开关，不是「更安全的默认值」。

想让右键直接给 pane 里的程序#

有些 TUI agent 自己有右键菜单。Herdr 给了两条路：

路 A：设一个透传修饰键（全局生效）

[ui]
right_click_passthrough_modifier = "..."   # 该修饰键 + 右键 → 透传给 pane 里的程序

设了之后，「该修饰键 + 右键」会把右键的按下、保持、拖动全部送给支持鼠标上报的 pane 程序。

路 B：只给某一个 pane 改（更常用）

在那个 pane 的菜单里选 Send right-clicks to pane，或者在里面执行：

herdr pane input --current --right-click pane

之后右键 pane 的边框可以重新打开 Herdr 自己的菜单——所以你不会把自己锁死。

第 4 步：跑第一个 agent#

在 pane 里正常启动你的 agent 就行：

claude

或者 codex、pi、opencode，或任何受支持的 agent 外部链接 。 官方原文：Herdr detects it automatically——自动检测，不需要你注册、不需要你配置。

检测生效之后，侧边栏会跨所有 workspace 显示每个 agent 是 working、blocked、done 还是 idle， 所以你随时知道哪个项目在等你。

本机实测（写这篇时的真实状态，一个集成都没装）：

$ herdr workspace list
{"id":"cli:workspace:list","result":{"type":"workspace_list","workspaces":[
  {"active_tab_id":"w3:t1","agent_status":"working","focused":true,
   "label":"rex-videos","number":1,"pane_count":3,"tab_count":3,
   "workspace_id":"w3"}]}}

$ herdr agent list   # 三个 pane，三个 pi agent
{"agent":"pi","agent_status":"working","cwd":"/Users/rex/codes/rex-videos",
 "pane_id":"w3:p1","tab_id":"w3:t1","terminal_title":"π - rex-videos","focused":true}
{"agent":"pi","agent_status":"working","cwd":"/Users/rex/codes/rex-hugo",
 "pane_id":"w3:p2","tab_id":"w3:t2","terminal_title":"π - rex-hugo"}
{"agent":"pi","agent_status":"working","cwd":"/Users/rex/codes/rex-hugo",
 "pane_id":"w3:p4","tab_id":"w3:t4","terminal_title":"π - rex-hugo"}

注意 workspace 层的 agent_status: "working" 是从内部 agent 汇总上来的， 不是它自己的状态。这个汇总就是「哪个项目需要你」的答案来源。

第 5 步：分割窗格，摆一个多 agent 布局#

两条路，效果一样：

  • 鼠标：右键 → 分割（右 / 下）
  • 键盘：prefix+v 向右分割、prefix+minus 向下分割

我实际在用的布局是按视图分 tab（这也是官方 concepts 页推荐的用法： agents / logs / server / review）：

tab里面放什么
agents每个 agent 一个 pane，横向排开，方便扫状态
logsnpm run dev / 日志 tail / 测试 watch
server数据库、后端服务这类长期进程
reviewgit、lazygit、diff 工具

为什么推荐用 tab 而不是把所有东西塞进一个 tab 分割：tab 可以被 CLI 和 socket API 寻址 （herdr tab ...），所以脚本可以「往 logs tab 里开个 pane 跑测试」而不抢走你正在看的焦点。 纯分割做不到这件事。

第 6 步：走人和回来#

prefix + q      # detach：client 走了，server 和 agent 全都在

或者直接关掉终端窗口，效果一样。

回来：

herdr

接回同一个会话，pane 里的进程从没停过。

真想全部停掉，只有这一条：

herdr server stop

这是新手最大的一个认知坑：以为关窗口就是停了。不是。 反过来说，如果你的 agent「莫名其妙消失了」，第一件事是查 server 是不是被停了、 或者机器是不是重启过——这两种情况的恢复路径完全不同， 见会话状态五条路径 。

第 7 步：唯一值得早学的键位 —— prefix+g#

前面说了全程可以用鼠标。但有一个功能鼠标替代不了，而且 agent 一多就是刚需：

goto picker（prefix+g）。它的行为（官方 keyboard 页原文口径）：

  • 每个 agent 或终端单独占一行，按 workspace 分组
  • 分割出去的 pane 不会被藏在别的行后面（这点比「按 tab 列」的选择器好用得多）
  • 点击一行或按 Enter 直接跳过去
  • 按 / 搜索：可搜名字、agent 类型、tab、workspace、分支、路径
  • 不在输入搜索词时，用 Up/Down 或 j/k 移动；Left/Right 跳到上一个/下一个 workspace 分区的第一个 agent 或终端（不回绕）；正在编辑搜索词时 Left/Right 变成移动文本光标
  • 不在搜索状态时，b / w / i / d 分别只看 blocked / working / idle / done 的 agent，a 恢复显示全部终端
  • 选中目标的位置和路径显示在列表下方
  • 列表溢出时可以用滚轮、点滚动条槽、拖滑块滚动，不会误跳到某个目标

最后那条 b（只看 blocked）就是「我有 8 个 agent，哪个在等我」这个问题的一键答案。 侧边栏能显示状态，但不能过滤；goto picker 能。

另外顺手记一个：prefix+? 列出当前全部生效的绑定（包括你自己改过的）， 帮助面板里按 / 可以过滤动作和快捷键，Backspace 编辑过滤词，ctrl+u 清空。 忘了键位就按它，别去翻文档。

什么时候必须上键盘#

老实说，只有这几种情况鼠标不够：

需求为什么鼠标不行用什么
按状态过滤 agent侧边栏只显示不过滤prefix+g 然后按 b/w/i/d
从历史输出里搜一个字符串拖选只能选可见区域prefix+[ 进 copy mode，/ 或 ? 搜，n/N 跳
detach关窗口虽然等效，但有时你不想关窗口prefix+q
快速在 9 个 tab 之间跳点侧边栏要点两下prefix+1..9
缩放某个 pane 看细节右键菜单里有，但键位快得多prefix+z
脚本化操作（模块 4 的内容）鼠标不可编程CLI / socket API

完整的键位表和 prefix-free 方案在下一篇：键盘控制 。

避坑指南#

  1. 别在 pane 里再跑 herdr。 先 echo $HERDR_ENV，为 1 说明你已经在里面；嵌套启动被设计阻止。
  2. 关窗口 ≠ 停。 想停只有 herdr server stop。同理，prefix+q 之后别以为进程没了。
  3. macOS 上别用 Cmd-click 点 pane 里的链接。 鼠标捕获开着的时候要用 Ctrl-click； Cmd-click 只在终端原生旁路（Shift-Cmd-click）或 mouse_capture = false 下有效。
  4. mouse_capture = false 不是「更安全」，是「换一套交互」。 关掉之后本文那张手势表全部失效。 想两全就用 right_click_passthrough_modifier，或者对单个 pane 用 herdr pane input --current --right-click pane。
  5. 不要把所有项目塞进一个 workspace。 汇总粒度就是 workspace，混在一起侧边栏就废了。
  6. 别指望「拖选复制」在 copy mode 之外的所有场景都符合直觉。 官方明确说： 鼠标拖选和用 v/Space/V 起的选区在输出和重绘期间保持有效， 复制读的是该区域当前的文本而不是冻结快照；但调整 pane 大小或在普通屏与备用屏之间切换 会清掉选区。想稳定地复制大段历史输出，还是进 copy mode。
  7. onboarding 没走完会一直弹。 它由 config.toml 里的 onboarding 控制； 选完就是 false。改完记得 herdr server reload-config（或全局菜单 → reload config）才作用于运行中的 server。

下一步#

鼠标够用了，接下来把键盘这一层补齐——尤其是怎么配一套 prefix-free 键位而不和 终端/桌面环境打架（官方为此实测了 10 个终端的默认键位，结论是 ctrl+alt 家族最安全）： 键盘控制 。

如果你更担心「跑着长任务的 agent 会不会丢」，直接跳会话状态五条路径 。

常见问题

用 Herdr 必须学快捷键吗？

不必。官方明确写 No keybindings are required to use Herdr。点击窗格/标签/工作区/agent 聚焦，拖动分割边框改大小，右键菜单里分割窗格和新建标签，拖选文字即复制。键盘是可选层。

第一次跑 Herdr 要做什么？

cd 到项目目录后执行 herdr。它会自动启动或接上默认后台会话；会话里没有任何 workspace 时会自动开一个。首次运行会走一遍 onboarding。你不需要管 socket。

怎么在 Herdr 里复制文字？

鼠标拖选，松开即复制到剪贴板，不需要 Ctrl+C。双击选中一个 token；第二下按住拖动可按整词扩展选区。键盘路线是 prefix+[ 进 copy mode，用 v 或 Space 起选、y 或 Enter 复制、q 或 Esc 退出。

macOS 上 Cmd+点击链接为什么有时不管用？

鼠标捕获开启时，Herdr 处理的 pane 链接走 Ctrl-click。Cmd-click 只在终端原生旁路下可用，例如 Shift-Cmd-click，或者把 ui.mouse_capture 设为 false。

关掉终端窗口，我的 agent 会停吗？

不会。server 持有 pane 和进程，detach（prefix+q）或直接关窗口之后一切照跑，再执行 herdr 就接回同一个会话。真想全停只有 herdr server stop。

只有一个键盘功能值得先学的话是哪个？

prefix+g 的 goto picker。它把每个 agent 或终端单独列一行、按 workspace 分组，分割出去的 pane 不会被藏在别的行后面；按 / 可搜名字、agent 类型、tab、workspace、分支和路径；不在搜索状态时按 b/w/i/d 可只看 blocked/working/idle/done 的 agent，a 恢复显示全部终端。
