Herdr 键盘控制：前缀键、五个必学键、copy mode 与一套不打架的 prefix-free 方案

Herdr 的键盘层完整拆解：前缀键为什么存在（OS、外层终端、pane 内程序三层都在抢按键）、prefix+c/v/minus/h-j-k-l/w/q 五个必学键、pane/tab/workspace 全键位表、Herdr 自有文本字段的编辑键、copy mode 的移动与搜索规则；[keys] 的绑定语法（prefix 可为数组、一个动作可绑多个键、命名标点、indexed 1..9）、[[keys.command]] 的 popup/pane/shell/plugin_action 四种类型，以及官方实测 10 个终端后给出的 ctrl+alt prefix-free 方案和必须避开的组合。

September 29, 2026 · 5 min · 977 words · 梦兽编程 -  |  English

验证版本： herdr 0.9.2（stable channel）· 本机实测 macOS / Apple silicon · 2026-09-29

上一篇 全程用鼠标跑通了第一个 workspace。 这一篇补键盘层——但重点不是键位表（那个 prefix+? 随时能查）， 而是两件更容易搞错的事：为什么要有前缀键，以及怎么配一套不和别人打架的直接键位。

先给结论：

前缀键不是历史包袱，是必需的。 一个按键要穿过三层才能到 Herdr：操作系统、外层终端、 pane 里跑的程序——它们已经占用了几乎所有常见组合。前缀键让 Herdr 只保留一个键而不是几十个。 如果你一定要 prefix-free，官方实测了 10 个终端 + GNOME/KDE 的默认键位， 结论是只有一个修饰键家族几乎没人碰：ctrl+alt。

一、前缀键到底解决什么问题#

官方 keyboard 页的解释非常清楚，值得原文引一次：

A terminal multiplexer sits between your terminal and the programs running inside it. Those programs already use most key combinations: ctrl+c interrupts, ctrl+r searches history, editors claim nearly everything else. If Herdr grabbed common keys directly, it would break the programs inside it.

多路复用器夹在你的终端和里面跑的程序之间。那些程序已经用掉了大部分组合键： ctrl+c 是中断，ctrl+r 是搜历史，编辑器几乎占掉了剩下的全部。 如果 Herdr 直接抢常见键，它就会破坏里面的程序。

所以：Herdr 只保留一个键（前缀），而不是几十个。

按法要特别强调一次，因为这是 tmux 新手最常卡住的地方：

prefix+c 的意思是：按下 ctrl+b，松开，然后按 c。

不是三个键同时按。

随时可用的两个救命键：

键作用
prefix+?列出当前生效的全部绑定（包括你自己改过的）。帮助面板里按 / 过滤动作和快捷键，Backspace 编辑过滤词，ctrl+u 清空
prefix+[进 copy mode（键盘复制）

从 tmux / zellij 过来的话：这套模型你已经会了。官方直接建议跳到 键位参考 外部链接 看完整默认键位图和配置语法。

二、先学这五个#

动作键
新建 tabprefix+c
向右 / 向下分割prefix+v / prefix+minus
在 pane 之间移动prefix+h/j/k/l
工作区导航prefix+w
detach，一切照跑prefix+q

官方原话：These cover most daily movement. Everything else can stay on the mouse. ——这五个覆盖了日常大部分移动，其余的继续用鼠标就行。

Workspace 与 session#

动作键

重命名 workspaceprefix+shift+w

prefix+g 是唯一一个我在上一篇 就强烈建议早学的： 它把每个 agent / 终端单独列一行、按 workspace 分组，分割出去的 pane 不会被藏在别的行后面， 而且不在搜索状态时按 b/w/i/d 可以只看 blocked/working/idle/done 的 agent，a 恢复全部。 「8 个 agent 里哪个在等我」这个问题，它是唯一的一键答案。

四、Herdr 自己的文本字段：另一套编辑键#

这一节最容易搞混，所以单独立一节。

适用范围：Herdr 的命名对话框、worktree 分支输入框、过滤器、copy mode 的搜索框。 不适用于 pane 里的 shell 或 agent——那些是 pane 内程序自己的键。

动作键
移动一个字符Left / Right、Ctrl+B / Ctrl+F
移到开头 / 结尾Home / End、Ctrl+A / Ctrl+E
移动一个词Alt+B / Alt+F
删前一个字符Backspace、Ctrl+H
删后一个字符Delete、Ctrl+D
剪到开头 / 结尾Ctrl+U / Ctrl+K
剪掉前一个词Ctrl+W、Alt+Backspace、Ctrl+Backspace
剪掉后一个词Alt+D
插入上次剪掉的文本Ctrl+Y

四条注意事项（都是官方明写的）：

  1. 输入和粘贴都在光标处插入
  2. 移动和删除尊重 Unicode grapheme 边界（所以 emoji、组合字符不会被切坏），长值会横向滚动
  3. 剪掉的文本只在当前字段内流转，不进系统剪贴板 —— 所以 Ctrl+Y 粘不出你刚才在 pane 里复制的东西
  4. Alt 系列快捷键需要终端能上报 Alt/Meta；Enter 和 Esc 保留对话框的确认/取消语义

五、Copy mode：从键盘复制历史输出#

prefix+[ 进入当前焦点 pane 的 copy mode。

移动：h/j/k/l、tmux 风格的 w/b/e 与大词版 W/B/E、{/}、 PageUp/PageDown、ctrl+b/ctrl+f、ctrl+u/ctrl+d。

搜索：/ 正向、? 反向，都是字面搜索；n 同向重复、N 反向重复。 大小写规则很聪明：查询里不含大写字母时不区分大小写，含大写就区分。

选择与退出：v 或 Space 起选，y 或 Enter 复制，q 或 Esc 不复制退出。 Esc 会先清掉当前选区或搜索，再退出（所以要按两次才真的出去）。

三个反直觉但重要的行为：

  1. copy mode 不暂停 pane 进程。 输出继续实时产生并在底部跟随； 当你往历史里翻时，视图钉住不动。
  2. 前缀键在 copy mode 里保留原本的含义。 用默认前缀时，ctrl+b 是进 prefix mode， 不是「向上翻页」。如果你想要 ctrl+b 当 copy mode 的翻页键，就得换一个前缀。
  3. 选区在输出和重绘期间保持有效（鼠标拖选的、以及 v/Space/V 起的都是）， 即使选区一部分在视口外；复制读的是该区域当前的文本，不是冻结快照。 但调整 pane 大小或在普通屏与备用屏之间切换会清掉选区。

最后补一句：鼠标拖选根本不需要进 copy mode，松开就复制。copy mode 的价值在于 搜历史和精确选择视口外的内容。

六、改任何绑定（包括前缀键本身）#

最小改动#

[keys]
prefix = "ctrl+a"

一个典型的覆盖块#

[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"

前缀键可以是数组#

需要多个键都能进 prefix mode 时（官方给的场景：同一份配置在 macOS 和远程 Linux 之间共用）：

[keys]
prefix = ["ctrl+space", "ctrl+s"]

每个配置的前缀都进入同一个 prefix mode，都能启动所有 prefix+... 动作。 第一个是状态栏显示的主前缀；prefix+? 的帮助面板会列出全部。

一个动作也可以绑多个键#

[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]

键字符串的语法#

支持：

  • 普通键、修饰组合：ctrl+a、shift+n、alt+1、cmd+k
  • 特殊键名：enter、tab、esc、left、right、up、down
  • 命名标点：minus、comma、ampersand、plus、backtick

安全规则（这条最容易踩）：

裸的可打印键（比如 n）是不安全的，因为它会拦截正常打字。 除非你确实想要一个直接绑定，否则一律用 prefix+n。

navigate 模式专用字段的额外限制：navigate_workspace_* 和 navigate_pane_* 可以用裸键（如 j、k），但不得使用 prefix+、esc、enter、tab、shift+tab、 left、right，以及不带修饰的 1 到 9。

还有三条细节：

  • 左右箭头是 pane-left / pane-right 导航的永久别名
  • navigate 模式的快捷键独立于一般动作绑定（例如 focus_pane_down = "prefix+j"）； 两者用同一个键时，navigate 模式打开期间 navigate 快捷键优先
  • Alt、Cmd/Super、带修饰的标点能否工作取决于你的终端（和 tmux 设置）

带编号的跳转#

[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"

1..9 是普通键位字段里的语法。旧的 [keys.indexed] 表仍然会被解析（兼容性）， 但新配置应该用上面这些显式动作字段。

自定义命令绑定#

这是 Herdr 键位系统里最有生产力的一块。四种 type：

[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
type行为
popup打开一个 session 级模态弹窗，不改变 tab 布局。弹窗接管全部终端输入，包括 Esc，直到它的命令退出
pane打开一个临时缩放 pane，命令退出时自动关闭
shell后台分离运行
plugin_action调用一个已安装插件的 action id；id 不全局唯一时用限定 id，例如 example.layout.apply

width / height 可以省略（默认半尺寸弹窗）、可以给数字（终端单元格数）、 也可以给 "80%" 这种字符串（占终端区域的百分比）。尺寸包含弹窗边框， 小于弹窗最小值的会被夹紧（clamp）。

description 可选；设了之后它会显示在 prefix+? 的帮助面板里，取代默认的 'custom command' 标签。

一个很实用的小技巧：在 Unix / macOS 上，用 popup 开一个临时便签终端， 不占分割也不占 tab：

[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"

Windows 上把命令换成 command = "powershell.exe -NoLogo" 之类。退出 shell 就关掉弹窗， 回到平铺视图。

还有个环境变量陷阱：popup 命令拿不到 HERDR_PANE_ID， 要用 HERDR_ACTIVE_PANE_ID 取底下那个平铺 pane。

想恢复默认键位#

herdr config reset-keys

它会备份 config.toml、移除 [keys] 和 [[keys.command]]， 重启或 herdr server reload-config 之后使用内置的 v2 默认键位。

改完配置记得让它作用于运行中的 server：

herdr server reload-config     # 或者全局菜单 → reload config
herdr config check             # 改之前先验语法，比启动一次快

七、Prefix-free：怎么配才不打架#

你可以把 Herdr 动作绑到完全不需要前缀的直接组合键上。 难点不是语法，而是知道哪些组合是安全的。

官方的分析框架是「三层存活」：一个组合键要能到 Herdr，必须穿过 操作系统 → 外层终端（Ghostty、iTerm2 等都自带默认键位）→ pane 里的程序。

两个具体反例（官方原文给的）：

  • ctrl+j 能到 Herdr，但 shell 和编辑器把它当 Enter
  • alt+k 在 Linux 上是空的，但在 macOS 上大多数终端会把它组合成一个特殊字符

官方做了什么：他们测绘了 Ghostty、iTerm2、Terminal.app、kitty、WezTerm、Alacritty、Warp、 Windows Terminal、GNOME Terminal、Konsole 的默认键位，加上 GNOME 和 KDE 的全局快捷键。 结论：

有一个修饰键家族几乎到处都没人用：ctrl+alt。 终端都留着它；它不受 macOS option 键组合行为的影响（那个行为会挡掉纯 alt 组合）； 而且即使在不支持现代键盘协议的终端里它也能传过去。

官方给出的 prefix-free 配置（保留 prefix 绑定，在上面叠加直接键）#

[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]

注意它是数组形式——prefix 版本继续有效，直接键叠加在上面。这是官方推荐的渐进路线， 不是「二选一」。

但这几个 ctrl+alt 组合要避开#

组合被谁占了
ctrl+alt+方向键GNOME 工作区切换、Ghostty 与 Konsole 默认
ctrl+alt+tUbuntu / Fedora 的「启动终端」
ctrl+alt+l / ctrl+alt+aKDE 锁屏 / 提醒窗口
ctrl+alt+s / ctrl+alt+uKonsole
ctrl+alt+f1..f12Linux 虚拟控制台切换

（注意上面那份官方配置里就有 ctrl+alt+l——在 KDE 上会被锁屏吃掉。 抄配置之前先看你的桌面环境。）

想要 tmux 风格的单键调大小#

不进 resize 模式、一个键直接调：

[keys]
resize_pane_left = "ctrl+shift+alt+left"
resize_pane_down = "ctrl+shift+alt+down"
resize_pane_up = "ctrl+shift+alt+up"
resize_pane_right = "ctrl+shift+alt+right"

这类可选动作默认是不绑的（unset）。绑的时候用 prefix+ 得到 prefix 模式行为， 或者像你确实想要直接快捷键时那样，用一个明确带修饰的组合。

如果直接键没反应#

官方给的判断很干脆：

你的终端或桌面环境在 Herdr 看到之前就把它吃掉了。 两边任选一边改： 在终端设置里释放这个组合，或者在 Herdr 里换一个组合。

排查顺序建议：先在另一个终端里试同一个组合（能确定是不是终端吃的）→ 再看桌面环境的全局快捷键列表 → 最后才怀疑 Herdr 配置（herdr config check）。

八、避坑指南#

  1. prefix+? 是唯一权威。 它是活的，显示当前真正生效的绑定。别拿网上的键位表当准。
  2. 别绑裸可打印键。 new_tab = "n" 会让你在所有 Herdr 输入框里打不出字母 n。 一律 prefix+n，除非你明确要直接键且带了修饰。
  3. 想要 ctrl+b 当 copy mode 翻页，就必须换前缀。 前缀键在 copy mode 里保留原义。
  4. Esc 在 copy mode 里要按两次——第一次清选区/搜索，第二次才退出。
  5. Ctrl+Y 粘不出系统剪贴板的东西。 Herdr 字段的剪切内容只在当前字段内流转。
  6. popup 会吞掉 Esc。 这是设计（弹窗接管全部输入直到命令退出），不是卡死； 退出弹窗里的命令就回来了。
  7. popup 里没有 HERDR_PANE_ID。 用 HERDR_ACTIVE_PANE_ID。
  8. navigate 模式字段有自己的禁用清单。 navigate_workspace_* / navigate_pane_* 不能用 prefix+、esc、enter、tab、shift+tab、left、right、裸 1–9。
  9. 改完配置要 reload。 编辑 config.toml 不会自动作用于运行中的 server： herdr server reload-config，或全局菜单 → reload config。

常见问题

Herdr 的前缀键是什么，怎么按？

默认 ctrl+b。按法是「按下 ctrl+b、松开、再按动作键」，不是三个键同时按。例如 prefix+c 新建 tab、prefix+w 工作区导航、prefix+q detach。前缀键本身可以在 [keys] prefix 里改，也可以写成数组配多个前缀。

最少需要记哪几个键？

五个：prefix+c 新建 tab；prefix+v / prefix+minus 向右/向下分割；prefix+h/j/k/l 在 pane 间移动；prefix+w 工作区导航；prefix+q detach（一切照跑）。其余都可以继续用鼠标。忘了就按 prefix+? 看当前生效的全部绑定。

为什么我绑的 ctrl+alt 组合键没反应？

按键要穿过三层才能到 Herdr：操作系统、外层终端（Ghostty/iTerm2 等自带默认键位）、pane 里运行的程序。任一层先吃掉就没反应。官方建议要么在终端设置里释放该组合，要么在 Herdr 里换一个。

哪些 ctrl+alt 组合要避开？

ctrl+alt+方向键（GNOME 工作区切换、Ghostty 与 Konsole 默认）、ctrl+alt+t（Ubuntu/Fedora 的启动终端）、ctrl+alt+l 与 ctrl+alt+a（KDE 锁屏/提醒窗口）、ctrl+alt+s 与 ctrl+alt+u（Konsole）、ctrl+alt+f1..f12（Linux 虚拟控制台切换）。

copy mode 里怎么搜索和复制？

prefix+[ 进入。/ 或 ? 做正向/反向字面搜索，n 或 N 同向或反向重复；查询里没有大写字母时搜索不区分大小写。v 或 Space 起选，y 或 Enter 复制，q 或 Esc 不复制退出（Esc 会先清掉当前选区或搜索再退出）。copy mode 不暂停 pane 进程，输出继续实时滚动。

怎么改回默认键位？

herdr config reset-keys。它会备份 config.toml、移除 [keys] 和 [[keys.command]]，重启或 herdr server reload-config 之后使用内置的 v2 默认键位。
