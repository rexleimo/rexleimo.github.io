CLI 部署：生产级命令行工具#

把 Agent 编译成二进制，通过 CLI 在服务器上跑——这是最简单也最灵活的生产部署方式。

编译二进制#

CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o my-agent .

参数说明：

  • CGO_ENABLED=0：静态编译，不需要 cgo
  • GOOS=linux：目标系统
  • GOARCH=amd64：目标架构

运行#

./my-agent
# 或者指定端口
./my-agent --port 9090

进程管理：systemd#

用 systemd 管理进程，实现自启动和崩溃恢复：

# /etc/systemd/system/my-agent.service
[Unit]
Description=My ADK Go Agent
After=network.target

[Service]
Type=simple
User=myuser
WorkingDirectory=/opt/my-agent
ExecStart=/opt/my-agent/my-agent --port 8080
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

启用服务：

sudo systemctl enable my-agent
sudo systemctl start my-agent
sudo systemctl status my-agent

日志管理#

journalctl 查看日志#

journalctl -u my-agent -f  # 实时跟踪
journalctl -u my-agent --since "1 hour ago"  # 最近1小时

日志轮转#

配置 logrotate：

# /etc/logrotate.d/my-agent
/var/log/my-agent.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
}

自启动配置#

开机自启#

sudo systemctl enable my-agent

健康检查#

配置 HTTP 健康检查端点：

./my-agent --health-check :8080/health

systemd 配置：

[Service]
ExecStart=/opt/my-agent/my-agent --port 8080
Restart=always

# 健康检查
StartLimitIntervalSec=300
StartLimitBurst=3

常见问题#

Q：进程 OOM 被 killed A：检查内存使用，dmesg | grep -i kill。配置适当的内存限制。

Q：磁盘满了 A：日志太多。配置日志轮转，或降低日志级别。

Q：更新 Agent 后需要重启 A：sudo systemctl restart my-agent
