CLI vs Web：ADK Go 运行方式对比与选择#

ADK Go 支持两种运行方式：CLI 和 Web。两种都能跑通 Agent，但适合的场景不同。这篇帮你搞清楚什么场景该用哪个。

运行方式一览#

模式命令适用场景优点缺点
CLIgo run agent.go调试、自动化脚本、生产服务轻量、无依赖、适合后台运行无界面
Webgo run agent.go web api webui用户测试、演示有界面、直观需要开端口、不适合纯后台

CLI 模式#

启动方式#

source .env
go run agent.go

工作原理#

用户输入 → ADK Go CLI → Agent → Model → Tool → 返回结果 → CLI 输出

CLI 模式下，ADK Go 的 launcher 从命令行读取输入，处理后输出到 stdout。这是一个同步的请求-响应循环。

适用场景#

调试和开发阶段

# 快速测试新的 Tool
go run agent.go
> 查询北京天气
北京今天晴，气温 15-22°C

> 查询上海天气
上海今天多云，气温 18-26°C

自动化脚本

可以把 CLI 输出重定向到文件：

echo "查询北京天气" | go run agent.go > output.txt

生产环境服务

配合 nohup 或 systemd，创建一个长期运行的后台服务：

nohup go run agent.go > agent.log 2>&1 &

Web 模式#

启动方式#

go run agent.go web api webui

这行命令会启动两个服务：

  • API 服务：localhost:8080，提供 REST API
  • Web UI：localhost:8080/webui，提供浏览器界面

工作原理#

用户浏览器 → Web UI → API 服务 → Agent → Model → Tool → 返回 → Web UI → 用户浏览器

Web 模式基于 HTTP，提供了状态保持的能力——可以开始一个会话（Session），多轮对话不需要每次重新输入上下文。

适用场景#

演示和用户测试

把 Web URL 发给同事或用户，让他们直接用浏览器和 Agent 对话，不需要装任何东西。

需要多轮对话的场景

CLI 每次都是独立运行，历史消息不会自动带到下一轮。Web 模式默认保持会话上下文：

# 第一轮
> 你好，我是助手
# 第二轮（Agent 记得上一轮）
> 我的名字叫什么？
（Agent 记得之前说过"我是助手"）

需要持久化的场景

Web 模式可以把会话存储到数据库或文件系统，断线后恢复。

两种模式的切换#

ADK Go 的 launcher 根据 os.Args[1:] 决定运行模式：

l := full.NewLauncher()
l.Execute(ctx, config, os.Args[1:])

常用命令参数#

参数模式说明
无CLI默认，启动交互式 CLI
webWeb API只启动 API，不带 UI
web api webuiWeb 完整API + Web UI
stream流式启用流式输出

通过代码切换#

更灵活的方式是在代码里根据环境变量切换：

func main() {
    mode := os.Getenv("ADK_MODE")
    switch mode {
    case "web":
        runWeb()
    default:
        runCLI()
    }
}

然后运行时：

ADK_MODE=web go run agent.go

选择指南#

场景推荐模式原因
本地调试CLI快、简单、日志直接可见
自动化脚本CLI无状态、适合管道处理
后台服务CLI + systemd稳定、可管理
用户演示Web有界面、零门槛
多轮对话Web默认保持上下文
Session 持久化Web支持会话存储

注意事项#

ADK Web 仅用于开发

官方文档特别强调：ADK Web 是开发专用，不要用在生产环境。生产环境应该用 Agent Runtime 部署（模块 7 会讲到）。

端口冲突

8080 端口可能被占用。指定其他端口：

go run agent.go web api webui --port 9090

网络访问限制

Web 模式默认只监听 localhost。如果需要从其他机器访问：

go run agent.go web api webui --host 0.0.0.0
