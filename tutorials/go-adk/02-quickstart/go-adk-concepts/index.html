Agent 核心概念：Model、Tool、Instruction 三要素#

第一次接触 ADK Go，最容易困惑的不是 API 怎么调，而是"Agent 到底是什么"。本文把 Agent 的核心概念讲清楚——Model、Tool、Instruction 三个要素之间的关系。

Agent 的本质：一个大语言模型的运行时包装#

Agent（智能体）的本质，是给大语言模型（LLM）装上手和脚，让它不只是回答问题，还能真正做事。

LLM 本身只会"想"——给一段文字，它返回一段文字。但一个 Agent 还知道：

  • 可以调用什么工具（Tool）
  • 怎么根据用户输入决定调用哪个工具
  • 调用工具后如何处理结果
  • 如何把结果返回给用户

ADK Go 中 Agent 核心由三个要素组成：Model、Tool、Instruction。

Model：Agent 的"大脑"#

Model 是 Agent 的推理引擎。ADK Go 默认使用 Google Gemini 系列模型，但也可以接入其他支持 OpenAI compatible API 的模型。

model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
    APIKey: os.Getenv("GOOGLE_API_KEY"),
})

Model 的职责：

  • 理解用户输入
  • 决定是否需要调用 Tool
  • 生成自然的回复文字

Model 的配置项：

配置项说明示例
模型名称使用哪个模型gemini-flash-latest
Temperature创造性程度（0~1）0.7
TopP采样阈值0.95
MaxTokens单次输出最大 token 数8192

Temperature 越低，输出越确定、越保守；越高，输出越有创造性但也可能越离谱。调试阶段设为 0.7 左右是个不错的起点。

Tool：Agent 的"手和脚"#

Tool 是 Agent 能做的事。ADK Go 预置了一些常用工具，也可以自己写。

ADK Go 预置工具：

工具说明
geminitool.GoogleSearch搜索工具，Agent 可以搜索实时信息
MCP Tool通过 MCP 协议接入外部服务
OpenAPI Tool从 OpenAPI spec 生成工具

自定义工具示例： 一个让 Agent 查询天气的工具：

type weatherTool struct{}

func (w weatherTool) Name() string {
    return "get_weather"
}

func (w weatherTool) Description() string {
    return "Get current weather for a city"
}

func (w weatherTool) InputSchema() string {
    return `{"type": "object", "properties": {"city": {"type": "string"}}}`
}

func (w weatherTool) Call(ctx context.Context, input string) (string, error) {
    var args struct {
        City string `json:"city"`
    }
    json.Unmarshal([]byte(input), &args)
    return fmt.Sprintf("Weather in %s: sunny, 22°C", args.City), nil
}

注册到 Agent：

Tools: []tool.Tool{
    weatherTool{},
    geminitool.GoogleSearch{},
}

当用户问"上海天气怎么样"时，Agent 会自动识别需要调用 get_weather，然后把结果"说"给用户听。

Instruction：Agent 的"性格"#

Instruction 是给 Model 的系统提示词（System Prompt），决定了 Agent 的角色定位、行为规范、回答风格。

timeAgent, err := llmagent.New(llmagent.Config{
    Name:        "hello_time_agent",
    Model:       model,
    Description: "Tells the current time in a specified city.",
    Instruction: "You are a helpful assistant that tells the current time in a city. "
                + "Be concise and friendly in your responses.",
    Tools: []tool.Tool{geminitool.GoogleSearch{}},
})

Instruction 的内容建议：

  • 角色定义：Agent 是什么身份？“你是xxx领域的专家”
  • 行为规范：Agent 应该怎么做？“回答要简洁”、“总要给出数据来源”
  • 边界约束：Agent 不能做什么？“不要编造数据”、“超出能力范围要说明”

Instruction 不是越长越好。太长会消耗大量上下文额度，而且 Model 容易忽略次要指令。最好的 Instruction 精准、简洁、明确。

三要素如何协同工作#

用户输入
    ↓
Instruction（定义行为边界）
    ↓
Model（理解输入，决定是否调用 Tool）
    ↓
Tool（执行动作）
    ↓
Model（处理 Tool 返回，生成回复）
    ↓
输出给用户

举例：

用户问：“上海今天天气怎么样？”

  1. Model 收到用户输入，结合 Instruction 理解：用户想知道天气
  2. Model 判断：需要调用天气工具
  3. Tool 被调用，返回：{"city": "Shanghai"} → "Weather in Shanghai: sunny, 22°C"
  4. Model 拿到工具返回结果，用自然语言组织回复
  5. 用户看到：“上海今天天气晴朗，气温 22°C”

案例：最小化 Agent 配置#

理解三要素后，看看一个最小化的 Agent 配置：

model, _ := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
    APIKey: os.Getenv("GOOGLE_API_KEY"),
})

agent, _ := llmagent.New(llmagent.Config{
    Name:        "my-agent",           // Agent 名称
    Model:       model,                // 大脑
    Instruction: "你是我的助手。",      // 性格
    Tools:       []tool.Tool{},        // 工具（这里为空）
})

没有 Tool 的 Agent 只能"聊天"。加上 Tool，Agent 就有"做事"的能力。

常见问题#

Q：Instruction 是不是越长越好？ A：不是。简洁精准比长篇大论更有效。上下文窗口有限，过长的 Instruction 会挤压实际对话空间。

Q：一个 Agent 可以加多少 Tool？ A：理论上可以加任意多个。但 Tool 越多，Model 选择成本越高，建议控制在 5~10 个以内。

Q：Instruction 和 Tool Description 有什么区别？ A：Instruction 是系统级提示词，决定 Agent 整体行为；Tool Description 是每个 Tool 的说明，告诉 Model 什么情况下该调用这个 Tool。
