API Key 与 Model 选择：成本、能力与场景的权衡#

用 ADK Go 开发应用，绕不开两个问题：API Key 怎么管理，模型那么多到底用哪个。这篇帮你理清这两个问题。

Google Gemini API Key#

获取 Key#

  1. 访问 Google AI Studio 外部链接
  2. 登录 Google 账号
  3. 点击 “Create API Key”
  4. 选择项目（已有项目或新建）
  5. 复制生成的 Key

管理 Key#

原则：绝不把真实 Key 提交到代码仓库。

常用方案：

方案一：.env 文件（团队开发推荐）

.env.example（提交）
export GOOGLE_API_KEY="your-api-key-here"

.env（不提交）
export GOOGLE_API_KEY="actual-key-value"

团队成员各自维护自己的 .env，.gitignore 排除 .env。

方案二：环境变量直接设置（快速验证）

export GOOGLE_API_KEY="your-key"
go run agent.go

方案三：Secret Manager（生产环境推荐）

生产环境不要放在 .env 文件里，用云厂商的 Secret Manager：

  • Google Cloud Secret Manager
  • AWS Secrets Manager
  • Azure Key Vault

在代码里读取：

import "cloud.google.com/go/secretmanager"

func getAPIKey() string {
    ctx := context.Background()
    client, _ := secretmanager.NewClient(ctx)
    defer client.Close()

    result, _ := client.AccessSecretVersion(ctx, &secretmanagerpb.AccessSecretVersionRequest{
        Name: "projects/my-project/secrets/gemini-api-key/versions/latest",
    })
    return string(result.Payload.Data)
}

模型选择：Flash vs Pro vs Experimental#

模型一览#

模型特点费用适用场景
gemini-flash-latest速度最快低日常对话、生产环境首选
gemini-pro能力更强中复杂推理、代码生成
gemini-2.0-flash-exp实验版，能力更强变尝鲜、测试新特性

速度 vs 能力#

gemini-flash-latest     ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  速度快，能力适中
gemini-pro             ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  速度慢，能力强
gemini-2.0-flash-exp   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  速度快，能力强（实验）

成本控制建议#

日常开发：用 Flash

Flash 最便宜，日常调试用 Flash 足够了。很多场景下 Flash 的能力已经远超"能用"。

对能力有要求时：升级到 Pro

当你发现 Flash 在复杂推理任务上表现不够好（比如多步数学题、代码 Debug），升级到 Pro。

实验特性：用 Experimental

gemini-2.0-flash-exp 等实验版有最新特性，适合尝鲜，不适合生产。

代码里切换模型#

// 开发环境
model, _ := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
    APIKey: os.Getenv("GOOGLE_API_KEY"),
})

// 生产环境（按需切换）
modelName := os.Getenv("GEMINI_MODEL")  // 从环境变量读取
model, _ := gemini.NewModel(ctx, modelName, &genai.ClientConfig{
    APIKey: os.Getenv("GOOGLE_API_KEY"),
})

配额与限制#

API 配额#

每个 Gemini API Key 有默认配额限制：

配额类型默认值说明
Requests per day1500每天最多多少次请求
Requests per minute60每分钟最多多少次请求
Tokens per day1,000,000每天最多多少 token

配额不够用怎么办：

  1. 在 Google AI Studio 申请配额提升
  2. 合理设计缓存策略，减少重复请求
  3. 在非高峰期使用

超配额错误#

429 RESOURCE_EXHAUSTED: Quota exceeded for quota group 'default'

遇到这个错误，说明配额用完了。需要等待配额重置或在 AI Studio 申请提升。

多 Key 轮询：负载与备份#

生产环境建议使用多个 API Key，轮询使用，分散配额压力：

type KeyPool struct {
    keys   []string
    index  int
    mu     sync.Mutex
}

func (p *KeyPool) GetKey() string {
    p.mu.Lock()
    defer p.mu.Unlock()
    key := p.keys[p.index]
    p.index = (p.index + 1) % len(p.keys)
    return key
}

func main() {
    pool := &KeyPool{
        keys: []string{
            os.Getenv("GOOGLE_API_KEY_1"),
            os.Getenv("GOOGLE_API_KEY_2"),
        },
    }

    model, _ := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
        APIKey: pool.GetKey(),  // 每次请求自动轮询
    })
}

常见问题#

Q：本地跑得好好的，部署到服务器报 UNAUTHORIZED A：检查服务器所在地区是否可以访问 Google API。中国大陆需要代理。

Q：同一个 Key 有时候能用有时候报配额不足 A：配额是按时间窗口重置的，高峰期容易超。实现 Key 轮询或多级缓存。

Q：Experimental 模型突然不可用了 A：Experimental 模型随时可能被 Google 下线或替换，生产环境不要依赖它。
