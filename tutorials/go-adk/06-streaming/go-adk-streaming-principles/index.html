Streaming 原理与 Event 模型：实时输出的核心技术#

传统请求-响应模式下，Agent 要等全部生成完才返回。Streaming 让你在每个 token 出来时就实时看到——打字机一样的体验。

为什么需要 Streaming#

模式等待时间体验
传统模式等全部生成完才返回等 10 秒，看到完整答案
Streaming每个 token 实时显示0.5 秒开始看到，逐步展开

对于长回答，Streaming 可以让用户感知到的等待时间从 10 秒降到 0.5 秒。

技术原理：Server-Sent Events#

Streaming 基于 HTTP Server-Sent Events（SSE）：

浏览器 ───HTTP 请求──→ Agent
浏览器 ←──SSE 流──── Agent
         data: 你好\n
         data, 好\n
         data: 吗？\n
         [done]

Agent 生成每个 token，通过 SSE 推送到客户端。客户端收到后立即显示。

ADK Go 中的 Streaming#

启用 Streaming#

agent, _ := llmagent.New(llmagent.Config{
    Name:        "my-agent",
    Model:       model,
    Instruction: "你是助手",
    Streaming:   true,  // 启用 Streaming
})

处理 Stream Event#

stream, _ := agent.RunStream(ctx, userInput)

for {
    event, err := stream.Recv()
    if err == io.EOF {
        break
    }
    if err != nil {
        log.Printf("Stream error: %v", err)
        break
    }

    // 处理每个 Event
    switch event.Type {
    case event.TextDelta:
        fmt.Print(event.Text)  // 实时打印
    case event.ToolCall:
        fmt.Printf("[调用工具: %s]", event.ToolName)
    case event.Done:
        fmt.Println("\n[完成]")
    }
}

Event 类型#

Event说明用途
TextDelta文本增量实时打印
ToolCall工具调用开始显示正在调用工具
ToolResult工具返回显示工具结果
Error错误显示错误信息
Done完成标记结束

常见问题#

Q：Streaming 和普通模式的性能差异 A：Token 生成速度相同，Streaming 只是输出方式不同。不会增加额外的计算开销。

Q：网络断开会丢消息吗 A：SSE 有重连机制。客户端应该在断开后自动重连，并从上次接收到的位置继续。

Q：可以在 Streaming 中途停止吗 A：可以。调用 stream.Cancel() 向 Agent 发送取消信号。
