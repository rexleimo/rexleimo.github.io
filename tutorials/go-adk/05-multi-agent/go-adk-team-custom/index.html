Custom Workflow：自定义工作流，复杂场景的终极方案#

Sequential、Parallel、Loop 都是预设模式。真实业务场景更复杂，需要自定义调度逻辑——Custom Workflow 就是这个终极方案。

使用场景#

场景不适合适合
固定流程SequentialSequential ✅
独立并行ParallelParallel ✅
迭代优化LoopLoop ✅
条件分支以上都不行Custom ✅

例如：“先搜索，如果结果多就让写作 Agent 整理，如果结果少就让审核 Agent 直接出结论”——这种条件分支需要 Custom。

使用方式#

customWorkflow := team.NewCustomWorkflow(
    team.WithStepHandler(func(ctx context.Context, state *team.WorkflowState) (string, error) {
        // 自定义调度逻辑
        result := state.LastResult

        // 根据结果决定下一步
        if strings.Contains(result, "多个结果") {
            return "run_writer", nil  // 跑写作 Agent
        } else {
            return "run_reviewer", nil // 跑审核 Agent
        }
    }),
)

注册可用的步骤#

customWorkflow.RegisterStep("run_writer", writerAgent)
customWorkflow.RegisterStep("run_reviewer", reviewerAgent)
customWorkflow.RegisterStep("run_search", searchAgent)

实战场景#

场景：智能路由#

customWorkflow := team.NewCustomWorkflow(
    team.WithStepHandler(func(ctx context.Context, state *team.WorkflowState) (string, error) {
        query := state.UserInput

        // 根据问题类型决定处理流程
        if isWeatherQuery(query) {
            return "run_weather", nil
        } else if isOrderQuery(query) {
            return "run_order", nil
        } else if isComplexQuery(query) {
            return "run_search_then_write", nil
        }
        return "run_general", nil
    }),
)

常见问题#

Q：Custom 和 Orchestrator 有什么区别 A：Orchestrator 是用 LLM 来决定下一步，Custom 是用代码逻辑。Custom 更确定，Orchestrator 更灵活。

Q：可以混合使用吗 A：可以。在 Custom 里调用其他 Workflow（Sequential、Parallel）。

Q：状态在步骤间怎么传递 A：通过 WorkflowState。每个步骤的输出存在 state.Results["step_name"]，下一步可以读取。
