Agent 路由：动态选择下一个 Agent#

用户输入多样化——一个问题到底该分配给哪个 Agent 处理？路由机制让 Agent 自动识别输入类型，智能分发到合适的处理 Agent。

路由 vs Custom Workflow#

机制判断方式适用场景
Routing基于规则或 LLM 判断输入分类、分发
Custom Workflow代码逻辑复杂流程编排

路由是 Custom Workflow 的一个特例——只做分发，不做流程编排。

使用方式#

基于规则的路由#

router := team.NewRouter(
    team.WithRoute("weather", isWeatherQuery, weatherAgent),
    team.WithRoute("order", isOrderQuery, orderAgent),
    team.WithRoute("default", nil, generalAgent),  // 默认
)

result, _ := router.Route(ctx, userInput)

基于 LLM 的路由#

router := team.NewLLMRouter(
    team.WithLLM(model),  // 用模型判断
    team.WithRouteAgent("weather", weatherAgent),
    team.WithRouteAgent("order", orderAgent),
    team.WithPrompt("根据用户输入判断类型：weather/order/general"),
)

实战场景#

场景：多功能助手#

router := team.NewRouter(
    team.WithRoute("weather", func(input string) bool {
        return strings.Contains(input, "天气")
    }, weatherAgent),

    team.WithRoute("search", func(input string) bool {
        return strings.Contains(input, "搜索") || strings.Contains(input, "查一下")
    }, searchAgent),

    team.WithRoute("writing", func(input string) bool {
        return strings.Contains(input, "写") || strings.Contains(input, "帮我整理")
    }, writingAgent),

    team.WithRoute("default", nil, generalAgent),
)

result, _ := router.Route(ctx, userInput)

路由规则优先级#

规则按注册顺序匹配，第一个匹配的生效：

// 先匹配 weather，再匹配 default
team.WithRoute("weather", isWeatherQuery, weatherAgent),
team.WithRoute("default", nil, generalAgent),

如果 weather 匹配但想让 default 也作为候选项，用 WithFallback：

team.WithRoute("weather", isWeatherQuery, weatherAgent),
team.WithRoute("search", isSearchQuery, searchAgent),
team.WithFallback(generalAgent),  // 前面的都不匹配，用这个

常见问题#

Q：没有任何规则匹配怎么办 A：使用 WithDefaultAgent 设置默认 Agent。

Q：可以返回多个 Agent 吗 A：可以。用 NewParallelWorkflow 包装路由结果。

Q：路由结果可以缓存吗 A：可以。同样的输入直接返回缓存结果，不用重新判断。
