ARTEX: The Championship Pentest Tool That Ended Up in the Korean Bank Breach List

ARTEX, champion of Baidu's agent+ challenge, was turned against nine Korean banks; the upstream repo is down and ThreatBook is commercializing it. Someone on linux.do got shells in two hours.

October 30, 2026 · 4 min · 758 words · Rexai Programming -  |  中文

On October 29, a linux.do poster wrote: picked a few random websites, got shells in two hours. The tool is ARTEX, the model ds1017uncensored. The post title reads “This ARTEX thing is scary… I’m having security anxiety now.” Behind that single post is a full lifecycle over two months: championship, open source, use in the Korean bank breaches, delisting, commercialization.

What ARTEX is#

An LLM multi-agent autonomous penetration-testing system from a Chinese team: Go monolith with an embedded Next.js frontend, state in PostgreSQL. Agents run asset mapping, scanning, exploit code generation and verification themselves; dangerous actions go through an approval card — the tool asks before it acts. It ships no model of its own; you plug one in. It won Baidu’s “agent+” offense-defense challenge in August, was open-sourced on GitHub July 26, and had 4,400 stars and 6,600+ forks by the time it went down in October.

The Korean incident#

Late September to early October, multiple Korean financial institutions suffered consecutive customer-data breaches — Shinhan, KB Kookmin, Hana among them; 36Kr’s tally is nine institutions with at least 65,000 personal and credit records. CrowdStrike’s October 7 analysis points at ARTEX: the operator paired it with Claude Code, using DeepSeek V4.1-Flash as the primary backend. The attack infrastructure sat on a Hong Kong IP with a public directory exposing Claude Code session histories, ARTEX config and Claude memory files — used as evidence by security vendors. One detail from the records: the operator had no monetization plan and had Claude draft a list of Korean-focused Telegram groups for selling the data. On October 8, ARTEX’s developer announced the project would close-source and disclaim all liability for abuse. On October 16, ChosunBiz reported China’s ThreatBook reselling it as a commercial service.

The two-hour getShell post#

The poster’s stack is ARTEX plus ds1017uncensored — the uncensored community variant of DeepSeek V4.1-Flash-1017, the minor version DeepSeek pushed on October 17, headlined as “wish-style programming.” Random targets, shells in two hours; the results panel shows a per-target row of “N vulns / N reported” with the high-severity rows in red.

Half the comments ask where to find uncensored model vendors; the rest look for the repo — mhtsec/ARTEX is gone from GitHub, and what remains are forks like Autumn-27’s with 2,000+ stars. One comment, verbatim: “In China, just target foreign sites.”

Pinning the numbers: the two-hour getShell is the poster’s self-report with a panel screenshot; not independently reproduced here. The most recent public reproduction is AhnLab’s: in a controlled environment, given only the target and allowed scope, ARTEX reached a file-upload vuln and executed a webshell; in an Apache ActiveMQ setup it pivoted from initial access to remote commands on four internal hosts.

The one thing that matters#

The attack surface here is old: test consoles exposed to the internet (a Korean server’s HTML title literally read “ARTEX — Autonomous Penetration Testing Console”), file-upload vulns, legacy middleware like ActiveMQ. ARTEX amplified the speed of discovery and chaining, not the vulnerability itself. The developer took the repo down, but the source is in the public domain: 4,400 stars, 6,600 forks, plus ThreatBook’s commercial build. Defense is the same pre-AI work: patch old middleware, delete test environments, close public directories. The change is that the offense side is now an agent that does the recon plus one human clicking approve.

The tool was delisted; the source code was not. AI amplified speed, not capability.

FAQ#

What is ds1017uncensored? The community-uncensored variant of DeepSeek V4.1-Flash-1017 (the official October 17 minor update, whose changelog cites reasoning, coding and agentic-task improvements).

Is the two-hour getShell credible? Self-reported with a results-panel screenshot, no independent reproduction. The closest public reproduction is AhnLab’s controlled-environment test: file upload to webshell, ActiveMQ lateral movement to four internal hosts.

Can the original repo still be found? mhtsec/ARTEX now 404s. Autumn-27/ARTEX (2,062 stars) and several pure-source backup repos remain on GitHub, AGPL-3.0.

What is ThreatBook’s role? ChosunBiz reported on October 16 that ThreatBook relaunches ARTEX as a commercial service; the original developer has disclaimed liability.

What should defenders check first? The three asset classes hit in this incident: internet-exposed ARTEX-class consoles, file-upload web vulns, legacy ActiveMQ-class middleware — plus any directory that should not be public; the operator’s own session history is how the attack source was located this time.
