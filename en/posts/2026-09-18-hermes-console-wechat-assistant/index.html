Zero-Command Private AI Assistant: A Full Hermes Console Tutorial

Want your own AI assistant but gave up at the first sight of a terminal? Hermes Console turns the whole setup into clicks: double-click to start, configure in the browser, scan a QR code to live inside WeChat. This is the full walkthrough, plus what it actually does under the hood.

September 18, 2026 · 3 min · 543 words · Mengshou Coding -  |  中文

If “deploy”, “CLI” and “yaml” are the words that make you close the tab, this tutorial is for you.

We turned the entire Hermes Agent setup into a web console — Hermes Console: double-click to start, a few clicks in the browser, one QR scan, and your assistant lives inside WeChat. No config files, no environment variables, no copy-pasting keys around.

What this is not: another hosted “AI chat site”. The assistant runs on your own machine — it can read your files, run tasks you assign, remember what you told it — and you command it from whichever chat app you already use.

The four walls of self-hosting#

Hermes Agent itself is powerful, but four gates stop beginners cold: environment setup (Python, dependencies, errors); config format (hundreds of fields in one config.yaml); key handling (where does the API key live, does it leak into logs); and chat-platform wiring (every IM has its own token ritual and callback setup).

Hermes Console turns all four gates into forms and buttons.

The walkthrough#

  1. Start. Clone rexleimo/hermes-setup External link , double-click start.bat (Windows) or drag start.sh into Terminal. Dependencies install themselves; first run about a minute. Browser opens http://127.0.0.1:8420 with a setup wizard that knows what your machine already has.
  2. Install the agent. One button runs the official install script with a live log. Already installed? Skip. Prefer to install manually? “Configure-only” mode leaves your system untouched.
  3. Pick a brain. 13 built-in provider presets (GLM, Kimi, DeepSeek, MiniMax, Doubao, Qwen, Anthropic, OpenAI, OpenRouter…): click the provider, paste your API key, done — endpoints and model names are pre-filled. The key goes into a permission-locked .env, never re-displayed in the UI.
  4. Connect WeChat. Click “login” on the WeChat card, the QR code appears right in the page, scan with your phone, and the token writes itself back. 14 platforms in total: WeChat, Feishu/Lark, QQ, DingTalk, WeCom, Telegram, Discord, Slack, WhatsApp, Email, Matrix, Signal, plus webhook and local API server.
  5. Go. Start the Gateway, send “hello” from your phone. It answers. Done — zero lines of configuration written.

What it actually does#

Hermes already defines the agent, the config schema and the gateway. The console just does three things around them: reads and writes config.yaml for you, supervises the gateway process (start/stop/logs/diagnostics), and manages key storage. It’s an external admin panel, not a fork — upgrade Hermes whenever you like.

After it’s live#

  • Model chains: primary GLM-4.6, auto-fallback to DeepSeek, then Kimi — you never think about who’s answering.
  • Skills & MCP: 24 skill categories and 64 audited MCP entries, install with one click.
  • One assistant, whole family: multi-user support keeps conversations and memory isolated per person.
  • Fully offline: LAN-only deployment for data-sensitive environments.

Honest caveats#

Model API costs are yours to pay. WeChat wiring depends on the iLink channel and may need to adapt as platform policies change. It’s an open-source tool, not a service desk — file issues on GitHub. By default the console binds to 0.0.0.0 (reachable from your LAN) and warns you about it on startup; set HERMES_CONSOLE_HOST=127.0.0.1 to keep it loopback-only, and enable the built-in account auth before exposing it further.
