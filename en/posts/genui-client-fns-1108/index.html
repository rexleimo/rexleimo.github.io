0 ms vs Hundreds of Tokens: Stop Asking LLMs to Do Math in Flutter GenUI

A2UI + 同步响应式信号：LLM 只负责推理与布局，确定性数学交给本地 Dart 函数 0ms 执行。

November 8, 2026 · 6 min · 1244 words · Dream Beast -  |  中文

The most common trap in generative UI is making a slider drag trigger a round trip to the remote model: the user scales a recipe from 2 to 6 servings, the client serializes the state, and the LLM burns hundreds of tokens computing 3.50 * 3 before the screen repaints seconds later. A Google Developer Expert (Randal L. Schwartz, part 39 of the BlocSignal series on dev.to, 2026-11-07) names this the round-trip calculation trap and ships the answer as client-side functions: the LLM designs the interface and binds expressions; deterministic execution runs in local Dart code registered in the client’s catalog. With the reactive layer done on synchronous signals, the original claims 0ms local execution and same-frame, 120 FPS repaint (both self-reported; not independently reproduced). I read the post, pulled the three pub.dev packages, and checked the A2UI protocol repo. Here’s the breakdown: how the trap forms, how the signal wiring works, what to steal, and whether any of this actually ships today.

Why a recipe multiplication shouldn’t hit the LLM#

The post opens with a line worth quoting in full: “An LLM is a phenomenal semantic reasoning engine, but it is an awful, slow, and expensive pocket calculator.” The scenario: an agent renders a recipe or cart card; the user drags a slider from 2 to 6 servings. In naive GenUI systems the client captures the change, serializes state and sends it to the remote model over SSE or WebSockets, the model spends hundreds of tokens on 3.50 * 3 — occasionally hallucinating float arithmetic — and responds after a multi-second gap. On a phone with an Apple Silicon or Snapdragon chip doing billions of operations per second (all figures as reported in the post), a remote AI call for two-number multiplication is, in the author’s words, an architectural anti-pattern.

The fix, demonstrated by Andrew “Red” Brogdon’s ~5-minute walkthrough on the Flutter channel (the “Commis” kitchen assistant), is the client-side function: the agent designs the UI and binds expressions, but delegates deterministic execution to local Dart functions registered in the client’s function catalog.

The missing link: reactivity without the async tax#

Running Dart locally fixes the latency and token cost — and creates a second problem: how does the UI react when local state changes? In async architectures you end up wiring StreamController pipelines, debouncers, or manual setState() callbacks, and every slider notch pays an event-loop and microtask tax.

bloc_signals_genui sidesteps this by sitting directly on Google’s official a2ui_core engine, which natively uses preact_signals. Client-side functions are therefore not just callable routines: they are first-class reactive computed() signals. The post’s flow: user drags the slider → the local DataModel signal updates (0ms) → a synchronous dependency trigger evaluates computed(() => calculateCost(...)) → a same-frame leaf rebuild repaints the text widget at 120 FPS. Zero network round-trips, zero microtask hops, zero flicker (self-reported).

Wiring it up: the five steps#

1. Define the function in pure Dart. Subclass FunctionImplementation (re-exported from a2ui_core), declaring name, return type, and a typed JSON argument schema:

class CalculateCostFunction extends FunctionImplementation {
  CalculateCostFunction()
      : super(
          name: 'calculateCost',
          returnType: A2uiReturnType.number,
          argumentSchema: Schema.object(
            properties: {
              'unitPrice': CommonSchemas.dynamicNumber,
              'quantity': CommonSchemas.dynamicNumber,
              'discount': CommonSchemas.dynamicNumber,
            },
            required: ['unitPrice', 'quantity'],
          ),
        );

  @override
  Object? execute(
    Map<String, Object?> args,
    DataContext context, [
    CancellationSignal? cancellationSignal,
  ]) {
    final unitPrice = (args['unitPrice'] as num?)?.toDouble() ?? 0.0;
    final quantity = (args['quantity'] as num?)?.toDouble() ?? 0.0;
    final discount = (args['discount'] as num?)?.toDouble() ?? 0.0;
    return (unitPrice * quantity) * (1.0 - discount);
  }
}

execute() receives a DataContext, so the function can read or scope additional local surface state, fully decoupled from Flutter widgets.

2. Register it in the catalog with StandardCatalog().copyWith(functions: [CalculateCostFunction(), ...BasicCatalog.v0_9().functions.values]), passed into A2uiSurfaceBloc(catalogs: [catalog]). When the app advertises its capabilities to the agent, the agent learns about calculateCost and its required parameters.

3. The agent streams the reactive binding. Instead of hardcoding a static string, it binds the text property of a Text component to the function call, with arguments referencing local DataModel paths:

{
  "id": "cost_display",
  "component": "Text",
  "text": {
    "call": "calculateCost",
    "args": {
      "unitPrice": 4.50,
      "quantity": { "path": "/cart/items/0/qty" },
      "discount": 0.10
    }
  }
}

4. Zero-latency execution underneath. DataContext.resolveSignal() from a2ui_core evaluates the dynamic call: every argument pointing at a DataModel path resolves to an underlying reactive signal; the whole call compiles into a native computed() signal; when the user changes a quantity, bloc.add(UpdateFormField('/cart/items/0/qty', newValue)) mutates the DataModel synchronously; the computed() signal marks itself dirty and recalculates in the same frame (0ms, zero microtasks); the Flutter widget does a surgical leaf rebuild at 120 FPS (both figures as reported in the post).

5. Two operational paths, don’t mix them. Path A, user interaction: tapping a Button dispatches SubmitAction to the A2uiSurfaceBloc, which either triggers a local client-side function (apply a coupon, validate a form) or emits an A2uiRendererAction outbound to the agent. Path B, bidirectional RPC: inbound CallRendererFunctionMessage lets the remote agent invoke registered client functions on demand — a verified total under client business rules, device GPS, local SQLite — with the client replying via a typed RendererFunctionResponseMessage; outbound callAgentFunction (via bloc.callAgentFunction()) lets the renderer invoke remote agent tools, resolving when the matching AgentFunctionResponseMessage returns.

The boundary table worth stealing#

ResponsibilityHandled byLatency & reliability
Generative layout & reasoningRemote LLM (Gemini, Claude, GPT)Async streaming over the network (SSE)
Deterministic business logic & mathLocal Dart functions (FunctionImplementation)0ms synchronous, on-device (as reported)
Reactivity & state synchronizationSignals graph (BlocSignal + a2ui_core)Same-frame update, no microtasks
Hardware & native platform APIsBidirectional RPC (CallRendererFunctionMessage)Local platform channels & secure sandbox

Three things I’d take from it: (1) draw the line between generation and certainty — the LLM produces layout plus expression bindings; anything verifiable (multiplication, discounts, stock checks) executes locally. (2) Make reactivity synchronous — compiling function calls into computed() signals keeps update-recompute-repaint in one frame instead of shuffling through the microtask queue. (3) Make the capability boundary explicit — two named message types, not an agent reaching into device APIs.

Is any of this shipping?#

Package status as of 2026-11-08 (pub.dev and GitHub API figures, pulled that day): a2ui_core — Google’s official Dart core of the A2UI protocol (messages, data model, data binding, expressions), latest 0.5.0 published 2026-11-04 under the labs.flutter.dev publisher, depends natively on preact_signals >=1.9.4, 34.6k downloads in 30 days. bloc_signals_genui / bloc_signals_genui_flutter — both at 1.0.0 (published 2026-10-20, verified publisher blocsignal.dev), 70 and 205 downloads in 30 days. The upstream a2ui-project/a2ui repo — “agents stream layout data, and apps render it with native components in React, Angular, Lit, Flutter, SwiftUI and Jetpack Compose” — sits at 17,007 stars, 1,375 forks, Apache-2.0, created 2025-09-24.

One watch item: bloc_signals_genui 1.0.0 pins a2ui_core ^0.3.0 while the official core is already at 0.5.0 (published the day before the post). The downstream packages are simply newer than the core’s cadence implies — check the a2ui_core version line before pulling this into anything production. The architecture story is coherent; production readiness waits on the version catch-up and the samples at blocsignal.dev.
