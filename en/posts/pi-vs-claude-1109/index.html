The Coding Harness Is the New Battleground: Why a Veteran User Ditched Claude Code

The coding-agent battleground moved off the model into the harness: two config formats, single-session wiring, a 15k-token system prompt — a year-long user's migration log and what the shell layer is worth.

November 9, 2026 · 9 min · 1798 words · Dream Beast -  |  中文

A user who ran Claude Code as his daily driver for a year decided to move his primary tool to the open-source Pi. A day after he made the switch, Anthropic announced Claude Code would start supporting AGENTS.md files — as if staged to keep him. His words: a beat too late.

The switch itself isn’t the news. What it exposes is the deeper layer: the coding-agent battleground has moved off the model and into the shell around it. The model layer keeps converging toward a commodity. What actually decides whether your day feels smooth or clunky, how much you burn on tokens, and whether the tool can grow into a team’s private workflow is the harness — the thing that assembles context, describes tools, manages sessions, and sets permissions. Every pain point in that migration sits in the shell, not in the model.

The Model Converges; Friction Sinks Into the Shell#

Claude Code writing code well was never going to be the reason to switch. None of its complaints are “the model is dumb”; every one points at the shell: how config files land, whether sessions stay wired to the IDE, whether the command set is complete, how long the system prompt is. A year-long user listing “where it’s clunky” hand is, by itself, a product health check more honest than any ad.

Zoom out and this is why the shell became the frontier. Each model generation flattens the “can it write it right” gap until coding ability is table stakes. What separates the daily feel is the friction coefficient of the shell you touch all day: how much context it stuffs in, whether the commands are there, whether sessions stay connected, whether you keep two config files. None of that shows up in model evals or benchmarks, yet it decides whether a tool feels smooth or catches you at every step. A smooth shell gets your whole workflow moved into it; a rough one loses users no matter how strong the model underneath is.

Format Fragmentation Is the Signature of Closed Source#

AGENTS.md and CLAUDE.md are two memory formats. The former is a cross-tool standard being pushed by the open-source side; the latter is Claude Code’s proprietary format. The result: the same “project conventions” must be kept in two places, copied back and forth or symlinked. CLAUDE.md files scatter across GitHub repos — penetration marketing for Claude, a tax for everything else.

Note the order: the standard was set by the open side first; Anthropic came after. Users voted with their feet for the AGENTS.md camp, and only then did Claude Code announce support. A vendor bolting on a standard to retain people has, by that act, admitted it was late. Selling a proprietary format as the standard is the old habit of closed ecosystems — grab the slot, then claim “we support it too.”

Single Sessions, Missing Commands: Invisible Tax#

Claude Code inside VS Code keeps only one session “wired” to the IDE. Open a second tab for another job and the original one still running stops receiving selected-text events. This was reported at least as far back as December 2025, and the issue was closed as “duplicate of some unrelated bug.” The official GUI extension opens multiple tabs, but half the built-in slash commands don’t fire in it, and custom status lines aren’t supported.

None of this is fatal alone; stacked, it’s daily micro-friction. The user who switched to Pi wrote a multi-tab picker extension in about 20 minutes — not because the original couldn’t do it, but because nobody owned it as a first-class priority. Features scattered across extensions, with no one deciding what matters, leave users to pick up the pieces.

Prompt Bloat Has a Hidden Line Item#

The default Bash tool description runs close to 3,000 tokens, most of it teaching the model how to use git and open PRs on GitHub. The model already knows this; the words burn context every turn. Anthropic cut the system prompt by 80% and Claude Code still costs far more than Pi — Pi starts from four tools and a system prompt under 1,000 tokens, while one side-by-side comparison puts Claude Code’s system prompt around 15,000.

This is not tidiness. Scale the math: a million daily actives, hundreds of millions of requests a day, cut a thousand tokens per request and the annual inference savings start in the seven-figure range. Every extra line in the system prompt is paid by the entire user base. A closed tool can’t easily publish that line item, but users feel it: the context gets stuffed and the space left for your actual task shrinks. The words in a tool description land, in the end, as your token bill. Worse, that 3,000-token description still teaches the model cat <<'EOF' style, which — before auto-mode became common — kept tripping manual-review rules; the saved tokens never arrived, and you got an extra detour for free.

Pi’s Subtraction: Four Tools, One Thousand Tokens, the Rest via Extensions#

Pi is a TypeScript monorepo split into six packages: a unified multi-provider LLM interface, the agent runtime, the terminal UI, the coding-agent CLI, plus web-UI components and a GPU deploy tool. The core hands the model read, write, edit, and bash — four tools. Sub-agents, plan mode, and MCP aren’t built in; they come from TypeScript extensions and Pi packages, installed on demand. It started with Mario Zechner, moved under Earendil in May 2026, the npm package rebranded to @earendil-works, MIT-licensed, on the order of 200,000 weekly downloads.

It runs in four modes: an interactive terminal, print/JSON, RPC for process integration, and an SDK to embed in your own app. The same agent loop, pointed at any provider’s model, switchable mid-session with /model. The “carve capability into swappable components” philosophy is the opposite of the closed tool’s “ship everything, on by default.”

It’s quick to pick up too. One script line curl -fsSL https://pi.dev/install.sh | sh, Node 22.19 or newer, run pi in a project dir; /login to hook an existing subscription or export ANTHROPIC_API_KEY for the API. No model preference; whatever provider you wire in works. For a team that wants to low-cost trial, that install-to-run distance is shorter than the closed tool’s.

Extensions can be packaged and shared. A written-up TypeScript extension, skill, prompt template, or theme becomes a Pi package, distributed over npm or git, installed with pi install and pinned to a version. A team distills “how we do this job” into one package, the next person reuses it, nobody rewrites from scratch. That “make the workflow into a shippable package” move is what a closed tool can’t offer.

Lock-In and Switchability: the Shell Decides Which Models You Can Use#

Claude Code only runs Claude; the model is welded shut. Pi is bring-your-own-key, fifteen providers or more — Anthropic, OpenAI, Google, AWS, DeepSeek, xAI on the cloud side, plus Ollama, vLLM, SGLang, LM Studio for local inference — switchable in-session with /model. The difference isn’t just savings: multi-provider means the shell doesn’t lock you; a model drops in price and you swap instantly, you have local cards and can run your own, compliance says data stays on-prem and everything can run local.

At the team level, this switchability rewrites the procurement and compliance game. A single-model shell turns “swap the model” into “swap the tool” — switching providers means retraining the team, rewriting prompts, rewiring permissions. A multi-provider shell drops “swap the model” back to a cost item, even letting you route by task: flagship model for the hard work, cheap model or local for the grunt, same shell throughout. The data-compliance line is harder still: a fully local option is not a bonus in healthcare, finance, or government — it’s the entry ticket. Whether the shell can abstract the model layer decides whether it’s good enough to sit inside those departments.

Nobody Is Responsible for Saying “No”#

The person who left gave Claude Code a straight verdict: it behaves like a product with no strong product view. A bunch of excited engineers and PMs each add the feature that fits their own workflow, and nobody stands at a height dedicated to saying no to certain requests. In product engineering, “refusal” is core work as much as “implementation”; skip it and the tool grows into a pile of stacked features the user has to clean up.

Pi does the opposite by restraint: cut what can be cut, keep the boundary clear, fill the rest with extensions. For someone who wants the agent to grow into the team’s private workflow, that flexibility is worth more than “everything out of the box.” You can let it grow into divided jobs instead of being pushed by a default config.

Honest Boundary#

This is user feel plus product analysis, not a benchmark. Pi is young: no built-in sub-agents, no plan mode, MCP via extension, a thinner ecosystem than Claude Code; Claude Code’s mature ecosystem, official support, and multi-model subscription binding are real value too. Which to pick depends on whether you want “stable restraint and deep customization” or “a ready-made all-in-one.” A year-long user pushed off by accumulated micro-friction is a product signal, not a verdict on “whose model is stronger.”

FAQ#

What is Pi, and how does it relate to Claude Code? Both are terminal coding-agent shells. Pi is open source (MIT) and multi-provider; Claude Code is closed and Claude-only. Pi is another choice of “shell,” not a model replacement.

Why is format fragmentation so painful? AGENTS.md is a cross-tool standard, CLAUDE.md is proprietary. Users copy and symlink between the two, keeping two copies of the same conventions. A standard set by the open side first and bolted on later by a closed vendor, used to retain people, is itself a sign of being late.

How bad is the prompt bloat? The default Bash tool description is near 3,000 tokens, mostly teaching git and PRs; after an 80% system-prompt cut the spend still exceeds Pi’s four-tool, sub-1,000-token start, and a comparison puts Claude Code around 15,000 tokens. Scaled to hundreds of millions of daily requests, it’s a seven-figure annual inference bill.

What does Pi lack? No built-in sub-agents, plan mode, or first-class MCP; the ecosystem is thinner. You install them via extensions or Pi packages, or let the model write them on the fly.

Should you switch too? It depends on whether you want flexibility or a ready-made all-in-one. People pushed off by accumulated friction want stable restraint and deep customization; the ecosystem and official support are still Claude Code’s real value — there’s no universal winner.
