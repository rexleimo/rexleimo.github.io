ggml's First 1.0: The Deprecated APIs Are Gone, and RPC v9 Refuses Incompatible Peers

ggml, the tensor library under llama.cpp, ships its first 1.0: deprecated API removed, RPC protocol bumped to v9 which refuses incompatible peers, FP8 support lands. Clean-build median on a 2-core EPYC slice: 102.3s. Full post and discussion live on the BBS.

November 14, 2026 · 3 min · 552 words · Dreambeast -  |  中文

On November 13, 2026, ggml-org shipped ggml 1.0.0 — the first 1.0 in the library’s 3.5-year history — and llama.cpp followed with its own 1.0.0 the same day.

For the local-inference ecosystem, ggml is not a model; it is the tensor layer underneath. llama.cpp’s quantization ops and every hardware backend’s kernels are built on its C API. Pure C/C++, no dependencies, spanning x86, ARM, RISC-V, LoongArch, PowerPC, s390x and WebAssembly, with quantization formats from 2–8 bit integers up to MXFP4/NVFP4 micro-scaling.

What 1.0 locks down#

The Hugging Face blog post says it straight: llama.cpp and ggml now follow semantic versioning, and breaking API/ABI changes are only allowed in the major version. A 3.5-year-old library locking its interface is what lets downstream teams that assemble inference pipelines on libggml finally write “upgrades will not break you” into their release process.

The 1.0 cut falls on deprecated surface: ggml clears its deprecated public API and removes the legacy DIAG_MASK_INF/DIAG_MASK_ZERO ops; the RPC protocol moves to v9 — faster loads, and an unreachable endpoint or a failed handshake now fails fast instead of hanging. Incompatible peers are refused at connect time, moving the compatibility question out of runtime and back to the connection. The paired llama.cpp 1.0 is the matching cut: llama.h drops llama_set_warmup plus 35 deprecated functions, and the NextN/speculative API set moves out of llama-ext.h into llama.h.

What 1.0 adds#

FP8 is the heavyweight item: OCP FP8 on the CUDA side, with MMQ fusing the NVFP4 gate/up GEMM and GLU into a single kernel. llama.cpp 1.0 picks up the FP8 KV cache (-ctk/-ctv f8_e4m3), which cuts the KV-cache memory bill again. YaRN truncation becomes configurable (ggml_rope_set_truncate), with OpenVINO, SYCL, Vulkan, WebGPU and RPC all supporting it.

The per-backend ledger, recorded separately: CUDA gains few-row quantized matmul (batch 2–24) and MoE fusion; Metal packs fusable MoE node groups into a single command buffer; Vulkan prefill takes the Intel FlashAttention path; SYCL adds a device-side MoE scheduler; WebGPU gains a batched tensor API plus new kernels; Hexagon adds Q5_0/Q5_1 and conv_3d.

Measured on our box#

The box is a 2-core slice of an EPYC 9354P (32-core chip, 2 vCPU allocated), no GPU, CMake 4.4.4 + clang 18.1.3. Three clean builds from the v1.0.0 tag (417a024): 109.3s / 102.3s / 102.0s, median 102.3 seconds. The full ctest suite passes 21/21 in 9.61s. Running the test-backend-ops -b CPU -o MUL_MAT correctness suite alone takes 225.9s before reporting 1/1 backends passed — 1.0 bakes the precision gates into the tests, and a full-parameter quantized validation round costs about three and a half minutes on two cores.

Honest boundaries#

No GPU on this box: CUDA, Metal, Vulkan, SYCL, OpenCL, WebGPU and Hexagon were not reproduced, so the release notes’ performance gains stand as vendor-reported. There is also no like-for-like v0.x vs 1.0.0 comparison — the public API drifts between those tags, so a shared build cannot serve both sides; we measured v1.0.0 on its own.

Frequently Asked Questions

Will ggml 1.0 break existing llama.cpp programs?

llama.cpp 1.0 removes llama_set_warmup plus 35 other deprecated functions from llama.h. If you use the old API, the compiler errors after the upgrade are your checklist; if you only touch libllama's public interface, you should be fine.

Can old RPC peers still connect to v9?

No. v9 refuses incompatible peers outright: an unreachable endpoint or a failed handshake now fails fast instead of hanging. That is deliberate 1.0 behavior.

Are the per-backend GPU gains independently measured?

No. This box is a 2-core EPYC slice with no GPU; CUDA, Metal, Vulkan, SYCL, OpenCL, WebGPU and Hexagon were not reproduced. Those figures are vendor-reported from the official release notes.
