Mistral Large 4 'Le Chonk': Spec Check — 1T Parameters, 49B Active, 512K Context, Open Weights Late October

Mistral shipped Large 4 (Le Chonk) on 2026-10-06: 1T params, 49B active, natively multimodal, API live now, open weights late October. I checked every circulating claim against primary sources: the '1M context' that got quoted everywhere measures 512K in the live API; the $0.68/$2.09 per-M pricing is a curl from my own machine against the public endpoint; the Artificial Analysis Intelligence Index score of 38 ties GPT-6 Luna. RL is still running — this is a preview, not the final model.

October 9, 2026 · 9 min · 1750 words · 梦兽编程 -  |  中文

On 2026-10-06, Mistral shipped a model they obviously refer to internally with a much shorter name: Le Chonk (“chonk” is internet slang for something big and chunky). Formal designation: Mistral Large 4. Three numbers up front: 1T parameters, 49B active, open weights end of October. OpenRouter listed the public preview the same day and Artificial Analysis published a score the same day — spec, price, and third-party eval all landed within 24 hours, denser than most model releases.

What I did is unspectacular: I matched every circulating claim to a primary source, verified on my own machine whatever is verifiable without a GPU (pricing, context length, modality), and labeled exactly who is saying what for the rest. This piece covers four things:

  1. The widely-quoted “1M context” claim does not match the live API — it’s 512K;
  2. What “natively multimodal” actually means — not a bolted-on vision tower;
  3. 3,800 GPUs, trained and served in Europe — half the story of this release is geopolitical;
  4. What you can use today is a preview, not the final model — RL hasn’t finished; weights ship end of month.

The circulating claim: 1M context — measured 512K#

The spec line that spread fastest on release day (an X post by @ItsmeAjayKV, 2026-10-06):

“1.05T parameters / 49B active per token / 1M context / Natively multimodal.”

Note that “1M context” appears nowhere in Mistral’s official X post, and nowhere in co-founder Guillaume Lample’s release thread — I pulled both primary texts; both only say 1T / 49B / natively multimodal / weights end of October. Context length is not mentioned. So where did 1M come from? Third-party paraphrase.

I checked the API side directly. On 2026-10-07 02:03 UTC from this machine, against OpenRouter’s public, unauthenticated endpoint, the mistralai/mistral-large-4-0 entry prints:

$ python3 - <<'EOF'
import json,urllib.request
d = json.load(urllib.request.urlopen("https://openrouter.ai/api/v1/models"))
for m in d["data"]:
    if "mistral-large-4" in m["id"].lower():
        print("id:", m["id"])
        print("context:", m.get("context_length"))
        print("pricing:", json.dumps(m.get("pricing")))
        print("arch:", json.dumps(m.get("architecture"))[:400])
EOF
id: mistralai/mistral-large-4-0
context: 524288
pricing: {"prompt": "0.00000068", "completion": "0.00000209", "input_cache_read": "0.00000007"}
arch: {"modality": "text+image->text", "input_modalities": ["text", "image"], "output_modalities": ["text"], "tokenizer": "Mistral"}

context_length: 524288 — 512K, not 1M. OpenRouter’s own model description hammers it in: “512K-token context window with up to 256K output tokens”. Practical conclusion: plan your architecture against 512K; treat “1M” as one paraphraster’s number until an official document backs it. MoE models regularly quote three different context numbers across training/inference/serving — that’s the one spec in this release that didn’t survive cross-checking.

What “natively multimodal” actually means#

One line from the measurement above: "modality": "text+image->text", input_modalities: ["text","image"].

In plain terms: images and text enter the same model. It is not “run CLIP or some vision tower first, then feed the vector into the LLM” — the official wording “natively multimodal” means image-text interleaving happened at training time in one transformer, not an adapter attached at inference. The engineering-visible difference is visual grounding: the official post’s own words are “surpasses closed frontier models on visual grounding”. Lample’s thread adds that it’s SOTA on “complex multimodal grounding benchmarks”.

I can’t run vision benchmarks on this machine, so take that as vendor-claimed; but it explains why the release announcement can afford to claim grounding above closed models — the modality is trained in, not patched on.

3,800 GPUs: half of this release is geopolitical#

Verbatim from Lample’s thread, second block:

“ML4 was trained on 3,800 NVIDIA Grace Blackwell GPUs in our European datacenters — our cluster in Bruyères-le-Châtel built using our Series B fundraise. We are investing heavily in infrastructure, with our Series C and D clusters coming online soon.”

The official post, same idea: “Forged in Europe end-to-end and is deployable from Europe via our own Mistral Cloud infrastructure.”

Read together, half the information content of this release is the Europe-locked stack itself: training, datacenter, cloud, and serving all stay inside the EU. For customers under EU AI Act / data-sovereignty constraints (the official post names them: cyber defense, manufacturing, finance), “the model runs in the EU and the weights are open” is worth more than the benchmark score — the product is compliance-ready availability, which US open-weights lines don’t sell.

What you get today is a preview: RL hasn’t finished#

The most important sentence in Lample’s first block:

“The RL run behind this preview is still in flight and shows no sign of saturation — we will release a final version before the end of the month along with the weights of the model.”

Three consequences stack:

  1. Today’s API is a Research Public Preview — RL hasn’t converged, scores will still move;
  2. Final model and weights ship together, end of month — anything you measure between 10-06 and 10-31 is probably stale by then;
  3. “No sign of saturation” is the co-founder’s own line, not marketing copy — read literally, the final version is expected to beat this preview, and that’s the vendor’s expectation, not mine.

So the expiry date on every number in this article: end of October, when weights land. If you’re making a buying decision, wait for the weights and run them yourself.

Measured pricing: what the half-price window actually is#

The pricing line from the same measurement (2026-10-07 02:03 UTC, OpenRouter public endpoint):

  • input 0.00000068 = $0.68 per million tokens
  • output 0.00000209 = $2.09 per million tokens
  • cache read 0.00000007 = $0.07 per million tokens

The OpenRouter announcement (via the aggregator, 10-06): “half price for the first two weeks” — the numbers above are the discounted price. The roughly $1.36/$4.18 recovery is my back-calculation from the 50% discount — arithmetic, not an official figure; don’t quote it as such. Cache reads at $0.07 are aggressive compared with typical 10–20% cache discounts in the wild; long-session cost will track your cache hit rate.

The useful anchor: once weights ship end of October, the comparison axis shifts from “API price” to “self-host TCO” — comparing API prices now has limited value; lock in 512K context and 256K output as your architecture constraints and move on.

How much to believe “best open weights in the US or Europe”#

The Artificial Analysis entry (via aggregator, 10-05) gives one checkable anchor: Intelligence Index 38, tied with GPT-6 Luna (max, 38), with the caption “the most intelligent model outside the US”. Lample’s thread quotes the vendor’s benchmark posture:

“On important coding and agentic benchmarks such as DeepSWE, AutomationBench, and AA-Briefcase, ML4 matches the performance of the best open-weight models. It is SOTA on finance and legal workflows, as well as on complex multimodal grounding benchmarks.”

Translated: coding/agentic claims are “matches the best open weights” (no superlative), while finance/legal/visual-grounding are claimed SOTA (superlative). That tiering of claims is actually restrained — SOTA where they say SOTA, “matches” elsewhere. The AA tie is third-party backup, but until weights ship, every third-party score is an eval-side number; I haven’t re-run anything, so treat the set as vendor-claimed plus third-party quoted, two separate tracks.

Arena has also listed Large 4 in Agent Arena and Code Arena (WebDev/Text/Vision), with scores “to be published later” (aggregator, 10-06) — that score is likely the endgame reference once weights land.

Self-hosting: what a 1T total-param budget implies#

49B-active MoE arithmetic (pure estimate — no GPU on this box, nothing was run):

  • 1.05T total params × FP8 (1 byte/param) ≈ 1TB of weights; int4 ≈ ~550GB
  • Per-token compute behaves like a 49B dense model — memory is the constraint, not FLOPs
  • In practice: a top single node (8×80GB = 640GB) sits right at the int4 edge; FP8 wants two nodes; throughput at serving time should track a 49B dense class

Bottom line: when weights drop, the honest answer to “can I run this privately?” is “yes, but budget for a terabyte of memory” — not the 70B-era habit of “one H100 node”. This is the first time an open-weights frontier-class model pushes the deployment floor to multi-node territory: good news for private-deployment customers, a dealbreaker for consumer hardware.

  • Not reproduced: AA Intelligence Index 38, DeepSWE/AutomationBench/AA-Briefcase matches, visual-grounding superiority over closed models — all vendor-claimed or third-party quoted; weights not out, no GPU here, nothing re-run.

Frequently Asked Questions

Can I use Mistral Large 4 right now?

Yes. As of 2026-10-06 it's in public API preview: live on OpenRouter (mistralai/mistral-large-4-0, 512K context, up to 256K output, tool calling and structured outputs) and on Mistral's own stack. Note it is a Research Public Preview — the official line says RL is still running; final version plus weights land end of month.

Is the 1M context window real?

The 1M figure (from an early rumor post) is not what the API serves: the OpenRouter model entry shows context_length 524288 (512K), and its description says 512K. 1M may be a training-side spec or a teaser; no official document backs it yet. Plan engineering against 512K.

What does it cost?

Measured 2026-10-07 from my machine against OpenRouter's public endpoint: $0.68/M input, $2.09/M output, $0.07/M cache reads — that's the public-preview half-price window (announced as 50% off for the first two weeks). The list prices work out to roughly $1.36/$4.18 (my arithmetic from the discount; not an official figure). Self-hosted cost lands separately when weights drop end of October.

When the weights drop, can I run it locally?

1.05T total params (49B active MoE). Pure arithmetic, not measured — no GPU here: FP8 weights ≈ 1TB of memory, int4 ≈ 550GB class. Even a top single node (8×80GB) won't hold it; multi-node serving is the realistic target. Because only 49B is active per token, compute behaves like a 49B dense model while the memory bill is the 1T one — memory-bound, not FLOP-bound.

What's actually strong about it?

Official claims: best open-weights model from the US or Europe on aggregated benchmarks; SOTA on finance and legal workflows and complex visual grounding; Artificial Analysis Intelligence Index 38, tied with GPT-6 Luna (max). Weights not out yet, so none of this is independently re-verifiable — treat the numbers as vendor-claimed until then.
