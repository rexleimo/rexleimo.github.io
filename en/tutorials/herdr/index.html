The Herdr Practical Guide

Baseline for this column: herdr 0.9.2 stable channel (tested on this machine: macOS / Apple silicon).

Every command, config key and socket method is aligned with the documentation source of the official pinned revision v0.9.2 (raw.githubusercontent.com/herdrdev/herdr/v0.9.2/docs/next/website/src/content/docs/*.mdx). Anything marked “verified on this machine” is the literal output of a real run, not written from memory.

Herdr in one sentence

Herdr is a terminal workspace manager for AI coding agents.

Like tmux, it is a multiplexer: a background server holds the real terminal processes, a client merely attaches to render them, and if you detach, close the window or drop your SSH connection, the processes in your panes keep running.

Unlike tmux in three specific ways — and those three are exactly the needs that appeared once “the work you do in a terminal in 2026” changed:

Dimensiontmux / zellijHerdr
Entry pointkeyboard-first, you must memorise bindingsmouse-first: panes, tabs, workspaces, split borders and the right-click menu are all clickable; the keyboard is an optional layer
What runs insidea pile of shell processesit recognises which coding agent is in a pane, and whether it is working or blocked waiting on you
State visibilityyou cycle through panes one by onethe sidebar rolls agent state up per workspace, so you see at a glance which project is waiting on you
Programmatic controlthe tmux send-keys string black magicfirst-class CLI + local socket API, for scripts and agents to orchestrate other agents
Multiple machinesone tmux per machineLocal and saved SSH machines in the same window, merged agent list, independent reconnect per connection
Extensibility.tmux.conf + scriptslocally executable plugins with a manifest (actions + event hooks + their own pane), with a marketplace

The official self-description is exactly that sentence: Terminal workspace manager for AI coding agents. Not “yet another tmux”, but a dispatch desk for multiple agents.

Why this deserves its own column now

Because “the processes in my terminal” changed. You used to run shells, editors, logs and services in a pane — things that are passive: if you don’t look, nothing moves. Now you run Claude Code, Codex, Pi, Hermes Agent and friends: active processes that work on their own, stop halfway to ask you to approve a command, and finish while waiting for you to look at the result.

So the real pain of “I have eight terminal windows” is no longer layout, it is:

  • Which agent is waiting on me? (blocked)
  • Which one already finished and I haven’t looked? (done)
  • My SSH dropped, I closed the laptop lid, the machine rebooted — are those half-finished agents still alive?
  • I want “when agent A finishes the tests, agent B is called in to fix them” — how do I write that script?

Herdr is designed around those four questions. Its own blog titles are blunt about it: Coding agents are becoming runtimes, Ten agents, three clients, 95% less CPU.

This is the single thing this column most wants to make clear: Herdr’s agent detection and Herdr’s agent integrations are two different systems. Detection works off the foreground process plus a screen manifest and needs no configuration at all; integrations (hooks / extensions) add lifecycle-grade state and agent-native session restore. Whether to install one, which one, and what changes once you do — module 3 takes that apart.

What this column solves

The official documentation has 21 clean pages, but it is a reference manual: organised flat by topic, silent about the order in which to learn things, and silent about which traps you will actually fall into. This column fills that gap:

  • First time using it — is the mouse enough? When do you genuinely need to learn ctrl+b?
  • Four layers, session / workspace / tab / pane — at which granularity should I actually cut?
  • Closing the window, dropping SSH, herdr update, rebooting the machine: in each of those four cases, is my agent still alive? (The answers differ, and one path called live handoff is the easiest to overlook.)
  • Remote work has three routes: SSH in and run herdr, run herdr --remote <host>, or save the machine with herdr machine add. What differs? Why does only one of them let you paste an image from your local clipboard into a remote pane?
  • Who decides that the sidebar says blocked? What is the difference between done and idle? Why does the state the CLI reports disagree with the badge on my screen?
  • I want a script — or another agent — to orchestrate these agents. CLI, or straight to the socket? Where is the boundary?

The answers are spread across six documentation pages and only assemble if you cross-read them. This column assembles them for you, and every claim is verified by an actual run.

Who should read this

  • People already using an AI coding agent (Claude Code / Codex / Pi / OpenCode / Hermes, any of them): this is your main battlefield — read module 0 in order.
  • Veteran tmux / zellij users: you already have the concepts; go straight to core concepts to align on the terminology differences, then jump to module 3 for the agent material.
  • People who never used a multiplexer: you can read this too. Herdr is mouse-first and needs no memorised bindings to get started, which is its biggest advantage over tmux on the entry ramp.
  • People building agent orchestration automation: module 4 “programmatic control” follows module 3 (CLI / socket API / agent-automation / plugins, opening in a later batch).

Not for you if: you only want a tmux config template (Herdr does not eat .tmux.conf; its config is config.toml); you need a native Windows ARM64 build (what runs today is the x86_64 build under Windows emulation); or you flatly reject the model of “a server process resident in the background”.

Version commitments

  • This column is baselined on herdr 0.9.2 stable; when upstream ships a new release, findings are added as supplementary articles rather than quietly rewriting old ones.
  • Every article states its verified version and platform at the top. Any claim that disagrees with the v0.9.2 official documentation source or with a run on this machine counts as a bug — please point it out in the comments.
  • No invented keybindings, config keys or CLI flags — that is also the first rule the official agent guide sets for AI, and this column obeys it.
  • When the preview channel comes up, it is always labelled as opt-in and able to regress.
  • Official conclusions are cited with links, never pasted wholesale.
