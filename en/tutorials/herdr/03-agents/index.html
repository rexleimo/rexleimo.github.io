Module 3: Agent Integrations

This is the differentiated core of the column, and the one capability where Herdr cannot be matched by tmux / zellij with “just some configuration”: it knows which agent runs in a pane, and whether that agent is waiting on you right now.

This module covers three things thoroughly: how state is decided, what you actually gain from each of the 18 official integrations, and how your own agent plugs in. Article 2 includes live measurements for Pi and Hermes Agent on this machine.

Baseline: herdr 0.9.2 stable · documentation source pinned at v0.9.2 · measured on this machine: with all 18 integrations not installed, Herdr still correctly identified 3 pi agents in state working

Prerequisites

  • You completed module 0 and herdr status shows the server running
  • You use at least one coding agent (Claude Code / Codex / Pi / OpenCode / Hermes, any of them)
  • Article 3 assumes you can write a little script (shell / TypeScript / Python, any of them) and read JSON

Learning goals

After this module you can answer:

  • The precise criterion behind each of working / blocked / done / idle / unknown, and why both done and idle mean “ready for input”
  • Why the state returned by the CLI / API may disagree with the Done badge on your screen (each client records the completions it has displayed, separately)
  • What “screen detection” and “integration reports” each provide: an integration may give lifecycle state, native session restore, or both — but it does not necessarily replace screen detection
  • How to diagnose “my agent was not recognised / its state is wrong”: herdr agent list for what it sees, herdr agent explain <target> --json for why it decided that
  • Why detection fails when the agent runs inside a VM or sandbox wrapper, and what to do about it
  • Where each of the 18 integrations lands on disk (for example Pi at ~/.pi/agent/extensions/herdr-agent-state.ts, Hermes at ~/.hermes/plugins/herdr-agent-state/__init__.py), and how to read herdr integration status
  • How to add Herdr support for an agent the official list does not cover: reporting state, reporting a resume command, releasing on exit, and the trade-offs of going straight to the socket

The short version

Detection and integrations are two different things: with no integration installed at all, Herdr still recognises your agent from the foreground process plus a screen manifest and gives you a state; what an integration buys is more reliable lifecycle state and agent-native session restore. Look at herdr agent list first, then decide whether to install one — not the other way round.
