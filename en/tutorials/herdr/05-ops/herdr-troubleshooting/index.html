Herdr Troubleshooting Checklist: 11 Real Failure Modes, and Why the "Just Restart" Remedy Kills Your Processes in Four of Them

Rewrite the 11 documented troubleshooting entries as symptom, root cause, remedy, and cost: the misplaced CJK IME window and the host_cursor trade-off, Enter/Tab/Backspace firing twice plus the minimum fixed version of each terminal, Option+arrow printing ;3D and the zsh bindkey fix, an updated binary with an old running session, macOS Keychain failures and why launchctl managername must be checked first, SSH or DNS failing after a macOS logout, and why herdr server stop exits every pane process, plus where the logs actually are. Verified locally: log paths, HERDR_LOG, config check, and launchctl output. Baseline herdr 0.9.2.

September 30, 2026 · 12 min · 2429 words · Mengshou Programming -  |  中文

Troubleshooting articles easily turn into an “if X, change Y” list that leaves you still unsure whether your problem is that one. This article works backwards instead: first the judgement, then the remedy, and finally what the remedy costs.

Because the most expensive action in Herdr troubleshooting is herdr server stop — it ends the processes in every pane. The docs mention it under two different failures, but it is a recovery measure, not a harmless retry. Knowing that distinction is what tells you when it is appropriate and when a named session does the job instead.

Baseline: herdr 0.9.2 stable · macOS · the outputs of every diagnostic command below were measured on this machine.

Conclusion first#

The first principle of Herdr troubleshooting is to split “who holds the problem”: the outer terminal, the operating system, or Herdr itself. The first two Herdr cannot fix (terminal double-sends keys, terminal IME cursor anchoring) and must be fixed in the outer terminal. Only the third is a Herdr configuration or session-lifecycle problem. And in every session-related remedy, herdr server stop is priced in: it ends pane processes. In a named session use herdr session stop <name> instead.

Zero. Collect facts before touching anything#

The official troubleshooting doc’s first requirement is exactly these, all obtainable on this machine:

herdr -V        # herdr 0.9.2
herdr status    # client / server / update

Beyond versions and session status, record: the operating system, the outer terminal’s name and version, whether the session is local or remote, and whether tmux is involved.

That last one is routinely forgotten and it matters a great deal — when Herdr is nested inside tmux, “a key was eaten by the layer above” and “Herdr drew it wrong” are two entirely different failures, and not checking for nesting sends you down the wrong path.

1. Input methods: a misplaced CJK candidate window#

Symptom#

The composition or candidate window of a Chinese, Japanese, or Korean input method appears in the wrong place.

Root cause#

Herdr draws the cursor as cell content by default on native Windows and WSL (host_cursor = "auto"), because a native cursor flickers, jumps, or shows stale positions while a ConPTY-based multiplexer repaints the screen. A drawn cursor cannot provide the native cursor anchor that IME composition UI depends on.

Remedy#

[ui]
host_cursor = "native"

This is trading flicker for positional accuracy: native mode restores the IME anchor but may reintroduce cursor movement artefacts during active output. To return to visual stability set host_cursor = "drawn", or remove the setting to use the Windows default.

The macOS counterpart#

macOS has no ConPTY problem, but TUIs hide the cursor themselves (Claude Code, pi, and codex all do), which costs macOS native input methods the candidate-window anchor. Herdr ships an experimental switch for this:

[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_cursor_shape = "steady_block"
cjk_ime_agents = ["claude", "pi", "codex"]

Its trade-off is stated in the configuration reference and is worth quoting: when enabled, an extra hardware cursor will be visible in the outer terminal for applications that hide the cursor without painting a replacement (vim normal mode, for instance). cjk_ime_agents limits the scope to specific agents; an empty list applies to any focused pane.

2. Repeated keys: Enter / Tab / Backspace firing twice#

Symptom#

One press of Enter executes twice; Tab and Backspace behave the same way.

Root cause#

An older version of the outer terminal emits the release of Enter, Tab, and Backspace as the same bytes as the press when an application enables Kitty keyboard event reporting. Herdr cannot distinguish the duplicate bytes after the terminal sends them.

Remedy: upgrade the outer terminal#

TerminalMinimum fixed version
kitty0.33.0
foot1.20.0
Alacritty0.15.0

This is especially common with older terminal packages from long-term-support Linux distributions, which pin versions. If it still reproduces on a current terminal version, report the exact terminal version and whether it also happens outside Herdr — those two facts move the problem from “probably the terminal” to “possibly Herdr”.

3. Option+arrow printing ;3D#

Symptom#

Pressing Option+Left puts ;3D on screen; Option+Right puts ;3C.

Root cause#

Terminals commonly send Alt+Left and Alt+Right as ESC[1;3D and ESC[1;3C. On macOS the outer terminal must first be configured to treat Option as Alt. If the shell has no binding for those sequences, zsh displays the remaining characters.

Remedy#

# in your own zsh configuration
bindkey $'\e[1;3D' backward-word
bindkey $'\e[1;3C' forward-word

Why kitty appears to work outside Herdr#

This is a particularly easy thing to misdiagnose: kitty’s automatic zsh integration only installs these bindings for shells it launched itself, not for shells created by a multiplexer. So in one kitty, a terminal you opened by hand works fine and the one inside Herdr does not.

The fix is to follow kitty’s manual shell-integration instructions, or to map the keys in kitty.conf so they are translated before they reach the shell:

map alt+left send_text all \x1bb
map alt+right send_text all \x1bf

Herdr deliberately does not rewrite them#

The docs give the reason: terminal applications may use Alt+Left and Alt+Right directly, and rewriting would break them. So this is a decision not to interfere, not an unfixable defect.

4. Updated Herdr but an old running session#

Symptom#

herdr update succeeds, but nothing about the interface or behaviour changed.

Root cause#

Updating the binary does not replace a compatible server that is already running.

Remedy#

herdr server stop
herdr

Check herdr status first to see whether the client or the server is behind. The command given in the docs has a cost: stopping a server exits the processes in its panes.

In a named session use:

herdr session stop <name>

Unix also offers live handoff, which transfers without killing pane processes — but handoff requires both sides to support it, so a server that arrived from an older version needs an update before it can take that path.

5. macOS: Keychain tools failing inside Herdr#

Symptom#

Tools that need Keychain access (git credentials, signing tools) fail in a Herdr pane.

First step: check the launch context, do not rush to restart#

launchctl managername

Measured output on this machine: Background. The docs specifically note that Background is normal for an automatically started macOS server and does not by itself indicate a Keychain problem. Plenty of people skip this step and restart for nothing.

Remedy#

Only if Keychain access genuinely fails and the server was started through SSH or a background job:

herdr server stop   # start Herdr again from a normal GUI terminal
herdr

Root cause#

Herdr’s panes inherit the macOS launch context of that long-lived server. A server started through SSH or a background job may not have access to interactive Keychain services.

6. macOS: SSH or DNS failing after logout#

Symptom#

After logging out and back in, SSH and DNS fail inside Herdr panes, with the characteristic errors:

No user exists for uid 501
Could not get manager name.
curl: (6) Could not resolve host

One genuinely counter-intuitive fact#

Logging back in does not repair that old server. You are logged in again, but the server still carries the pre-logout context.

Remedy#

Stop the affected session and start Herdr from a GUI terminal in the new login. This ends live pane processes but restores the saved session layout.

Why handoff cannot save you here#

The docs explain the cause directly: live handoff preserves the source server’s service context, and the root cause of this failure is precisely its inherited context. Older servers therefore need a full session restart to adopt the fix; handoff cannot repair it.

If a freshly started server still fails#

Look in herdr-server.log for:

could not select persistent user service context

The docs say when this appears: Herdr keeps the inherited context if the required macOS APIs are unavailable.

Auto-started versus explicitly started#

Automatically started macOS servers use a per-user service context, so logging out does not leave their panes with a dead connection to macOS services; an explicit herdr server launch retains the caller’s context. That difference decides whether you will meet this failure at all.

The order to investigate a keybinding that does nothing#

This one stalls most often, because at least three layers can be responsible. Eliminate them in this order:

  1. The OS layer: macOS system keyboard shortcuts may have claimed the chord (certain input methods’ switching keys, for instance). Look in System Settings.
  2. The outer terminal layer: kitty and Alacritty both have their own bindings, and they may consume the combination before it ever reaches Herdr.
  3. Herdr’s own configuration: only if the first two are ruled out. Module 1 article 2 covers how to free a specific keybinding from the conflict list.

8. Where the logs are, and what server stop really costs#

Logs#

~/.config/herdr/herdr.log
~/.config/herdr/herdr-client.log
~/.config/herdr/herdr-server.log

Measured: all three files exist, and herdr-server.log records structured events continuously, for example:

2026-09-30T10:49:24.154095Z  INFO herdr::logging: pane child spawned event="pane.spawned" subsystem="pane" outcome="ok"
2026-09-30T10:49:24.154263Z  INFO herdr::logging: tab focused event="tab.focus" subsystem="tab" outcome="ok" workspace_id=...

The format is itself useful: grepping for outcome="error" or a specific event= during an incident is far faster than reading the timeline.

For more detail:

HERDR_LOG=herdr=debug herdr status     # verified available

When reporting a problem, include the current log and its rotated siblings.

The cost of server stop (again)#

CommandScopePane processes
herdr server stopWhichever server the command routed toare ended
herdr session stop <name>The named session you specifythat session’s panes are ended
herdr agent rename / config reload / the various pane commands—no other process is affected

Article 1 covered the trap: if you forget --session, server stop stops the session you are using. Whenever a script needs to stop a test session, use session stop <name>.

9. Trap list#

  1. Do not reach for server stop at the first anomaly. It ends every pane process. Use herdr status to decide whether the client or the server is behind.
  2. In a named session always use session stop <name>, which has an unambiguous scope.
  3. launchctl managername returning Background does not mean there is a Keychain problem — measured on this machine it is exactly that value, and it is the normal state of an auto-started server.
  4. Logging back in does not repair the server with broken SSH/DNS after logout; you must fully restart from a GUI terminal.
  5. Live handoff preserves the source server’s context, which is why it cannot repair a failure caused by that context.
  6. Repeated key presses must be fixed in the outer terminal (kitty ≥0.33.0 / foot ≥1.20.0 / Alacritty ≥0.15.0). Changing Herdr configuration achieves nothing.
  7. host_cursor = "native" trades flicker for the IME anchor; it is not a pure fix.
  8. reveal_hidden_cursor_for_cjk_ime adds a visible hardware cursor for applications that hide the cursor without drawing a replacement (vim normal mode is typical). Narrow it with cjk_ime_agents.
  9. kitty’s automatic zsh integration does not install bindings for a multiplexer’s shells, which is the common real cause of “fine outside, broken inside”.
  10. Do not try to “fix” Alt+arrow globally by rewriting in your shell config; use explicit bindkey bindings.
  11. The first step of troubleshooting is always recording whether tmux is involved. When layers are nested, their symptoms mask each other.
  12. Grep the log for outcome= rather than reading it linearly.

Frequently Asked Questions

Why did all my terminals disappear after following the docs and running herdr server stop?

Because stopping the server ends the processes in all its panes — that is not a bug, it is the parent-child relationship between server and panes. The docs mention it in two different failures (an old running session after an update, and Keychain access failing), but it is a recovery step rather than a free action. If you only want to close a test session, use herdr session stop <name>, which stops that one named session and leaves the session you are using alone. Before stopping a default session, confirm there is no long-running work in its panes.

Enter fires twice inside Herdr. How do I fix it?

An older version of the outer terminal emits the release of Enter, Tab, and Backspace as the same bytes as the press when an application enables Kitty keyboard event reporting, and Herdr cannot distinguish the duplicate bytes once sent. The fix is to upgrade the outer terminal to a version containing the upstream fix: kitty 0.33.0, foot 1.20.0, Alacritty 0.15.0. This is most common with older terminal packages from long-term-support Linux distributions. If it still happens on a current terminal version, report the exact terminal version and whether it also occurs outside Herdr.

Pressing Option+Left types ;3D. What now?

Terminals send Alt+Left and Alt+Right as ESC[1;3D and ESC[1;3C, and on macOS the outer terminal must first be configured to treat Option as Alt. If the shell has no binding for those sequences, zsh displays the remaining characters as ;3D and ;3C. Add explicit bindings: bindkey $'\e[1;3D' backward-word and bindkey $'\e[1;3C' forward-word. kitty can appear to work outside Herdr because its automatic zsh integration adds these bindings only to shells it started directly, not to shells created by a multiplexer. Herdr deliberately does not rewrite modified arrows, because terminal applications may use Alt+Left and Alt+Right directly.

I upgraded Herdr but the interface is still the old one.

Updating the binary does not replace a compatible server that is already running. Start Herdr again to use the updated client. If you also need server-side changes from the release, check herdr status, then stop the session and launch Herdr again. Keep two kinds of update apart: client-side changes (interface, keybindings, themes) need only a restart of the client, while server-side changes (pane processes, detection manifests, the plugin registry) require restarting the corresponding session. Unix also has live handoff for transferring without killing processes, but older servers need an update before they can use it.

Where are the logs, and what should I include in a report?

By default they live under ~/.config/herdr/: herdr.log, herdr-client.log, herdr-server.log (all three verified present here, and the server log records structured events continuously). For more detail set HERDR_LOG=herdr=debug. Include the current log and its rotated siblings when reporting. The official troubleshooting doc also asks for versions and session status up front: herdr -V and herdr status.
