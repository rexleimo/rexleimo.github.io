Module 2: Remote and Multi-Machine

“the agent runs on a remote machine, the human is local (or on a phone)” is the most common shape of this work in 2026. This module splits Herdr’s remote capability into two layers: multi-machine management in one window (Local plus several SSH machines side by side) and choosing among the three remote paths (the differences are larger than they appear, especially around clipboard and theme ownership).

Baseline: herdr 0.9.2 stable · documentation source pinned at v0.9.2

Prerequisites

  • You completed module 0 and can start a workspace locally
  • You have one SSH-reachable machine (cloud box, company dev box, a mini PC at home — any of them)
  • Reading module 1 article 3 on session state makes “what lives on which machine” much easier to follow

Learning goals

After this module you can answer:

  • What exactly herdr machine add <host> --label <label> stores, and how it relates to a Host entry in ~/.ssh/config
  • With several machines in one window, how the sidebar merges their agent lists, and why one machine dropping out does not affect the other connections
  • How to triage each connection failure (authentication, DNS, host key, jump host), plus the known macOS post-login SSH/DNS failure
  • The essential difference between the three remote paths: which machine the server is on, who renders the UI, whose theme wins
  • Why only herdr --remote <host> can bridge an image from your local desktop clipboard into a remote pane
  • What you need to use Herdr on a phone (answer: just an SSH client — no app, no web dashboard)
  • How to upgrade Herdr on a remote machine, and why herdr update lists your saved SSH machines as a reminder

The short version

Want remote sessions to feel local → use herdr --remote <host>; just want a tmux inside a remote shell → ssh in and run herdr; watching agents on several machines at once → save them with herdr machine add and run them all from one window.
