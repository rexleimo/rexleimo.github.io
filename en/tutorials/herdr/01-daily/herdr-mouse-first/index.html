Herdr's Mouse-First Workflow: Create a Workspace and Run Your First Agent Without Touching a Single Binding

Herdr is mouse-native: click panes/tabs/workspaces to focus, drag split borders to resize, right-click menus to split and create, drag-select to copy, double-click to select a token, Ctrl+click to open links. This article walks the official quick-start order to your first workspace and first agent, marks exactly which actions need the keyboard (only one is genuinely worth learning early: the prefix+g goto picker), and includes real workspace list / agent list output from herdr 0.9.2 on this machine.

September 29, 2026 · 10 min · 2117 words · Mengshou Programming -  |  中文

Verified version: herdr 0.9.2 (stable channel) · tested on this machine: macOS / Apple silicon · 2026-09-29

The official docs say the same sentence on both the quick-start and concepts pages:

No keybindings are required to use Herdr.

That is not a courtesy line. Herdr is mouse-native and the keyboard is an optional layer. So this article completes your first workspace and first agent entirely with the mouse, and at the end names the one binding genuinely worth learning.

Conclusion first:

Do not touch the keyboard for the first 30 minutes. The mouse covers every daily action: creating workspaces, splitting, switching, copying, opening links, renaming. The single thing worth learning early is prefix+g (the goto picker) — because once you have 8 agents it is the only entry point that filters by state, and clicking the sidebar cannot do that.

Step 1: cd into the project, run herdr#

cd ~/codes/your-project
herdr

Two lines. The docs single out two behaviours:

  • it starts or attaches the default background session automatically; you do not manage the socket
  • when the session has no workspace at all, Herdr opens one for you

The first run walks you through onboarding (once completed it writes onboarding = false into config.toml — measured on this machine, that line is the file’s only content).

Note: if you are already inside a Herdr pane (echo $HERDR_ENV prints 1), do not run herdr again. Herdr blocks nested startup by design.

Step 2: learn your way around the UI#

You will see three regions:

RegionWhat it isMouse actions available
sidebarthe workspace list; under each workspace, its tabs/panes listed as agents and terminals, with stateclick a workspace to switch; click an agent row to jump straight to that pane
main areathe pane layout of the current tabclick a pane to focus; drag a split border to resize; right-click for the menu
status barcurrent mode, primary prefix key, etc.read-only; prefix+? expands full help

Sidebar width is configurable (sidebar_width) and can also be dragged. On this machine session.json has sidebar_width: null, meaning “use the default”.

On workspace granularity, the official advice is one repo / one task / one investigation = one workspace, justified in core concepts : sidebar state rolls up per workspace. Cram eight projects into one workspace and you have thrown away Herdr’s most valuable capability.

Step 3: the complete mouse gesture table#

Treat this section as a cheat sheet. Everything comes from the official quick-start and concepts pages:

GestureEffect
click a pane / tab / workspace / agentfocus
drag a split borderresize a pane
right-clickcontext menu, containing split pane and new tab
drag-select textreleasing copies to the clipboard, no ctrl+c needed
double-clickselect a token
double-click, holding the second press and draggingextend the selection word by word
Ctrl + clickopen a link inside the pane (OSC 8 hyperlinks, http://, https://)
Ctrl + hoverunderline the visible segment of a link
wheel / click the scrollbar trough / drag the thumbscroll an overflowing goto picker list without accidentally jumping to a target

Details worth expanding:

Wrapped links are still clickable#

Ctrl-click supports wrapped links whose start or end falls outside the visible area — a detail that pays off constantly in logs with long URLs. The hover highlight clears in three situations: the pointer moves away, the pane content changes, or Herdr receives a Ctrl-release event. The docs add one caveat: some terminals only report modifier changes when the mouse moves, so “holding Ctrl but no highlight appears” may be the terminal’s doing rather than Herdr’s.

Ctrl vs Cmd on macOS#

This is what confuses Mac users most:

  • with mouse capture on (the default), pane links handled by Herdr use Ctrl-click
  • Cmd-click only works through the terminal’s native bypass, e.g. Shift-Cmd-click, or if you turn capture off:
[ui]
mouse_capture = false

With capture off, Herdr stops grabbing the mouse — every mouse event goes straight to the terminal and the program in the pane. The price is that you lose every gesture in the table above. This is a binary trade-off, not a “safer default”.

Sending right-clicks to the program in a pane#

Some TUI agents have their own right-click menu. Herdr offers two routes:

Route A: a passthrough modifier (global)

[ui]
right_click_passthrough_modifier = "..."   # that modifier + right-click → passthrough to the pane program

Once set, “that modifier + right-click” hands the right button’s press, hold and drag to any mouse-reporting pane program.

Route B: change it for one pane only (what you will actually use)

Choose Send right-clicks to pane in that pane’s menu, or run inside it:

herdr pane input --current --right-click pane

Afterwards, right-clicking the pane’s border brings Herdr’s own menu back — so you cannot lock yourself out.

Step 4: run your first agent#

Start your agent in the pane as usual:

claude

Or codex, pi, opencode, or any supported agent External link . The official wording: Herdr detects it automatically — no registration, no configuration.

Once detection works, the sidebar shows whether each agent is working, blocked, done or idle across all your workspaces, so you always know which project is waiting on you.

Measured on this machine (the actual state while writing this, with no integration installed):

Note that agent_status: "working" at the workspace level is rolled up from the agents inside, not its own state. That rollup is where the answer to “which project needs me” comes from.

Step 5: split panes into a multi-agent layout#

Two routes, same result:

  • mouse: right-click → split (right / down)
  • keyboard: prefix+v splits right, prefix+minus splits down

The layout I actually use splits tabs by view (also what the official concepts page recommends: agents / logs / server / review):

tabwhat goes in it
agentsone pane per agent, laid out side by side so you can scan state
logsnpm run dev / log tails / test watchers
serverdatabases, backend services and other long-lived processes
reviewgit, lazygit, diff tools

Why tabs rather than splitting everything inside one tab: tabs are addressable from the CLI and socket API (herdr tab ...), so a script can “open a pane in the logs tab and run the tests” without stealing the focus you are looking at. Pure splitting cannot do that.

Step 6: leaving and coming back#

prefix + q      # detach: the client leaves, server and agents all remain

Or just close the terminal window; same effect.

Coming back:

herdr

You reattach to the same session; the processes in the panes never stopped.

To actually stop everything, there is exactly one command:

herdr server stop

This is the biggest cognitive trap for newcomers: believing closing a window stopped things. It did not. Conversely, if an agent “mysteriously vanished”, the first thing to check is whether the server was stopped or the machine rebooted — those two cases have completely different recovery paths, see the five session-state paths .

Step 7: the one binding worth learning early — prefix+g#

I said the mouse suffices throughout. But one feature the mouse cannot replace becomes essential as soon as you have several agents:

the goto picker (prefix+g). Its behaviour (per the official keyboard page):

  • each agent or terminal gets its own row, grouped by workspace
  • split panes are never hidden behind another row (much better than selectors that list by tab)
  • click a row or press Enter to jump straight there
  • / searches: name, agent type, tab, workspace, branch, path
  • when not typing a query, Up/Down or j/k move; Left/Right jump to the first agent or terminal of the previous/next workspace section (no wrap-around); while editing a query, Left/Right move the text cursor instead
  • when not searching, b / w / i / d show only blocked / working / idle / done agents, and a restores all terminals
  • the selected target’s position and path are shown below the list
  • when the list overflows you can scroll with the wheel, the scrollbar trough, or the thumb, without accidentally jumping

That last filter, b (blocked only), is the one-key answer to “I have 8 agents, which one is waiting on me”. The sidebar displays state but cannot filter; the goto picker can.

Also worth memorising: prefix+? lists every binding currently in effect (including your own changes). In the help panel, / filters actions and shortcuts, Backspace edits the filter, ctrl+u clears it. When you forget a key, press it instead of reading docs.

When the keyboard is mandatory#

Honestly, only these cases:

NeedWhy the mouse is not enoughUse
filter agents by statethe sidebar displays but does not filterprefix+g, then b/w/i/d
search a string in scrollbackdrag-select only reaches visible regionsprefix+[ into copy mode, / or ? to search, n/N to step
detachclosing the window is equivalent, but sometimes you do not want to close itprefix+q
jumping among 9 tabs fastthe sidebar needs two clicksprefix+1..9
zoom one pane for detailit is in the right-click menu, but the binding is much fasterprefix+z
scripted operation (module 4 material)the mouse is not programmableCLI / socket API

The full binding table and the prefix-free scheme are in the next article: keyboard control .

If what worries you is “will I lose an agent mid-task”, jump straight to the five session-state paths .

Traps to avoid#

  1. Do not run herdr inside a pane. echo $HERDR_ENV first — 1 means you are already in; nested startup is blocked by design.
  2. Closing a window ≠ stopping. Only herdr server stop stops. Likewise, after prefix+q do not assume the processes are gone.
  3. On macOS, do not Cmd-click links in a pane. With mouse capture on, use Ctrl-click; Cmd-click only works via the terminal’s native bypass (Shift-Cmd-click) or with mouse_capture = false.
  4. mouse_capture = false is not “safer”, it is “a different interaction model”. Turn it off and every gesture in this article’s table stops working. To have both, use right_click_passthrough_modifier, or per pane: herdr pane input --current --right-click pane.
  5. Do not put all your projects in one workspace. The rollup granularity is the workspace; mix them and the sidebar is worthless.
  6. Do not expect drag-select copying to feel intuitive in every situation outside copy mode. The docs are explicit: a mouse drag-selection and one started with v/Space/V stay valid across output and redraws, and copying reads the current text in that region rather than a frozen snapshot; but resizing a pane or switching between normal and alternate screen clears the selection. To reliably copy a large block of scrollback, use copy mode.
  7. Onboarding keeps appearing until you finish it. It is controlled by onboarding in config.toml; completing it sets false. After editing, remember herdr server reload-config (or the global menu → reload config) for the running server to pick it up.

The mouse is enough; now fill in the keyboard layer — above all how to configure a prefix-free scheme that does not collide with your terminal or desktop environment (the official team tested the default bindings of 10 terminals for this and concluded the ctrl+alt family is the safest): keyboard control .

Frequently Asked Questions

Do I have to learn keybindings to use Herdr?

No. The docs state plainly: No keybindings are required to use Herdr. Click panes/tabs/workspaces/agents to focus, drag split borders to resize, split panes and create tabs from the right-click menu, drag-select text to copy. The keyboard is an optional layer.

What do I do the first time I run Herdr?

cd into your project directory and run herdr. It starts or attaches the default background session automatically, and opens a workspace if the session has none. The first run walks you through onboarding. You never manage the socket.

How do I copy text in Herdr?

Drag-select with the mouse; releasing copies to the clipboard, no Ctrl+C needed. Double-click selects a token; holding the second click and dragging extends the selection word by word. The keyboard route is prefix+[ into copy mode, then v or Space to start a selection, y or Enter to copy, q or Esc to leave.

Why does Cmd+click sometimes not open a link on macOS?

While mouse capture is on, pane links handled by Herdr use Ctrl-click. Cmd-click only works through the terminal's native bypass, for example Shift-Cmd-click, or with ui.mouse_capture set to false.

If I close the terminal window, does my agent stop?

No. The server holds the panes and processes; after detach (prefix+q) or just closing the window everything keeps running, and running herdr again reattaches to the same session. Only herdr server stop actually stops things.

If only one keyboard feature is worth learning first, which?

The prefix+g goto picker. It lists each agent or terminal on its own row grouped by workspace, so split panes are never hidden behind another row; / searches names, agent types, tabs, workspaces, branches and paths; and when not searching, b/w/i/d show only blocked/working/idle/done agents while a restores all terminals.
