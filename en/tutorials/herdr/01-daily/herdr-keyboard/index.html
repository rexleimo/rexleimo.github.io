Herdr Keyboard Control: the Prefix Key, Five Keys to Learn First, copy mode, and a prefix-free Scheme That Does Not Fight Back

The complete breakdown of Herdr's keyboard layer: why the prefix key exists (the OS, the outer terminal and the program in the pane all claim keystrokes), the five keys worth learning first (prefix+c/v/minus/h-j-k-l/w/q), the full pane/tab/workspace binding table, the editing keys of Herdr's own text fields, copy-mode movement and search rules; the [keys] binding syntax (prefix may be an array, one action may bind several keys, named punctuation, indexed 1..9), the four [[keys.command]] types popup/pane/shell/plugin_action, and the official ctrl+alt prefix-free scheme measured across 10 terminals along with the combinations you must avoid.

September 29, 2026 · 13 min · 2597 words · Mengshou Programming -  |  中文

Verified version: herdr 0.9.2 (stable channel) · tested on this machine: macOS / Apple silicon · 2026-09-29

The previous article got a first workspace running entirely with the mouse. This one adds the keyboard layer — but the point is not the binding table (prefix+? shows it any time you like); it is the two things people get wrong: why a prefix key is necessary, and how to configure direct bindings that do not collide with anything.

Conclusion first:

The prefix key is not legacy baggage, it is necessary. A keystroke must survive three layers before Herdr sees it: the operating system, the outer terminal, and the program running in the pane — between them they already occupy nearly every common combination. The prefix lets Herdr claim one key instead of dozens. If you insist on prefix-free, the official team mapped the default bindings of 10 terminals plus GNOME/KDE and concluded that exactly one modifier family is nearly unclaimed everywhere: ctrl+alt.

1. What problem the prefix key actually solves#

The official keyboard page explains it well enough to quote in full:

A terminal multiplexer sits between your terminal and the programs running inside it. Those programs already use most key combinations: ctrl+c interrupts, ctrl+r searches history, editors claim nearly everything else. If Herdr grabbed common keys directly, it would break the programs inside it.

A multiplexer sits between your terminal and the programs inside it. Those programs already use most combinations: ctrl+c interrupts, ctrl+r searches history, editors claim nearly all the rest. If Herdr grabbed common keys directly it would break the programs inside it.

Hence: Herdr claims one key (the prefix), not dozens.

The press deserves emphasis, because it is where tmux newcomers stall:

prefix+c means: press ctrl+b, release, then press c.

Not three keys at once.

Two lifelines available at any time:

KeyPurpose
prefix+?lists every binding currently in effect (including your own changes). In the help panel / filters actions and shortcuts, Backspace edits the filter, ctrl+u clears it
prefix+[enter copy mode (keyboard copy)

Coming from tmux / zellij: you already know this model. The docs suggest going straight to the keybinding reference External link for the complete default map and config syntax.

2. Learn these five first#

ActionKey
new tabprefix+c
split right / downprefix+v / prefix+minus
move between panesprefix+h/j/k/l
workspace navigationprefix+w
detach, everything keeps runningprefix+q

The official line: These cover most daily movement. Everything else can stay on the mouse. — these five cover most daily movement; the rest can stay on the mouse.

3. The remaining bindings, grouped by task#

Pane#

ActionKey

swap panesprefix+shift+h/j/k/l
enter resize modeprefix+r
enter copy modeprefix+[

Tab#

ActionKey
next / previous tabprefix+n / prefix+p
jump to tab 1–9prefix+1..9
rename tabprefix+shift+t

Workspace and session#

ActionKey
new workspaceprefix+shift+n
rename workspaceprefix+shift+w
close workspaceprefix+shift+d
goto pickerprefix+g
toggle sidebarprefix+b

prefix+g is the one I strongly recommended learning early in the previous article : it lists each agent / terminal on its own row grouped by workspace, split panes are never hidden behind another row, and when you are not searching, b/w/i/d show only blocked/working/idle/done agents while a restores everything. For “which of my 8 agents is waiting on me”, it is the only one-key answer.

4. Herdr’s own text fields: a different set of editing keys#

This is the easiest thing to confuse, so it gets its own section.

Applies to: Herdr’s rename dialogs, the worktree branch input, filters, the copy-mode search box. Does not apply to the shell or agent in a pane — those are the pane program’s own keys.

ActionKeys
move one characterLeft / Right, Ctrl+B / Ctrl+F
move to start / endHome / End, Ctrl+A / Ctrl+E
move one wordAlt+B / Alt+F
delete character beforeBackspace, Ctrl+H
delete character afterDelete, Ctrl+D
cut to start / endCtrl+U / Ctrl+K
cut previous wordCtrl+W, Alt+Backspace, Ctrl+Backspace
cut next wordAlt+D
insert the last cut textCtrl+Y

Four caveats (all stated in the docs):

  1. typing and pasting both insert at the cursor
  2. movement and deletion respect Unicode grapheme boundaries (so emoji and combining characters do not get sliced), and long values scroll horizontally
  3. cut text circulates only within the current field and never enters the system clipboard — so Ctrl+Y cannot paste what you copied inside a pane
  4. the Alt family requires a terminal that reports Alt/Meta; Enter and Esc keep the dialog’s confirm/cancel semantics

5. Copy mode: keyboard copying of scrollback#

prefix+[ enters copy mode for the currently focused pane.

Movement: h/j/k/l, tmux-style w/b/e and the big-word variants W/B/E, {/}, PageUp/PageDown, ctrl+b/ctrl+f, ctrl+u/ctrl+d.

Search: / forward, ? backward, both literal searches; n repeats in the same direction, N in the opposite. The case rule is smart: if your query contains no uppercase letters the search is case-insensitive; if it does, it becomes case-sensitive.

Selection and exit: v or Space start a selection, y or Enter copy, q or Esc leave without copying. Esc first clears the current selection or search, then exits (so it takes two presses to actually leave).

Three counter-intuitive but important behaviours:

  1. copy mode does not pause the pane process. Output keeps being produced in real time and the view follows the bottom; when you scroll into history, the view pins.
  2. The prefix key keeps its original meaning inside copy mode. With the default prefix, ctrl+b enters prefix mode, it is not “page up”. If you want ctrl+b as a copy-mode page key, you must change the prefix.
  3. Selections survive output and redraws (both mouse drag-selections and those started with v/Space/V), even when part of the selection is off-screen; copying reads the current text in that region, not a frozen snapshot. But resizing a pane or switching between normal and alternate screen clears the selection.

One more note: mouse drag-select never needs copy mode at all — releasing copies. The value of copy mode is searching history and precisely selecting content outside the viewport.

6. Changing any binding (including the prefix itself)#

The minimal change#

[keys]
prefix = "ctrl+a"

A typical override block#

[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"

The prefix can be an array#

When you need several keys to enter prefix mode (the official scenario: sharing one config between macOS and a remote Linux box):

[keys]
prefix = ["ctrl+space", "ctrl+s"]

Every configured prefix enters the same prefix mode and can start every prefix+... action. The first one is the primary prefix shown in the status bar; the prefix+? help panel lists all of them.

One action can also bind several keys#

[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]

Key string syntax#

Supported:

  • plain keys and modifier combos: ctrl+a, shift+n, alt+1, cmd+k
  • special key names: enter, tab, esc, left, right, up, down
  • named punctuation: minus, comma, ampersand, plus, backtick

The safety rule (this is the one people break):

A bare printable key (such as n) is unsafe, because it intercepts normal typing. Use prefix+n unless you genuinely want a direct binding.

Extra restrictions on navigate-mode-only fields: navigate_workspace_* and navigate_pane_* may use bare keys (j, k), but must not use prefix+, esc, enter, tab, shift+tab, left, right, or unmodified 1 through 9.

Three more details:

  • the left/right arrows are permanent aliases for pane-left / pane-right navigation
  • navigate-mode shortcuts are independent of general action bindings (e.g. focus_pane_down = "prefix+j"); when both use the same key, the navigate shortcut wins while navigate mode is open
  • whether Alt, Cmd/Super and modified punctuation work depends on your terminal (and its tmux settings)

Indexed jumps#

[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"

1..9 is syntax usable in ordinary binding fields. The legacy [keys.indexed] table is still parsed (for compatibility), but new configuration should use the explicit action fields above.

Custom command bindings#

This is the most productive part of Herdr’s keybinding system. Four type values:

[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
typeBehaviour
popupopens a session-level modal popup and does not change the tab layout. The popup takes over all terminal input, including Esc, until its command exits
paneopens a temporary zoomed pane that closes automatically when the command exits
shellruns detached in the background
plugin_actioninvokes an installed plugin’s action id; use a qualified id such as example.layout.apply when the id is not globally unique

width / height may be omitted (default half-size popup), given as numbers (terminal cells), or as strings like "80%" (percentage of the terminal area). Sizes include the popup’s borders, and values below the popup minimum are clamped.

description is optional; when set it appears in the prefix+? help panel instead of the default 'custom command' label.

A genuinely useful trick: on Unix / macOS, use a popup as a scratch terminal without taking a split or a tab:

[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"

On Windows replace the command with something like command = "powershell.exe -NoLogo". Exiting the shell closes the popup and returns you to the tiling view.

There is also an environment variable trap: popup commands do not receive HERDR_PANE_ID; use HERDR_ACTIVE_PANE_ID to get the tiled pane underneath.

Restoring default bindings#

herdr config reset-keys

It backs up config.toml, removes [keys] and [[keys.command]], and after a restart or herdr server reload-config the built-in v2 defaults apply.

After editing config, make it apply to the running server:

herdr server reload-config     # or the global menu → reload config
herdr config check             # validate syntax before you apply; far faster than a restart

7. Prefix-free: how to configure it without starting a fight#

You can bind Herdr actions to direct combinations that need no prefix at all. The hard part is not syntax but knowing which combinations are safe.

The official framework is “survive three layers”: for a combination to reach Herdr it must pass the operating system → the outer terminal (Ghostty, iTerm2 and friends all ship defaults) → the program in the pane.

Two concrete counter-examples (from the docs):

  • ctrl+j does reach Herdr, but shells and editors treat it as Enter
  • alt+k is free on Linux, but on macOS most terminals compose it into a special character

What the official team did: they mapped the default bindings of Ghostty, iTerm2, Terminal.app, kitty, WezTerm, Alacritty, Warp, Windows Terminal, GNOME Terminal and Konsole, plus GNOME and KDE global shortcuts. Conclusion:

There is one modifier family that is nearly unclaimed everywhere: ctrl+alt. Terminals leave it alone; it is not affected by the macOS option-key compose behaviour (which blocks plain alt combinations); and it passes through even terminals that do not support modern keyboard protocols.

The official prefix-free configuration (keeps the prefix bindings and layers direct keys on top)#

[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]

Note the array form — the prefix variants stay live and the direct keys are layered on top. This is the official incremental route, not an either/or.

But avoid these ctrl+alt combinations#

CombinationClaimed by
ctrl+alt+arrow keysGNOME workspace switching, and Ghostty / Konsole defaults
ctrl+alt+tUbuntu / Fedora “launch terminal”
ctrl+alt+l / ctrl+alt+aKDE lock screen / notification window
ctrl+alt+s / ctrl+alt+uKonsole
ctrl+alt+f1..f12Linux virtual console switching

(Observe that the official config above does contain ctrl+alt+l — on KDE the lock screen will eat it. Check your desktop environment before copying a config.)

tmux-style single-key resizing#

Resize with one key, without entering resize mode:

[keys]
resize_pane_left = "ctrl+shift+alt+left"
resize_pane_down = "ctrl+shift+alt+down"
resize_pane_up = "ctrl+shift+alt+up"
resize_pane_right = "ctrl+shift+alt+right"

These optional actions are unbound by default (unset). Bind them with prefix+ for prefix-mode behaviour, or with an explicitly modified combination when you really do want a direct shortcut.

If a direct key does nothing#

The official diagnosis is blunt:

Your terminal or desktop environment claimed it before Herdr saw it. Change one of the two: free the combination in your terminal settings, or pick a different one in Herdr.

Suggested triage order: try the same combination in another terminal first (that isolates whether the terminal is the culprit) → then check your desktop environment’s global shortcut list → only then suspect the Herdr config (herdr config check).

8. Traps to avoid#

  1. prefix+? is the only authority. It is live and shows what is actually bound right now. Do not trust keybinding tables from the internet.
  2. Do not bind bare printable keys. new_tab = "n" will make the letter n untypeable in every Herdr input field. Always prefix+n unless you deliberately want a modified direct key.
  3. If you want ctrl+b as a copy-mode page key, you must change the prefix. The prefix key keeps its meaning inside copy mode.
  4. Esc takes two presses in copy mode — the first clears the selection/search, the second exits.
  5. Ctrl+Y cannot paste from the system clipboard. Cut text in Herdr fields circulates only inside that field.
  6. A popup swallows Esc. That is by design (the popup owns all input until its command exits), not a freeze; exit the command inside and you are back.
  7. There is no HERDR_PANE_ID inside a popup. Use HERDR_ACTIVE_PANE_ID.
  8. navigate-mode fields have their own forbidden list. navigate_workspace_* / navigate_pane_* cannot use prefix+, esc, enter, tab, shift+tab, left, right, or bare 1–9.
  9. Reload after editing config. Editing config.toml does not apply to the running server automatically: herdr server reload-config, or the global menu → reload config.

Frequently Asked Questions

What is Herdr's prefix key and how do you press it?

It defaults to ctrl+b. The press is 'ctrl+b, release, then the action key', not three keys at once. For example prefix+c opens a new tab, prefix+w opens workspace navigation, prefix+q detaches. The prefix itself is configurable under [keys] prefix and can be an array to support several prefixes.

Which keys do I minimally need to remember?

Five: prefix+c new tab; prefix+v / prefix+minus split right / down; prefix+h/j/k/l move between panes; prefix+w workspace navigation; prefix+q detach (everything keeps running). Everything else can stay on the mouse. When in doubt press prefix+? to list every binding currently in effect.

Why does my ctrl+alt binding do nothing?

A keystroke has to survive three layers before Herdr sees it: the operating system, the outer terminal (Ghostty/iTerm2 and friends ship their own defaults), and the program running in the pane. If any layer claims it first, nothing happens. The official advice is to either free the combination in your terminal settings or pick a different one in Herdr.

Which ctrl+alt combinations should I avoid?

ctrl+alt+arrow keys (GNOME workspace switching, and defaults in Ghostty and Konsole), ctrl+alt+t (Ubuntu/Fedora launch terminal), ctrl+alt+l and ctrl+alt+a (KDE lock screen / notification window), ctrl+alt+s and ctrl+alt+u (Konsole), ctrl+alt+f1..f12 (Linux virtual console switching).

How do I search and copy in copy mode?

Enter with prefix+[. / and ? do forward/backward literal search, n and N repeat in the same or opposite direction; the search is case-insensitive unless your query contains an uppercase letter. v or Space start a selection, y or Enter copy, q or Esc leave without copying (Esc first clears the current selection or search, so it takes two presses).

How do I get the default keybindings back?

herdr config reset-keys. It backs up config.toml, removes [keys] and [[keys.command]], and after a restart or herdr server reload-config the built-in v2 defaults are used.
