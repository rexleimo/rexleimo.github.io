Module 0: Getting to Know Herdr

Before touching anything, nail down three things: what Herdr is (and is not), how to install it correctly and prove that you did, and at what granularity each of the six concept layers should be used. Get these three fixed and no later module will be read crooked.

Baseline: herdr 0.9.2 stable · documentation source pinned at v0.9.2 · verified on this machine: macOS / Apple silicon

Prerequisites

  • You can use a terminal (cd, ssh, you can read environment variables)
  • No tmux / zellij / screen experience required — article 1 explains why you can skip memorising bindings this time
  • Any of macOS / Linux / Windows x86_64 (Windows ARM64 runs under emulation, see article 2)

Learning goals

After this module you can answer:

  • Which three points hold the essential difference between Herdr and tmux, and why all three are needs that only appeared once agents started running in panes
  • How each of the five installation channels (installer script / Homebrew / mise / Nix / manual download) upgrades, and why only one of them can use herdr update
  • The trade-off between the stable and preview channels, and why an old preview install on Windows cannot switch back to stable
  • The containment relationship of the four layers session / workspace / tab / pane, and when to open a new workspace versus merely a new tab
  • The precise meaning of each of the five agent states (blocked / working / done / idle / unknown), and why done and idle are easy to confuse
  • What terminal / prefix / navigate mode each do, and why the prefix key defaults to ctrl+b

The short version

If you just want to start using it: read article 2, install it, then jump straight to module 1 and drive it with the mouse — come back to article 3 for concepts when you hit one. If you are migrating from tmux: read article 3 first to align terminology, otherwise you will keep forcing Herdr into your tmux mental model and keep confusing the session and workspace layers.
