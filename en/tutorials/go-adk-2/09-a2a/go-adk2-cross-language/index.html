Cross-language interoperability: the default-deny policy of `remoteagent.NewA2A` and its two metadata namespaces

agent/remoteagent/v2 and the server/adka2a metadata contract in ADK Go v2.4.0: the bidirectional adk_ and a2a: prefixed namespaces, the nine action fields that get carried across, the security rationale behind AllowTransferToAgent defaulting to false (a remote peer must not redirect local orchestration), the origin validation of agent cards and ErrUntrustedCardInterface, how aggregatePartial reassembles a peer's partial artifact chunks into a non-partial event, the text folding rule, RemoteTaskCleanupCallback defaulting to a 5-second cancel RPC, and the known gaps when interoperating with adk-python.

September 26, 2026 · 16 min · 3401 words · Mengshou Programming -  |  中文

Verified against: google.golang.org/adk/v2 v2.4.0, sources agent/remoteagent/v2/{a2a_agent.go,a2a_agent_run_processor.go,client.go,utils.go}, server/adka2a/v2/{metadata.go,parts.go}.

1. A remote agent is just a local agent.Agent#

import "google.golang.org/adk/v2/agent/remoteagent"

peer, err := remoteagent.NewA2A(remoteagent.A2AConfig{
	Name:                  "translation_agent",
	Description:           "Translates Chinese into any target language",
	AgentCardProvider:     remoteagent.NewAgentCardProvider("https://translate.example.com"),
})
if err != nil { /* … */ }

root, _ := llmagent.New(llmagent.Config{
	Model: m, Name: "orchestrator",
	SubAgents: []agent.Agent{peer},   // exactly like a local sub-agent
})

func NewA2A(cfg A2AConfig) (agent.Agent, error) — it returns an agent.Agent, so a remote agent can appear anywhere an agent is accepted: SubAgents, workflow.NewAgentNode, a member of a SequentialAgent.

⚠️ Which also means the model can autonomously transfer work to a remote agent (see module 6, article 2). Once that agent reaches the public internet, “the model decides whom to call” becomes “the model decides which data leaves”. In production, pin it with a graph node (who calls it and with what stays in code), or at least add a BeforeRequestCallbacks layer as an egress review.

Two kinds of card source#

// AgentCard is a static agent card. Either AgentCard or AgentCardProvider must be set.
AgentCard *a2a.AgentCard
// AgentCardProvider resolves an agent card on each agent invocation.
// Use [NewAgentCardProvider] to create a provider from a URL or file path.
AgentCardProvider AgentCardProvider
  • NewAgentCardProvider(source, opts...) first runs classifyCardSource to decide URL versus file path: URLs go through agentcard.DefaultResolver.Resolve, files through os.ReadFile + json.Unmarshal.
  • The provider resolves on every call (the comment says on each agent invocation), so the addresses in the card can roll forward with your deployment. If the card content is stable in production, cache it to save time.
  • File mode skips origin validation, with the reason stated in the comment: “a card read from a local file did not come off the network here, and its target is left to the caller.” — you already control a local file, so do not expect the library to protect you from yourself.

2. Every A2AConfig field (grouped by purpose)#

type A2AConfig struct {
	Name        string
	Description string
	AgentCard           *a2a.AgentCard
	AgentCardProvider   AgentCardProvider
	BeforeAgentCallbacks  []agent.BeforeAgentCallback
	BeforeRequestCallbacks []BeforeA2ARequestCallback
	Converter             A2AEventConverter
	AfterRequestCallbacks []AfterA2ARequestCallback
	AfterAgentCallbacks   []agent.AfterAgentCallback
	AllowTransferToAgent  bool
	A2APartConverter      adka2a.A2APartConverter
	GenAIPartConverter    adka2a.GenAIPartConverter
	ClientProvider        A2AClientProvider
	MessageSendConfig     *a2a.SendMessageConfig
	RemoteTaskCleanupCallback A2ARemoteTaskCleanupCallback
}

Three callback layers with different semantics (this is the easiest thing in the module to mix up):

LayerCallbacksKey point from the comments
agent layerBeforeAgentCallbacks / AfterAgentCallbackssame meaning as ordinary agent callbacks: a non-nil content returned skips the agent run
request layerBeforeRequestCallbacks“in the order they are provided until there’s a callback that returns a non-nil result or error. Then the actual request is skipped” → usable as a cache (return the cached response directly)
request layerAfterRequestCallbacks“the actual remote agent event is replaced with the returned result/error” → the right place for recording responses, token accounting, post-processing
conversion layerConvertera2a.Event → session.Event; without one the default adka2a.ToSessionEvent is used (errors become events carrying an error payload)

That “short-circuit skips the request” behaviour of BeforeRequestCallbacks is one of the few places in v2.4.0 that explicitly supports implementing a cache with a callback.

3. AllowTransferToAgent: default-deny control flow#

The comment is blunt and worth reading whole:

// AllowTransferToAgent controls whether a transfer_to_agent value set by
// the remote A2A peer in its response metadata is honored by the local
// orchestrator.
//
// TransferToAgent drives which agent runs next within the caller's own
// configured multi-agent tree, so accepting it from a remote peer lets
// that peer redirect the local orchestrator's control flow. This
// defaults to false (the peer-supplied value is redacted) so that
// connecting to an agent you do not fully trust is safe by default. Set
// this to true only for closed, trusted deployments that rely on the
// remote peer being able to select the next local agent.
//
// This is applied uniformly after conversion, whether the default
// converter or a custom Converter is used.
AllowTransferToAgent bool

The implementation (inside NewA2A):

// See toEventActions: TransferToAgent is restored here, after
// conversion, only when the caller has opted in via
// AllowTransferToAgent.
if err == nil && event != nil && a2aEvent != nil && cfg.AllowTransferToAgent {
	if transferToAgent, ok := adka2a.TransferToAgentFromMeta(a2aEvent.Meta()); ok {
		event.Actions.TransferToAgent = transferToAgent
	}
}

Three consequences:

  1. The default converter wipes TransferToAgent (it is not carried out at the toEventActions stage), and when enabled it is re-attached after conversion.
  2. “applied uniformly after conversion” — a custom Converter cannot bypass this policy either, because it is applied to everything after conversion. This is a real security boundary, not converter self-discipline.
  3. The only legitimate reason to turn it on is “a closed, trusted deployment where the peer genuinely must pick my next local agent”. Never enable it over the public internet or with partners.

4. Agent card origin validation: stopping an open redirect from moving the trust anchor#

NewAgentCardProvider enforces it on the URL branch (the file branch does not validate):

card, err := agentcard.DefaultResolver.Resolve(ctx, source, opts...)
// …
if err := validateCardInterfaceOrigins(card, source); err != nil { return nil, err }

The policy, verbatim from the comment:

Every interface the card declares is checked, not only whichever one a
given transport negotiation would select, since any of them could end up
being used. Each must be https, or http on a loopback host (the shape
local-development tooling emits, and a host an attacker who does not
already control this machine cannot redirect a fetch to), and must share
the origin of the configured agent card source -- not necessarily the
origin the fetch actually landed on, if the resolver followed a redirect.
Pinning to the configured source rather than the final URL is
intentional: pinning to wherever a fetch actually lands would let an open
redirect move the trust anchor.

Broken into four rules:

RuleContentReason
check allevery SupportedInterfaces entry in the card is validated, not just the one transport negotiation would selectany of them could end up being used
schememust be https, or http on a loopback hostloopback is the shape local development tooling emits, and “an attacker who does not already control this machine cannot redirect a fetch to loopback”
same originmust share the origin of the card source you configurednot the origin the fetch actually landed on
pin the configured sourcedeliberately pinned to the source, not the final URL“pinning to wherever a fetch actually lands would let an open redirect move the trust anchor”

The origin comparison is normalised too (a real subtlety in the implementation):

// Comparing url.URL.Host directly, as an earlier version of this check did, treats
// "https://Agent.Example.com" as a different origin from "https://agent.example.com",
// and "https://agent.example.com:443" as different from "https://agent.example.com"
// -- rejecting same-origin cards that spell the port explicitly or the host in a
// different case, even though DNS hostnames are case-insensitive and both name the
// same origin.
func urlOrigin(u *url.URL) (scheme, host, port string)   // host case-folded, default port filled in per scheme
var defaultPorts = map[string]string{"http": "80", "https": "443"}

And the comment states outright that this normalisation is aligned with adk-python’s _url_origin / _DEFAULT_PORTS — in cross-language interop both sides must validate to the same strictness, otherwise one connects and the other refuses.

The failure error is ErrUntrustedCardInterface (testable with errors.Is), with context: interface URL %q must use https, or http on a loopback host / does not share the origin of the configured agent card source (%q).

Deployment note: if your card is published through a CDN or gateway, supportedInterfaces[].url and the card source must be same-origin or the process cannot reach the peer. The classic mistake is a card that names an intranet address such as http://10.0.0.5:8080/a2a — not loopback and not https, so it is refused outright.

5. Two metadata namespaces#

ADK and A2A each have their own metadata; conversion tells them apart by prefix:

// ToA2AMetaKey adds a prefix used to differentiate ADK-related values stored in Metadata of an A2A event.
func ToA2AMetaKey(key string) string { return "adk_" + key }
// ToADKMetaKey adds a prefix used to differentiate A2A-related values stored in custom metadata of an ADK session event.
func ToADKMetaKey(key string) string { return "a2a:" + key }

The action fields that get carried across (server/adka2a/v2/metadata.go):

ADK-side fieldA2A metadata key
Actions.Escalateadk_escalate
Actions.TransferToAgentadk_transfer_to_agent
(error code)adk_error_code
(is this an error message)adk_is_error_message
(partial flag)adk_partial
citationsadk_citation_metadata
groundingadk_grounding_metadata
usageadk_usage_metadata
(custom)adk_custom_metadata

Inbound: A2A-specific values land in an ADK event’s custom metadata with the a2a: prefix.

Two practical consequences:

  1. If a packet capture shows adk_*, that is ADK semantic payload, not a standard A2A field. Third-party (non-ADK) A2A clients will not read them — so capabilities like escalate, transfer_to_agent and partial only work between ADK peers.
  2. The reverse also holds: when connecting to a non-ADK A2A service, do not rely on these keys; interact purely through standard A2A semantics (task / artifact / status message).

Reading adk_partial is unusual#

func IsPartialFlagSet(meta map[string]any) bool {
	if meta == nil { return false }
	_, isSet := meta[metadataPartialKey].(bool)
	return isSet
}

It only checks that the key exists and is a bool, never the value. Because Partial: false is ADK’s zero value and never gets serialised (addMeta returns immediately when data == nil). So:

The presence of adk_partial means “this is partial” — do not read its boolean value.

6. aggregatePartial: reassembling a peer’s chunks into a non-partial event#

A remote stream returns A2A artifact chunks; the client reassembles them (a2a_agent_run_processor.go):

func (p *a2aAgentRunProcessor) aggregatePartial(ctx agent.InvocationContext, a2aEvent a2a.Event, event *session.Event) []*session.Event

The branch table (in code order):

InputBehaviour
meta carries adk_partialpassed through unchanged, comment: “ADK partial events should be aggregated by ADK and emitted as a non-partial artifact update. That’s why we skip them regardless of the actual isPartial value. This is the legacy OutputMode.”
TaskStatusUpdateEvent whose state is Terminal()first flush every buffered artifact as non-partial events in order, then emit the terminal event
*a2a.Task (a snapshot)clear the aggregation state (“published a snapshot which should have all the data we potentially aggregated. Reset the aggregation so that it is not published twice.”), emit that event only
anything that is not a TaskArtifactUpdateEvent (i.e. a status update)not aggregated, passed through
Append == falsereset that artifact’s aggregation; if it is also LastChunk, force event.Partial = false before emitting (“non-append event which is the last chunk must already be non-partial”)
Append == true, LastChunk == falseaccumulate, pass the current event through
Append == true, LastChunk == trueemit the current (partial) event first, then immediately a synthesised non-partial aggregate event

A direct answer to section 9.2 of module 7: the A2A client already reassembles chunks, so a Go↔Go A2A link does not automatically hit the “stream ends on a partial” trap because the peer streamed — unless the peer is on the legacy OutputMode and never sends LastChunk or a terminal state.

The text folding rule#

if part.Text != "" { // collapse small text-block parts to bigger text blocks
	if len(agg.parts) > 0 {
		lastPart := agg.parts[len(agg.parts)-1]
		// check if last part is a text block of the same 'Thought' type
		if lastPart.Text != "" && lastPart.Thought == part.Thought {
			lastPart.Text += part.Text
			continue
		}
	}
	agg.parts = append(agg.parts, &genai.Part{Text: part.Text, Thought: part.Thought})
} else {
	agg.parts = append(agg.parts, part)
}

Three points:

  1. Only parts with Text != "" are folded (streaming tokens are the common case); other types are appended as-is.
  2. Text parts with a different Thought flag never merge — a reasoning segment and a body segment are not glued into one.
  3. ⚠️ Parts with part.Text == "" (an empty text, or a part carrying only a functionCall) take the else branch and are kept verbatim, excluded from folding.

This is why “the number of aggregated events ≠ the number of A2A frames”. When counting tokens or events, use the aggregated part count, not the frame count.

Synthesised events re-run the callbacks#

The emit loop in NewA2A contains very fine-grained correctness handling:

for _, toEmit := range processor.aggregatePartial(ctx, a2aEvent, event) {
	// aggregatePartial may synthesize a brand-new non-partial event from buffered
	// partial chunks (the reassembled artifact). That event has not passed through
	// the after-callbacks, so run them here. The pass-through `event` already ran
	// callbacks above; skip it (same pointer) to avoid invoking callbacks on it twice.
	if toEmit != event {
		if cbResp, cbErr := processor.runAfterA2ARequestCallbacks(ctx, toEmit, nil); …
	}
}

Pointer equality decides “is this the event that already ran the callbacks”. Implications for you:

  • AfterRequestCallbacks may run several times after a single A2A frame (the original event plus the synthesised one). When doing analytics or billing, dedupe by event.ID or you will double-count tokens.
  • Do not write a callback that assumes “one call per increment”.

7. Remote task cleanup: a 5-second cancel RPC by default#

// RemoteTaskCleanupCallback is called if Run exited before a terminal event was received
// from the remote A2A server. If Run exited due to an error including context cancellation
// it will be passed as cause.
// The context passed to this callback is the original context, but with Err() removed by
// context.WithoutCancel.
// If no callback is provided the default behavior is to make a cancel RPC request with 5
// second timeout.
type A2ARemoteTaskCleanupCallback func(ctx context.Context, card *a2a.AgentCard, client A2AClient, taskInfo a2a.TaskInfo, cause error)

Four points:

  1. Trigger: the local Run exited before a terminal event arrived (context cancellation, an error, or an upstream break). Without cleanup the remote task keeps running and keeps billing.
  2. The default is a cancel RPC with a 5-second timeout. The value 5s is hard-coded in the comment and not exposed as a parameter — implement your own callback if you need longer.
  3. The ctx is context.WithoutCancel(original) (with Err() removed), so the callback can still make RPCs when the exit was caused by cancellation.
  4. ⚠️ Consequently a callback cannot use ctx to detect cancellation (ctx.Err() is always nil) — the reason for the cancellation is only available through the cause parameter.

The symmetric server-side cleanup callback (ExecutorConfig.A2AExecutionCleanupCallback, which additionally carries subAgentCards) is in article 1, section 4 .

8. Interoperating with adk-python: four known gaps#

This section is where real integration work wastes the most time, and every item comes from a source comment.

① What crosses the boundary (server-side view)#

toInvocationMeta / toEventMeta in server/adka2a/v2/metadata.go define the set (full code in article 1, section 5.5 ):

userID, sessionID := "A2A_USER_"+reqCtx.ContextID, reqCtx.ContextID
DirectionContent
into your agent (peer → you)message parts (text/file/data), ContextID (→ sessionID), TaskID, the peer’s metadata, the authenticated identity attached by a2a-go
out of you (you → peer)event bodies (artifacts / status message), adk_app_name, adk_user_id, adk_session_id, adk_invocation_id, adk_author, adk_branch, citations/grounding/usage, custom_metadata, error_code, actions (adk_escalate / adk_transfer_to_agent)

Three security-relevant conclusions:

  1. adk_branch reveals your internal agent hierarchy to the peer (in module 6 a branch has the form <parent>.<child>). If you do not want that exposed, avoid parallel/graph topologies that write branches, or prune the metadata with a custom GenAIPartConverter / AfterEventCallback.
  2. adk_custom_metadata carries the whole event.CustomMetadata out — and CustomMetadata is a place any callback or tool can write freely. Do not put internal prompts, sensitive user fields or internal IDs into CustomMetadata and then expose the agent over A2A; it reaches the peer verbatim.
  3. The session scope is decided entirely by the peer’s ContextID. A malicious or merely misconfigured client can read and write the history of any session that “already exists” simply by guessing, because those sessions really are in your store. So the A2A surface must have authentication wired in (see config.A2AOptions / module 10 article 1); the A2A_USER_ prefix alone is not access control.

② Long-running function calls survive only via the extension metadata#

server/adka2a/v2/extension.go (fully discussed in article 1, section 5):

A client that does not find the key may assume artifacts hold the whole response.
An ADK Python client does exactly that, and consequently misses the long-running
function call of an input-required task, synthesizing a
mock_function_call_for_required_user_input in its place.
See https://github.com/google/adk-go/issues/913.

Symptom: the Go side issues input-required, and the Python reply contains a fake function call named mock_function_call_for_required_user_input; your real adk_request_input is gone and the HITL chain does not line up.

Root cause: the Python client reads only artifacts, while ADK Go puts long-running function calls in the status message.

Test: check whether task.metadata / the status-update metadata of the response carries https://google.github.io/adk-docs/a2a/a2a-extension/. This is also why the key travels as metadata rather than through the standard X-A2A-Extensions header (Python does not read that header), and why declaring it in the agent card alone is not enough (the card describes the agent before the request; how a client reads a response comes from the response itself).

③ A partial stream must not terminate mid-flight on the peer#

Module 7 covered this: base_flow discards the entire invocation when a stream “ends with Partial=true”. And the source comment names A2A explicitly:

This commonly happens when an agent receives a partial event
from a streaming A2A peer and then the stream ends, e.g. due to an error.

Under cross-language plus streaming, an abnormal disconnect on the peer makes this local turn’s history disappear, although earlier turns already persisted in session.Service remain. Design retries as “this turn never happened”, and do not assume the history is complete.

④ Both sides must validate to the same strength#

Section 4’s origin normalisation was explicitly aligned with Python’s _url_origin. The implication: if Go refuses to connect while Python connects, first check the case and port spelling of the URLs in the card — historically that is a symptom of divergent validation, aligned as of v2.4.0, so encountering it means the two sides are out of sync.

9. A cross-language onboarding checklist#

peer, err := remoteagent.NewA2A(remoteagent.A2AConfig{
	Name: "peer", Description: "…",
	AgentCardProvider: remoteagent.NewAgentCardProvider(cardURL),
	// AllowTransferToAgent: false,   // deliberately off: never hand control to the remote
	BeforeRequestCallbacks: []remoteagent.BeforeA2ARequestCallback{egressAudit},   // egress review + optional cache
	AfterRequestCallbacks:  []remoteagent.AfterA2ARequestCallback{metricsByName},   // note: may fire more than once
	RemoteTaskCleanupCallback: cancelWithLongerTimeout,
})
if err != nil {
	if errors.Is(err, remoteagent.ErrUntrustedCardInterface) { /* the card address is non-compliant, not a network fault */ }
}
  • the card’s supportedInterfaces[].url values are same-origin with the card source, and are https (or loopback http)
  • AllowTransferToAgent decided explicitly, and stays false for public-internet scenarios
  • egress is reviewed: peer request content, invocation_id, branch and author all cross the boundary as metadata (see article 1, section 5.5)
  • AfterRequestCallbacks implemented assuming “may be called multiple times” (dedupe by event.ID)
  • event and token accounting uses aggregated parts, not A2A frame counts
  • cleanup callbacks read cause for the exit reason (the ctx has been WithoutCancel’d)
  • when interoperating with Python, verify the adk_* metadata and the extension key are present — especially for the long-running call of an input-required task
  • a fallback exists for abnormal disconnects in cross-language streaming (this local turn may be discarded wholesale)

Summary#

The two articles of module 9 are the front and back of one protocol:

  • Server side (article 1 ): the Executor projects ADK events into A2A through a seven-step mapping, OutputMode sets artifact granularity, and ADKExtensionURI makes sure clients know the content is scattered.
  • Client side (this article): remoteagent.NewA2A projects a remote agent into a local one while refusing by default any remote interference with local control flow, enforcing trusted card origins, reassembling chunks and cleaning up unfinished tasks.

With this, the functional surface of the whole series (model / tools / sessions / graph / multi-agent / streaming / deployment / A2A) is complete. The final chapter, Module 10: Production Hardening , assembles registry, authentication, plugins and observability into a deployable whole.

Frequently Asked Questions

How do I use an ADK agent written in another language as a local agent?

remoteagent.NewA2A(remoteagent.A2AConfig{Name, Description, AgentCardProvider: remoteagent.NewAgentCardProvider(cardURL)}) returns an ordinary agent.Agent, so you can drop it straight into SubAgents or a graph node.

Can a remote agent make my orchestration transfer to another local agent?

Not by default. AllowTransferToAgent defaults to false, and a transfer_to_agent value the peer puts in its response metadata is redacted. That default is deliberate: honouring it would let an untrusted peer steer your own agent tree.

Can an agent card be hijacked through a redirect?

There is a defence. Every SupportedInterfaces.URL in a fetched card must be https (or http on a loopback host) and must share the origin of the card source you configured; otherwise ErrUntrustedCardInterface is returned. The check pins the configured source rather than the URL the fetch actually landed on, because otherwise an open redirect could move the trust anchor.

How are a peer's streaming chunks handled?

The client's aggregatePartial buffers chunks per artifact and synthesises one non-partial event at the terminal status or at LastChunk. So you may see fewer events than A2A frames, and the synthesised event runs the after-request callbacks again.

Does a remote task leak if we exit before it finishes?

The default is a cancel RPC with a 5-second timeout. To customise it (audit logging, say) supply a RemoteTaskCleanupCallback; note its ctx is the original with Err() removed (context.WithoutCancel), so the cancellation reason must be read from the cause parameter.

How do two ADK sides tell which metadata is theirs?

Two prefixes. ADK semantics written into A2A metadata get adk_ (ToA2AMetaKey); A2A-specific values stored back into an ADK event's custom metadata get a2a: (ToADKMetaKey).
