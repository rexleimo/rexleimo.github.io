Three routes to Hello World, and wiring up a model: launcher, runner, workflowagent

Getting started with ADK Go v2.4.0: one line with the launcher, driving the event stream directly with the runner (iter.Seq2), or starting with a graph via workflowagent. Every llmagent.Config field is covered — Instruction templates, GlobalInstruction, OutputSchema injection, the Mode default that changes with position — plus the gemini/openaimodel/apigee model layer.

September 26, 2026 · 9 min · 1746 words · Mengshou Programming -  |  中文

Verified against: google.golang.org/adk/v2 v2.4.0 · sources agent/llmagent/llmagent.go, runner/runner.go, cmd/launcher/*.

The same agent can be run three ways, and each has a completely different purpose. In the 1.x era everyone only knew the launcher, so tests and batch jobs ended up routing around it everywhere. This article covers all three routes and every field of llmagent.Config in one pass — you will come back to that field table in every later module.

Route A: the launcher (development, demos, joint debugging — one line to a service)#

package main

import (
	"context"
	"log"
	"os"

	"google.golang.org/genai"

	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/agent/llmagent"
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/full"
	"google.golang.org/adk/v2/model/gemini"
	"google.golang.org/adk/v2/tool"
	"google.golang.org/adk/v2/tool/geminitool"
)

func main() {
	ctx := context.Background()

	model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
		APIKey: os.Getenv("GOOGLE_API_KEY"),
	})
	if err != nil {
		log.Fatalf("failed to create model: %v", err)
	}

	a, err := llmagent.New(llmagent.Config{
		Name:        "weather_time_agent",
		Model:       model,
		Description: "Agent to answer questions about the time and weather in a city.",
		Instruction: "Your SOLE purpose is to answer questions about the current time and weather in a specific city.",
		Tools:       []tool.Tool{geminitool.GoogleSearch{}},
	})
	if err != nil {
		log.Fatalf("failed to create agent: %v", err)
	}

	l := full.NewLauncher()
	if err := l.Execute(ctx, &launcher.Config{
		AgentLoader: agent.NewSingleLoader(a),
	}, os.Args[1:]); err != nil {
		log.Fatalf("run failed: %v\n\n%s", err, l.CommandLineSyntax())
	}
}

go run . console

The point: print l.CommandLineSyntax() in the error branch — it tells you which subcommands the current launcher supports. Every official sample does this; do not skip it.

Route B: the runner (tests, batch jobs, your own service)#

Drive the agent directly and take the event stream, with no launcher:

ss := session.InMemoryService()        // in-memory sessions; session/database and session/vertexai also exist

r, err := runner.New(runner.Config{
	AppName:           "weather-agent",
	Agent:             a,
	SessionService:    ss,
	AutoCreateSession: true,
})
if err != nil {
	log.Fatal(err)
}

msg := &genai.Content{
	Role:  "user",
	Parts: []*genai.Part{{Text: "What's the weather in Shanghai right now?"}},
}

for ev, err := range r.Run(ctx, "user-1", "sess-1", msg, agent.RunConfig{}) {
	if err != nil {
		log.Printf("event error: %v", err)
		break
	}
	// ev.Author / ev.Partial / ev.Actions.StateDelta ...
	fmt.Println("author:", ev.Author, "partial:", ev.Partial)
}

I compiled and ran this exact snippet (runner.New + session.InMemoryService() + the iter.Seq2 loop). Two additions:

  • runner.New reports errors at construction time: cfg.Agent == nil → “root agent is required”; cfg.SessionService == nil → “session service is required”. Assembly mistakes do not survive to the first request.
  • For the lazy “all three services in memory” setup, v2.1.0 added a convenience constructor: runner.NewInMemory(appName, agent), which internally is session.InMemoryService() + artifact.InMemoryService() + memory.InMemoryService(). It is the shortest form in tests.

The signature (verbatim from source):

func (r *Runner) Run(ctx context.Context, userID, sessionID string,
	msg *genai.Content, cfg agent.RunConfig, opts ...RunOption) iter.Seq2[*session.Event, error]

Three design points worth noting:

  1. It returns iter.Seq2[*session.Event, error] (a Go 1.23+ range-over-func iterator). So for ev, err := range is the canonical form and you never build a channel yourself. The bonus: break is cancellation, with no subscription cleanup.
  2. opts ...RunOption currently offers two: WithStateDelta(map[string]any) (pre-seed state for this turn) and WithYieldUserMessage() (yield the user-message event before agent events; the source comment says it aligns with adk-python’s yield_user_message, and it currently only takes effect on the node path).
  3. RunLive(ctx, userID, sessionID, cfg agent.LiveRunConfig, opts...) (agent.LiveSession, iter.Seq2[*session.Event, error], error) — bidirectional streaming (voice/realtime) enters here, covered in module 7.

When the runner is mandatory: unit tests, offline batch evaluation, and embedding an agent inside your own gRPC/HTTP service. Even for production assembly, do not hand-roll a runner — it has default-resolution logic for the Compaction field (next section), and the launcher is less work.

Route C: workflowagent (start from a graph)#

greet := workflow.NewFunctionNode("greet",
	func(ctx agent.Context, name string) (string, error) {
		return "Hello, " + name + "!", nil
	}, workflow.NodeConfig{})

root, err := workflowagent.New(workflowagent.Config{
	Name:        "hello_graph",
	Description: "minimal graph agent",
	Edges:       workflow.Chain(workflow.Start, greet),
})

For a new application I would actually start here: its context signature (func(agent.Context, In) (Out, error)) forces you to think in terms of the unified context from the first line, instead of writing transfers first and retrofitting later. Full topology in module 5 .

llmagent.Config field by field (checked against the v2.4.0 source)#

Identity and structure#

FieldSemanticsTrap
Namenon-empty and unique within the agent treeit may not be "user" (reserved for end-user input)
Descriptionthe LLM uses it to decide whether to delegate a task to this agentone line is enough; write it vaguely and delegation goes wrong
SubAgents []agent.Agentdelegable sub-agentsADK automatically points the parent back at this agent to support transfer, do not set the parent/child relation again yourself
GlobalInstructiona uniform instruction for the whole treeonly the copy on the root takes effect
OutputKeywrite this agent’s output into a state keyused to pass values between agents, or to retrieve an upstream conclusion inside a tool

Instructions: three spellings, do not mix them#

Instruction: "Current user is {user_name}, located in {location?}. Please cite {artifact.resume}."

The rules (from the source comment):

  • {key_name} is resolved by ADK at runtime from session state and context;
  • names must match ^[a-zA-Z_][a-zA-Z0-9_]*$, otherwise the text is treated as a literal;
  • a missing variable or artifact is an error; add ? ({var?}) to make it optional;
  • {artifact.key_name} inserts that artifact’s text content;
  • do not want template semantics → use InstructionProvider (when both are set it takes precedence over Instruction and performs no {} substitution; to inject state variables you must call util/instructionutil.InjectSessionState yourself).

GlobalInstructionProvider likewise takes precedence over GlobalInstruction.

Model and generation parameters#

Model:                 model,      // the model.LLM interface
GenerateContentConfig: &genai.GenerateContentConfig{
	Temperature:   new(float32(0.2)),      // Go 1.26's new(expr) assigns an optional pointer field directly
	SafetySettings: ...,
},

Not every field of GenerateContentConfig is usable here — the source says so plainly: tools must go through Tools/Toolsets, do not stuff them in here. Also, optional fields like Temperature *float32 can use the new(0.2) form on Go 1.26+ to skip a helper (rationale in module 0, article 3 ).

The six callback slots (ordering semantics matter)#

SlotFires whenConsequence of a non-nil return
BeforeAgentCallbacksbefore the agent runs, in ordershort-circuit: skips this run of the agent and the remaining callbacks, building a new event from its content/error
AfterAgentCallbacksafter the agent completes, in orderbuilds a new event from its content/error, skipping the remaining callbacks
BeforeModelCallbacksbefore each LLM call, in orderskips the real LLM call and uses the returned response/error — the official docs name caching as an implementation
AfterModelCallbacksafter the LLM returnsreplaces the real response; suits metrics and post-processing
OnModelErrorCallbackswhen the model errorserror handling / degradation
BeforeToolCallbacks / AfterToolCallbacksaround tool calls, in orderreturning a result skips the real tool execution
OnToolErrorCallbackswhen a tool errorserror handling

Returning a cached response from BeforeModelCallbacks to save tokens is a genuinely useful combination: a cache hit produces no model call at all. Hang your own semantic cache here (module 10 has a minimal implementation).

Structured input and output#

InputSchema:  &genai.Schema{Type: genai.TypeObject, Properties: map[string]*genai.Schema{...}, Required: []string{...}}
OutputSchema: &genai.Schema{Type: genai.TypeObject, ...}
  • InputSchema: constrains the arguments when this agent is invoked as a tool;
  • OutputSchema: once set, the framework transparently injects a set_model_response tool, so the model can still call other tools (function tools, RAG, agent transfer) while producing structured output. Implementation in internal/llminternal/outputschema_processor.go;
  • upstream left a TODO here about possibly switching from genai.Schema to jsonschema — do not hard-wire that type into your abstraction layer.

Mode: the default changes with position (the most-stepped-on item in 2.x)#

The source comment, verbatim:

Default value is ModeChat as a sub-agent, ModeSingleTurn as a node in a workflow.

ModeUnset     // the zero value when nothing is set explicitly
ModeChat       Mode = "chat"
ModeTask       Mode = "task"
ModeSingleTurn Mode = "single_turn"

The difference is substantial: the same agent can talk to the user by default under SubAgents, and cannot by default inside a graph node. To let an LLM node in a graph ask the user something, you must set Mode: llmagent.ModeChat (or ModeTask) explicitly.

Related to it: IncludeContents (source comment: when unset, an agent acting as a single_turn graph node sees only the current turn; set it explicitly to retain history inside the graph), plus DisallowTransferToParent / DisallowTransferToPeers.

Those three together form 2.x’s “conversation visibility” model for multi-agent work, which module 6 covers in a dedicated article.

Choosing a model adapter (three in the 2.x tree)#

PackageAvailabilityUsage
model/geminiboth 1.x and 2.xgemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{APIKey: …}); for Vertex use GOOGLE_GENAI_USE_VERTEXAI=true + ADC
model/openaimodel2.x onlyOpenAI-compatible endpoints (self-hosted gateway or relay). v2.4.0 fixed a compatibility issue around optional function call output IDs
model/apigeeboth linesthe Apigee AI gateway

The unifying constraint is the model.LLM interface — so you can write your own wrapper for timeouts, retries and fallback. The official examples/workflow/complex/resilient_model.go demonstrates exactly that: wrap the shared model in a resilientModel, add a timeout per call, cap retries, and fail open to a fallback model on error. I expand this pattern in module 5, article 4 .

Additionally, v2.1.0 introduced a name-based model registry (Register / NewLLM): configuration carries a model-name string, resolved at runtime to an implementation, so swapping models needs no code change.

Compile and self-check#

go build ./... && go vet ./...
go run . console                       # route A
go doc google.golang.org/adk/v2/agent/llmagent.Config    # verify fields (Go 1.27 supports the pkg@version form)

An error like undefined: llmagent.ModeTask almost always means the dependency was not pinned to v2.x (confirm with go list -m google.golang.org/adk/v2).

Frequently Asked Questions

What is the smallest Hello World in ADK Go 2.x?

Build a model with gemini.NewModel(ctx,name,cfg), build the agent with llmagent.New(llmagent.Config{...}), then run it with full.NewLauncher().Execute(ctx, &launcher.Config{AgentLoader: agent.NewSingleLoader(a)}, os.Args[1:]) and call go run . console.

How do I get the event stream without the launcher?

Use the runner package: runner.New(runner.Config{AppName, Agent, SessionService}) gives you a *Runner, then for ev, err := range r.Run(ctx, userID, sessionID, msg, runCfg) — Run returns iter.Seq2[*session.Event, error].

What is the default of llmagent.Config.Mode?

It depends on position: ModeChat when the agent is a sub-agent, ModeSingleTurn when it is a node in a workflow graph. The official comment states this difference explicitly.

How are {variables} in Instruction resolved?

At runtime ADK substitutes {key_name} from session state and context; names must match ^[a-zA-Z_][a-zA-Z0-9_]*$. A missing name is an error unless you add a question mark ({var?}) to make it optional, and {artifact.key_name} inserts that artifact's text content. To skip templating entirely, use InstructionProvider.

What happens when I set OutputSchema?

The framework transparently injects a set_model_response tool, so the model can still call other tools (function tools, RAG, agent transfer) while producing structured output.

Does ADK Go 2.x support OpenAI models?

Yes — model/openaimodel is a package unique to 2.x (absent from the v1.7.0 tree). model/apigee exists on both lines.
