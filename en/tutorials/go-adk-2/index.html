Go ADK 2.0 in Practice: The Complete Guide

This series is pinned to google.golang.org/adk/v2 v2.4.0, Go 1.26.6+ (worked against go1.27.1).

This is not a revision of the Go ADK Complete Guide . It is a 2.x series rewritten from scratch. The old series was written against v0.2.0, and in 2.x that version’s install commands, module path and API signatures fail to compile, line for line.

Why a separate series was unavoidable

ADK Go shipped 2.0.0 on 2026-06-30. This is a real major version, not a number change:

Dimension1.x (including our old series on v0.2.0)2.x (this series)
Module pathgoogle.golang.org/adkgoogle.golang.org/adk/**v2**
Go floorgo.mod go 1.24.4 / 1.25.0go.mod go 1.26.6
CLIcmd/adk (adk version)cmd/adkgo (adkgo; adk version no longer exists)
Contextsplit ToolContext + CallbackContextunified agent.Context
Eventssession.NewEvent(invocationID)session.NewEvent(ctx, invocationID)
Orchestrationthree fixed workflow agents: Sequential / Parallel / Loopgraph workflow engine: nodes / edges / routing / fan-out-fan-in / concurrent scheduler
Human-in-the-looptoolconfirmation only (tool-level)engine-level HITL: RequestInput pauses, ResumeOrRequestInput re-enters
Multi-agentsub-agent tree + transfercollaboration modes: chat / task / single_turn, sub-agents hand control back automatically
Testabilityhand-rolled mocks that break whenever an interface movesagent.StrictContextMock + platform time/UUID providers

In one line: 1.x teaches you how to get an agent running; 2.x teaches you how to write orchestration as a graph.

What this series actually solves

The official README-v2.md lists breaking changes and migration points, but says nothing about how to use them in engineering practice. That gap is what this series fills:

  • In a fan-out/fan-in research workflow, how do you handle JoinNode timeouts and partial failure?
  • After RequestInput pauses, the session lives in a database — how do you recover across a process restart?
  • When do you reach for NewDynamicNode versus a static graph, and where is the boundary?
  • With llmagent.Config{Mode: ModeTask} plus InputSchema/OutputSchema, what happens when schema validation fails?
  • When 1.x Sequential/Parallel/Loop move to workflowagents/*, where does the behaviour differ?
  • After agent.Context was unified, callbacks and tools share one context — how do you draw the side-effect boundary?

Only someone who has actually read the v2 source tree and its examples can answer these. This series is that, systematised.

Who it is for

  • You have written 1.x ADK Go: read the migration map in module 0 first, then jump to 05-workflow for the new paradigm.
  • You are new to ADK: start at module 1 and read in order. 2.x is actually easier to teach than 1.x — the graph engine’s mental model is complete.
  • You know Go (can write an HTTP service, understand goroutines and channels) and have used an LLM API (Gemini or OpenAI).

Not for you if: you are new to Go entirely; you only want a demo and never intend to ship; or your team will not accept the Go 1.26.6+ toolchain floor (in that case stay with the old series , which is kept as-is for 1.x).

Version commitments

  • This series is maintained within v2.x only. Patch releases (v2.5, v2.6…) are covered by new companion articles; existing articles are never quietly rewritten.
  • Every article states the version it was verified against. Anything that contradicts the upstream v2.4.0 source tree counts as a bug — say so in the comments.
  • Every Go snippet in the body has actually been compiled: go build passes against google.golang.org/adk/v2 v2.4.0 + Go 1.26.8, including launcher / runner / llmagent.Config fields / graph nodes and edges / routing / JoinNode / dynamic graphs / HITL / StrictContextMock usage. (Blocks explicitly labelled “verbatim from the upstream sample” are excluded — that code is upstream’s own.)
  • Upstream still maintains 1.x (v1.7.0, 2026-09-14), so this series does not predict 1.x’s future, and does not argue you should stay on 1.x.
