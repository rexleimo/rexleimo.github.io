Session and State: three prefixes, one delta merge, and a storage contract you can test

The full ADK Go v2.4.0 session layer: the real signatures of session.Session/State/Events, the app:/user:/temp: state scopes, how StateDelta reaches storage via AppendEvent and strips temporary keys, the {var}/{var?}/{artifact.file} placeholder rules in instructions, the session/database (GORM) and vertexai persistence options, the sessiontestsuite conformance suite, and where the artifact and memory sibling services begin and end.

September 26, 2026 · 10 min · 2001 words · Mengshou Programming -  |  中文

Verified against: google.golang.org/adk/v2 v2.4.0, sources session/{session.go,service.go} (Event, EventActions, RequestInput, NodeInfo and EventCompaction all live in session.go), session/database, session/vertexai, session/sessiontestsuite, internal/llminternal/instruction_processor.go, util/instructionutil.

Module 2 already showed you the Runner’s construction parameters: SessionService, ArtifactService, MemoryService. This article covers all three, with the emphasis on state scoping and the persistence contract — 2.x turned the latter into a testable specification, which is its most substantive advance over 1.x.

Three interfaces, signatures copied verbatim#

type Session interface {
	ID() string
	AppName() string
	UserID() string
	State() State
	Events() Events
	LastUpdateTime() time.Time
}

type State interface {
	Get(string) (any, error)          // missing key → session.ErrStateKeyNotExist
	Set(string, any) error
	All() iter.Seq2[string, any]      // 2.x: Go 1.23+ range-over-func
}

type Events interface {
	All() iter.Seq[*Event]            // order preserved
	Len() int
	At(i int) *Event
}

Under a read-only context you receive a ReadonlyState (one method short: no Set), so a tool can write through agent.Context while a callback’s read-only view can only read — the type enforces it for you, rather than relying on discipline.

Get fails with a sentinel error, not a (value, ok) pair:

v, err := ctx.State().Get("topic")
if errors.Is(err, session.ErrStateKeyNotExist) {
	v = "default topic"
} else if err != nil {
	return nil, err
}

Scope is decided by the key prefix#

const (
	KeyPrefixApp  string = "app:"   // application scope, across all users and sessions
	KeyPrefixUser string = "user:"  // user scope, shared across sessions within one app
	KeyPrefixTemp string = "temp:"  // current invocation only, discarded when it ends
)
PrefixLifetimeTypical contentPersisted
bare keyone sessionthis turn’s task state, drafts✅
app:the whole applicationconfiguration, vocabularies, feature flags✅ (stored per app)
user:one user across sessionspreferences, language, addresses✅ (stored per user)
temp:one invocationintermediate variables, retrieval results, the authenticated principal❌ stripped

temp: is one of the most underrated tools in 2.x. It separates “pass a value inside this call” from “write into the permanent history”:

ctx.State().Set("temp:retrieved_docs", docs)   // the next tool or callback can read it, the session cannot
ctx.State().Set("user:preferred_lang", "en")   // still there in the next session

The AppendEvent interface comment, verbatim: “used to append an event to a session, and remove temporary state keys from the event” — stripping happens at the storage layer, so every implementation must honour it.

The database backend really does store by dimension: storageSession / storageEvent / storageAppState / storageUserState (those four are what AutoMigrate migrates), and it uses extractStateDeltas to split one StateDelta into app/user/session parts, then mergeStates to reassemble a single view on read. Your custom implementation needs the same semantics, otherwise app: keys degrade into the illusion of “one copy per session”.

The real path of a single write#

// inside a tool
ctx.State().Set("counter", n)     // immediately readable
// ↓ the framework records this change on the event
event.Actions.StateDelta["counter"] = n
// ↓ the Runner calls SessionService.AppendEvent(ctx, sess, event)
// merged into session state, temp: stripped, event stored

Three places that commonly trip people:

  1. After Set it is visible within the turn, but persistence happens when the event is appended. If the turn panics midway, the change may never reach storage.
  2. NewEvent already initialises both maps to non-nil (source: Actions: EventActions{StateDelta: make(...), ArtifactDelta: make(...)}), so when hand-building an event do not use a bare Event{} literal — otherwise StateDelta is a nil map and writing to it panics.
  3. StateDelta is an increment, not a snapshot. A later write to the same key overwrites the earlier one, and merging across events follows chronological order.

Referencing state inside an Instruction: four spellings#

Template parsing lives in internal/llminternal/instruction_processor.go, with the regex {+[^{}]*}+. The rules:

{topic}                 reads state["topic"]; a missing key → error
{topic?}                optional: a missing key renders as an empty string
{user:preferred_lang}   with a scope prefix
{artifact.chart.png}    loaded from ArtifactService, taking Part.Text

Three lines from the source deserve to be singled out:

  • Legal names: isValidStateName accepts only a bare identifier, or app:/user:/temp: followed by an identifier (first character a letter or underscore, the rest alphanumeric or underscore). {my-key} and {a.b} (except artifact.) are kept verbatim and not substituted — so name your keys as legal identifiers, not with hyphens.
  • The artifact. branch calls ctx.Artifacts().Load(...), and without an artifact service it errors with artifact service is not initialized. Using runner.NewInMemory(...) avoids this entirely.
  • A missing key is an error by default, which fails the whole turn. When writing templates, add ? by default, unless the key genuinely must exist.

You can also pre-render yourself (a route separate from InstructionProvider):

// util/instructionutil
text, err := instructionutil.InjectSessionState(ctx, "user {user:lang}, topic {topic?}")

Note that the public function takes an agent.ReadonlyContext — a read-only context suffices, you do not need the full InvocationContext.

llmagent.Config has four matching entry points: Instruction / InstructionProvider / GlobalInstruction / GlobalInstructionProvider. A Provider takes an agent.ReadonlyContext and returns (string, error), is re-evaluated every turn, and takes over when both are set; Global* is supplied by the root agent and applies to all sub-agents.

⚠️ One line in the source comment bites people often: InstructionProvider performs no {} substitution, treating those as ordinary characters. That means the moment you move a template from Instruction to InstructionProvider, every {user:lang} appears literally in the prompt. If you need templating, call InjectSessionState above yourself. Conversely, if your instruction contains braces to begin with — a JSON example, say — then Provider is the correct choice (Instruction would try to parse them; illegal names survive verbatim, but legal-looking names get substituted by accident).

Three session services, plus a conformance suite#

// 1) in-memory: a function in the session package, there is no session/inmemory sub-package
svc := session.InMemoryService()

// 2) a relational database (GORM)
svc, err := database.NewSessionService(dialector, opts...)        // opens its own connection
svc, err := database.NewSessionServiceFromDB(existingGormDB)      // reuse a connection (new in v2.4.0)
err = database.AutoMigrate(svc)                                   // migrate the four tables

// 3) the Vertex AI session library
svc, err := vertexai.NewSessionService(ctx, vertexai.VertexAIServiceConfig{
	ProjectID: "p", Location: "us-central1", ReasoningEngine: "re-id",
})

Two traps:

  • AutoMigrate works by type-asserting to the private implementation *databaseService; pass any other session.Service and you get invalid session service type. So the order must be “New first, then AutoMigrate”, and do not treat AutoMigrate as a general capability — it is specific to the database backend.
  • In the Vertex variant, event IDs are assigned by the server and are not written back to the caller’s object. The interface comment names this exception explicitly: “session/vertexai is one, and it does not assign in place”. Code that reads event.ID immediately after AppendEvent will get an empty string when the backend changes.

Implementing session.Service yourself? Run the suite first:

// session/sessiontestsuite
func RunServiceTests(t *testing.T, opts SuiteOptions, setup func(t *testing.T) session.Service)
func Snapshot(s session.Session) ExpectedSession

func TestMySessionService(t *testing.T) {
	sessiontestsuite.RunServiceTests(t, sessiontestsuite.SuiteOptions{}, func(t *testing.T) session.Service {
		return newMyService(t)
	})
}

The interface comment is blunt that these two obligations are checked by that suite, “so an implementation that misses either goes red there rather than failing quietly in production”. The obligations are:

  1. An event without an ID must be given one (events built by agents and tools via struct literals bypass NewEvent, and without an ID they cannot be referenced by ID);
  2. EventActions.Compaction must round-trip unchanged — a compaction summary event has a nil LLMResponse.Content and no state or artifact delta, so a backend that decides “should I store this” by content will silently drop it, and the consequence is “that stretch of history was neither summarised nor kept, so it gets summarised again after paying for it, every single turn”.

A third convention: wrap the sentinel error when something is not found, with the form given in the comment — fmt.Errorf("%w: …: %w", session.ErrNotFound, err) — and test with errors.Is(err, session.ErrNotFound) rather than comparing strings.

Get also has two bounding fields that long sessions must use:

resp, err := svc.Get(ctx, &session.GetRequest{
	AppName: "my-app", UserID: "u1", SessionID: "s1",
	NumRecentEvents: 40,          // take only the last 40 events
	After:           time.Now().Add(-24 * time.Hour),
})

Artifact and Memory: where the boundaries lie#

Artifact (artifact.Service): Save/Load/Delete/List/Versions/GetArtifactVersion, addressed by AppName + UserID + SessionID + FileName, carrying a Version int64.

resp, err := artifactSvc.Save(ctx, &artifact.SaveRequest{
	AppName: "my-app", UserID: "u1", SessionID: "s1",
	FileName: "chart.png",
	// the binary field on genai.Part is InlineData *genai.Blob, and MIMEType lives on the Blob
	Part: &genai.Part{InlineData: &genai.Blob{Data: pngBytes, MIMEType: "image/png"}},
})
// reading back: LoadResponse.Part is a *genai.Part; for text artifacts just use .Part.Text
  • Every request carries a Validate(), and file names go through validateFileName (blocking path traversal) — do not skip this in your own implementation;
  • after a write, the framework maintains Actions.ArtifactDelta[fileName] = version on the event, which is the audit trail for “which event produced which version”;
  • on the model side there is a load_artifacts tool (tool/loadartifactstool, name "load_artifacts", description "Loads the artifacts and adds them to the session.");
  • backends: artifact.InMemoryService() and artifact/gcsartifact (GCS).

Memory (memory.Service) has exactly two methods:

type Service interface {
	AddSessionToMemory(ctx context.Context, s session.Session) error
	SearchMemory(ctx context.Context, req *memory.SearchRequest) (*memory.SearchResponse, error)
}
// SearchRequest{Query, UserID, AppName} → SearchResponse{Memories []Entry}

Remember the semantic difference: a session is “everything that happened in this conversation”, memory is “a retrievable summary across sessions”, and memory is write-only-by-session (you can only feed a whole session in, not insert individual entries). Two ready-made tools:

ToolBehaviourFits
load_memory (tool/loadmemorytool)packages itself as a tool so the model searches by query, and appends usage instructionslarge memory, sparse relevance
preload_memory (tool/preloadmemorytool)before every request, searches with the current user input and injects hits straight into the instructionsmall memory, almost always relevant

Both implement toolinternal.RequestProcessor (ProcessRequest) and neither is long-running (IsLongRunning() returns false), but their mechanisms are completely different:

  • load_memory uses toolutils.PackTool to attach the tool itself to the request, then appends a usage note — the model decides when to query and what for;
  • preload_memory attaches no tool: it takes ctx.UserContent().Parts[0].Text as the query and calls ctx.SearchMemory, appending the retrieved text to the instruction on a hit. The source has three early returns: empty user content / no parts / first part has no text → skip; no search results → skip.

⚠️ Which means preload_memory looks only at the first text Part of this turn’s user input: if the user sent an image, or a meaningless greeting first, no memory is injected that turn. Do not attach both at once, which would put the same memory into the prompt twice.

In tests, wire everything in one line:

r, err := runner.NewInMemory("my-app", rootAgent)   // session/artifact/memory all in memory

Summary and self-check list#

  • key names are legal identifiers (otherwise {} is not substituted); when prefixed, only app:/user:/temp: are used
  • every optional key in a template carries ?
  • intermediate variables use temp:, so the persistent history stays clean
  • a custom session.Service has passed sessiontestsuite.RunServiceTests
  • Get is bounded with NumRecentEvents/After, so long sessions are not pulled in full
  • when switching backends, confirmed whether event IDs are written back in place (vertexai does not)

Frequently Asked Questions

How many state scopes does ADK Go 2.x have?

The prefix decides: a bare key is session scope; app: is application scope (across all users); user: is user scope (across sessions within the app); temp: lives only for the current invocation and is discarded afterwards. The constants are session.KeyPrefixApp/KeyPrefixUser/KeyPrefixTemp.

When does a state change made in a tool actually reach storage?

You write it into the event's Actions.StateDelta, and SessionService.AppendEvent merges it into the session; keys prefixed temp: are stripped inside AppendEvent and never persisted.

How do I reference state inside an Instruction?

{key}, scoped as {user:key}, optional as {key?}, and {artifact.filename}. Illegal names are kept verbatim; a missing key is an error by default, and only the ? form renders as an empty string.

What should I know when implementing session.Service myself?

Two hard obligations checked by the conformance suite: events without an ID must be assigned one, and EventActions.Compaction must round-trip unchanged. Also wrap session.ErrNotFound when something is missing.

For a very long session, does Get pull everything?

It does, unless you bound it: GetRequest has NumRecentEvents and After time.Time, so you can take only the last N events or everything after a point in time.

How do I split state versus artifacts?

Small structured decision values go in state; large binary or text blobs (images, PDFs, generated files) go in artifacts, addressed by AppName/UserID/SessionID/FileName with versioning. The {artifact.x} template placeholder loads it automatically and takes Part.Text.
