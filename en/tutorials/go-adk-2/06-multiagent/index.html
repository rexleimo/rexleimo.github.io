The new behaviour of the workflowagents trio on top of the graph engine, plus llmagent’s chat/task/single_turn collaboration modes and structured input/output

Module 6: New Multi-Agent Patterns

Multi-agent in 1.x meant “a tree plus transfer”; 2.x splits it into two orthogonal lines: structure goes to the graph (module 5), interaction goes to the mode (Mode).

Fact boundaries

  • The package paths agent/workflowagents/{sequentialagent,parallelagent,loopagent} already existed in v1.7.0, and v2.4.0 still does not route them through the graph engine — in the source they are three plain loops (Sequential/Loop are for subAgent := range ctx.Agent().SubAgents(), Parallel is errgroup plus rebuilding the child ctx). So do not assume they gained routing, fan-in barriers, HITL resume, or retries; if you need those, wrap them yourself as workflow.NewAgentNode(seq, cfg).

  • Each of the three has a Config with only AgentConfig agent.Config (LoopAgent adds MaxIterations uint), and AgentConfig.Run != nil errors outright.

  • Only Sequential implements RunLive (Parallel/Loop do not).

  • Loop exits when MaxIterations is exhausted or any child event sets Actions.Escalate; 0 = unlimited.

  • Parallel automatically assigns children a branch (<parent>.<child>) → siblings are mutually invisible by default; early stop cancels but waits for teardown to finish.

  • llmagent.Config.Mode is 2.x’s interaction switch. It is defined in internal/llminternal, aliased as type Mode = llminternal.Mode:

    ModeUnset      = llminternal.ModeUnset       // not explicitly set
ModeChat       Mode = "chat"                 // reachable via transfer_to_agent
ModeTask       Mode = "task"                 // clarifies with the human over several turns
ModeSingleTurn Mode = "single_turn"          // never asks the human, returns the result when done

  • The official collaboration sample contrasts the three modes: the root coordinator uses chat; a single_turn sub-agent does not converse with the user and automatically returns its result; a task sub-agent may ask clarifying questions and automatically hands back a structured result.

  • InputSchema / OutputSchema (*genai.Schema) are used together with ModeTask. The official testdata contains TestDelegation_07_ChatToTaskValidationRetry (retry after schema validation failure), TestDelegation_06_ChatToTaskHITLResume (pausing for a human inside a task sub-agent) and TestDelegation_09_ChatPeerTransferAcrossSiblings (transfer between peers) — those three cases are effectively this module’s table of contents.

  • DisallowTransferToParent controls whether transfer upward to the parent is allowed; SubAgents []agent.Agent attaches sub-agents.
