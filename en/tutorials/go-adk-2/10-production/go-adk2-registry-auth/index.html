Agent Registry and inbound authentication: the allow-all Noop defaults, and the risk of treating one header as an identity

The registry and authentication layers of ADK Go v2.4.0: the agentregistry client (ADC plus mTLS endpoint selection, quota project precedence, the All* iterators, the RemoteAgent/MCPToolset factories and the cleanName identifier rules); the four inbound authn implementations (Noop/Header/IAP/Custom) and the 401 versus 500 split; the CanActAsUser semantics of authz with its Noop/Strict pair; which routes are Public; which controllers never reach an authorizer at all; and the outbound auth package with ConsentRequiredError and its logging prohibitions.

September 26, 2026 · 15 min · 3133 words · Mengshou Programming -  |  中文

Verified against: google.golang.org/adk/v2 v2.4.0, sources agentregistry/{registry,client,factory,resolve,types}.go, server/authn/{authn,noop,header,iap,custom}.go, server/authz/{authz,noop,strict}.go, server/adkrest/{handler.go,internal/routers/routers.go}, auth/{credential,providers,transport}.go.

This opens the production chapter: it attaches identity and a governed capability catalogue to the deployment shapes from module 8 .

1. The conclusion first: adkrest ships unprotected#

The opening lines of adkrest.New:

authorizer := cfg.Authorizer
if authorizer == nil {
	authorizer = authz.NewNoop()
}
// …
authenticator := cfg.Authenticator
if authenticator == nil {
	authenticator = authn.NewNoop()
}

The ServerConfig comments spell the consequences out (read them sentence by sentence):

// When nil it defaults to [authn.Noop], which authenticates every request as
// an empty caller's identity — leaving every endpoint reachable without credentials.
// Setting an Authenticator without also setting an Authorizer authenticates
// callers but lets any authenticated caller act as any user; pair it with an
// Authorizer to restrict that.

// When nil it defaults to [authz.Noop], which permits any identity to act as
// any user. Use [authz.NewStrict] to require the authenticated UserID to match
// the path — but only alongside an Authenticator that sets a non-empty
// UserID, since [authn.Noop]'s empty caller's identity would then be denied for every
// user.

The four-quadrant quick table (the thing most worth remembering from this article):

AuthenticatorAuthorizerActual effect
nil (Noop)nil (Noop)every non-Public endpoint reachable without credentials, and any caller can read or write any userID’s sessions
real providernil (Noop)the identity is authenticated, but it has no relation to the path userID → a logged-in caller can impersonate anyone
nil (Noop)authz.NewStrict()every request is denied (an empty identity cannot equal any userID) — looks “safer”, actually takes the service down
real providerauthz.NewStrict()✅ the only correct combination (or substitute your own Authorizer)

2. Which routes need no authentication#

SetupSubRouters decides per route whether to attach the authn middleware:

var authMiddleware func(http.Handler) http.Handler
if authenticator != nil {
	authMiddleware = authn.Middleware(authenticator)
}
for _, api := range subrouters {
	for _, route := range api.Routes() {
		var handler http.Handler = route.HandlerFunc
		if authMiddleware != nil && !route.Public {
			handler = authMiddleware(handler)
		}
		router.Methods(withHead(route.Methods)...).Path(route.Pattern).Name(route.Name).Handler(handler)
	}
}

Three points:

  1. Routes with route.Public true bypass authn entirely. In v2.4.0 only /version carries Public: true (routers/version.go).

  2. /health is even more special — it is registered directly on the root router inside adkrest.New, not in the subrouters loop at all:

    router.HandleFunc("/health", healthHandler).Methods(http.MethodGet, http.MethodHead)

    So the health check is unauthenticated by nature (correct for probes), but that also means your Authenticator policy has no effect on it.

  3. withHead(route.Methods) — the “GET automatically gains HEAD” behaviour from module 7 section 9.4 happens on this line, which also means HEAD requests pass through the authn middleware too.

Which controllers never reach an authorizer#

The call sites of CanActAsUser (a full grep):

ControllerAuthorizer?Where the userID comes from

debug.go✅sessionID.UserID

Conclusion: /apps/{app_name} and the agent graph are visible to every “authenticated” caller (an Authorizer only answers “may you act as this userID”, and these have no userID). Inside them sit your agent names, hierarchy and descriptions (module 6, article 2: an agent name is a model-visible tool contract).

If agent names or descriptions are themselves sensitive (internal product codenames, unreleased features), these two endpoints need another gate at the gateway — or skip the web/api surface altogether and use only A2A / triggers.

3. The four authn providers and the 401/500 split#

type Caller struct {
	UserID string            // the stable identity
	Claims map[string]any    // provider-specific attributes (email, roles, token scopes…), may be nil
}
type Authenticator interface {
	Authenticate(r *http.Request) (*Caller, error)
}

The four providers#

ConstructorSemanticsFits
authn.NewNoop()always returns an empty Callershould only ever appear in development
authn.NewHeader(name)reads UserID from a single request header. The implementation rejects two cases: the header missing, and the same header appearing with multiple values (defence against header splitting and duplication). Comment: “This is not HTTP Basic authentication; it trusts a header set by a trusted upstream (a proxy or gateway), so only use it when clients cannot set that header themselves.”behind a gateway / IAP
authn.NewIdentityAwareProxy()reads X-Goog-Authenticated-User-Email / -Id written by GCP IAP (UserEMailHeader, UserIDHeader); the comment names the setting: “for instance for Cloud Run-based deployment”Cloud Run + IAP
authn.NewCustom(AuthenticatorFunc)you write func(r *http.Request) (*Caller, error)OIDC, in-house tokens, mTLS SAN…

Error classification: 401 for credential problems only, everything else 500#

// ErrUnauthenticated reports that a request carried no valid credentials. An
// [Authenticator] returns it, or an error wrapping it, to make [Middleware]
// answer 401 Unauthorized. Any other error is treated as an internal provider
// failure and answered 500.
func writeAuthError(w http.ResponseWriter, err error) {
	if !errors.Is(err, ErrUnauthenticated) {
		// A provider-internal failure (for example an unreachable token
		// issuer), not a credential problem. Keep the detail out of the
		// response; a provider is expected to log its own errors.
		http.Error(w, "authentication failed", http.StatusInternalServerError)
		return
	}
	http.Error(w, "unauthorized", http.StatusUnauthorized)
}

Three implementation requirements:

  1. To get a 401 you must return ErrUnauthenticated, directly or wrapped — the test is errors.Is, so fmt.Errorf("...: %w", authn.ErrUnauthenticated) works.

  2. The 500 body is a fixed string, "authentication failed", with none of the error content. The comment gives the reason: “Keep the detail out of the response; a provider is expected to log its own errors.” → your custom provider must log its own errors, otherwise production shows nothing but a 500 with no clue.

  3. One more branch that is easy to miss:

    if id == nil {
    // A provider that reports neither caller's identity nor error is
    // treated as a decline rather than silently letting the
    // request through unauthenticated.
    writeAuthError(w, ErrUnauthenticated)
    return
}

    (nil, nil) counts as a refusal (401), not as admission. When writing a custom provider, short-circuiting means returning a real identity.

Middleware(nil) is safe pass-through#

// A nil a yields pass-through middleware, so a caller can wire Middleware
// unconditionally.

So you may write authn.Middleware(myAuth) unconditionally, without a nil check.

4. authz: one question only — may you act as this userID#

// Authorizer provides information whether the [Caller] can act as a userID
// It is used in ADK REST API (adkrest), which has the userID in paths.
type Authorizer interface {
	// CanActAsUser returns nil iff the [Caller] from the ctx can act as a userID. Otherwise returns an error
	// WARNING: avoid returning PII data in the error, it will be send back to the client.
	CanActAsUser(ctx context.Context, userID string) error
}

Two lines of comment, each worth a veto-level reading:

  1. The interface granularity is CanActAsUser alone — there is no “may I list sessions” or “may I delete this artifact”. v2.4.0’s authorisation model is user-scoped (the {user_id} path segment); resource-level granularity is yours to implement, either reading the path from ctx inside your own Authorizer or gating outside the controllers.

  2. ⚠️ The error text goes back to the client verbatim (WriteHTTPStatusForAuthError concatenates err.Error() into the 403 body):

    func WriteHTTPStatusForAuthError(rw http.ResponseWriter, err error) {
 errMsg := "forbidden"
 if err != nil {
 	errMsg = errMsg + ": " + err.Error()
 }
 http.Error(rw, errMsg, http.StatusForbidden)
}

    → Never put user records, employee names, internal IDs or database details into an authz error. This is the other face of the same principle as the authn 500 above, which deliberately leaks nothing.

The status-code choice is deliberate too:

// Forbidden, not Unauthorized (401): the
// caller is authenticated but not permitted to act as the requested user.

401 = identity unknown, 403 = identity known but overstepping. A frontend uses exactly that to decide between “go log in” and “you lack permission”.

The two-state implementations#

func NewNoop() Authorizer    // allows any [authn.Caller] to act as any userID
func NewStrict() Authorizer  // ensures exact match between the authenticated user and the user from the payload

NewStrict means “the path userID must equal Caller.UserID”. Enough for the common single-tenant or internal-tool case; with a role model, implement Authorizer yourself (say admins may act as any user).

5. The complete wiring#

import (
	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/universal"
	"google.golang.org/adk/v2/cmd/launcher/web"
	"google.golang.org/adk/v2/cmd/launcher/web/api"
	webui "google.golang.org/adk/v2/cmd/launcher/web/webui"
	"google.golang.org/adk/v2/server/authn"
	"google.golang.org/adk/v2/server/authz"
)

l := universal.NewLauncher(
	web.NewLauncher(api.NewLauncher(), webui.NewLauncher()),
)
err := l.Execute(ctx, &launcher.Config{
	SessionService:  sessSvc,
	AgentLoader:     agent.NewSingleLoader(root),
	Authenticator:   authn.NewIdentityAwareProxy(),   // Cloud Run + IAP
	Authorizer:      authz.NewStrict(),
}, os.Args[1:])

launcher.Config is the injection point for authn/authz (its field table was listed in module 8, article 2 , where Authenticator / Authorizer appear). The adkapi sub-launcher passes both straight into adkrest.ServerConfig:

// cmd/launcher/web/api/api.go
		Authenticator:   config.Authenticator,
		Authorizer:      config.Authorizer,

⚠️ Mind the coverage: this injection path belongs to adkapi (adkrest). Module 9’s A2A surface takes another route — its authentication must be configured through launcher.Config.A2AOptions ([]a2asrv.RequestHandlerOption), and only then does callCtx.User.Name in toInvocationMeta override the default A2A_USER_<ContextID> (module 9 article 1, section 5.5). The two surfaces authenticate by different mechanisms; do not assume configuring one covers both. webui and the triggers likewise each mind their own.

6. agentregistry: a governed catalogue of A2A agents and MCP servers#

// Package agentregistry provides a client for the Google Cloud Agent Registry
// (agentregistry.googleapis.com), a governed catalog of A2A agents, MCP
// servers, and model endpoints.

Constructing the client#

type Config struct {
	ProjectID  string      // required
	Location   string      // required, e.g. "us-central1"
	HTTPClient *http.Client // nil = authenticate with ADC and auto-resolve the mTLS endpoint
}
func New(ctx context.Context, cfg Config) (*Client, error)

The first thing New does is a hard check: an empty ProjectID or Location returns an error immediately.

Endpoint and authentication details:

const (
	baseURLProd = "https://agentregistry.googleapis.com/v1"
	baseURLMTLS = "https://agentregistry.mtls.googleapis.com/v1"
)
// …
// Resolve the endpoint and client certificate from one source: the
// transport honors GOOGLE_API_USE_MTLS_ENDPOINT / GOOGLE_API_USE_CLIENT_CERTIFICATE
// and returns the endpoint it dialed, so endpoint and mTLS can't disagree.

“Resolve the endpoint and client certificate from one source” — this avoids inconsistencies like “using an mTLS client certificate against the plain endpoint”. For a supplied client the comment is explicit: “A supplied client manages its own mTLS.”

The quota project precedence (matching adk-python):

// x-goog-user-project quota header, adk-python precedence on the ADC path:
// GOOGLE_CLOUD_QUOTA_PROJECT, then creds' quota_project_id, then ProjectID.
// A caller-supplied client has no ADC creds, so only env var / ProjectID apply.

Three resource kinds × two read styles#

func (c *Client) ListAgents(ctx, opts ...ListOption) (*ListAgentsResponse, error)
func (c *Client) GetAgent(ctx, name string) (*Agent, error)
func (c *Client) AllAgents(ctx, opts ...ListOption) iter.Seq2[*Agent, error]
// MCP servers / endpoints are isomorphic: ListMCPServers / GetMCPServer / AllMCPServers
//                                        ListEndpoints / GetEndpoint / AllEndpoints

All* is iter.Seq2 again (the fourth occurrence in this series), and pagination is handled inside the library:

for agent, err := range client.AllAgents(ctx, agentregistry.WithFilter(`labels.env="prod"`)) {
	if err != nil { return err }
	use(agent)
}

The three ListOptions: WithFilter(string), WithPageSize(int), WithPageToken(string). Response types: ListAgentsResponse / ListMCPServersResponse / ListEndpointsResponse. The error type is APIError (errors.As to get the status code).

Producing runnable objects straight from the catalogue#

func (c *Client) RemoteAgent(ctx context.Context, name string, opts ...RemoteAgentOption) (agent.Agent, error)
func (c *Client) MCPToolset(ctx context.Context, name string, opts ...MCPToolsetOption) (tool.Toolset, error)

This is the registry’s real value: one name in, and you get back an agent.Agent (module 9’s remoteagent) or a tool.Toolset (module 3’s MCP) — endpoint resolution, protocol selection and card fetching all happen inside the library.

There are only four companion options, but they decide the egress behaviour:

func WithA2AHTTPClient(c *http.Client) RemoteAgentOption
func WithA2AHeaders(h map[string]string) RemoteAgentOption
func WithMCPHTTPClient(c *http.Client) MCPToolsetOption
func WithMCPHeaders(h map[string]string) MCPToolsetOption

egressConfig is an unexported type, and c.egressClient(rawURL, ec) derives the egress client from the registry’s own httpClient (comment: “the factory helpers reuse it for egress to *.googleapis.com endpoints (parity with adk-python)”).

⚠️ Passing WithA2AHeaders means writing credentials into the egress request; be careful not to log a token-bearing map (the same prohibition as the auth package, see section 7).

The actual protocol and binding values#

const protocolTypeA2AAgent = "A2A_AGENT"
// Registry protocol-binding wire values.
const (
	bindingJSONRPC  = "JSONRPC"
	bindingHTTPJSON = "HTTP_JSON"
	bindingGRPC     = "GRPC"
)
const cardTypeA2AAgentCard = "A2A_AGENT_CARD"
const defaultA2AProtocolVersion = "0.3.0"

Two points:

  1. The A2A protocol version defaults to 0.3.0 — while module 9 showed the Go server’s own agent card carrying Version: "2.0.0". The registry side and the ADK side use different version vocabularies; during cross-system integration trust supportedInterfaces[].protocolVersion, not the card’s version.
  2. Cards come from two sources: embedded (the A2A_AGENT_CARD type, with Content json.RawMessage carrying it directly) and synthesised (when no card is embedded, one is assembled from endpoint/protocol using connectionURI + transportBinding). The embedded form is the fast path.

cleanName: registry name → Go identifier#

// cleanName converts an arbitrary display name into a valid identifier suitable
// for use as an agent or tool name. It mirrors adk-python's _clean_name:
// non-identifier characters become underscores, runs of underscores collapse,
// leading/trailing underscores are trimmed, and a leading digit is prefixed
// with an underscore.
func cleanName(name string) string {
	s := reNonIdentifier.ReplaceAllString(name, "_")   // [^a-zA-Z0-9_] → _
	s = reUnderscores.ReplaceAllString(s, "_")          // __+ → _
	s = strings.Trim(s, "_")
	if s != "" && s[0] >= '0' && s[0] <= '9' {
		s = "_" + s
	}
	return s
}

Why “it must be a valid identifier” has real consequences in ADK: an agent name is the tool name visible to the model (module 6, article 2: the delegation tool name comes straight from Name()). Therefore:

  • a display name made entirely of non-identifier characters (CJK names, emoji, spaces-only) → collapses to the empty string. Such a name may exist in the registry but cannot serve as an agent name (the factory falls back to another field or errors).
  • 24x7-support → _24x7_support.
  • Two different display names can collapse to the same identifier (a-b versus a_b) → a hidden source of name collisions when registering in bulk.

7. The outbound auth package: ConsentRequiredError must never be logged#

Credentials for tools and MCP live in a different package (google.golang.org/adk/v2/auth) and have nothing to do with inbound authn:

type Credential interface {
	// Apply writes the credential's auth headers onto h.
	Apply(h http.Header) error
}
type CredentialProvider interface { … }   // plus the ProviderFunc adapter

The ready-made providers:

func StaticToken(token string) CredentialProvider
func APIKey(name, value string) CredentialProvider
func TokenSourceProvider(ts oauth2.TokenSource) CredentialProvider
func ADC(scopes ...string) CredentialProvider
func ServiceAccount(cfg ServiceAccountConfig) CredentialProvider
func WithHeaders(inner Credential, headers map[string]string) Credential

Credential types: APIKeyCredential, BearerCredential, BasicCredential, OAuth2Credential; Transport is what mounts a provider into an http.Client.

The crucial part is the ConsentRequiredError comment, reproduced verbatim:

// ConsentRequiredError signals that interactive, 3-legged OAuth consent is needed
// before a credential can be issued. Consumers detect it with errors.As.
type ConsentRequiredError struct {
	// AuthURI is the URL the end user must visit to grant consent.
	//
	// Hand it to that user and to nobody else. It is built by the credentials
	// service, and a 3-legged authorization URI normally carries the acting user
	// in a login_hint parameter, so it is not redacted the way service text in
	// other errors is — the identifier in it is what makes the URL work. Do not
	// log it, do not put it in a span, and do not serialize this error: every
	// field is exported, so a json.Marshal of it publishes the URI whatever
	// Error() says.
	AuthURI string
	// Nonce is an opaque value echoed back to correlate the consent response.
	// Sensitive on the same terms as AuthURI, which embeds it.
	Nonce string
	// Key is the credential-store key to resume the flow under.
	Key string
}

Four disciplines (the harshest passage in the official comments):

  1. AuthURI embeds the login_hint (i.e. the acting user’s identity), so it is deliberately not redacted — that identifier is exactly what makes the URL work.
  2. Do not log it, do not put it in a span, and do not json.Marshal this error struct (every field is exported, so serialising it necessarily leaks).
  3. Hand it only to that user.
  4. Detect it with errors.As, not errors.Is.

⚠️ Rule 2, together with section 4’s “keep PII out of authz errors” and section 3’s “the 500 leaks nothing”, forms one engineering principle repeated across three separate code paths in ADK Go v2.4.0: an error message is a public surface. This matters most when building observability (the next article ): a trace exporter carries error messages out of your process.

The correct handling of a ConsentRequiredError is “return the AuthURI to that specific user alone, let them grant consent, then resume the flow under Key” — it is an interaction protocol, not a failure.

8. Pre-flight authentication review#

  • Authenticator and Authorizer configured together (the last row of the quadrant table)
  • before choosing the Header provider, confirm the gateway strips client-supplied headers of the same name (the library already blocks multi-value, but a single spoofed value passes)
  • on Cloud Run prefer NewIdentityAwareProxy() over hand-rolled header parsing
  • custom Authenticators log their own errors (the 500 body is a fixed string, so production has no clue otherwise)
  • custom Authenticators never return (nil, nil) (it is refused as a 401)
  • Authorizer errors contain no PII (they are sent to the client with the 403)
  • aware that /apps/{app} and the agent graph bypass the authorizer, so sensitive agent names need extra shielding
  • A2A surface authentication configured separately through launcher.Config.A2AOptions (it does not inherit adkapi’s)
  • trigger-surface userID comes from the subscription/source (module 8 article 2) and is unaffected by authn
  • ConsentRequiredError.AuthURI / Nonce never reach logs, spans or serialised payloads
  • registry names go through cleanName, with collisions and empty results checked

Frequently Asked Questions

Does adkrest authenticate anything by default?

No. A nil Authenticator becomes authn.NewNoop (every request is authenticated as an empty identity) and a nil Authorizer becomes authz.NewNoop (any identity may act as any user). Both nil means every endpoint except /health and /version is reachable with no credentials. The source comments state this plainly.

Is configuring only the Authenticator enough?

Better than nothing, but still incomplete. The comment says it directly: setting an Authenticator without an Authorizer authenticates callers yet lets any authenticated caller act as any user. The userID sits in the URL path, so the authorizer is that boundary.

What is the risk of using NewHeader?

It trusts a header written by an upstream proxy or gateway; it is not HTTP Basic authentication. The comment requires using it only where clients cannot set that header themselves. If your gateway does not strip a client-supplied header of the same name, anyone naming themselves becomes that user.

When must authz.NewStrict not be used?

When the Authenticator does not provide a non-empty UserID (for example authn.Noop). Strict requires the authenticated identity to equal the path userID exactly, so an empty identity denies every request.

How do I wire up Agent Registry?

agentregistry.New(ctx, agentregistry.Config{ProjectID, Location}) — both fields are required. By default it authenticates with ADC and automatically picks the mTLS endpoint; to pre-authenticate, pass your own HTTPClient (then mTLS is your client's responsibility).

Can a registry agent name be used directly as a Go agent name?

No. Run it through cleanName: non-identifier characters become underscores, runs of underscores collapse, leading and trailing underscores are trimmed, and a leading digit gets an underscore prefix. These rules mirror adk-python's _clean_name.
