Plugins and OpenTelemetry: 14 lifecycle hooks, early-exit semantics, and three fields nobody reads

The cross-cutting layer of ADK Go v2.4.0: the 14 hooks of plugin.Config and their four signature families, the early-exit and duplicate-name registration semantics of PluginManager, the implementation fact that CloseFunc and PluginConfig.CloseTimeout have no caller at all in v2.4.0, the three built-in plugins (loggingplugin with all twelve hooks, retryandreflect which injects failures back into the model, functioncallmodifier which rewrites the model-visible schema), the nine Options of telemetry.New with environment-driven exporters, the five span naming shapes, and the privacy asymmetry where tool arguments are reported unconditionally while conversation content needs an explicit environment variable.

Verified against: google.golang.org/adk/v2 v2.4.0, sources plugin/plugin.go, internal/plugininternal/plugin_manager.go, plugin/{loggingplugin,retryandreflect,functioncallmodifier}/, telemetry/{config.go,telemetry.go,setup_otel.go}, internal/telemetry/{telemetry.go,node_tracing.go,compaction.go,logger.go,genaimessages.go}.

1. plugin.Config: 14 hooks across four phases#

type Config struct {
	Name string

	OnUserMessageCallback OnUserMessageCallback
	OnEventCallback       OnEventCallback

	BeforeRunCallback BeforeRunCallback
	AfterRunCallback  AfterRunCallback

	BeforeAgentCallback agent.BeforeAgentCallback
	AfterAgentCallback  agent.AfterAgentCallback

	BeforeModelCallback  llmagent.BeforeModelCallback
	AfterModelCallback   llmagent.AfterModelCallback
	OnModelErrorCallback llmagent.OnModelErrorCallback

	BeforeToolCallback  llmagent.BeforeToolCallback
	AfterToolCallback   llmagent.AfterToolCallback
	OnToolErrorCallback llmagent.OnToolErrorCallback

	CloseFunc func() error
}

One New(cfg) builds one plugin, returning (*Plugin, error); the only safety net inside New is:

// Ensure closeFunc is never nil so p.Close() doesn't panic
if p.closeFunc == nil { p.closeFunc = func() error { return nil } }

(New currently performs no validation at all — an empty name still succeeds, though an empty name makes the duplicate-name check below dangerous.)

The signature decides the capability#

type OnUserMessageCallback func(agent.InvocationContext, *genai.Content) (*genai.Content, error)
type BeforeRunCallback     func(agent.InvocationContext) (*genai.Content, error)
type AfterRunCallback      func(agent.InvocationContext)
type OnEventCallback       func(agent.InvocationContext, *session.Event) (*session.Event, error)
HookWhat it can changeWhat it can block
OnUserMessageCallbackreplace the user input contentreturning a non-nil content uses it, and later plugins do not run
BeforeRunCallbackfabricate a content out of nothingsame, and the comment’s semantics are “skip the normal processing”
OnEventCallbackreplace the event about to be persisteda non-nil event is used
AfterRunCallbacknothing (no return value)purely an observation point

The agent / model / tool layers reuse the callback types from module 2 and module 3 — a plugin is simply “an agent-level callback lifted to every agent of the whole run”, with exactly the same semantics (e.g. a BeforeAgentCallback returning non-nil content skips that agent).

OnEventCallback is both the strongest and the most dangerous position#

It receives a *session.Event (module 4) and can rewrite Actions, LongRunningToolIDs and CustomMetadata — it edits what actually gets persisted. Module 5 showed Actions.StateDelta is applied by the scheduler before writing the session, and whether OnEventCallback sits upstream or downstream of that depends on where in the event flow it runs: to change state from a plugin, prefer the RunOption WithStateDelta (module 4); use event rewriting only for redaction, labelling and audit, i.e. cases that do not change meaning.

⚠️ Also, module 4 covered that platform compaction events are filtered by IsPlatformEvent() and never reach appendEvent — so OnEventCallback does not see them.

2. The two hard rules of PluginManager#

Rule one: early exit — order is priority#

In internal/plugininternal/plugin_manager.go, every Run* method has the same shape:

for _, plugin := range pm.plugins {
	callback := plugin.BeforeToolCallback()
	if callback != nil {
		newArgs, err := callback(ctx, tool, args)
		if err != nil {
			return nil, err
		}
		if newArgs != nil {
			return newArgs, nil // Early exit
		}
	}
}
return nil, nil

Three consequences:

  1. err != nil terminates the whole chain immediately, and the remaining plugins do not run.
  2. A non-nil return value also terminates immediately — later plugins never see this call at all.
  3. Therefore:
    • an observability plugin (logging, metrics) must always return nil, nil, or it “swallows” the other plugins in the same batch.
    • registration order = priority. To take precedence, register first; to let others look first, register later.
    • Want “several plugins each transform it in turn” chaining? This manager does not support it (BeforeRunCallback cannot see the previous plugin’s output, because a non-nil value returns immediately).

AfterRunCallback is the only non-short-circuiting kind (no return value, all run).

Rule two: names must be unique#

// RegisterPlugin adds a new plugin to the manager.
func (pm *PluginManager) registerPlugin(plugin *plugin.Plugin) error {
	if plugin == nil {
		return fmt.Errorf("cannot register nil plugin")
	}
	for _, p := range pm.plugins {
		if p.Name() == plugin.Name() {
			return fmt.Errorf("plugin with name '%s' already registered", plugin.Name())
		}
	}
	pm.plugins = append(pm.plugins, plugin)
	return nil
}

Built-in plugin names are hard-coded (retryandreflect uses "RetryAndReflectPlugin"). So:

  • registering the same plugin package twice fails outright (runner.New returns an error).
  • Safe naming: prefixed unique names such as mycompany_auth_plugin, metrics_v1.

Rule three (a pitfall, not a rule): the Close path is unwired in v2.4.0#

func (pm *PluginManager) Close() error {
	var errors []error
	for _, plugin := range pm.plugins {
		if err := plugin.Close(); err != nil {
			errors = append(errors, fmt.Errorf("error closing plugin '%s': %w", plugin.Name(), err))
		}
	}
	// …
}

The result of a full grep across v2.4.0:

FactEvidence
PluginManager.Close() has no non-test callera whole-library search finds it only in plugin_manager_test.go
runner.Runner has no Close() methodgrep "func (r \*Runner) Close" returns nothing
CloseTimeout is assigned but never readonly 4 sites in the whole library: runner/runner.go:85 (field declaration), :129 (passed to the manager), plugin_manager.go:34,40,46 (declaration and assignment) — no fifth site reads it

Conclusion: plugin.Config.CloseFunc and runner.PluginConfig.CloseTimeout are both dead configuration in v2.4.0. If your plugin holds a connection pool, file handle or background goroutine, you must manage it yourself:

plugins := []*plugin.Plugin{logging, retry, mine}
r, err := runner.New(runner.Config{
	AppName: appName, Agent: root, SessionService: sessSvc,
	PluginConfig: runner.PluginConfig{Plugins: plugins},   // writing CloseTimeout has no effect
})
// …
// collect it on the process exit path yourself
defer func() {
	for _, p := range plugins {
		if err := p.Close(); err != nil {
			log.Printf("close plugin %s: %v", p.Name(), err)
		}
	}
}()

(Same class of issue as module 8’s -trigger_max_concurrent_runs being inert for Pub/Sub: a configuration field existing ≠ it taking effect.)

3. The three built-in plugins#

loggingplugin: all twelve hooks on#

func New(name string) (*plugin.Plugin, error) {
	if name == "" { name = "logging_plugin" }
	p := &loggingPlugin{name: name}

	return plugin.New(plugin.Config{
		Name: name,
		OnUserMessageCallback: p.onUserMessage,
		BeforeRunCallback:     p.beforeRun,
		OnEventCallback:       p.onEvent,
		AfterRunCallback:      p.afterRun,
		BeforeAgentCallback:   p.beforeAgent,
		AfterAgentCallback:    p.afterAgent,
		BeforeModelCallback:   p.beforeModel,
		AfterModelCallback:    p.afterModel,
		OnModelErrorCallback:  p.onModelError,
		BeforeToolCallback:    p.beforeTool,
		AfterToolCallback:     p.afterTool,
		OnToolErrorCallback:   p.onToolError,
	})
}

Twelve hooks, with a fallback to "logging_plugin" when name is empty (so it allows several instances for routed logging, as long as they get distinct names). It is the reference implementation of an observability plugin — no hook consumes the return value, so it never trips early-exit.

In production it is the first thing to enable: for “the graph does not advance” problems (module 5’s scheduler table), logging at the invoke_node boundary is far faster than reading code.

retryandreflect: injecting tool failures back into the model#

r := &retryAndReflect{
	maxRetries:           3,   // A sensible default
	errorIfRetryExceeded:  false,
	scope:                Invocation,
	scopedFailureCounters: make(map[string]map[string]int),
}
// …
if r.maxRetries < 0 { return nil, fmt.Errorf("maxRetries must be a non-negative integer") }
return plugin.New(plugin.Config{
	Name:                "RetryAndReflectPlugin",
	AfterToolCallback:   r.afterTool,
	OnToolErrorCallback: r.onToolError,
})

Three configuration options:

func WithMaxRetries(maxRetries int) PluginOption
func WithErrorIfRetryExceeded(errorIfRetryExceeded bool) PluginOption
func WithTrackingScope(scope TrackingScope) PluginOption

const (
	Invocation TrackingScope = "invocation"   // counted per invocation
	Global     TrackingScope = "global"       // counted globally, across turns and users
)

It mounts only AfterTool + OnToolError, and the mechanism is rendering the failure into text fed back to the model (reflection.md):

The call to tool `{{.ToolName}}` failed.

**Error Details:**
{{.ErrorDetails}}

**Tool Arguments Used:**
{{.ArgsSummary}}

Three judgements:

  1. The Global scope is a counter shared across users. Enabling Global in a multi-tenant service means one tenant failing furiously exhausts the retry budget of that tool for every tenant (the response type constant is reflectAndRetryResponseType = "ERROR_HANDLED_BY_REFLECT_AND_RETRY_PLUGIN"). The default Invocation is the safe one.
  2. It guards the counters with a sync.Mutex — which shows a plugin instance shares state across concurrent sessions (module 6 article 1: “one instance serving many sessions”); the same applies to plugins you write.
  3. maxRetries=0 is legal (only <0 errors), which semantically means “no retries but keep rewriting the error”. To disable it entirely, do not register the plugin.

functioncallmodifier: editing the tool contract the model sees#

type FunctionCallModifierConfig struct {
	Predicate           func(toolName string) bool
	Args                map[string]*genai.Schema
	OverrideDescription func(originalDescription string) string
}

Match by tool name, then replace the argument schema and the description. The uses are concrete:

  • the model keeps sending a wrong enum value to some tool → tighten the schema;
  • a tool name is too long or too jargon-y → rewrite the description so the model picks it more reliably;
  • ⚠️ it is directly related to the delegation tool names of module 6 article 2: a delegation tool name is the sub-agent’s Name(), so this plugin can change the model-visible toolset — but it does not change routing in your code.

It is “the second place to tune model behaviour after prompt engineering”, and the price is that the declaration can drift from the actual implementation (schema changed, tool did not), so keep the Predicate narrow.

The nine Options:

func WithOtelToCloud(value bool) Option            // switch: whether to export to GCP
func WithGcpResourceProject(project string) Option

launcher.Config.TelemetryOptions is item 9 of the field table in module 8, article 2 , and otelToCloud comes from each sub-launcher’s command-line switch.

Three links in order: an explicit WithGcpResourceProject → the ADC project → GOOGLE_CLOUD_PROJECT (implemented as strings.TrimSpace(os.Getenv(...))). Resource attributes additionally follow standard OTel environment variables:

5. Exporters are decided by environment variables — by default nothing is exported#

The real logic of configureExporters (structure copied as-is):

otelEndpointEnv       := strings.TrimSpace(os.Getenv("OTEL_EXPORTER_OTLP_ENDPOINT"))
otelTracesEndpointEnv := strings.TrimSpace(os.Getenv("OTEL_EXPORTER_OTLP_TRACES_ENDPOINT"))
if otelEndpointEnv != "" || otelTracesEndpointEnv != "" {
	exporter, err := otlptracehttp.New(ctx)
	spanProcessors = append(spanProcessors, sdktrace.NewBatchSpanProcessor(exporter))
}
if cfg.oTelToCloud {
	spanExporter, err := newGcpSpanExporter(ctx, cfg)
	spanProcessors = append(spanProcessors, sdktrace.NewBatchSpanProcessor(spanExporter))
}
otelLogsEndpointEnv := strings.TrimSpace(os.Getenv("OTEL_EXPORTER_OTLP_LOGS_ENDPOINT"))
if otelEndpointEnv != "" || otelLogsEndpointEnv != "" {
	exporter, err := otlploghttp.New(ctx)
	logProcessors = append(logProcessors, sdklog.NewBatchProcessor(exporter))
}
// Golang OTel exporter to CloudLogging is not yet available.

Four rows:

TargetTrigger
OTLP tracesOTEL_EXPORTER_OTLP_ENDPOINT or OTEL_EXPORTER_OTLP_TRACES_ENDPOINT non-empty
GCP tracesoTelToCloud == true (WithOtelToCloud or a sub-launcher switch)
OTLP logsOTEL_EXPORTER_OTLP_ENDPOINT or OTEL_EXPORTER_OTLP_LOGS_ENDPOINT non-empty
GCP logs❌ not implemented (comment: “not yet available”)

Two knock-on effects:

  1. initTracerProvider returns nil when there is no span processor at all (if len(cfg.spanProcessors) == 0 { return nil }) → no environment variable means no TracerProvider, and SetGlobalOtelProviders becomes a no-op.
  2. ⚠️ OTEL_EXPORTER_OTLP_ENDPOINT is a blanket switch — setting it turns on OTLP export for both traces and logs. To export only traces, use the more specific ..._TRACES_ENDPOINT.

6. Span naming and semantic conventions#

The five span kinds created by internal/telemetry:

Span nameAttribute source
invoke_agent <name>gen_ai.agent.name, gen_ai.agent.description, gen_ai.conversation.id, gcp.vertex.agent.invocation_id
invoke_workflow <name>gen_ai.workflow.name, gen_ai.conversation.id
invoke_node <name>gen_ai.node.name, gen_ai.conversation.id
generate_content <model>gen_ai.request.model, gcp.vertex.agent.invocation_id
execute_tool <name>gen_ai.tool.name, gcp.vertex.agent.tool_call_args.args_name

Plus one for compaction (module 4):

tracer.Start(ctx, fmt.Sprintf("%s %s", compactEventsName, params.Trigger), …)

invoke_workflow / invoke_node are specific to the v2 graph engine — module 5’s troubleshooting table of “why was a node SKIPped or RETRIEDed” shows up in a trace as a missing or failing invoke_node. These three span levels locate a stuck node at a glance.

One attribute also hides a migration note worth knowing:

gcpVertexAgentInvocationID.String(ictx.InvocationID()), // used by adk-web
// … original comment: Used by adk-web, can be removed once it reads the invocation id from invoke_agent span.

The Chat UI’s “which invocation does this reply belong to” currently rides on this private attribute (module 7 section 9), so do not drop gcp.vertex.agent.* attributes in a custom exporter.

The privacy asymmetry: tool arguments unconditional, conversation content opt-in#

// Request is the request about to be sent to the model. It is used only
// to record the opt-in gen_ai.input.messages and
// gen_ai.system_instructions attributes, and may be nil.

semconv.GenAIConversationID(sessionID(ictx)),   // session id: unconditional
gcpVertexAgentToolCallArgsName.String(safeSerialize(params.Args))  // tool arguments: unconditional
const captureMessageContentEnvVar = "OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT"
DataReported by default?
model name, agent name, tool name, node name, invocation id, conversation id (= sessionID)✅ unconditionally
tool call arguments (safeSerialize(args))✅ unconditionally
conversation content gen_ai.input.messages, system instructions gen_ai.system_instructions❌ requires OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT

The content attributes also have a timing subtlety (comment verbatim):

// After the sampling decision, not before: converting a whole conversation
// costs milliseconds, and on a span the sampler drops it buys nothing. …
// Still before the model call, so the prompt is on the span even when the call
// fails and no response is ever traced.

Content attributes are written after the sampling decision and before the model call — skipping serialisation for spans that get dropped, while still guaranteeing “a failed call leaves the prompt behind”.

⚠️ Tool arguments get no such protection: pass an ID number, an address or a token as a tool argument (a common shape in module 3) and it lands in the trace. This is the same issue as the ConsentRequiredError prohibition above: a trace exporter is a data egress channel (see article 1 , section 7).

Production advice: add a BeforeToolCallback plugin that redacts for sensitive tools (returning the replaced args — note that early-exit means your plugin monopolises the chance to change args), or drop argument attributes in the exporter using a gen_ai.tool.name allow-list.

7. A minimal production wiring#

import (
	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/plugin"
	"google.golang.org/adk/v2/plugin/loggingplugin"
	"google.golang.org/adk/v2/plugin/retryandreflect"
	"google.golang.org/adk/v2/runner"
	"google.golang.org/adk/v2/telemetry"
)

// 1) telemetry must be established before the runner, and registered as global providers
providers, err := telemetry.New(ctx,
	telemetry.WithGcpQuotaProject(quotaProject),
	telemetry.WithOtelToCloud(false), // for now go only to our own OTLP collector
)
if err != nil { log.Fatal(err) }
providers.SetGlobalOtelProviders()

// 2) plugins: names must be unique; register observers first
logP := loggingplugin.MustNew("audit")                 // an empty name falls back to logging_plugin
retryP, err := retryandreflect.New(
	retryandreflect.WithMaxRetries(2),
	retryandreflect.WithTrackingScope(retryandreflect.Invocation), // not Global
)
if err != nil { log.Fatal(err) }
defer func() { // the framework will not call it, so do it yourself
	for _, p := range []*plugin.Plugin{logP, retryP} {
		if cerr := p.Close(); cerr != nil {
			log.Printf("close plugin %s: %v", p.Name(), cerr)
		}
	}
}()

r, err := runner.New(runner.Config{
	AppName: appName, Agent: root, SessionService: sessSvc,
	PluginConfig: runner.PluginConfig{Plugins: []*plugin.Plugin{logP, retryP}},
})
if err != nil { log.Fatal(err) }
defer func() { _ = r.Close() }()   // only closes its own resources such as artifactService (modules 3/4)
_ = agent.Name

Environment variables (in a container, give the full set — do not pass only OTEL_EXPORTER_OTLP_ENDPOINT):

export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://otel-collector:4318
export OTEL_SERVICE_NAME=my-agent
export OTEL_RESOURCE_ATTRIBUTES="deployment.environment=prod"
# only once you have confirmed this data may leave the perimeter
# export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true

8. Pre-flight observability review#

  • every plugin has a unique non-empty name (a duplicate fails the whole runner.New)
  • observer plugins always return nil, nil, so they do not swallow the plugins behind them
  • you know that plugin order is priority, and pre-empting plugins are registered first
  • call Plugin.Close() yourself (the framework will not), and do not count on CloseTimeout
  • retryandreflect uses the Invocation scope (Global leaks across tenants)
  • you know maxRetries=0 still rewrites the error
  • set OTEL_EXPORTER_OTLP_TRACES_ENDPOINT rather than the generic one, unless you truly want logs exported too
  • for GCP traces, explicitly enable WithOtelToCloud(true); GCP logs are unavailable — do not configure one and assume it works
  • keep gcp.vertex.agent.invocation_id (the Chat UI depends on it)
  • sensitive tool arguments are redacted (they are an unconditional export)
  • ..._CAPTURE_MESSAGE_CONTENT is off, or its compliance was confirmed before enabling

Frequently Asked Questions

Do all plugin hooks run?

No. Every Run* method of PluginManager is an early-exit loop: as soon as one plugin returns a non-nil result, it returns and the remaining plugins never run. So registration order is priority, and an observability plugin must make sure it always returns nil.

Can two plugins share a name?

No. registerPlugin returns a plugin with name '%s' already registered error on a duplicate, which fails the whole runner.New. Built-in names are fixed (for instance RetryAndReflectPlugin), so choose yours carefully.

Is a plugin's CloseFunc ever called?

In v2.4.0 no non-test path calls PluginManager.Close(), and Runner has no Close method, so CloseFunc never runs automatically; runner.PluginConfig.CloseTimeout is assigned but never read. Hold your own plugin slice and call Close() on process exit.

Where does OTel data go by default?

Nowhere. An OTLP exporter is only built when OTEL_EXPORTER_OTLP_ENDPOINT or the corresponding *_TRACES_ENDPOINT / *_LOGS_ENDPOINT is set, and the GCP span exporter additionally needs oTelToCloud=true. The GCP log exporter is marked as not yet available in the official comment.

Will traces contain conversation content?

Two cases. The generate_content span's gen_ai.input.messages and gen_ai.system_instructions are opt-in via OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT, but execute_tool serialises tool arguments unconditionally.

Is there a ready-made plugin that retries tool errors back into the model?

Yes, plugin/retryandreflect. Defaults are maxRetries=3, scope=Invocation, errorIfRetryExceeded=false. It renders the failing tool name, error detail and the arguments used into text and feeds it back so the model can adjust and retry.
