Installing and Verifying ADK Go 2.x: go get /v2, the adkgo CLI, and your first working agent

Install ADK Go v2.4.0 from scratch: the Go 1.27.1 toolchain, go get google.golang.org/adk/v2, credential setup (Gemini API key / Vertex ADC), the adkgo deployment CLI versus how the launcher actually runs your agent, with a full verification checklist and a failure triage table.

September 26, 2026 · 6 min · 1226 words · Mengshou Programming -  |  中文

Verified against: google.golang.org/adk/v2 v2.4.0 · Go 1.27.1 (floor 1.26.6) · 2026-09-26

This article does one job: install the environment correctly, and leave you able to prove you did. Where every version number comes from is argued in module 0, article 3 and is not repeated here.

Step 0: confirm the toolchain#

go version
# go version go1.27.1 darwin/arm64   ← needs to be >= 1.26.6

go env GOTOOLCHAIN GOPROXY

If you are below 1.26.6, fix that first — otherwise the next step hits a wall immediately:

go: google.golang.org/adk/v2@v2.4.0 requires go >= 1.26.6 (running go 1.25.6; GOTOOLCHAIN=local)

Step 1: create the module and pull the dependency#

mkdir myagent && cd myagent
go mod init myagent
go get go@1.27.1                              # raise the go directive; see the trap below
go get google.golang.org/adk/v2@v2.4.0        # the real dependency, version pinned

There is a trap here you are guaranteed to hit: since Go 1.26, go mod init deliberately writes the go directive as “current toolchain minor minus one”, so you end up with go 1.26.0 — below the 1.26.6 ADK requires. So the go get go@1.27.1 line is not optional.

The expected go.mod:

module myagent

go 1.27.1

require (
	google.golang.org/adk/v2 v2.4.0
	google.golang.org/genai v1.x.x   // resolved by go get
)

Prove the version yourself (do not go looking for adkgo version; it does not exist):

go list -m google.golang.org/adk/v2                     # google.golang.org/adk/v2 v2.4.0
go list -m -f '{{.Path}} {{.Version}} needs go {{.GoVersion}}' google.golang.org/adk/v2

Step 2: credentials#

Two routes, pick one.

Route A: a Gemini API key (fastest)

export GOOGLE_API_KEY="your-key"

Route B: Vertex AI (enterprise / compliance)

gcloud auth application-default login
export GOOGLE_GENAI_USE_VERTEXAI=true
export GOOGLE_CLOUD_PROJECT="your-project"
export GOOGLE_CLOUD_LOCATION="your-region"     # e.g. us-central1

Both sets of variable names are taken verbatim from the official examples/workflow/README.md (v2.4.0 text), not invented by me.

About .env#

The official ADK Go samples use os.Getenv throughout; there is no built-in .env loader. If you want the .env experience, choose one of these:

// Option 1: load explicitly (preferred, behaviour is visible)
import "github.com/joho/godotenv"

func main() {
	if err := godotenv.Load(); err != nil && !os.IsNotExist(err) {
		log.Printf("no .env loaded: %v", err)   // do not panic: CI usually has no .env
	}
	// ...
}

# Option 2: keep it out of the code, let the environment do it
direnv allow                 # or EnvironmentFile=/etc/myagent/env in a systemd unit

Never commit .env. Make it the first lines of .gitignore:

.env
.env.*
!.env.example

Keep a .env.example in the repo (key names, no values) so a newcomer can copy it and run.

Step 3: a minimal agent that compiles#

// main.go
package main

import (
	"context"
	"log"
	"os"

	"google.golang.org/genai"

	"google.golang.org/adk/v2/agent"
	"google.golang.org/adk/v2/agent/llmagent"
	"google.golang.org/adk/v2/cmd/launcher"
	"google.golang.org/adk/v2/cmd/launcher/full"
	"google.golang.org/adk/v2/model/gemini"
	"google.golang.org/adk/v2/tool"
	"google.golang.org/adk/v2/tool/geminitool"
)

func main() {
	ctx := context.Background()

	model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
		APIKey: os.Getenv("GOOGLE_API_KEY"),
	})
	if err != nil {
		log.Fatalf("failed to create model: %v", err)
	}

	a, err := llmagent.New(llmagent.Config{
		Name:        "weather_time_agent",
		Model:       model,
		Description: "Agent to answer questions about the time and weather in a city.",
		Instruction: "Your SOLE purpose is to answer questions about the current time and weather in a specific city. You MUST refuse to answer any questions unrelated to time or weather.",
		Tools:       []tool.Tool{geminitool.GoogleSearch{}},
	})
	if err != nil {
		log.Fatalf("failed to create agent: %v", err)
	}

	l := full.NewLauncher()
	if err := l.Execute(ctx, &launcher.Config{
		AgentLoader: agent.NewSingleLoader(a),
	}, os.Args[1:]); err != nil {
		log.Fatalf("run failed: %v\n\n%s", err, l.CommandLineSyntax())
	}
}

Compared with 1.x, three things must differ in this code:

  1. every import carries /v2;
  2. gemini.NewModel(ctx, ...) takes ctx first (this actually changed back in v1.0, but the old series documented the ctx-less form);
  3. l.Execute(ctx, config, os.Args[1:]) is also the ctx-taking signature.

The cmd/launcher/full composition, from the source, is universal.NewLauncher(console.NewLauncher(), web.NewLauncher(webui, a2a, pubsub, eventarc, api)), so it supports every subcommand below.

Step 4: run it#

go build ./... && go vet ./...     # pass static checks first
go run . console                   # console mode

Once in the console, ask anything — What's the weather in Shanghai? — and an answer means the whole chain (model, tool, launcher, session) is connected.

When you do not know which subcommands exist, make it tell you:

go run . --help
# or run with no arguments on purpose: Execute returns an error and the program prints l.CommandLineSyntax()

The web forms (Dev UI / API / A2A):

go run . web api webui

Do not confuse these: adkgo is not a run command#

go install google.golang.org/adk/v2/cmd/adkgo@latest
adkgo --help

After installing you will find adkgo exposes only a deploy subcommand tree (deploy cloudrun / deploy agentengine) — it is a deployment CLI, it does not run agents. Running an agent means the binary built from your own main.go, plus launcher subcommands. The old series treated adk version / ./adk as the run entry point; that is v0.x-era legacy and no longer works anywhere.

Step 5: verification checklist (all green before the next article)#

go list -m google.golang.org/adk/v2        # expect v2.4.0
go version                                 # expect >= go1.26.6
grep -c 'google.golang.org/adk/v2' go.mod  # >= 1
go build ./... && go vet ./...             # no output
go run . console                           # type one line, a reply means it passed

# leave a trace for production builds (record the dependency versions embedded in the binary)
go install ./...
go version -m "$(go env GOPATH)/bin/myagent" | grep 'adk/v2'

Frequently Asked Questions

How do I install ADK Go 2.x?

Run go get google.golang.org/adk/v2@v2.4.0 inside your project; in production pin the exact version rather than using @latest.

What is adkgo and how do I install it?

go install google.golang.org/adk/v2/cmd/adkgo@latest installs the deployment CLI (adkgo deploy cloudrun / agentengine). It does not run agents — the runtime subcommands come from the launcher inside your own main.go.

Why does go install google.golang.org/adk/cmd/adk@latest fail?

Because there is no cmd/adk package in the 2.x tree; the CLI was renamed to cmd/adkgo. Also note adkgo has no version subcommand, so check versions with go list -m google.golang.org/adk/v2.

What must be configured before running an agent?

For the Gemini route set GOOGLE_API_KEY. For Vertex AI set GOOGLE_GENAI_USE_VERTEXAI=true, GOOGLE_CLOUD_PROJECT and GOOGLE_CLOUD_LOCATION, and complete gcloud auth application-default login.

Does ADK Go read .env automatically?

No. The official samples consistently use os.Getenv and there is no built-in .env loader; if you want .env, bring godotenv yourself or use direnv / a systemd Environment directive.

How do I get the first agent running?

go run . console enters the console; go run . --help, or letting the program print l.CommandLineSyntax() on error, shows which subcommands the current launcher supports.
