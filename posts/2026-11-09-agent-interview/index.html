Agent 开发岗面试实录：我被面试官连环追问的 7 个问题

上周去面了一家做 Agent 应用的公司，岗位是 Agent 开发。面试官不怎么聊八股，全程围绕实际项目抠细节。把当场被问到的核心问题和我的回答整理出来，给大家参考。

November 9, 2026 · 1 min · 75 words · 梦兽 -  |  English

上周去面了一家做 Agent 应用的公司，岗位是 Agent 开发，面试官不怎么聊八股，全是围绕实际项目抠细节。我把当场被问到的几个核心问题和我的回答整理出来，给大家参考。

Q1：调用外部工具的 Agent，怎么处理参数格式错误和重复调用#

面试官问，如果你来设计一个能调用外部工具的 Agent，怎么处理模型输出参数格式错误和重复调用风险。

我答，我会用 ReAct 模式，让模型边思考边调工具，中间加一层 JSON 解析做校验。参数缺了就让它下一轮补，但必须设最大步数，比如 25 轮，超了直接报错退出，不然容易卡死。防重的话靠幂等键，再配合数据库事务回滚，像扣款这种写操作就不会重复执行。

Q2：幂等键怎么生成，并发怎么办#

接着追问，幂等键你怎么生成？遇到并发怎么办？

我不会简单拿用户 ID 拼业务类型，那样并发拦不住。一般会让网关或前端先申请一个幂等键，写入时用乐观锁，实在不行再上 Redis 锁做拦截，不靠数据库硬抗。

Q3：Agent 查业务数据库，怎么防它乱删表或泄露敏感信息#

面试官问，如果 Agent 需要查业务数据库，你怎么防止它乱删表或者泄露敏感信息。

我答，绝对不让模型直连数据库，全部封装成工具，Agent 只能调我们写好的接口。权限用服务账号加细粒度 scope 控制，敏感字段在代码层就脱敏，连数据库视图都只开只读权限。

Q4：线上偶发答非所问、有答案却瞎编，怎么排查#

面试官问，线上用户反馈 Agent 偶尔答非所问，明明知识库有答案却瞎编，你怎么排查。

我答，我们先接了 Langfuse 把每一轮的检索内容、模型输入都打日志。如果发现检索对了但模型答偏，就看它有没有按引用标记用资料，没用就是被长上下文淹了。还不行就上 Sonnet 这类强模型当打分 Agent，低于 0.5 分就判跑偏。检索错了就抽样算命中率、MRR 这些指标。

Q5：多轮订行程，怎么记住预算和出发地又不撑爆上下文#

面试官问，要做多轮订行程的 Agent，怎么记住用户最开始的预算和出发地，又不把上下文撑爆。

我答，主 Agent 拆子任务，查机票、酒店并行跑。短期对话放滑动窗口，快到水位线就保前 3 条后 3 条，中间轮次丢给小模型压成摘要。用户明确说的预算、目的地抽出来存长期记忆，下次检索能直接捞回来。

Q6：多个 Agent 组队，怎么防它们把流程卡死#

面试官问，多个 Agent 组队，比如一个查资料、一个写代码、一个审核，怎么防它们吵起来把流程卡死。

我答，不用简单链式，直接上 LangGraph 状态机。每个 Agent 写完状态加分布式锁，别的先读后写。状态里记重试次数，超了就走仲裁降级，不会让它们互相耗着。

这场面试下来，感觉对方根本不在乎名词，就盯着你有没有真写过、踩过坑。后面我打算再把 Claude Code 和 PyAgent 的上下文策略啃一遍，补点代码级细节。

常见问题

设计能调用外部工具的 Agent，怎么处理模型输出参数格式错误和重复调用风险？

ReAct 循环中间加 JSON 校验层，缺参数下一轮补齐，最大 25 轮硬退出；写操作用幂等键加数据库事务回滚，防重复执行。

幂等键怎么生成？遇到并发怎么办？

不拿用户 ID 拼业务类型。由网关或前端先申请专用幂等键，写入走乐观锁，不够再上 Redis 锁拦截，不靠数据库硬抗。

Agent 要查业务数据库，怎么防止它乱删表或泄露敏感信息？

模型绝不直连数据库，全部封装成工具；服务账号加细粒度 scope，敏感字段代码层脱敏，数据库视图只开只读。

线上偶尔答非所问、知识库有答案却瞎编，怎么排查？

Langfuse 打全轮日志：检索对但答偏先看引用标记有没有被用上，没用就是长上下文淹了；再上强模型当打分 Agent，低于 0.5 判跑偏；检索错就抽样算命中率与 MRR。

多轮订行程，怎么记住最初的预算和出发地又不把上下文撑爆？

主 Agent 拆子任务并行跑机票酒店；短期对话滑动窗口保前 3 条后 3 条，中间轮次小模型压摘要；明确说过的预算目的地抽进长期记忆，检索直接捞回。

多个 Agent 组队，怎么防它们把流程卡死？

LangGraph 状态机加分布式锁，每个 Agent 写完状态别的先读后写；状态记重试次数，超限走仲裁降级。
