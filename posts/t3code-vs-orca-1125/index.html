T3 Code vs Orca：多 Agent 编程编排工具怎么选（2026 年实测对比）

T3 Code 和 Orca 怎么选？本文对比两款多 Agent 编程编排工具：T3 Code 主打轻量控制面和手机远程审批，Orca 主打 Worktree 重度并行与可视化调试。含 GitHub 实数、安装命令与选型清单。

November 26, 2026 · 2 min · 328 words · 梦兽编程 -  | 

先说结论。想轻快，想在外面用手机盯着 Agent 干活，装 T3 Code。要同时开三到八个隔离任务，要前端可视化调试，要把常驻机器人塞进代码库，装 Orca。两个都装也不打架，它们用的还是你本机同一套 CLI 订阅。

这两个工具火起来，是因为多开 Agent 很快就撞上两堵墙。一堵是几个 Agent 同时改一个文件，Git 冲突一路冒出来。另一堵是你离开工位十分钟，后台任务卡在一条权限确认上不动了。前一种情况，站里那篇多 Agent 指令冲突 拆得更细，冲突不只在文件，也在指令本身。

它们的底座是同一个东西：Git Worktree。普通开发一次只能待在一个分支上，Worktree 让同一个本地仓库长出好几个独立目录和分支，每个 Agent 在自己的目录里改、自己跑测试，谁也不覆盖谁。底座一样，上面盖的房子完全不同。

先看热度：MIT 协议，不倒卖 token#

截至 2026 年 11 月 25 日，GitHub 仓库 pingdotgg/t3code（github.com/pingdotgg/t3code）是 77,647 星，stablyai/orca（github.com/stablyai/orca）是 136,266 星，数据取自两个仓库的公开页面。两款都是 MIT 协议，都不倒卖 token，直接复用你本机已经登录的 Claude Code、Codex 这些 CLI 订阅，项目里的 CLAUDE.md、AGENTS.md、Hooks 和 MCP 配置会被原样继承。这种复用本机订阅的路子，和编程 Agent 成本对比 里算的是同一笔账：钱花在订阅上，不再按 token 过一道手。

也就是说，迁移成本几乎为零，选错了换一个就是。

T3 Code 走的是轻快路线#

T3 Code 是一个轻量级控制面，主打低摩擦调度和手机远程审批。它的交互是收件箱式的，后台线程闷头干活，只在需要你拍板或者交付增量 Diff 的时候才浮出来。Hacker News 上不少开发者认可这点，说它少了来回切窗口的心智负担。

真正拉开差距的是 T3 Connect。有独立开发者在家用 Mac Mini 跑远程 Agent，实测下来认为论日常便利性 T3 Code 明显领先。它走自研输入层，你在外面用手机打字或者语音批一条权限，几乎没有传统远程终端那种卡顿和粘贴错位。官方还把掉帧当 Bug 处理，界面切换和滚动都轻快。桌面端和手机端怎么分工，可以看Agent 桌面端实践 。

它也有短板。功能边界是刻意收窄的，单点小需求用它会觉得多了一层壳。没有内置浏览器调试，没有移动端模拟器，多 Agent 自动派单也没有。不过有个细节挺实用：同一个线程里能中途换模型，前半段让 Claude Code 搭骨架，卡住了就切给 Codex 接着改，上下文直接接上。换模型的取舍，在编程模型对比 里也讨论过。

Orca 是个全功能工作台#

Orca 把并行隔离当成一等公民，把调度权交给 Agent 自己。

它内置 Chromium 浏览器和 Design Mode，页面上点一下元素，HTML、CSS 和选择器就直接喂给 Agent。Diff 面板能像 PR Review 那样逐行划词留评论，打回让它改。这些对前端和全栈的人很对味。

更狠的是 Orca Bots 和主从编排。主 Agent 可以自己把需求拆开，用 orca CLI 拉起子 Worktree 并行跑再汇总；接上 GitHub、Linear、Slack 之后，代码库里能常驻按 PR 或定时触发的机器人，直接交出改好并跑通测试的 Worktree。

远程这块它强在把重型 Worktree 扔到 SSH 服务器或者云端 VM 上通宵跑。同一个会话能在清爽的 Chat UI 和完整终端之间无损互切，日志和上下文都不丢。

代价是学习曲线陡，第一次上手比 T3 Code 费劲。早期有人反馈弱网下终端中继会刷新闪烁，新版加了 Chat UI 和原生终端无损互切之后已经好很多。

怎么选，看三件事#

1、你平时是一条需求一条需求地推，还是一上来就三到八个任务并行；前者 T3 Code，后者 Orca。2、你是不是重度前端，需不需要点选页面元素、逐行批注 Diff；需要就 Orca。3、你主要在哪儿审批；通勤路上用手机，T3 Connect 更顺手，把活扔到远端服务器通宵跑，Orca 的 Remote Runtime 更合适。

两个都装也完全合理。日常轻量改需求、路上盯进度用 T3 Code，大型重构、前端精调和多 Agent 协作切回 Orca。轻量改需求的流程想少踩坑，可以先看vibe coding 落地复盘 。

工具从代码补全走到单窗口对话，再到多 Worktree 并行编排，真正抬高的是一个人同时审查和交付多条分支的吞吐上限。

上手和避坑#

上手前只做一件事：确保本机至少登录了一个 CLI Agent，claude auth login 或者 codex login，二选一。

T3 Code 有 Node 环境就直接 npx t3@latest 在浏览器里试，顺手了再装客户端，macOS 用 brew install --cask t3-code，Windows 用 winget install T3Tools.T3Code，macOS 和 Linux 还能走 curl -fsSL https://t3.codes/install.sh | sh。装完导入本地 Git 仓库，新建 Thread 选 Agent，多任务并行时勾上独立 Worktree，先开 Supervised 模式按轮次看增量 Diff，跑偏就 Checkpoint 回滚，确认后一键提交 PR。

Orca 从 orca.dev 下载安装包。用 Homebrew 一定要写全路径 brew install --cask stablyai/orca/orca，裸命令 brew install --cask orca 装的是 Plotly 那个同名软件，这个坑不少人踩过。导入项目后一键新建 Worktree，自动隔离分支还兼容父目录的 .envrc，然后点顶部 Chat 和 Terminal 开关体验无损互切。

还有个共同的坑。高频建 Worktree 很吃磁盘，前端项目每个 Worktree 各自装一遍 node_modules，几个任务下来硬盘就见底。不管用哪个，合并 PR 之后记得及时归档和清理。

几个常被问的问题#

T3 Code 和 Orca 哪个更适合新手？T3 Code。界面干净，概念少，单点小需求不需要先搭一套工作台。

它们会额外消耗 token 吗？不会。两款都不倒卖 token，复用你本机已经登录的 CLI 订阅。

两者能同时用吗？能。它们读的是同一套本地配置和订阅，没有迁移成本，按任务切就行。

必须装多个 CLI Agent 吗？不用，登录一个就能跑；Orca 预配置 30 多家、T3 Code 支持 10 多家加任意 ACP Agent，想混着用再补。

装一个跑通两条并行任务，比看任何参数表都直观。
