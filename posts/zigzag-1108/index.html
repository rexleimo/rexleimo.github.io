18 MB 对 871 MB：Arc 停服前，我读完了这个 18 MB 的开源 Mac 浏览器

Zigzag：Swift+AppKit+WebKit 原生 Mac 浏览器，18 MB、Apache 2.0、自带广告拦截与 Chrome 扩展兼容。

November 8, 2026 · 2 min · 404 words · 梦兽 -  |  English

导语：Arc 浏览器 12 月 22 日停服，Mac 上的 Arc 手感党开始找下家。上周 linux.do 上一个叫 Zigzag 的开源项目把这事做完了：Swift + AppKit + 系统 WebKit 原生写，安装后 18 MB（原帖自报，未独立复现），作者自己机器上的 Arc 是 871 MB（原帖自报）。我读完了它的 README 和整个发帖线程，这篇是拆解：它怎么把 18 MB 装下 Arc 的手感、扩展兼容桥怎么搭、Arc 用户迁移会撞上哪些墙，以及做端侧工具的人该抄哪三条。

18 MB 对 871 MB，小在哪、为什么小#

我比的第一组数就是标题这组：Zigzag 安装后 18 MB，作者电脑上的 Arc 871 MB（原帖自报，未独立复现，871 MB 是 Arc 全量安装体积含 Chromium 内核）。

差距的来源 README 写得很直白：没有 Chromium，没有 Electron，内核就是 macOS 自带的 WebKit。每个标签页一个 WKWebView，不活动的标签保留快照和状态、切回来不重新加载；引擎的安全修复随 macOS 更新下发，作者不用自己补内核 CVE。结果是整个应用约 56,000 行 Swift 6 + AppKit（README），配约 190 个测试（README，覆盖导入、密码、地址处理、历史与安全修复）。

仓库 11 月 8 日当天 27 stars（GitHub API 读数），Apache-2.0，可以商用可以 fork——但名字、图标、logo 是商标，fork 要改名（README）。beta 状态，作者自述「是我每天用的浏览器，但你会找到 bug」（README）。

架构：扩展兼容是这座桥，macOS 15.4 是过桥费#

Zigzag 最值钱的工程点在扩展。它用 WebKit 自带的 WKWebExtensionController（这正是最低系统要求 macOS 15.4 的原因，README），流程是：从 Chrome Web Store 下载 CRX3 包 → 验签 → 加载。Chrome 有而 WebKit 没有的 API——history、bookmarks、downloads、notifications、side panels、offscreen 页面、web 登录、tab 音频、新标签页、用户脚本——由 Zigzag 自实现一个小 bridge 来应答，并且按每个扩展自报的 permissions 逐项校验（README）。1Password 走 native messaging 连它自己的 helper。

这套东西的效果是：Chrome Web Store 里点「Add to Zigzag」就能装 1Password、Dark Reader、Shazam（原帖自报）。但油猴是个反例，后文说。

数据也全在本地：空间和收藏在 Library.json，开着的标签在 Session.json，历史是 SQLite，都在 ~/Library/Application Support/Zigzag 下；写操作 debounce + 原子，读不出来的文件被搁置、绝不覆盖（README）。密码存 Keychain，iCloud Keychain 同步、Touch ID 解锁、支持 passkey；从 Chromium 系导入密码时用那个浏览器 Keychain 条目里的密钥解密，macOS 先弹授权（README）。

广告拦截约 130,000 条规则：EasyList + EasyPrivacy + EasyList China，离线用 SafariConverterLib 编译成 WKContentRuleListStore，编译一次缓存（README）。注意规则不自己更新、随 Zigzag 发版走（README）。

手感：侧边栏、空间、分屏、Peek#

README 的功能表我逐条过了一遍，对 Arc 用户的价值集中在四块（功能描述来自 README 与原帖）：

  • 空间（Spaces）：各自的颜色、置顶标签、文件夹；在侧边栏上滑动或鼠标轮横向拨切换。原帖自评「比 Arc 帅很多」。
  • 分屏：把标签直接拖到网页上，就在旁边开；pin 住就常驻。
  • Peek：Shift 点链接，在当前页上方预览，不丢位置。
  • 全标签（⇧⌘\）：一次看所有空间的全部标签，可输入过滤，可把标签拖进别的空间。

迁移侧的硬数据：File › Import from Another Browser 选 Arc，空间、置顶标签、置顶文件夹、收藏、历史、密码全带走；那堆开着的旧标签故意不带，让你从干净状态开始（README）。支持的源还有 Chrome、Safari、Dia、Edge、Brave、Vivaldi、Opera、Firefox、Zen（README）。

隐私这块我单独拎出来，因为它比大多数浏览器都硬：没有账号、没有统计遥测、不依赖作者的服务器——作者唯一托管的是 Sparkle 2 更新 feed（EdDSA 签名，Developer ID + 公证），这个 feed 没了，应用照跑（README “It can’t be switched off”）。主动联网只有四类：每日一次的更新 feed（只报版本号）、地址栏搜索建议（可关，只有 Google/DuckDuckGo/Brave/Bing/Kagi/Ecosia 提供）、站点图标、扩展更新检查（README “Privacy” 逐条列了）。

缺口清单：Arc 用户会撞到的墙#

这部分照 README “What’s missing” 加原帖「还缺的」整理，迁移前先看：

  1. 多台 Mac 之间、Mac 到 iPhone 之间无同步；密码只走 iCloud Keychain，空间标签不同步。
  2. 没有按空间分开的 profile/登录，所有空间共享登录态。
  3. 空间 emoji/图标还不存在，Arc 的空间 emoji 带不过来；空间颜色按最近色迁移。
  4. 没有 Little Arc，别处链接直接以本窗口标签打开。
  5. 没有 Boosts、Easels、Notes，也没有任何 AI 功能（原帖强调「没有 AI slop」）。
  6. 扩展桥还缺几个 Chrome API：tab groups、proxy/debugger 设置、Chrome 的 Google 登录（identity.getAuthToken）、老式 webRequest。
  7. 仅 macOS 15.4+；整体 beta。

67 条回帖里三条有用的信号#

线程 67 条回帖（78 赞，841 views），我把有信息量的三条摘出来（均为楼主 Zigao Wang 的自述回复，未独立复现）：

iPad 在路上，WebKit 是可行性根据。 有人催 iPad 版，作者回：自己也是 iPad 用户，「iPad 也是 WebKit，所以 zigzag 的路也适合 iPad，先做好 mac 版因为 12-22 之后真没了」。iPad 版不在路线图承诺里，只说做了会在帖子里讲——但 WebKit 是 macOS/iPadOS 共有内核，技术路线天然相通。

油猴，原帖乐观了。 原帖正文说 Tampermonkey 可用、Greasy Fork 上点安装、GitHub 这种严限制站的脚本也能跑；作者随后在回帖里修正：新版油猴（MV3）依赖 Chrome 专供用户脚本的 userScripts 接口，WebKit 没有，现在「装上能启动、脚本跑不起来」，他准备在 Zigzag 里自实现注入——「不只是看起来能用，而是脚本要真的能注入、能跑」。这条写进预期：装油猴之前等下一版。

作者是谁。 被问是不是古法手搓，作者答代码「大部分还是 claude code 写的，但也不是 AI slop」「我是真人！我是上海高中生」。一个上海高中生，用 Claude Code 协作，写出 56,000 行 Swift、当主力浏览器用了好几周的原生浏览器，发帖时本人就在用 Zigzag（原帖自报）。另有人要 Windows 版，作者回 Swift + AppKit + 系统 WebKit 三样 Windows 都没有，等于从头重写，一人先把 Mac 做完（thread 自述）。

该抄什么：端侧工具的三条设计#

Zigzag 是 Swift 不是 Rust，但它的产品算术对写端侧工具的人照样成立，我圈了三条：

  1. 薄壳 + 系统内核。不打包内核，体积和 CVE 面直接消失：56k 行换 18 MB，引擎安全修复随系统更新。Rust 侧的等价路线是 WebKitGTK + wry 一类组合，同样的算术。
  2. API 缺口用 bridge 补，不用引擎补。扩展桥按扩展自报的 permissions 逐项校验，缺什么 API Zigzag 自己应答——迭代速度脱离了内核节奏。
  3. 坏数据不覆盖。debounce + 原子写，读不出来的文件搁置。浏览器是存密码和历史的地方，这条的权重比性能还高。

判断：Arc 12-22 停服会抽走 Mac 上一支「空间/分屏」手感用户。27 stars（11-08 GitHub API 读数）说明接住的人刚起步；beta + 单人维护是风险，Apache-2.0 是兜底——代码开源了，作者不维护也fork 得动。

你现在的浏览器是 Arc 留守、Chrome/Safari 原教旨，还是 WebKit 系替代（Search Browser 之类）？18 MB 对 871 MB，你信哪边？评论区聊。
