Google 扔了个 11.9k star 的 Harness²：工位比脑子值钱，AIOS 把它放上记分台，+34.7pp

Harness² 是 Google Cloud AI Research 的递归 agent 框架：模型冻住，递归改的是工位（prompt、护栏、记忆、工具指导），单步在 JobBench 上官方自报最高 +4.5 分。RexAI 把同一套 JobBench 评测搬上自己机器，把 AIOS 工程纪律也放上记分台：裸机 51.1% → 85.8%，+34.7pp。首轮 +14.8 被自己作废——判分器方差 ±15pp，多轮中位数才站得住。

October 20, 2026 · 2 min · 367 words · 梦兽编程 -  | 

一句话#

Google Cloud AI Research 丢出来一个 11.9k star 的框架叫 Harness²：模型权重冻住，递归改的是工位——系统提示词、护栏、记忆、工具指导这些外壳。官方自报单步在 JobBench 上最高 +4.5 分。RexAI 那篇把它整条 JobBench 评测管线搬上自己机器，顺手把 AIOS 的工程纪律也放上同一张记分台：同一个模型、同一个任务，裸机 51.1% → 85.8%，+34.7pp，比论文最大单步增益高一个量级。

这篇把两侧数字都摆出来：论文报告值（官方自报，未独立复现）和 AIOS 原生臂实测值（源文数据，转述未独立复现），以及中间那条最值钱的自我纠错——首轮 +14.8pp 被自己作废了。

先说三句话#

第一，Harness² 的核心主张可以压成一行：agent 成绩的下限由 harness 决定，不是由模型决定——所以把改进的算力花在递归改外壳上。

第二，RexAI 的 AIOS 臂在同一记分台测出 +34.7pp（51.1 → 85.8），方向与论文一致、幅度更大，但 n=1 单任务，只算方向性证据。

第三，最硬的细节不是 85.8，是那条作废记录：首轮单轮实测 +14.8pp，三轮重复判分后站不住（判分器方差 ±15pp），主动作废、改用多轮中位数——这套自我纠错本身就是 harness 工程纪律的一部分。

Harness² 的两层递归#

Harness² 把「harness」拆成八个可编辑件：系统提示词、护栏、记忆、工具指导、子代理、技能、脚本、插件，前四个管上下文构造，中间两个管工具接口与委派，插件管中间件。改进过程是两层递归：

任务级递归，对当前任务做 Propose–Probe–Compose：先提出 harness 编辑，再让候选编辑在同一任务上各跑一遍、观察行为差异，最后组合成精化后的 harness。这条链路不需要标准答案——开世界任务测试时没有 ground-truth 验证器，靠的是执行对比。

harnessing 级递归，把每个任务采纳的编辑和证据支持的教训写进一个持续改进的 harness，指导下一个任务。论文原话的方向：一次任务级的改进同时喂给未来。

官方结果（论文表 1/表 2，三张榜 × 四个模型-harness 配置）：

基准单步最高增益k=5 并行递归再增
WorkBuddy-Bench+11.5 分+3.9
JobBench+4.5 分+4.2
LAB（partial）+11.8pp+6.7

JobBench 上 Gemini 3.5 Flash 配 OpenCode 从 74.9 起步（对照：裸系统提示词 72.4 → k=1 到 77.5 → k=5 到 80.8，官网案例数字）。论文里那个 JobBench 案例也值得记：基础 agent 把源文件改了一半从不回看自己的输出，改进后的 harness 加了验证护栏、对账技能和精确的工具指导，才把「改完不收尾」这个行为修掉。

复现 = 另一套 harness 工程#

论文教会你改哪个 harness，没教你怎么让评测在自己的机器上真实跑起来。RexAI 那篇把缺口全列出来了，每一条都是本地工程的账：

工单先行。开跑前立 decision 与 delivery 两张工单：打分走 non-leaderboard、只引用同管线内的 Δ；允许写入的范围；失败怎么分类。后面所有争议回工单解决，不靠聊天记录。

成本护栏协议。第一次全量尝试踩了坑：按额计费通道上跑了 50 分钟烧掉 ¥60。这条教训直接写成规则——开跑前核计费属性，冒烟实测单臂请求数再外推预算，driver 里内置花费和失败率熔断。正式实测全部切到单一廉价通道，solver、improver、judge 同一个模型。

环境隔离。不动用户全局配置：独立 XDG 世界 + 钉版客户端 + 看门狗回收僵尸进程。评测炸一千次，机器上其他工作流不动。

证据链。每个「完成了」都要带证据：管线三段 exit 0 落盘、逐条 rubric 判分 JSON 存盘、记分卡从配置文件可复算、正文里每个数字都有对应产物。没证据的声明会被门禁打回。

记忆与检查点。数小时长跑里，通道坑位、判分标准、成本教训实时钉进项目记忆，会话压缩后不丢。

记分台：论文报告值 vs AIOS 实测#

同一个任务（JobBench management_analysts/task1）、同一个模型（agnes-3.0-flash）、同一个客户端（pi），唯一变量是工位上有没有 AIOS 工程纪律：

工位方案论文报告本机实测Δ vs 裸机
Harness² 单步递归（JobBench 多任务均值）+4.5pp同管线复测未再现增益（递归臂 53.4 中位 vs 裸臂 64.8）—
AIOS 工程纪律工位（原生臂）—裸 pi 51.1 → pi+AIOS 85.8+34.7pp

三条都写进正文、不藏脚注：

递归臂没跑出正增益。官方 +4.5 用的是 Gemini 3.5 Flash 配 OpenCode，本机是 agnes-3.0-flash 配 pi——模型和 harness 实现都换了，增益是否可迁移，原文未覆盖，本文不下结论。

+14.8pp 被作废。最初单轮实测的 +14.8 在三轮重复判分下站不住（判分器自身方差 ±15pp），主动作废、改多轮中位数。AIOS 双臂差 34.7pp 远大于该噪声，原文的判断是结论稳健。

局限四条：n=1 单任务（方向性证据，扩样本幅度会移动）；solver 与 judge 同型号，绝对分有自判偏差、相对 Δ 才是主证据；WorkBuddy-Bench 与 LAB 未覆盖（GCP/许可硬前置）；全部分数是 non-leaderboard 的本机测量，不引用到排行榜语境。

为什么这个数（暂且）可信#

唯一的变量是工位：干活、改工位、打分的都是同一个模型，judge 用同一份 rubric、同一参数贯穿全臂。可审计：逐条评分 JSON、管线日志、判分脚本全部留档（仓库 runs/jb8_quickjudge_*.json），任何人可复算。边界写死：n=1、同源自判、三基准只覆盖其一。

「暂且」两个字是源文自己加的——方向性证据，不是统计结论。

FAQ#

Q1：Harness² 到底改的是什么？ 不改模型权重，改模型外围的八个 harness 件（提示词/护栏/记忆/工具指导/子代理/技能/脚本/插件）。任务级递归改当前任务的 harness，harnessing 级递归把教训沉淀给未来任务。

Q2：+34.7pp 和官方 +4.5 能直接比吗？ 不能。任务集不同（单任务 vs 多任务均值）、模型不同（agnes-3.0-flash vs Gemini 3.5 Flash）、harness 实现不同（AIOS 工程纪律 vs Harness² 递归臂）。两边唯一共享的是「同模型换工位提升成绩」这个方向。

Q3：为什么首轮 +14.8 被作废？ 判分器自身方差 ±15pp，单轮数字落在这个噪声带里，三轮重复后站不住。多轮中位数下的 51.1 → 85.8 双臂差远大于噪声，才进结论。

Q4：我自己跑 agent 能抄什么？ 两条：开跑前给 agent 装成本熔断（¥60/50 分钟是真实账单）；任何「+X pp」结论先跑三遍判分再信。

Q5：代码能直接用吗？ Harness² 本体 Apache 2.0，uv pip install -e '.[render]' + harness2-setup jb 就能起 JobBench；需要 Vertex AI 项目与模型配置。AIOS 那套门禁是工程纪律不是库，抄的是规则不是代码。

诚实声明#

论文侧数字（+11.5 / +4.5 / +11.8、k=5 再增益、72.4→77.5→80.8）为 Google Cloud AI Research 官方报告，本文未独立复现；11.9k star 为抓取时点 GitHub 数值。AIOS 侧数字（51.1 / 85.8 / +34.7 / 53.4 vs 64.8 / ±15pp / ¥60）转述自 RexAI 源文实测（2026-10-19），本文未独立复现，全部局限以源文 Limitations 节为准。递归臂未再现官方增益的差异归因（模型+客户端不同），本文不下「Harness² 失效」的结论。

常见问题

Harness² 到底是什么？

Google Cloud AI Research 的递归 agent 框架（arXiv 2610.14224，Apache 2.0，仓库 11.9k star）。把模型权重冻住，递归改的是模型外围的 harness——系统提示词、护栏、记忆、工具指导、子代理、技能、脚本、插件八个可编辑件。任务级递归做当前任务的 harness 改进（对比式 Propose–Probe–Compose，不需要标准答案），harnessing 级递归把经验沉淀给下一个任务。

官方数字多大？

单步改进最高 +11.5 分（WorkBuddy-Bench）、+4.5 分（JobBench）、+11.8pp（LAB partial pass rate）；k=5 并行递归再加最高 +3.9/+4.2/+6.7。官方自报，三张榜 × 四个模型-harness 配置，GLM-5 与 Gemini 3.5 Flash 均正向。

+34.7pp 怎么来的，可信吗？

RexAI 把 JobBench 的 management_analysts/task1 搬上本机：同一模型（agnes-3.0-flash）、同一客户端（pi），唯一变量是工位上有没有 AIOS 工程纪律。裸 pi 51.1 → pi+AIOS 85.8。局限原文写死：n=1 单任务、solver 与 judge 同型号（自判偏差）、只覆盖三基准之一的 JobBench 管线、判分器方差 ±15pp——首轮 +14.8 就是这个方差里作废的。

Harness² 递归臂为什么没跑出正增益？

同一管线上复测，递归臂 53.4（中位）vs 裸臂 64.8，没再现官方 +4.5。官方实验用的是 Gemini 3.5 Flash 配 OpenCode，本机是 agnes-3.0-flash 配 pi——模型与 harness 实现都换了，增益是否迁移，原文明说未覆盖，本文也不下结论。

跟我跑 agent 有什么关系？

两个可直接抄的动作：开跑前给 agent 装成本熔断（按额计费通道 50 分钟烧掉 ¥60 是真实教训）；任何「+X pp」结论先跑三遍判分再信——判分器噪声 ±15pp，单轮数字没有资格进结论。
