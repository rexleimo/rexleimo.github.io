OpenMotion 入门：AI 爱好者怎么把参考片变成可编辑的品牌短片

OpenMotion 是什么？怎么接入云端 MCP 或本地源码？本文面向 AI 爱好者，讲清 Motion.md、HTML/CSS 视频工程、上手流程、成本边界与适用场景。

November 27, 2026 · 2 min · 295 words · 梦兽编程 -  | 

OpenMotion 最值得 AI 爱好者关注的地方，不是“一句话生成视频”，而是把视频变成一份能继续改的工程。你拿到的不只是 MP4，还有 Motion.md、HTML/CSS 场景和时间轴。产品界面换了、文案改了、品牌色调整了，可以直接改源码，不必重新抽卡。

截至 2026 年 11 月 26 日，OpenMotion 官方仓库把它定位为 Claude Motion 与剪映（CapCut）的开源替代方案，采用 Apache-2.0 许可证。它最适合产品演示、品牌短片、界面动效和数据叙事。长课程、复杂实拍混剪、频繁改台词的口播，仍然应该交给传统剪辑或更专门的工具。

它和普通 AI 视频工具，差在哪一层#

普通 AI 视频工具大多停在“给提示词，等一条结果”。OpenMotion 把过程拆开了。Agent 先研究参考片，拆出开头、镜头顺序、字体、转场和声音提示，再用 Motion.md 记录节奏，用 HTML、CSS 和 JavaScript 重建画面，最后在 Studio 里调整时间轴并导出 MP4。

Motion.md 就是这支片子的文字分镜。它不只记“第几秒出现什么”，还记镜头顺序、停留时长、转场和可替换素材。品牌身份、语气和已确认的产品事实，则放进 Brand Kit。以后想做第二条同系列视频，你继承的是方法和结构，不是上一代随机生成的结果。

BYOA 和 BYOK 也要分开理解。BYOA 是 Bring Your Own Agent，你继续用顺手的编码 Agent；BYOK 是 Bring Your Own Keys，图片、视频、音乐和旁白可以接自己的模型账号。官方当前列出 22 个本地 Agent，包括 Claude Code、Codex、OpenCode、Gemini CLI、DeepSeek TUI、WorkBuddy 等，文档口径来自 OpenMotion 官方仓库。

开源免费不等于所有环节零成本。官方说明里，本地工作流不收软件订阅费或单次渲染费，但你自己的 Agent 订阅、第三方模型调用、字体和素材授权仍然可能收费。云端 MCP 服务的具体计费也要以服务方当时页面为准，不能把“开源”直接理解成“白嫖全部模型”。

现在怎么接入：云端 MCP 是默认路线#

想先体验，别一上来就折腾源码。当前官方推荐的是云端 MCP，通过 Streamable HTTP 加 OAuth 2.1 连接，不需要在本机安装 Node.js、Chromium 或 FFmpeg。

可以先安装 OpenMotion 的 Skill：

npx skills add nexu-io/openmotion --skill openmotion

然后把自己的 Agent 叫过来，让它阅读官方接入文档并连接 OpenMotion。授权完成后，Agent 会打开云端模板库。你选模板、给素材和创作要求，它负责拆解、搭建工程和调用已配置的模型。

这条路适合想快速验证工作流的人，也适合不想维护本地运行环境的人。它的边界是，工程和素材上传会经过云端服务，账号授权、素材隐私和服务可用性都要提前考虑。

本地源码适合什么人#

如果你要把工程、素材和密钥都留在自己机器上，或者准备深度改 OpenMotion，再走本地源码。

按当前 README 的源码运行步骤，需要 Git、npm 和 Node.js 26.11.1；预览与导出还需要 Chrome 或 Chromium，以及 FFmpeg 与 FFprobe。基本启动命令是：

git -c filter.lfs.process= -c filter.lfs.smudge= -c filter.lfs.required=false clone --depth 1 --single-branch --branch main https://github.com/nexu-io/openmotion.git
cd openmotion
npm ci
npm run build:studio
npm start

启动后打开终端打印的 studioUrl 或 previewUrl，不要死记某个端口。工程与凭据要放在仓库外，工作目录可以用 MOTION_DATA_DIR 指定。

这里有个容易踩的坑：仓库 package.json 的最低 Node 约束仍写着 >=22.18.0，但 README 的本地源码步骤明确要求 26.11.1。最低能启动和官方推荐运行版本不是一回事。新手直接按 README 准备，别拿最低版本赌导出稳定性。

第一条片，先从复刻开始#

新手最容易踩的坑，是工具还没摸清，就让 Agent 从零写一条大片。我的建议是先做一条 20 到 30 秒的产品片，只讲一个产品、一句承诺、三五个镜头。第一条片的目标不是炫技，是把“参考、拆解、改稿、预览、导出”整条链跑通。

素材先准备 Logo、标题与正文字体、主色、产品截图、三到五句确认过的文案和结尾行动号召。第一版尽量用自己的截图与文字，不要急着生成大量图片和视频。节奏没跑对之前，生成越多，返工越狠。

给 Agent 的指令要写清四件事：研究什么、保留什么、替换什么、生成什么。比如可以直接这样说：

用 OpenMotion 复刻我提供的参考片。研究开头、镜头顺序、字体层级、转场和声音提示。保留产品揭示方式与整体节奏。把标志、界面、文案和片尾换成我提供的品牌素材。缺少的画面只用已配置模型生成，并遵循 Brand Kit 与已确认脚本。创建可编辑工程，在 Studio 里打开，并在相同时间点对比参考片。说明还剩哪些差异，等我审阅后再导出 MP4，保留源码。

做完不要只看最终 MP4。要在 Studio 里把参考片和复刻片放在同一时间点看：开头是否太快，标题是否清楚，产品揭示有没有留住，字幕有没有抢画面，结尾是否留够阅读时间。OpenMotion 官方也强调，导出只是交付固定版本，源码和素材要一起保留，后面才能继续改。

Studio 里真正值钱的，是“改得动”#

Agent 交付工程，只是把骨架搭好。真正决定质感的，是 Studio 里对时间轴、排版、缓动和声音的逐段调整。

小改动可以自己拖时间轴、调透明度和位移；大改动交给 Agent，比如“标题入场放慢一点”“按钮淡入改成弹性缓动”“最后一句多留两秒”。两边改的是同一份 HTML 工程，不是各改各的副本。官方文档还说明，工程写入带版本检查，旧请求不能随手覆盖新改动。

这也是 OpenMotion 和“抽卡式生成”最实质的区别。生成结果不满意时，你不必再许一遍愿，而是能找到具体镜头、具体源码和具体时间点，把它改到能交付。

这些场景，别硬用 OpenMotion#

要做半小时课程，OpenMotion 会很吃力。它的画面主要靠浏览器逐帧渲染再编码，复杂场景的渲染成本会随着时长和图层数量上涨。短片、品牌动效和产品演示才是舒适区。

台词频繁改的口播也别硬塞。时间轴按秒对齐，旁白一改、语速一变，字幕和画面就要重新校时。口播矩阵更适合按词或句锚定的工具，OpenMotion 的强项是静态版式、图形动效和精确节奏。

多机位实拍、复杂调色和大规模混剪，仍然交给传统剪辑软件更省时间。OpenMotion 是动效与工程编排工具，不是全能剪辑器。

想“一键发布全平台”也要降低预期。当前官方路线图里，平台连接器、定时发布和表现回流仍在规划中。现在能做的是导出不同画幅的 MP4，再手动上传到对应平台。README 对渠道发布的描述，不等于已经上线自动发布功能。

成本、版权和验收，一个都不能省#

先用已有素材把流程跑通，再决定哪些镜头需要生成模型。每生成一张图、一段视频或一条旁白，都要先问它是否真的不可替代。模型调用按供应商规则计费，失败重试也可能产生成本，别让 Agent 在后台无限抽卡。

参考片只用来研究节奏和结构，品牌、文案、界面与事实必须换成自己的。字体、音乐、图片和模型生成素材都要确认授权，尤其不要把带第三方商标或人物肖像的参考画面直接当成品发布。

验收分两层。技术层看 MP4 的尺寸、帧率、时长、音轨和完整解码；创作层看文案、品牌、画面、声音和节奏。官方导出流程会做技术校验，但“文件能播”不等于“这条片能发”。

几个常见问题#

OpenMotion 免费吗？软件本地工作流开源免费，采用 Apache-2.0 许可证。Agent 和媒体模型的费用另算，云端服务也以官方当时说明为准。

不会编程能用吗？可以先用模板和云端 MCP，主要工作是准备素材、写清需求、审片和改时间轴。但想用得深，懂一点 HTML/CSS 会轻松很多，因为大改最终落在源码上。

它和 Sora、可灵这类视频生成模型是什么关系？不是同一层。OpenMotion 负责拆解、编排、编辑、版本和导出，生成模型负责补画面。你也可以完全用自己的实拍、图片和声音，不调用生成模型。

支持哪些 Agent？官方当前列出 22 个本地 Agent，覆盖 Claude Code、Codex、OpenCode、Gemini CLI、DeepSeek TUI、WorkBuddy 等。具体连接方式以你使用的客户端和官方适配文档为准。

能直接发布到抖音、小红书或 B 站吗？目前主要是导出 MP4 后手动发布。多平台连接、排期和自动画幅重构仍在路线图里，不要当成现有功能。

Node.js 22.18 够不够？package.json 写的是最低 >=22.18.0，但当前 README 的本地源码步骤要求 26.11.1。实际跟源码运行，优先按 README 的版本准备，同时装好 Chrome/Chromium、FFmpeg 和 FFprobe。

AI 爱好者真正该学的，不是多一个提示词，而是把创意拆成可修改的工程。OpenMotion 把镜头节奏、品牌规范和源码放进同一个项目，这才是它比“看运气抽卡”更值钱的地方。先用一条 30 秒产品片验证，别急着建生产线。
