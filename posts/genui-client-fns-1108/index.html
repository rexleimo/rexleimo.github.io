0ms 对几百 token：别让 LLM 做算术，我拆完了 Flutter GenUI 的客户端函数

A2UI + 同步响应式信号：LLM 只负责推理与布局，确定性数学交给本地 Dart 函数 0ms 执行。

November 8, 2026 · 4 min · 644 words · 梦兽 -  |  English

导语：生成式 UI 最常见的坑，是让用户拖一下 slider 就要把「3.50 × 3」发回给远端大模型去算——烧几百 token、隔几秒才回来。Google GDE（Google Developer Experts）在 dev.to 上把这条路叫「往返计算陷阱」，给出的解法是 Client-Side Functions：让 LLM 只负责设计界面和绑定表达式，把确定性计算交给客户端本地 Dart 代码，再用同步响应式信号把结果在同一帧画回去。原文自述：0ms 本地执行、120 FPS 同帧重绘（未独立复现）。我读完了这篇 39 章连载的第 39 篇、翻了 pub.dev 上的三个包、查了 A2UI 官方协议仓库，这篇是拆解：陷阱怎么形成、同步信号怎么接、该抄哪三条，以及这套东西现在到底跑没跑起来。

一个菜谱乘法，凭什么要 LLM 去算#

原文开篇一句话我直接搬：「LLM 是绝佳的语义推理引擎，但它是糟糕、缓慢又昂贵的口袋计算器。」（原文自述）

场景很具体：AI agent 给用户生成一张菜谱卡或购物车卡，用户把分量从 2 份拖到 6 份。在 naive 的 GenUI 系统里，接下来发生的是（原文 Step-by-Step 之前那段）：

  1. 客户端捕获输入变化；
  2. 把状态序列化，经 SSE 或 WebSocket 发回远端模型；
  3. LLM 烧几百 token 算 3.50 * 3，偶尔浮点幻觉或格式漂移，隔「数秒」延迟才回（原文自述，未独立复现）；
  4. 客户端终于重绘。

原文的判断很直白：在一台 Apple Silicon / Snapdragon 每秒能跑十亿次运算（原文自述）的设备上，为两个数相乘发一次远端 AI 调用，是「架构反模式」。解法是 Red Brogdon 在 Flutter 频道那个 5 分钟 demo（Commis 厨房助手）里展示的 Client-Side Functions：agent 设计界面、绑定表达式，但确定性执行委托给客户端本地 Dart 代码——注册进 client 的函数目录。

缺的那一环：把「响应式」做成同步信号#

本地跑 Dart 函数，确实解决了 LLM 往返的延迟和 token 成本。但它立刻制造了第二个架构问题（原文 “The Missing Link” 一节原话）：本地状态变了，UI 怎么反应？

异步架构里，开发者往往被迫接 StreamController 管道、debouncer，或手动 setState()，把本地算的结果传回生成的 widget。每一格 slider 都交一次 event-loop 和 microtask 税。

bloc_signals_genui 的处理方式是：它直接建在 Google 官方的 a2ui_core 引擎上，而 a2ui_core 原生用 preact_signals。于是 client-side 函数不再是「可调用例程」，而是一等响应式 computed() 信号。原文那张同步链路图（我按原文 mermaid 抄了一份源码放素材里）：

flowchart TD
    User["User Drags Slider / Edits Field"] -->|"1. Updates Local DataModel (0ms)"| Data["DataModel Signal ('/recipe/servings')"]
    Data -->|"2. Synchronous Dependency Trigger"| Computed["computed(() => calculateCost(...))"]
    Computed -->|"3. Same-Frame Leaf Rebuild (120 FPS)"| Widget["Text Widget ('$14.50')"]

用户一调数量，计算就在同一帧跑完。零网络往返、零 microtask 跳、零 UI 闪烁（原文自述，未独立复现）。

五步把客户端函数接上#

以下是原文 Step-by-Step，我把代码原样保留、注释译成中文，方便你直接对着抄。

1. 用纯 Dart 定义函数#

子类化 FunctionImplementation（从 a2ui_core 再导出），声明函数名、返回类型，以及带类型的 JSON 参数 schema（用 CommonSchemas.dynamicNumber）：

import 'package:bloc_signals_genui/bloc_signals_genui.dart';
import 'package:json_schema_builder/json_schema_builder.dart'
    hide ValidationResult;

class CalculateCostFunction extends FunctionImplementation {
  CalculateCostFunction()
      : super(
          name: 'calculateCost',
          returnType: A2uiReturnType.number,
          argumentSchema: Schema.object(
            properties: {
              'unitPrice': CommonSchemas.dynamicNumber,
              'quantity': CommonSchemas.dynamicNumber,
              'discount': CommonSchemas.dynamicNumber,
            },
            required: ['unitPrice', 'quantity'],
          ),
        );

  @override
  Object? execute(
    Map<String, Object?> args,
    DataContext context, [
    CancellationSignal? cancellationSignal,
  ]) {
    final unitPrice = (args['unitPrice'] as num?)?.toDouble() ?? 0.0;
    final quantity = (args['quantity'] as num?)?.toDouble() ?? 0.0;
    final discount = (args['discount'] as num?)?.toDouble() ?? 0.0;
    return (unitPrice * quantity) * (1.0 - discount);
  }
}

注意 execute() 收到一个 DataContext：意味着你的函数可以按需读或限定额外的本地 surface 状态，完全和 Flutter widget 解耦。

2. 注册进 catalog#

把你的函数加进 StandardCatalog，再传给 A2uiSurfaceBloc：

final catalog = StandardCatalog().copyWith(
  functions: [
    CalculateCostFunction(),
    ...BasicCatalog.v0_9().functions.values,
  ],
);
final surfaceBloc = A2uiSurfaceBloc(catalogs: [catalog]);

当你的 app 把能力和系统提示词通告给 agent，agent 就知道了有 calculateCost 以及它要的必填参数。

3. agent 流式下发「反应式绑定」#

agent 下发一个 A2UI JSON 组件时，它不硬编码静态字符串，而是把 Text 组件的 text 属性绑到函数调用上，参数用本地 DataModel 路径引用：

{
  "id": "cost_display",
  "component": "Text",
  "text": {
    "call": "calculateCost",
    "args": {
      "unitPrice": 4.50,
      "quantity": { "path": "/cart/items/0/qty" },
      "discount": 0.10
    }
  }
}

4. 底层零延迟执行#

bloc_signals_genui / bloc_signals_genui_flutter 解析这个组件时，a2ui_core 的 DataContext.resolveSignal() 会求值这次动态调用（原文给的是概念化伪代码）：

  • 每个指向 DataModel 路径的参数（如 /cart/items/0/qty）解析成底层响应式信号；
  • 整个函数调用编译成原生 computed() 信号；
  • 用户一在 TextField 或 Slider 上改数量，bloc.add(UpdateFormField('/cart/items/0/qty', newValue)) 就同步变异 DataModel；
  • computed() 信号置脏、当帧立即重算（原文自述 0ms、零 microtask）；
  • Flutter 组件（NodeResolver/A2uiSurfaceView）做「外科式」叶节点重建（原文自述 120 FPS）。

5. 交互动作 vs 双向 RPC#

除了动态展示属性，client-side 函数还和「用户动作 + 远端 agent 协同」打通。原文特意分了两条路径，别混：

  • 路径 A：用户交互 SubmitAction。用户点一个 Button，客户端向 A2uiSurfaceBloc 派发 SubmitAction。这个动作要么触发本地 client-side 函数（比如应用本地 coupon、校验表单），要么向外发 A2uiRendererAction 给远端 agent。原文示例：
{
  "id": "apply_coupon_btn",
  "component": "Button",
  "text": "Apply 20% Discount",
  "action": {
    "functionCall": { "call": "applyDiscountCode", "args": { "code": "SAVE20" } }
  }
}
  • 路径 B：双向 RPC（CallRendererFunctionMessage 与 callAgentFunction）。GenUI 不是单向的，A2uiSurfaceBloc 提供跨 client-agent 边界的完整双向 RPC：
    • 入站 RPC（CallRendererFunctionMessage）：远端 agent 可主动调用已注册的本地函数——按 client 业务规则算一个已校验总价、读设备 GPS、查本地 SQLite；client 本地执行 catalog 函数，回一个带类型的 RendererFunctionResponseMessage。
    • 出站 RPC（callAgentFunction）：渲染端经 bloc.callAgentFunction() 调用 agent 的远端工具能力，异步 resolve 到匹配的 AgentFunctionResponseMessage 返回。

一张职责边界表：该抄什么#

原文收尾给了这张表，我照抄并翻译成中文，这是整篇最值得截走的一张：

职责谁处理延迟与可靠性
生成布局与推理远端 LLM（Gemini / Claude / GPT）网络异步流式（SSE）
确定性业务与数学本地 Dart 函数（FunctionImplementation）设备端 0ms 同步执行（原文自述）
响应式与状态同步信号图（BlocSignal + a2ui_core）同帧 UI 更新、无 microtask
硬件与原生平台 API双向 RPC（CallRendererFunctionMessage）本地 platform channels + 安全沙箱

我圈三条给做端侧工具 / GenUI 的人抄（我的判断，非原文）：

  1. 把「确定性」划给本地，把「生成」留给 LLM。 乘法、格式化、折扣、库存校验这类结果可验证的逻辑，根本不该过网络。LLM 只出布局 + 表达式绑定，执行落本地——这是整篇的主线。
  2. 响应式用同步信号做，别交 microtask 税。 把函数调用编译成 computed() 信号，让「状态变 → 重算 → 重绘」在同一帧完成，而不是塞进 event-loop 异步队列。这是 preact_signals / a2ui_core 这一层真正值钱的地方。
  3. 双向 RPC 把「能力边界」显式化。 哪些函数是本地可信执行、哪些要回 agent，用 CallRendererFunctionMessage / callAgentFunction 两条明确的消息类型隔开，而不是让 agent 直接伸手摸设备。

包与协议：这套东西现在跑没跑起来#

我查了三处（2026-11-08 拉取，数字是 pub.dev / GitHub 读数，非原文）：

  • a2ui_core（Google 官方，pub.dev 发布者 labs.flutter.dev）：最新 0.5.0（2026-11-04 发），原生依赖 preact_signals >=1.9.4，30 天下载 34.6k。它是 A2UI 协议在 Dart 侧的核心：消息、数据模型、数据绑定与表达式。
  • bloc_signals_genui / bloc_signals_genui_flutter：都停在 1.0.0（2026-10-20 发），发布者 blocsignal.dev（pub.dev verified），30 天下载 70 / 205。
  • A2UI 协议主仓 github.com/a2ui-project/a2ui：官方定位「agent 流式下发布局数据、App 用原生组件渲染」，覆盖 React / Angular / Lit / Flutter / SwiftUI / Jetpack Compose；2026-11-08 读数 17,007 stars、1,375 forks、Apache-2.0、2025-09-24 创建。

一个我要提醒的 watch 项（我的判断）：bloc_signals_genui 1.0.0 系锁的是 a2ui_core ^0.3.0，而官方核心已经到 0.5.0（就在发文章前一天）。说明这套下游还新，没跟上官方核心的节奏——用之前先核对 a2ui_core 版本线，别直接 pub get 就上线。

结论：方向成立，「GenUI 的创意灵活性 + native 的速度/精度/可靠性」这个卖点在架构上讲得通；但要生产级，得等 bloc_signals 把 a2ui_core 版本追上来、样本跑在 blocsignal.dev 上看过再说。

你现在的 GenUI 是把所有状态都回传 LLM，还是已经开始在客户端切一块确定性逻辑出来？评论区聊。
