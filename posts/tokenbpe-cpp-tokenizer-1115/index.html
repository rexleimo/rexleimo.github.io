TokenBpe：手搓 C++20 分词器，240 MB/s 来自十几个相乘的小技巧

Unica2804/Token_BPE，0 star 的个人仓库，C++20 手写 BPE，编码吞吐自报 240 MB/s。我把源码全量拉下来逐条对机制，又在本机 2 核上跑了一组单路对照。全文与讨论沉在 BBS。

November 16, 2026 · 1 min · 195 words · 梦兽编程 -  |  English

每个 LLM 请求都要过两次分词器，进去一次、出来一次，几乎没人多看它一眼。一个叫 Unica2804/Token_BPE 的个人仓库把这笔隐形固定开销做成了 C++20 手写 BPE 实现，编码吞吐自报 240 MB/s。0 star、0 fork、无 release、MIT、14 个 commit。正文所有性能数字都是作者在自己机器上的输出，无外部复现，基准脚本也是作者自己写的；我做的事是把源码全量拉下来逐条对机制，又在本机 2 核上跑了一组单路对照。它的价值不在让人信 240 MB/s，在让人看懂这些钱是怎么省出来的。

管线图自绘，依据 main 分支源码文件与行号（2026-11-15 拉取核对）；吞吐数字均为作者自报。

没人盯着的固定开销#

这个位置的主流答案是两家：OpenAI 的 tiktoken，Rust 内核加 Python 绑定（官方 README 自述比可比开源分词器快 3-6 倍，测于 1GB 文本、对照 tokenizers 0.13.2 旧版）；Hugging Face 的 tokenizers，同样 Rust 内核，11,247 star（GitHub API 读数，11-15）。TokenBpe 走的是另一路：一个人从零写 C++20，把上面两家当对照组。

热路径里的机关#

预分词丢掉正则引擎：swar.hpp 用纯 64 位整数 ALU 一次判 8 个字节，零 SSE/AVX intrinsic，一条指令顶八次分支。merge 阶段把片段铺在 thread_local 草稿区，一字节一个链表节点，合并是三次赋值的 O(1) 摘链，热路径零字符串分配。每路独享 512 KiB 直接映射缓存（8192 个缓存行对齐槽），22 字节以内的短片段命中就整段跳过 merge。双游标在中点空白处把文本切两半，两条互不依赖的指令流喂同一个核——拿的是指令级并行，不开新线程。作者的总账一句话：没有单项绝招，加速是十几个相乘的小系数。

不走算法的那 1.75 倍#

最隐蔽的一笔开销在跨进 Python 的那一步。TokenBpe 用 nanobind 把 encode 结果经 capsule 移交堆上的 vector，ndarray 原位读，计算段临时摘 GIL。作者自报的 README 基准表：ndarray 输出路径 239.98 MB/s，同模型同输入换成返回 list[list[int]] 的路径 137.40 MB/s——1.75 倍纯是边界差。这笔账对所有 Python 扩展分词器都成立。

我这边 2 核机器上的数#

本机是 2 核共享 vCPU（EPYC 9354P），编不动作者那套 -march=native 产物的全量对照（他的环境：i5-11260H、GCC 14.3.0、Python 3.13）。可做的是一组单路对照：pip 装 tiktoken 0.14.0（与作者同版本），仓库同款 shakespeare.txt 1,115,394 字节，照 benchmark.py 切 18 块 64KiB 换行对齐分块，RAYON_NUM_THREADS=1，15 次取中位——2.15 MB/s，比作者单路自报的 tiktoken 11.55 MB/s 低约 5 倍，符合共享核机器的水位。更硬的一组读数：本机吐出 338,025 个 token，与作者 README 基准表里 tiktoken 列逐字节相同，跨机对照的分母是同一份。

局限比数字值钱#

同语料下 TokenBpe 产出 331,572 个 token，比 tiktoken/HF 的 338,025 少约 1.9%（作者自报）——预分词对 GPT-2 正则的近似在这里现形。拿它当加速器可用；对账计费、复现训练数据、做 prompt 缓存键的场合不能直接替换 tiktoken，这条边界作者自己写进了 Known limitations。工作池单一任务槽、threads 参数实际被忽略、22 字节以上片段不进缓存，也都在逐条对源码的清单里。

常见问题

TokenBpe 能直接替掉项目里的 tiktoken 吗？

不能。预分词是对 GPT-2 正则的近似，同语料 token 数差约 1.9%，id 空间不对齐。对 token 数有精确要求的场合（计费、缓存键、数据复现）别换。

它的性能优势主要从哪几层来？

三层。算法层少做事：SWAR 分类、直接映射缓存、链表 merge；结构层喂饱硬件：双游标 ILP、常驻工作池；边界层少搬运：capsule 移交、摘 GIL。边界一层单独就值 1.75 倍（作者自报）。

作者自报的基准脚本可信度怎么样？

方法学控制留了底：换行对齐分块、同词表、先 roundtrip 后计时、中位取 9 次，脚本全公开可复跑；但写项目的人和写脚本的人是同一个，没有外部复现记录。当线索读，不当结论读。
