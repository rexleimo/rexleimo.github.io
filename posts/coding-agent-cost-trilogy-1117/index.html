省下 Agent 的冤枉钱：本地搜索、幂等执行与推理档位三则

三篇 dev.to 实战放在一起读：XERJ 本地搜索引擎把 Agent 的输出 token 砍到 grep 的三分之一；一次超时重试揭开 7 层重试叠加的重复扣款；7 个模型 15 道 AIME 难题实测，高档思考贵 3.9 倍、Gemini 4 三款满分不变。

November 17, 2026 · 2 min · 296 words · 梦兽编程 -  |  English

上周三篇 dev.to 实战，我是连起来读的。表面三件事，漏的其实都是 Agent 的钱：整文件读漏一笔，超时重试漏一笔，高档思考再漏一笔。好在三篇都给了止漏办法和数字，这篇把它们拼成一张清单。

XERJ：让 Agent 读段落，别读文件#

Alex Rashkov 介绍的 XERJ 外部链接 是 Rust 写的本地搜索引擎：单个二进制，能索引代码、文档、日志和 PDF，对外给 Elasticsearch 兼容 API 和 MCP。Agent 不再整文件读，只拉命中的段落，回答里直接带文件和行号引用。

图为 xerj-org/xerj 仓库 OpenGraph 头图。作者原话：这类检索只在模型没见过代码时有效。

项目方报了两组自家基准数：XERJ 方案输出 token，约是 grep 直读的三分之一（2.7 倍），纯记忆问答的二十六分之一（26 倍）。涨得也快：从上一篇介绍时的 4.2k star 到约 19.1k，版本到 v1.0.0-rc.102（2026-11-06 发布）。

我的读法分两半。token 账是实的：私库场景下整文件读，本来就是浪费。但 2.7 倍、26 倍都是项目方自报基准，没有独立复现，引用得挂上这句。落地先小规模对照：同一批任务，一路全文塞上下文，一路 XERJ 按段落拉，输出 token 和答对率各记一笔，再决定换不换。

超时不等于失败：给工具调用加上幂等#

Rudratosh Shastri 那篇，是最贵的一种漏水。Agent 调支付工具：第一次其实成功了，响应丢了，Agent 看到超时又调一次，用户被扣两次。例子里那张发票是 INV-2048，480 美元。

图源：Rudratosh Shastri 原文配图，第一次扣款成功、响应丢失、第二次调用造成重复扣款。

原文关键句说得很准：超时只说明调用方没收到响应，不说明服务端没提交。服务端那边可能是成功，调用方这边是未知。把未知当失败处理，重复副作用就来了。

Agent 把这事放大了：一条执行链上有 7 层各自可能重试——模型、Agent 框架、工具执行器、HTTP 客户端、队列、worker、支付 SDK。单看每层都在帮忙，合在一起就是重复扣款。

解法是一套组合，关键是把两个 ID 拆开：

  • tool_call_id（如 call_A123、call_B456）标识某次调用，重试会变；
  • operation_id（如 op_9f71c3）标识用户的一次真实意图，重试必须复用。

新调用 ID 绝不能自动等于新支付操作。服务端用 operation_id 当幂等键（Idempotency-Key: op_9f71c3），下游透传同一个稳定键。

工程细节原文给全了：Postgres 操作台账（tool_operations，主键租户+operation_id）、7 态状态机（PENDING / IN_PROGRESS / SUCCEEDED / UNKNOWN / RECONCILING / RETRYABLE / FAILED_FINAL）、请求指纹 SHA256(租户+发票+金额+币种+操作类型) 防同键不同参、事务性发件箱（transactional outbox）解决双写、指数退避加抖动。引用挂了四处：RFC 9110 第 9.2.2 节的幂等定义、AWS 的重试安全指南、IETF Idempotency-Key draft-08，还有 SQS at-least-once、Lambda 事件源可能重复投递两条官方说法。

最该抄走的是两条。超时一律先记 UNKNOWN 再走对账，不记失败；给 Agent 的返回要诚实——status: UNKNOWN / retry_allowed: false，而不是一句"失败了"，否则模型转头就会再创一个新操作。原文还列了 10 项故障注入测试，第一项就是"服务端成功、响应丢包"，对账后只能有一次副作用。

高档思考不一定高分：先算成本再开档位#

xbill 那篇是实打实的烧钱实测：7 个模型（Gemma 4 26B/31B、Gemini 3.5 Flash-Lite、3.8 Flash、Gemini 4 Hydrogen/Carbon/Argon），AIME 2025 第一卷 15 道题，每个模型用最低档和最高档各跑一遍，输出上限统一 32,768 token，预算封顶、全程记账。

图源：xbill/gemma4-dev 仓库实测封面图。7 个模型、15 道题、双档位，总花费 7.47 美元。

结论很直接：两档合计花 7.47 美元（最低档 1.53，最高档 5.95，3.9 倍），高档几乎没买到分数。Hydrogen、Carbon、Argon 在两档都是 15/15 全对；小模型各多对 12 题，但在 15 题样本上，分数差要约 35 个点才能排除运气，最大的一档增益只有 13 个点（2 题），配对检验 p 值 0.51，全都可能是噪音。

成本侧数字值得逐条记：付费模型高档是低档的 2.614.75 倍（Flash-Lite 2.61x、Argon 3.24x、Carbon 3.93x、3.8 Flash 4.20x、Hydrogen 4.75x）；Argon 最低档平均每题只想 215 token，最高档 4,129，Hydrogen 则从 2,468 涨到 15,062；耗时拉长 3.25.9 倍。单题对题成本最低是 Argon 最低档，0.0162 美元；同 15 分下 Hydrogen 最高档 0.1232、Carbon 最高档 0.1297 美元，贵 7~8 倍。另有两笔现实账：Carbon 与 Argon 输出价 2026-12-01 从每百万 10 美元涨到 20 美元；Gemma 26B 在免费档超时 2 次、7 次写到输出上限撞墙。

作者的执行建议可以直接拿去用：Gemini 4 做难数学题先开最低档；小模型是否开高档，用自己的题先测再付 2.64.2 倍的价。评论区一条复算也核过表：成本表、Wilson 区间、McNemar p 值都能从 evidence 复现，只有"4,129 对 11,61315,742"那句的区间上限混进了 Gemma 的数，读的时候以 Step 6 分模型表为准。

三件事其实是一件事：给 Agent 建一本账#

三篇拼在一起，动作清单只有三条：读侧按段落拉（XERJ 路线，先小规模对照 token 和答对率）；写侧按 operation_id 去重（台账+指纹+UNKNOWN 对账，超时不判失败）；想侧先低档起步（难数学题上 Gemini 4 最低档已满分，按 12 月新价重算预算）。三笔账都先在小样本上复算一遍：XERJ 的 2.7 倍、幂等的 10 项注入、思考档的 3.9 倍，各自原文都留了复现路径。

诚实声明：XERJ 的 token 倍数是项目方自报基准，我没跑；幂等篇是工程方案不是实测，无独立验证；思考档的数字来自作者公开的 replies、logs 与 derived 表，评论区已有第三方复算成本表一致。Argon 最低档 0.0162 美元按涨价前输出价算，12-01 后翻倍。

常见问题

XERJ 能直接替代 grep / 向量库吗？

看场景。它的卖点是本地单二进制、按文件行号给引用、Agent 按需只读命中的段落；输出 token 自报比 grep 少 2.7 倍、比纯记忆问答少 26 倍。但这是项目方自报基准，无独立复现，私有库先小规模对照再换。

Agent 调支付接口，最小可用的一套幂等怎么做？

三件：服务端生成的 operation_id 且重试复用；请求指纹（租户+发票+金额+币种+操作类型）防同键不同参；超时写 UNKNOWN 走对账、不写失败。下游支持幂等键就透传同键，不支持就按商户号查单。

Gemini 4 做难数学题，思考档位怎么开？

这组 15 题实测里三款 Gemini 4 最低档已是 15/15，直接开最低档：Argon 最低档每道对题 0.0162 美元。注意 Carbon 与 Argon 输出价 2026-12-01 翻倍，账要按新价重算。
