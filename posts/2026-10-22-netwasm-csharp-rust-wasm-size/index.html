C# 在 Wasm 体积上反超 Rust：47,895 对 53,635 字节，但对照条件要拆开看

NetWasm 把 C# 编译到 47,895 字节的独立 WASI 组件，比 Rust 的 53,635 小 10.7%。我把仓库数字、对照条件差异和 HN 104 条评论里的三个争议点拆了一遍。

October 22, 2026 · 1 min · 209 words · 梦兽编程 -  | 

一个 258 star 的仓库（2026-08-10 建），本周在 HN 拿了 160 分 104 评：NetWasm——一套独立的 C# / .NET CIL → WebAssembly 编译器和运行时，作者 zion-sati 一个人写了 256 次提交。README 开头一句话：「C# now beats Rust on Wasm size」。

数字先摆出来（全部来自仓库 README 现值）：

工具链原始 WasmBrotli-11角色
NetWasm（Compact GC）47,895 B13,660 B独立 WASI P2 组件，含运行时 + 精确 GC
Rust 1.95.0 体积档53,635 B16,963 B同条件对照
Kotlin 2.4.0 wasmWasi79,293 B22,655 BP1 参照
TinyGo 0.39.093,043 B26,931 BP1 参照

同一个 print-42 工作负载：Rust 小 10.7%（原始）、小 19.5%（Brotli 压缩后）。

对照条件必须先说清#

README 自己写了对照条件：Rust 侧不是裸 cargo build，而是叠加了 Cargo 文档化的全部体积设置——opt-level = "z"、LTO、单 codegen unit、panic = "abort"、strip 符号。NetWasm 侧的 wasm-opt 不是后处理步骤，是编译器流水线内置的，每次普通构建都跑。

这意味着「Rust 输 10.7%」的前提是 Rust 已经打满体积档设置。HN 上 drhagen 直接列了 Rust 还能再压的一长串：去位置信息、清 debug formatter、按体积重编 stdlib、panic 不带错误信息（引 min-sized-rust 那套「更怪的做法」）。所以更准确的表述是：在 Rust 常规体积档之上，还有多少压空间取决于你愿意走多深。

HN 三个争议点（104 条里挑实的）#

  1. 「不公平比较」（sondr3，首评）：C# 侧有后处理，其他目标没有。作者回应（torginus）：Rust 侧同样叠了体积档；而且这个仓库的重点不是赢基准，是打 Blazor——官方 .NET WASM 构建动辄 10MB+，NetWasm 把这条基线砍到 14KB（Brotli 后）。
  2. 「跨语言基准可以直接忽略」（xxs）：基准本来就难做，托管语言更难，写基准的人得同时是两门语言的专家。这条下面有回怼（galangalalgol）：基准真正的价值是暴露取舍，不是排名。
  3. 双标质疑（pjmlp）：C 用非标准 freestanding 扩展算，Rust 用 no_std 算，别的语言做类似的事就不算同一门语言了。

和本系列前两篇的关系#

10-05 发 Topcoat、10-18 发 Proa，都在测「Rust 写 Web 有多快」。这篇是第一次站在 Rust 的对面：有工具链在体积上把它按下去了。结论写进 FAQ 那句——单一工作负载测量结果，不是语言级排名。真正值得记住的是第二个数：Blazor 官方 WASM 常超 10MB，NetWasm 同类负载 13,660 B（Brotli 后），差 740 倍，这个差距跟 Rust 没关系，是 .NET 生态自己的事。

常见问题

47,895 和 53,635 是什么对照条件？

同一个 print 42 工作负载，两个工具链各自的标准构建产物（独立 WASI Preview 2 组件）。Rust 侧已叠加 Cargo 官方体积档（opt-level=z、LTO、单 codegen unit、panic=abort、strip），NetWasm 侧的 wasm-opt 是其编译器流水线内置步骤。

能说 C# 全面比 Rust 小吗？

不能。这是单一工作负载的测量结果，不是语言级体积排名。HN 高赞评论直接说跨语言基准可以忽略；作者自己在仓库也注明「measured workload/profile result, not a language-wide size ranking」。

本机复现了吗？

没有。本机无 .NET SDK 也无 rust wasm32 target，全部数字引自 NetWasm 仓库 README（仓库 258 star，2026-08-10 创建），未独立复跑。
