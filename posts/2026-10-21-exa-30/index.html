Exa 3.0 八个 benchmark 全第一：91.8 分里最该看的是那个 0.3 的差距

Exa 10-19 发 3.0：八榜自报全第一，但 BrowseComp 领先 Perplexity 只有 0.3 分。真正改成本曲线的是 Dynamic Highlights（省 95% 上下文 token）+ Exa Lite $4/1000 请求；Artificial Analysis 独立评 80 分并列第一。

October 20, 2026 · 2 min · 373 words · 梦兽编程 -  |  English

Exa 10 月 18 日发了 3.0，官方通稿的原话是"我们在每个测试的 benchmark 上都排第一"。八个榜：BrowseComp 91.8、DSQA 88.2、WideSearch 56.1、ATLAS 42.0、WebCode 75.5、FinSearchComp 68.0，外加 Company/People FindAll 两个垂直检索。对手是它自己点名的 Perplexity、Brave Search、Parallel。

先说结论：这是把"agent 用的搜索"当军备竞赛打了一轮，但最值钱的信号藏在 91.8 那个数字的旁边——BrowseComp 上 Exa 3.0 领先 Perplexity 只有 0.3 分。八榜全第一的标题下，主榜是贴着对手跑的。

进步从哪来：没有新算法叙事#

官方把 3.0 的收益全归到三件堆料的事：最大的 embedding 模型（更多算力、更多数据训出来的）、数百亿新文档（商品、本地商家、航班、体育、天气这些以前搜索 API 不认真覆盖的垂直面）、Dynamic Highlights 转 GA。

没有新架构，没有新训练技巧，通稿里最硬的一句承认是"我们不是在声称一个聪明的新技术，我们是在检索精度这个真正决定胜负的地方上堆输了全场的算力与数据"。这对用户是好消息：检索质量的提升来自索引和 embedding 规模，不是调参玄学，后续版本还可能有得抢。

Exa 跑自己的 crawler 和 index，不包 Google/Bing，官方说法是 2T URL、服务 100B 页面，托管 API 延迟可配 450ms~1s。

最该看的数字是 0.3#

自报榜的水分先放一边（毕竟对手是 Exa 自己选的，榜也是它自己定义的），把第三方交叉摆进来：Artificial Analysis 的独立 Search Index（统一用同一个 agent 模型 + 开源 Stirrup harness 测 29 家产品），Exa 3.0 Auto 档加 Dynamic Highlights 打 80 分，和 Perplexity 并列第一；Lite 档 79。Dev.to 开发者社区 20 个 agent 搜索维度的评分，Exa 8.7，Perplexity 6.8，Tavily/Serper/Brave 挤在中间；一个独立的 500 query 评测，Exa 准确率 64.8% 对 Perplexity 60.1%。

两套外部数字都确认 Exa 领先，但领先幅度（并列第一、0.3 和 4.7 个点）跟"八榜全第一"的标题完全不是一个量级。Artificial Analysis 还顺手记录了 Exa 自己的表没有的东西：Auto 档每任务 token 从 29.9 万降到 15.7 万（-47%），成本从 $0.083 降到 $0.066（-21%），Lite 档 $0.044——Dynamic Highlights 的收益是落在成本曲线上，不只在质量表里。Exa 自己的 ATLAS 42.0 也是八个榜里最弱的一项（领先优势最大的反而在这里，42.0 vs 37.2）——主检索榜贴身、弱项榜拉开，这个形状说明 3.0 的提升偏"全面垫高"而不是"单点突破"。

我的判断：Exa 3.0 的真实地位是把 agent 搜索的质量基线又抬了一截，但没有拉开代差。选型别只看它家榜，拿自己的 query 集对 Perplexity/Tavily 跑一轮 20 个维度的维度分（Dev.to 那套方法就行），领先 5 个点以内等于没有领先。

真正改成本曲线的：Dynamic Highlights + $4#

这版里比"全第一"值钱的是两条定价与产品动作。

Dynamic Highlights 从网页里只抽相关片段，自报比喂整页省 95% token 且答案质量不降。搜多轮的 agent 循环里，预算大头不是 API 调用次数是上下文 token，这条如果外部复现，等于把 agent 搜索的单轮成本砍掉一大截。95% 是 Exa 自报，第三方评测 64.8% 的准确率里没有单独拆出 Highligths 的贡献——这是下一个该被社区复现的点。

Exa Lite 定价 $4/1000 请求，配合 Auto 档（每查询多烧算力）形成明确的两档。高并发 agent 场景的账是算得过来的：1000 次请求 $4，按 Dynamic Highlights 的 token 节省量级，搜索侧可以压到整个 agent 预算的个位数百分比。这是 Exa 从"研究者玩具"往"可规模化基建"走的一步，50 万+开发者、5000 家公司的接入清单（Cursor、Cognition、HubSpot、OpenRouter、monday.com）就是这一步的底盘。

四行总结#

项 Exa 3.0 数字 来源 判定
BrowseComp 91.8（领先 Perplexity 0.3） 自报 主榜贴身，非代差
独立 500 query 准确率 64.8% vs 60.1% 第三方 确认领先，幅度 4.7
Dynamic Highlights 省 95% 上下文 token 自报，待复现 agent 成本曲线的真变量

FAQ#

八个榜全是自己跑的？ 是。Exa 选对手、定榜、出分一条龙。外部参照只有 Dev.to 维度评分（8.7 vs 6.8）和那个 500 query 评测（64.8 vs 60.1），两个都比官方标题保守。

我该怎么选型？ 先算你的场景是"搜得多"还是"搜得准"。高频检索 agent 循环上 Lite + Dynamic Highlights 先跑起来，成本占位；关键决策链上拿自家 query 集把 Exa/Perplexity/Tavily 三家跑同一套维度分，5 个点以内不分高下。

95% token 节省可信吗？ 机制上可信（抽取替代全文），幅度是 Exa 自报。等第三方评测把 Highlights 单独拆开再信数字，现在按"成本会明显降"记，不按 95% 记账。

能给我的产品直接接吗？ API 是标准 REST，支持 output_schema 结构化输出和 LLM 摘要。延迟分五档：instant ~250ms / fast ~450ms / auto ~1s / deep-lite 4s / deep 4-15s，按你的交互性选档。

Exa 和 Google 什么关系？ 没有包它的索引，Exa 自建 crawler + 2T URL 索引。定位差异也清楚：Google 排序给"人"看，Exa 的结构化结果给"另一个软件"用，用户是 agent。

结尾#

“八榜全第一"是通稿标题，贴出 0.3 分才知道真实的领先幅度。Exa 3.0 真正改牌的信号是两条产品动作：Highlights 把上下文成本砍到官方自报的 5%，Lite 把搜索侧变成可规模化的预算项。agent 搜索的第一阶段价格战，从这两个数字算。

常见问题

benchmark 是谁跑的？

Exa 自己。8 个榜（BrowseComp/DSQA/WideSearch/ATLAS/WebCode/FinSearchComp 等）全部自报，对手（Perplexity/Brave/Parallel）是 Exa 点名选的。第三方交叉：Dev.to 维度评分 8.7 vs Perplexity 6.8，独立 500 query 评测 64.8% vs 60.1%。

进步从哪来？

官方说法：训了它史上最大的 embedding 模型（更多算力+更多数据）+ 数百亿新文档（商品/本地商家/航班/体育/天气）+ Dynamic Highlights GA。没有新算法叙事，就是堆料堆数据。

Dynamic Highlights 是什么？

从网页里抽相关片段替代整页文本，自报比全页省 95% token 且答案质量不降。对搜多轮的 agent 循环，上下文 token 才是预算大头，这条如果外部复现，成本曲线直接改写。

Exa Lite 贵不贵？

$4/1000 请求，主打高并发 agent 场景。另有 Exa Auto 每查询多烧算力换质量，延迟可配 450ms~1s（deep 档 4-15s）。

能替代 Google/Bing 吗？

不能，也没打算。Exa 跑自己的 crawler+index（声称 2T URL、服务 100B 页面），产品定位是给 agent 的结构化检索 API，不是给人看排序页。
