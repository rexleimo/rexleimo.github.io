没有 N 卡的机器上，我把 NVIDIA 的闭源网络拆到能拆为止

NVIDIA 的 DLSS 5 神经渲染网络，被人用纯 Vulkan 重实现到 75 个 block 边界逐字节对齐。我手上这台机器没有 N 卡，验不了它最招牌的 GPU bit-exact。但我把仓库浅克隆下来读了源码、核对了 71-block 图、本机真跑了一条 PTX 除法器回归——把能拆的拆到能拆为止，能说的就说我能说的，跑不了的我写死跑不了。

October 1, 2026 · 3 min · 578 words · 梦兽编程 -  |  English

NVIDIA 的 DLSS 5「神经渲染」网络，被人用纯 Vulkan 重实现到了 75 个 block 边界逐字节对齐。不是「跑通个大概」，是 bit-exact。

我手上这台机器没有 N 卡（nvidia-smi 直接给我 command not found），所以我验不了它最招牌的那件事——GPU 侧的 bit-exact parity。但我没就停在那。我把仓库浅克隆下来，读了它的 src/nr_graph.h（kBlockCount = 71 跟 README 对得上）、数了 13 个 GLSL 参考核、本机真跑了一条它自带的 PTX 除法器回归测试——能拆的我拆到能拆为止，能说的就说我能说的，跑不了的我写死跑不了。

这篇讲我实际干到了哪一步。每个数字都指回我 grep 到的行号或者我重跑的输出，没复现就标「没复现」。

它到底是什么#

我读 docs/network.md 读出来的第一件事：它不是上采样器。docs/network.md:27 原文写着 The network is resolution-preserving——输入输出同分辨率。它做的是「重新渲染引擎已画好的那一帧」：从 3 路注入的高斯噪声里生成细节，按 style / tone / structure / skin 四个条件微调。

docs/network.md:7-8 把输入输出写得很清：

输入特征：f32 [fullHeight * fullWidth][16]   （16 个通道）
输出 head：f32 [fullHeight * fullWidth][4]    （RGB residual + 1 个 temporal-blend logit）

README:18 那句 Input and output are the same resolution; it is not [an upscaler] 把边界钉死了。

网络结构：我 grep 出来的 71#

src/nr_graph.h:40 那行 static constexpr uint32_t kBlockCount = 71; 是我读源码时最实的一锤：71 个 block，README:5 原话说 The same 71-block Swin / ViT network as DLSS-NR build 310.8.0。

README:16 把关键参数一句话说全：FP8 (E4M3) activations with FP16 accumulation, 141 MiB of weights。

我 ls shaders/*.comp 数出来的 GLSL 参考核是 13 个：fused_block32 / gemm_f16 / gemm_fp8 / gemm_mlp / gemm_reduce / global_attend / global_attention / global_normalize / ops / preprocess / qkv_attention / window_attend / window_normalize。E4M3 字面出现在其中 10 个文件里（grep -rln 过），分布跟 docs/numerics.md 描述的对应。

我本机真跑通的那一条#

这台机器没有 N 卡，跑不了 GPU 侧 parity。但仓库 scripts/ptx/ 下有个 test_fast_divmod.py——纯 Python，不依赖 GPU，它解释 PTX fast path 生成的除法器指令、跟精确无符号除法比对。我本机跑了两次：

$ python3 scripts/ptx/test_fast_divmod.py
fast_divmod: every n < 2^24, d = 1..32: exact

这是我能对这篇文章说「我跑了」的那一条。不是性能数字，不是 bit-exact parity，就是一条 PTX 除法器的回归测试，在本机（无 N 卡）上过了。

我跑不了的部分，我怎么说#

我把边界写死，不混：

  • GPU 侧 bit-exact parity：本机无 N 卡（nvidia-smi 不存在），没复现。仓库的 parity 命令需要 NVIDIA Ada+ 暴露 VK_KHR_cooperative_matrix / VK_NV_cooperative_matrix2 / VK_EXT_shader_float8 / VK_NV_cuda_kernel_launch 四个扩展（README:88-89），我没有这个硬件。

  • 性能表：README:59-64，RTX 4070 SUPER, whole network per frame, minimum over 40 frames：

    分辨率时间
    768×7682.8 ms
    1920×10807.8 ms
    2560×144012.6 ms
    3840×216029.3 ms

    这是作者机器上的数字，我没测。README:61 自己说了「The GPU alternates between two clock states under sustained load, so medians run a few percent higher. Compare minima.」——所以对比时看最小值，不是中位数。

  • 141 MiB 权重：README:16 说 141 MiB of weights，README:109 说权重目录不随仓发行（Nothing in this repository produces such a directory）。要跑，得自备模型目录。

  • WebGPU 浏览器移植：ports/browser-webgpu/README.md:188 原文：A warm frame at 512×512 is 73 ms across 451 dispatches, against about 2.7 ms for the Vulkan implementation on [the same GPU]。我核对了那个目录里 27 个 .ts/.wgsl/.mjs 文件的体量，但本机无 Chrome，parity 没跑。

精确在规格，不在硬件。 这是我对 README:79 那句 the exactness is in the specification, not in the hardware 的理解——WebGPU 移植没有 tensor core、没有 FP8、没有融合、没有 chaining，但字节一样。差 26 倍（73ms vs 2.7ms），但精确性不变。

我读代码时的一个判断#

这是规格级复刻，不是功能复刻。README:109 说 a model with a different block count is refused at load——它只认 71-block 的 310.8.0 网络，别的直接拒。权重闭源不随仓，「免费用上 DLSS 5」这件事它做不了。它的价值在把 NVIDIA 报告里没讲透的执行细节摊开：13 个可读的 GLSL 核 + Python 生成器产的 PTX，每一条都能对着 docs/ 下的 6 篇文档（network / execution / numerics / weights / frame，共 1037 行）一行行对。

我浅克隆了这个仓（research/opendlss-repo/），docs 六篇拷到 research/opendlss-docs/，正文深挖时逐条引。

收尾#

没有 N 卡，我就把源码和测试拆到能拆为止。71 个 block、13 个核、E4M3 分布、141MiB 权重、16 入 4 出、同分辨率非上采样——这些我本机 grep 出来、行号对得上。PTX 除法器回归我本机真跑了，输出是 every n < 2^24, d = 1..32: exact。

GPU 侧 bit-exact、4070S 性能表、WebGPU parity——我没复现，标「来自作者 README」。不混。

这是我能对它说的话。

FAQ#

Q：我能直接拉个权重跑起来吗？ A：不能。README:109 说 Nothing in this repository produces such a directory——141MiB 模型目录 NVIDIA 不随仓发行。你得自己搞到一份 310.8.0 build 的权重，格式是 manifest.json + stage files（packed E4M3 bytes）。

Q：没有 N 卡，我能验到哪一步？ A：源码核对（71 blocks、13 核、E4M3 分布）+ PTX 除法器回归（本机纯 Python，不依赖 GPU）。再往上的 parity / 性能 / demo 都要 GPU 或 Chrome，我本机停在这。

Q：72ms vs 2.7ms 那 26 倍差，哪个数字是作者测的？ A：都是作者 README 里的数字（README:79 + ports/browser-webgpu/README.md:188），我本机没跑。但那个 27 文件体量的 WebGPU 移植目录我核过，代码量跟描述对得上。

Q：OpenDLSS 的价值在哪，不是免费用 DLSS 5 吗？ A：不是。价值在规格级复刻——把 NVIDIA 报告没讲透的 71-block 执行细节用 13 个可读核 + PTX 生成器摊开，对着 docs 6 篇一行行对。权重闭源不随仓，「免费用」这条它做不到。

Q：我本机到底跑了什么？ A：scripts/ptx/test_fast_divmod.py，输出 fast_divmod: every n < 2^24, d = 1..32: exact，重跑 2 次都过。这是唯一我能写「我跑了」的那条。其余标来源：本机 grep / 作者 README / NVIDIA 报告，三分不混。

诚实声明#

  • 我把仓库浅克隆到 research/opendlss-repo/（本机无 N 卡，跑不了 GPU 侧 parity / demo / WebGPU）。
  • 本机已跑：scripts/ptx/test_fast_divmod.py（PTX 除法器回归，输出 every n < 2^24: exact）+ 源码核对（kBlockCount=71、13 个 .comp、E4M3 分布、docs 六篇 1037 行）。
  • 未复现：Vulkan fast path / GPU 侧 bit-exact parity / 性能表（4070S）/ WebGPU parity（无 Chrome、权重自备）。这些数字来自作者 README / NVIDIA 报告，不写「我测的」。
  • 每个数字标来源：本机输出（PTX 回归、grep 行号）/ 作者 README（141MiB、性能表、72ms/2.7ms、bit-exact 结果）/ NVIDIA 报告（网络结构描述），三者不混。

**你是哪一派：规格级复刻算不算「真正开源」？你手里有没有一份 310.8.0 的权重，打算怎么用？评论区晒一下，我攒够一批出一篇：在你机器上把那份权重喂进 OpenDLSS，跑通 parity 命令，把 75 个 block 边界的 bit-exact 输出贴出来。转给那个还在到处 .unwrap() 的同事。微信搜索「梦兽编程」。

常见问题

你验了哪些？哪些没验？

验了（本机真跑）：PTX 除法器回归测试（输出 every n < 2^24, d = 1..32: exact，重跑 2 次都过）；源码核对 71-block 图（src/nr_graph.h:40 kBlockCount = 71）；13 个 GLSL 核的数量与分布；WebGPU 移植 27 个文件的体量。没验（本机无 GPU 跑不了）：Vulkan fast path 的 GPU 侧 bit-exact parity、性能表数字（4070S 上 2.8~29.3ms，作者机器测的）、141MiB 权重加载。

OpenDLSS 是干什么的？能让我免费用上 DLSS 5 吗？

不能。权重 NVIDIA 不随仓发行，你得自备 141MiB 的模型目录。这个仓库的价值不是'免费用上 DLSS 5'，而是把 NVIDIA 报告里没讲透的 71-block 执行细节用 13 个可读 GLSL 核 + PTX 生成器摊开给人读——规格级复刻，不是功能复刻。

本机到底能跑它的哪部分？

能跑的：PTX 除法器回归（纯 Python，不依赖 GPU）。不能跑的：所有 GPU 侧验证（无 N 卡）、WebGPU 验证（无 Chrome、权重自备、fixture 不在仓里）、demo（Windows + NVIDIA 专用）。我能对这篇文章说的'我跑了'只有那一条 PTX 回归 + 源码 grep 出来的行号，其余标'来自作者 README'。
