这周有一门新语言在程序员圈子里冲了个顶：Aardappel（做 Bitcoin 钱包库出名的作者）放出 Goose，官网第一句就是「比惯用 C++ 快 3.5 倍、比 Rust 快 1.1 倍，内存还省 25%」。三个数字摆在一起，Rust 读者没法不点开——它直接动了「Rust 已经是安全语言里最快那档」这个共识。

我没打算只看官方那张表。这篇文章我干的事：把它 16 个官方 benchmark 里的 4 个，在我自己这台 2 核 EPYC（9354P）上逐条复跑，看这三个数字到底是玄学还是能复现的。先说结论：「比惯用 C++ 快 3.5x」我能坐实，量级对得上；「比 Rust 快 1.1x」在我复跑这几条上基本是打平，真正拉开的是内存。

一、它凭什么没有 GC 还没堆#

先讲清机制，不然倍数没意义。落到语言层就一句话：没有堆分配器、没有 GC、没有 lifetime 标注。动态值全放在编译器划好的 data stack 里，作用域结束指针一退就完成释放，free 一个百万元素结构就是一次 store。

几个设计点，每个都对应后面的 benchmark：

  • 窄 link：结构里的指针换成 1/2/4 字节相对偏移，结构本身就成了文件格式，存是写、读是加一次校验。
  • 内置构造：items.push(parse(line)) 直接构造到最终位置，没有出参，没有二次搬运。
  • enum 按实际大小存：可变长 ADT 每个 variant 付自己那份，官方说比 Rust 的 enum 省 4 倍内存、快 2 倍。
  • 跨调用返回：return err from load 能一路弹栈，不用 Result 不用 ?。

二、我复跑的 4 个 bench#

环境先钉死：我这边是 AMD EPYC 9354P（用 2 核）+ gcc 13.3 + rustc 1.99；官方那张表是 Windows 11 + Ryzen 9 9950X3D + MSVC/clang + rustc 1.98。CPU 和 C/C++ 工具链都不一样，所以我复的是「方向和量级」，不是逐格复刻。

四条 medium 档，全进程墙钟（含生成输入 / 建结构 / 销毁，官方就是这么测的）：

sum：构造 1600 万个 i32 再扫 8 遍。Goose 103.4ms，惯用 C++ vector 194.7ms（1.88 倍），加 reserve 的 C++ 140.2ms（1.36 倍），Rust Vec collect 104.0ms——Rust 那条反而快了 0.6ms，打平。

push：推 1600 万条 record、每 64 条留个指针。Goose 138.3ms，惯用 C++ 249.0ms（1.80 倍），reserve C++ 150.1ms（1.09 倍），Rust Vec+reserve 143.7ms，打平（0.96 倍）。

strlist：文本切成 200 万个词存列表扫 4 遍。Goose 150.2ms，惯用 C++ 331.5ms（2.21 倍），Rust Vec 311.4ms（2.07 倍）、Rust Vec<&str> 158.6ms，打平（0.95 倍）。

records：建 400 万条 variant record 再聚合 4 遍。这条最能体现「representation 决定一切」——Goose 可变 enum 143.2ms，惯用 C++ 489.7ms（3.42 倍），Rust enum+String 327.5ms（2.29 倍）。注意 Rust 这条用的是「每格按最大 payload 预留」的 enum，Goose 用的是按实际大小的，所以差距大。

三、三个数字逐个拆#

「比惯用 C++ 快 3.5x」——坐实了。 我 4 条对惯用 C++ 是 1.88 / 1.80 / 2.21 / 3.42，几何均值 2.3 倍，量级跟官方 16 条全量几何均值 3.51 倍在一个方向上。它快的来源很干净：整进程计时下，惯用 C++ 要付 vector 扩容、unique_ptr 分配、enum 最大 payload 预留三份账，Goose 的 data stack + 窄 link + 内置构造直接绕开了。

「比 Rust 快 1.1x」——在我复的几条上没接住。 官方那个 1.13 / 1.19 是「16 个 bench 里每条挑最快的 safe Rust 行再取几何均值」。我这边默认写法：sum 打平、push 打平、strlist 借用版打平。真正把 Rust 甩开的是 records 那种「大 payload enum / 堆上 String」场景（2.29 倍），靠的是 representation，不是语言本身。所以更准确的表述是：速度上 Goose 和 safe Rust 基本同档，它真正拉开的是内存（官方 1.25 倍）和你不用写 lifetime / arena / index 那套样板。

四、先别急着换语言，看这三条边界#

  1. 它是「受限」的。没有 GC，意味着你得能静态定死有几个 growable 区、每个多大。能定死的场景（解析器、确定性数据流、定长池）它飞快；写不定就还是得自己管。有人一句「一门语言不用代表所有程序」说的就是这个。
  2. 环境差异是实打实的。官方数字在 9950X3D + MSVC，我在 9354P 2 核 + gcc。倍数会随 C 后端漂移，官方自己都写了「同一工具链下 MSVC 的 C 和 clang 的 C 都会掉」——别拿 3.5x 当普适常数。
  3. 编译链路。Goose 先编译成 C，再用 gcc/clang/MSVC 编那个 C，预编译发行版把 gfx / audio / ui / physics 编进去了，约 10MB。它不是 drop-in，是有配套 runtime 的。

五、结论#

Goose 不是 Rust 的替代品，是另一条路线：把通用性全押给专用场景，换回速度 + 内存 + 零样板。对 Rust 读者真正值得带走的一句话：官方「比 Rust 快 1.1x」里，速度的那一截基本是打平的，别被那个 1.1 骗了，它真正的红利在内存和省心，不在吞吐。 我复跑的 4 条里，sum / push / strlist 三条 Rust 都稳稳接住了 Goose，只有 records 那种重 payload 场景 Goose 才明显领先。

你们手上有没有「能静态定死内存布局」的活儿？我手上正好有个解析器 + 定长池的场景想试 Goose 的 data stack，跑出来贴这儿。另外想问问：你们看新语言 benchmark，第一反应是复跑还是直接看官方表？我是那种不复跑就不信的人。
