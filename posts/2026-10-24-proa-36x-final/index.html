Proa 官方号称比 React 快 36 倍：我在 2 核机器上复跑了 7 个渲染器，结论一半成立

Proa 官方 10-21 scoreboard 写着比 React 快 36.3 倍。我把官方 7 渲染器基准仓拉到 2 核 EPYC 上复跑：36 倍只在 25KB 小页面上成立，1000 行大表格离 memcpy 地板还有 23.5 倍距离，Askama/Sailfish 反超的格子也复现了。

October 24, 2026 · 3 min · 610 words · 梦兽编程 -  |  English

Proa 官方基准表上写着 component 页渲染 2.00 微秒，比 React 快 36.3 倍。这组数字我复跑了。2 核 EPYC、官方 7 渲染器基准仓原样跑，36 倍在 25KB 的小页上方向成立，但 1000 行大表格里 Proa 离物理地板还有 23.5 倍的距离。快是真快，「快 36 倍」是把最利好的工况挑出来讲的故事。

这篇文章拆四件事：Proa 到底在赌什么、官方 scoreboard 里官方自己保留的反直觉数据、本机 7 渲染器复跑的完整数字、以及拉仓编译时踩的两个坑。机器、版本、命令全部落在文末，可复现。

36 倍只在小页面上成立#

Proa 是 10-15 上的 Show HN（106 分，今天重新回到 HN front page），定位是 Rust 写的 Web 框架，主打两条：服务端渲染极快，多目标渲染（同一套组件代码同时出 HTML 给人、出 Markdown 给 agent 读）。它的赌注是把「渲染」当成一个序列化问题：模板在编译期固化，热路径零分配，最终就是往字符串里写 token，没有运行时布局引擎。

这个赌注决定了它的成绩单形状。小页面、无交互、纯静态结构，就是字符串拼接本身，Proa 拼得比谁都快；页面越大、数据越重，速度天花板越早顶到数据搬运上，框架本身省下来的那点时间就被摊薄了。

机制上可以把渲染拆成三段：模板实例化（把组件树展开成标签序列）、数据填充（把字段值写进标签之间）、序列化输出（转义、写缓冲）。虚拟 DOM 路线在前三段里都摊时间，Proa 把前两段压缩到接近 0，剩下的就是第三段。小页面上第三段几乎等于数据本身的搬运，所以 36 倍能成立；大表格里模板展开成本随数据量线性涨，框架逻辑重新变得可观，倍数自然塌。本机 7 渲染器实测正好把这个形状量出来了，先看官方自报，再看我这边对不上和能对上的是哪些。

多目标渲染这条线值得单独说。同一套组件代码，服务端出 HTML 是常规动作，出 Markdown 给 LLM 读是 Proa 的差异化卖点：agent 不需要解析 DOM，Markdown 是它原生语言。官方 benchmark 里 products 页（96 卡加 480 星）就是为这条线准备的——数据里带富文本字段，人看是 HTML 表格，agent 看是 markdown list。这条卖点没有竞品对照（Leptos/Dioxus/Topcoat 都不出 Markdown 目标），本文只记事实：多目标渲染目前只有 Proa 给完整实现。

官方 scoreboard：官方自己保留的反超格#

官方基准仓（proa-benchmarks）跑的是 Apple M4 Max，当前 scoreboard 是 2026-10-21 的 capture（10-15 上 HN 时是 09-05 版 35.4 倍，四天后又刷了一轮）。三个页面的结论：component 页 2.00 微秒，React 72.7 微秒，36.3 倍；1000 行 table 0.25ms，React 3.64ms，14.3 倍；product grid 0.026ms，React 0.40ms，15.4 倍。倍数从 36 掉到 14，掉得比大多数人预期的快。

官方 scoreboard 里还留着自己没解释的格子：同一个 component 页，Askama 1.54 微秒，比 Proa 的 2.00 微秒还快 0.77 倍（数字小于 1 就是反超）；Askama 在 product grid 上 0.85 倍也反超，只有 1000 行 table 上落回 2.34 倍。Sailfish 在 component 页 1.17 倍、product grid 0.94 反超，table 上 2.12 倍。也就是说这两个纯编译期模板引擎在多数页面上比 Proa 更快，官方在表下注明了这些格子但没有展开。方向我在本机复现了：小页面上 Askama、Sailfish 同样反超 Proa。Proa 卖的是框架（路由、流式输出、RSJS islands 浏览器交互），不是裸渲染速度，裸拼字符串这件事专业模板引擎更熟。

本机 2 核复跑：7 渲染器 × 3 页面#

方法论先交代：官方基准仓直接跑，release 构建，每个渲染器绑在物理核 1 上跑 p50（压测器核 0，服务端核 1，loopback），对照地板是同数据量的 memcpy。官方是 M4 Max 8 物理核加双线程，我这边是 2 核 EPYC 共享 VPS，8GB 内存，rustc 1.95，proa 与 benchmarks 仓都钉在具体 commit。绝对值没有跨机型可比性，文章里只报比值。

表格读法：第一行地板是「把同样字节数复制一遍」的理论下限，任何渲染器快不过它太久，倍数就是离下限的距离。Proa 在卡片页离地板 7.2 倍，在大表格里离地板 23.5 倍——大页面的瓶颈在 989KB 数据本身的搬运，不在框架逻辑。Askama 大表格反而只有 2.0 倍，Sailfish 1.7 倍，离地板更近：纯模板引擎在数据密集页面上没有运行时开销可摊，这是官方没展开、我这边量出来的方向。

一个必须说的对照：Askama 与 Sailfish 在小页面输出 44,849 字节，Proa 输出 25,108 字节（保留了源文件缩进），字节计量不同，官方 scoreboard 对这一点有注明。语义 DOM 一致，但计时不是同一起跑线，对比时心里要有数。

冷启动：官方 8.63ms，我这边 13 到 16ms#

官方 README 写「fresh process 多久能回第一个 200」：Proa 8.63ms、4.5MiB 内存，React 69.0ms、75.9MiB，Go 15.2ms、12.5MiB。本机两轮各 3 次，spawn 到首个 200：第一轮 13、15、15ms，第二轮 15、13、16ms。量级一致，方向一致，绝对值比我这边 M4 官方数据高约 60%，共享 VPS 的调度税。内存侧峰值 RSS 17.7MB（压测前 5.6MB），React 官方自报 75.9MiB，这条差距是实打实的。

HTTP 线：单核能喂到 4000 RPS#

压测走 loopback，服务端绑核 1、压测器绑核 0，三个路由各跑 c=1、c=50、c=200：

拉仓才知道的两个坑#

第一个坑在 benchmarks 仓的 lockfile 里：它把上游 proa 主仓钉在 main 分支的一个 rev 上，上游 force-push 过一次，那个 rev 直接变成 not our ref，clone 下来 cargo 直接拒编译。我把依赖改成本地 path 指向同一棵树的 commit 才编起来。如果你按官方步骤拉仓时遇到「ref 不存在」，九成是这个，不用怀疑自己。

第二个坑是时间。本机 2 核 release 首构建，cargo 自报 6 分 33 秒纯编译（不含 git fetch），wall 计时 7 分 10 秒。对照 10-05 发过的 Topcoat 篇：同一台机器 Topcoat 首构建 3 分 57 秒。Proa 依赖树比 Topcoat 重，冷启动快 8 毫秒的代价是开发机多等两倍构建，这个账团队要自己算。

还没复跑的部分#

React、Marko 等 Node 系对照没跑（本机没有 Node 压测驱动，表格里的 React 数字是官方 M4 自报，我只背书 Proa 侧与 Askama/Sailfish/Topcoat/Leptos/Dioxus 的实测值）。RSJS 浏览器端 islands 没验（无 GUI 环境）。Proa 同时开了一条商用 Pro 组件订阅，HN 评论区有人讨论开源与订阅的边界，官方目前答复是订阅组件不进框架本体，本文不展开。

FAQ#

问：我页面都是小卡片多，该选 Proa 吗。答：卡片页 Proa 离地板 7.2 倍、比 Leptos/Dioxus 快一个量级，方向上成立；但先看你的框架依赖（组件库、生态）是否兼容 Proa 的组件模型，渲染速度只在页面结构定型后才成为主要矛盾。

问：36 倍为什么只在小页面上成立。答：渲染时间 = 框架逻辑 + 数据搬运。页面越小，数据搬运越接近 0，框架逻辑占比越大，Proa 的零分配优势越显眼；989KB 表格里搬运是 21.72 微秒的地板，Proa 510 微秒里有 23.5 倍的空间全是数据本身。

问：Askama 反超了 Proa，是不是 Proa 不如它。答：不同层级的东西。Askama 是纯编译期模板引擎，没有路由、状态、浏览器交互；Proa 的卖点里包含 RSJS islands 和流式输出，拿模板引擎的裸速度对比框架是不对等比较。

问：构建 6 分 33 秒算慢吗。答：对照同期 Rust 全栈框架（Topcoat 同机 3 分 57 秒），Proa 偏重；如果是团队共享 CI 且页面数量多，增量构建是关键指标，本文未测增量，只测了全量冷构建。

问：官方 8.63ms 冷启动可信吗。答：量级可信（本机 13-16ms 同数量级），但机型与调度环境不同，跨机器引用这组数字时注明「官方 M4 Max 数据」，别当通用值。

你是哪一派#

用 React 全家桶、把渲染速度排在生态后面的，Proa 对你的现实收益接近零；正在 Rust 里写 SSR 且页面以卡片为主的，值得拿自己的页面跑一遍官方基准仓再决定；做 agent 时代的「机器可读 Web」——同一套内容出 HTML 给人、出 Markdown 给 LLM——多目标渲染是目前 Rust 生态里只有 Proa 给完整实现的。评论区晒一下你的页面尺寸与选型，攒够样本出一篇「页面尺寸决定框架选择」的续篇。

资料出处#

官方基准仓 proa-benchmarks（scoreboard.md 当前 main，M4 Max，2026-10-21 capture；本机 10-18 跑的是 7ab85e1 版，官方 10-21 更新后 React 从 70.9 微秒变 72.7 微秒、35.4 倍变 36.3 倍，两处已按当前版引用）。Proa 主仓 README「How fast does a fresh process answer」段（冷启动 8.63ms/4.5MiB）。本机实测全部脚本在 proa-1018 项目仓（run-render-bench.sh、run-http-bench.sh、load_test.py），数据落 results/render 与 results/http，机器 2 核 EPYC / 8GB / rustc 1.95，本机数据 2026-10-18 采、官方 scoreboard 当前版 2026-10-21 capture。

常见问题

36.3 倍这个数为什么只在小页面成立？

渲染时间 = 框架逻辑 + 数据搬运。Proa 把框架逻辑压到接近 0，但 989KB 大表格里搬运本身是 21.72 微秒的地板，Proa 实测 510 微秒，离地板 23.5 倍的空间全是数据本身。页面越小倍数越好看。

Askama 反超了 Proa，是不是 Proa 不如它？

不同层级的东西。Askama 是纯编译期模板引擎，没有路由、状态、浏览器交互；Proa 的卖点含 RSJS islands 和流式输出，拿裸模板引擎速度对比框架是不对等比较。

官方 8.63ms 冷启动可信吗？

量级可信（本机 2 核 13-16ms 同数量级），机型与调度环境不同，跨机器引用这组数字要注明官方 M4 Max 数据。

我卡片页多，该选 Proa 吗？

卡片页 Proa 离地板 7.2 倍、比 Leptos/Dioxus 快一个量级，方向成立；先看组件模型和生态是否兼容，渲染速度只在页面结构定型后才成主要矛盾。
