零 API 费用、免高配 PC：我们用 ChatGPT + inkloom.im 复刻了日本爆款 AI 视频工作流

日本 AI 电影节获奖作者 あぎ 用 Pika H3 Flex 做出了零 API 费用、免高配 PC 的带声视频工作流。我们把他的三条 Floyo 工作流用 ChatGPT 翻译、拆成结构化提示词卡，发布到 inkloom.im——复制粘贴就能零成本出片。一篇可复现的提示词整理与分发实操案例。

November 20, 2026 · 1 min · 131 words · 梦兽编程 -  |  English

一条日本爆款工作流的中文复刻记录：把散落在长文里的提示词，用 ChatGPT 清洗成卡片，再放上 inkloom.im 供人取用。

最近，日本 AI 电影节 CM 奖得主 あぎ（@agi_aibusi）发了一篇长文：用 Pika H3 Flex，不买高配电脑、不付 API 费用，写一句提示词、按下播放，就能直接产出带对白和环境音的视频。他在 Floyo 上开源了三条工作流——Text to Video、Image to Video、Reference to Video，还附了 1 个月免费码。

我们读完觉得，这条路线几乎是为「提示词即产品」量身定做的：真正值钱的不是模型有多神，而是一段结构清晰、可直接复制的提示词。于是我们用一套固定的两步流水线，把它复刻成了自己的案例。

第一步：ChatGPT 做「翻译 + 结构化」#

原文是日文，三段提示词写得极细，参数却散落在正文各处。我们把它们丢给 ChatGPT，按统一模板重写成三张中文提示词卡——场景 / 主体 / 镜头 / 对白 / 声音 / 参数，一卡一用，复制即走。野生提示词就这样从「读得懂」变成「用得上」。

整理时我们刻意保留了提示词里的日语对白：出片时模型要照着这段发音，翻成中文声音就废了。归位的只是画幅、帧率、时长这些字段——比如 15 秒 / 1344×768 / 24fps，统一提到卡片的参数行，不再让人去正文里翻。

第二步：inkloom.im 做「分发 + 复用」#

整理好的提示词统一发布到 inkloom.im。用户不用翻日文长文、不用记参数——打开 inkloom.im 搜「Pika H3 Flex」，三套场景提示词一目了然，点复制、贴进 Pika / Floyo，就能零成本出片。

对做提示词的人来说，这一步把「东西写好了」变成「东西有人用了」。提示词躺在笔记里不叫产品，能被搜到、被复制、被改，才算。

结果：一条可复用的内容管线#

这就是我们说的「inkloom.im + ChatGPT」方案：ChatGPT 负责把散落的野生提示词清洗、翻译、结构化；inkloom.im 负责把它们变成人人可取、可搜、可复用的公共提示词库。一个负责生产，一个负责分发。拿到提示词的人，不需要懂日文，也不需要调参数。

三套提示词已实际发布在 inkloom.im，搜「Pika H3 Flex」即可找到——这是这篇案例能叫「实操」而不是「设想」的原因。

三条工作流速览#

Text to Video：纯文字出带声视频。示例是夏日傍晚河边散步，女方用日语说「え、また撮ってるの？」「ひとくち、いる？」，15 秒 / 1344×768 / 24fps。

Image to Video：一张照片动起来。白沙发自拍 + 三花猫伸懒腰，女方回头笑说「見て、起きちゃった」，保留原人物与服装，约 10 秒。

Reference to Video：拿角色设定图生成同人物同服装短片。粉发 + 粉色耳机 + 黄色抹胸的设定图，霓虹后巷说「ねえ、今の曲聴いた？」，10 秒。

为什么值得抄这个作业#

  • 零 API 费用：Pika H3 Flex 不按次收费，慢一点（实测得片 6–16 分钟），但免费。
  • 免高配 PC：全部在 Floyo 云端跑，本地只要浏览器。
  • 提示词现成：inkloom.im 上直接复制，省掉日文翻译和参数调试。

要提醒一句：慢是这套方案的真实代价。6–16 分钟含 Floyo 的模型加载时间，赶时效的活儿别用它；批量做样片、试提示词，倒是刚好。

常见问题

这套方案到底省了什么钱？

Pika H3 Flex 不按次收 API 费用；对照 MiniMax H3 Max，15 秒 768P 一次约 1.32 美元。工作流跑在 Floyo 云端，本地不需要高配显卡。

出片要等多久？

实测从提交到拿到成片约 6–16 分钟，含 Floyo 的模型加载时间。免费换来的是等待，不是即时预览。

在哪里拿到现成提示词？

打开 inkloom.im 搜「Pika H3 Flex」，三套场景提示词（Text / Image / Reference to Video）已整理成结构化卡片，复制即可用。
