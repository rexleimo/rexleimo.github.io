Vibe Coding 一年，我摸索出的 6 条纪律：委托单元从一行代码长到多周项目

我把 coding agent 当正式同事用了 1 年多，停掉手写代码。委托单元一年走了四个阶段，从行到多周项目。这篇是 6 条踩出来的纪律：生产环境不会消失、AGENTS.md 慷慨建、反馈回路、Skill 挑着用、设计文档和计划文件、/goal 切大活。

October 12, 2026 · 2 min · 221 words · 梦兽编程 -  | 

一年前我做过一次 Cursor 和 Claude Code 的对决，Claude Code 赢了，从那之后我就没再回头。这一年多我都在生产环境里 vibe coding，手写代码这件事基本停了。

这篇是我把这一年多捋出来的东西。先讲委托单元怎么一路变大，再讲 6 条纪律。

委托单元，四个阶段#

回头看，这一年多的演进分四个阶段。我丢给 AI 的活，每一阶段都在变大：从行，到函数，到 feature，到跨周的项目。

阶段 1：当个聪明编辑器。 一两年前我开始用 Cursor，在单个文件里改代码、搜代码库、用 typeahead。它很好用，但本质上代码还是我在写，AI 就是个带搜索引擎的高级补全。

阶段 2：agent 进场（去年夏天）。 去年夏天一切都变了。Claude Code 加 Sonnet 4 成了我的主力，我彻底停掉手写。但我那时候还特别小心：架构、接口、数据模型，经常连单个函数都是我先定好，让 agent 去填实现。我赚到了大量效率，但设计思考全在我这边。agent 执行，我出规格。

阶段 3：Opus 4.5 改掉了范围（2025 年 12 月）。 2025 年 12 月 Opus 4.5 出来，能丢给模型的量一下就变了。接口和数据模型我不用这么操心了，agent 自己扛得住。我描述结果和约束，中间的合理设计交给它定。委托单元从"实现这个函数"直接跳到"做出这个 feature"。

阶段 4：长程活（2026）。 最近我用 Codex 配 GPT 5.6 Sol 在 xhigh 推理档上跑真正的长程项目，一跑就是几周。

阶段工具委托单元我干什么
1Cursor行 / 文件聪明编辑器，代码还是我写
2Claude Code + Sonnet 4函数我出架构/接口/数据模型，它填实现
3Opus 4.5feature我描述结果和约束，中间设计它定
4Codex + GPT 5.6 Sol（xhigh）多周项目上下文工程 + 设计文档 + 实施计划，执行循环化

一个 22 阶段的项目，具体怎么跑#

阶段 4 我最近一个项目的实际链条是这样。

输入是上下文工程：把整个代码库、公开文档、前后端两个 monorepo 全喂进去。产出是一份 RFC 设计文档，再基于设计文档出一份详细的实施计划，22 个以上阶段，工作量横跨好几周。

这一步是全部里最难的。 设计和计划一旦有了，执行就坍缩成一个循环：

/goal 实施计划里第 X 个阶段 /path/to/plan

一个阶段一个目标，一次 review，重复。方向、砍需求、验收是我；跑活是它。

回头算账，智力工作几乎全部前移到了上下文、设计和计划里。这三样花掉的力气，抵得上后面好几周的执行。这个比例跟传统开发是倒过来的。

6 条纪律#

一年下来我攒了 6 条，按我自己的体会排：

1. 生产环境的 vibe coding 不会消失。 短期内它会成为生产代码的主要产出方式，至少到 agent 抢走我们所有工作之前。你还把 agentic coding 当新奇玩意或者副线实验，就落后了。问题已经不是"要不要在生产环境 vibe code"，而是"你能不能做得好"。

2. AGENTS.md 是你朋友，慷慨地建。 这条我半年前就说过，一年下来更成立了。每个仓库、每个服务、每个有非显而易见约定的目录，都该有一份 AGENTS.md。写起来很便宜，agent 自己能起草初版，而且它是有复利的：每个 session 以正确上下文开始，就不会浪费时间重新摸索。

3. 给 agent 建反馈回路。 这是拿到最高质量输出最关键的一条。验证是它的另一个名字：测试、类型检查、linter、本地 code review，任何能让 agent 自己检查、自己迭代、你还没看到之前它就已经纠偏的机制。能自我验证的 agent 和盲飞的 agent，质量差距是巨大的。如果你只投一件事，投这里。

4. Skill 是巨大的加成，前提是选对。 对的 skill 是变革性的，我现在常用的几个让 agent 真正能做的事变多了。但挑着用。用错的 skill 就是往 agent 上下文里塞噪音，比没有还糟。

5. 设计文档和计划文件，用来管长期项目。 任何跨天到跨周的活，一份设计文档加一份落盘的计划文件就是你的项目管理系统。agent 没有跨 session 的持久记忆，但计划文件本身就是持久记忆。它扛得过上下文窗口、扛得过重启、扛得过换 agent。我那份 22 阶段的实施计划就是让多周 agentic 工作变得可做的单一事实源。

6. 用 /goal 切更大的活。 /goal 是你把一个有意义的整块活丢给 agent、然后放它跑的方式。我日常最高频的循环就是：把 /goal 指向计划里的一个阶段，让模型端到端执行。一个阶段、一个目标、一次 review，重复。

一年，一条贯穿线#

一年前，生产环境 vibe coding 的意思是给 agent 一份仔细写好的规格，然后每个函数都过一遍 review。今天的意思是给 agent 一份设计文档、一份计划、一个 goal，然后 review 结果。

四个阶段穿过一条简单的线：杠杆一路往技术栈上层走。模型越来越强，能委托的单元越来越大，工程师的活越来越偏向方向、验证、判断。

我不知道第五个阶段长什么样。如果过去这一年是参照，我会比预计更快撞见它，而且会比预计的更大。

一年多过去，我还是 all in。

诚实说明：本篇改述自一篇外文长文，四阶段时间线、22 阶段计划与 /goal 循环为原作的流程，笔者未逐一复跑。
