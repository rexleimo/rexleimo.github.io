Ghostty 之父的新终端 Rex：复用器不该嵌在快终端里面

Mitchell Hashimoto 的新公司 Superlogical 放了第一个产品：终端复用器 Rex，基于从 Ghostty 提取的 libghostty，复用器即终端本体，持久会话/远程/程序活动状态是头牌，macOS 公测 10-05 开放。

October 20, 2026 · 2 min · 256 words · 梦兽编程 -  |  English

Mitchell Hashimoto 又开了一家公司，叫 Superlogical，7 月 29 日宣布，10 月 5 日把第一个产品开放了公测。产品名 Rex，一个终端复用器。一个刚把 Ghostty 捐给非营利组织、嘴上说着再也不做商业项目的人，又下场做了个终端公司——这事本身比产品值得先说两句。

为什么"又"做终端#

Hashimoto 自己讲的路径很清楚：Ghostty 是 2023 年离开 HashiCorp 后"以为会扔掉的个人项目"，最后长成了日活数百万、一打核心维护者、近 50 名本地化成员的社区项目，2025 年整体捐给联邦认证的非营利组织，法律上绑死公益属性，“永远不会商业化”。

但写终端这十几年，他越来越关心的是终端外面那一圈问题：终端用法为什么比历史上任何时候都普及？agent 时代终端 IO 的模式在往哪走？tmux 之于快终端是什么关系？这些问题他自己写着写着写不进 Ghostty（非营利项目的边界在那），就成了 Superlogical 的全部立项理由。Rex 只是入口，他原话：复用器"不是整个愿景"。

Rex 在解决什么#

现有复用器的结构是：你开一个快终端（Ghostty/Kitty/Alacritty），在里面跑 tmux/zellij，复用器再模拟一个慢终端。Hashimoto 给的自估数字是：现代终端的 IO 路径比复用器内嵌的模拟器快一到两个数量级，于是你得到的是"快终端里的慢体验"——scrollback 卡顿、选择行为怪异、滚动丢帧，全是内层模拟器的锅。

Rex 的架构主张反过来：复用器就当那个终端。它基于 libghostty（Ghostty 团队提取出的 MIT 终端库，Vercel 的 Turborepo 等已经在用它），外层原生，持久会话、远程连接、程序活动状态是主打功能。官方定位是"drop-in replacement for whichever terminal you use today"：关掉 App 会话还在，换设备接回来，远程开发直接连。另配一个 CLI 做自动化和 hook（Hashimoto 在 X 上专门秀了这个 CLI）。

这张官方截图把 Rex 的主张摊开在了一张图里：顶栏一排会话标签，每个标签是一个可远程的终端（Mac Studio 上的 rex-snake、Bun、fish 并行开着）；左上跑着代码审查的 agent 会话，左下是内嵌的 Git 交互面板（Stage/Commit/Stash 快捷键），右侧直接跑着贪吃蛇 TUI。tmux 的同类截图是黑底绿字的格子，Rex 卖的是"这个层本身就是一个应用"。

对 agent 工作流这是实打实的需求：跑着长任务的终端挂了、网络断了，会话能保下来、状态能看见、重连能接上——tmux 半吊子在做的事，Rex 把它当第一特性设计。

CLI 这层是公测期最值得玩的部分。Hashimoto 自己发推专门展示了配套 CLI：把 Rex 当自动化入口，hook 进 CI、给 coding agent 开任务、从脚本读程序活动状态。tmux 的 CLI 是 tmux send-keys 那套二十年老接口，Rex 直接把"程序活动状态"做成一等公民——一个 agent 在会话里跑到第几步、卡在哪个审批，脚本可查。公测文档里 CLI 和远程连接是并列的头牌功能，不是事后补丁。

值得警惕的地方#

三个点。

它还不是一个可迁移的工具链。公测只有 macOS，Linux 排期没给。tmux 最大的资产不是功能而是"哪台机器都有"，Rex 短期内抢不了这块，它的真实竞争对手是 zellij 和"给 Ghostty 配 tmux"的现有习惯。

公司形态和产品承诺之间存在张力。Ghostty 捐非营利是信用的来源，Superlogical 是商业公司。Hashimoto 在个人声明里特意写了"Ghostty 保持非营利，使命、治理、许可证、路线图都不变"，把两条线切开——但 libghostty 从 Ghostty 提取、Rex 的商业产品长在 libghostty 上，这条依赖链以后怎么治理，值得盯。

“持久会话层"的野心大于今天的复用器。跨设备、agent 后台任务、多人共享终端、incident response——每一项都踩在 VPC/远程开发/协作工具的成熟地盘上，这不是终端项目能自己收场的。Superlogical 真正的赌注是终端在 agent 时代的基础设施位置，Rex 只是先手棋。团队 4 人（Hashimoto、Pearkes、Monk、Simpson），全是有终端或基础设施产品背景的人，配置是为"窄深"设计的。

四行总结#

维度 Rex tmux/zellij 判定
架构 复用器=终端本体（libghostty） 快终端里的内层模拟器 IO 路径原生，快 1-2 个数量级
会话 持久/跨设备/远程 本机会话为主 agent 长任务场景赢
可用性 macOS 公测（10-05） 全平台、十年惯性 迁移成本是它自己的最大阻力
依赖 libghostty（MIT，Ghostty 提取） 无 治理方式待定，商业/公益依赖链要盯

FAQ#

Ghostty 以后没人管了？ 没。Ghostty 捐给非营利、约 12 名核心维护者持续开发，Hashimoto 仍在其中；Superlogical 的声明明确 Ghostty 的许可证、路线图不变。

Linux 用户呢？ 公测阶段只有 macOS。libghostty 是跨平台的，架构上能落 Linux，但官方没给日期，现在装只能用 Mac。

和 tmux 能共存吗？ 可以。Rex 定位是替代"终端+复用器"整条链路，不影响你继续在任何终端里跑 tmux；反过来 Rex 的会话持久化也兼容在 Rex 里跑 tmux 的老习惯。

beta 怎么进？ Superlogical 官网注册 newsletter，公测资格从 10-05 开始发。团队在招工程和设计岗位（jobs 页挂着）。

值得现在就切吗？ macOS 重度终端用户+agent 长任务多，进 beta 玩玩，会话持久化这条值得亲手验。生产主力机，等 Linux 版和第一个正式版再动。

结尾#

tmux 用了 20 年证明复用层是刚需，但它的形态还停在"跑在终端里的 shell 脚本”。Rex 赌的是这个层该原生长进终端里，并且是 agent 时代的基础设施。10 月 5 日公测才刚开始，产品判断先放一放，值得跟进的是它把"持久会话"做成第一特性之后的生态动作。

你在终端里跑长任务被断过几次？tmux 的 scrollback 你忍了多少年？评论区聊。转给那个还在服务器上 tmux attach 摸黑的同事。

常见问题

Rex 是 Ghostty 的替代品吗？

不是。Rex 是终端复用器（tmux/zellij 的同类），但它自己就是一个终端应用——开箱即带终端，会话、分屏、持久化一体。Ghostty 保持非营利，路线不变。

现在能用吗？

macOS 公测中（2026-10-05 开放），注册 newsletter 拿 beta 通道，Linux 还没说排期。

和 tmux 什么区别？

tmux 跑在你已有的终端里，是内层软件；Rex 的外层就是终端本身，基于 libghostty（从 Ghostty 提取的 MIT 库），原生支持 scrollback/选择/滚动，不经过慢复用器的 IO 路径。

Superlogical 团队都是谁？

Mitchell Hashimoto（Ghostty 作者、HashiCorp 联合创始人），Jack Pearkes（HashiCorp 第一号员工、前 VP Eng），Alasdair Monk（Poolside/Vercel/HashiCorp/Heroku），Hector Simpson（设计）。

以后会做什么？

官方说法：从终端复用器起步，愿景是跨本地开发、远程接入、coding agent、后台任务的持久会话层，支持共享终端和多人协作。
