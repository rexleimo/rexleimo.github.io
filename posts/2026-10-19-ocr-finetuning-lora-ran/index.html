SFT 教程全是公式？我把手撕 LoRA 那段真跑了：初始化输出与原模型逐位相等，7B 全参要 75.3GB

一篇基础微调教程讲清了 SFT 数据构造、Loss Mask、LoRA 低秩分解、QLoRA 量化，但所有结论停在公式。我把「手撕 LoRA + SFT 训练流程」在 2 核 EPYC 上真跑了一遍：B 零初始化时 LoRA 输出与原模型 diff=0，7B 全参显存账 75.3GB（不含激活），LoRA r=8 把可训练参数砍到 0.39%。

October 19, 2026 · 4 min · 715 words · 梦兽编程 -  | 

整理微调知识时，我读到一篇基础教程：SFT 数据怎么构造、Loss Mask 怎么写、LoRA 为什么能分解、QLoRA 的 NF4 是什么，讲得清楚，公式都对。但整篇没有一个数字跑出来过——「7B 全参要 14G 权重 + 14G 梯度 + 56G 优化器状态」是口算的，「LoRA 可训练参数少」是推理的。

我做的事就是把教程尾部那段「手撕 LoRA + 简单 SFT 训练流程」在 2 核 EPYC 8GB（torch 2.14.1+cpu）上真跑三组，把公式钉成数字：等价性 0 差、可训练占比 0.39%、7B 显存账 75.3GB。

先说结论，三句#

第一，LoRA 挂上模型的那个瞬间，输出和原模型逐位相等（实测最大 diff = 0.0）——因为 B 矩阵零初始化让低秩分支 delta 恒为 0。教程说「初始化不破坏原矩阵」，这句话的可验证含义就是它。

第二，7B 全参微调的显存地板是 75.3GB（不含激活）：BF16 权重 12.6 + 梯度 12.6 + AdamW 双 FP32 动量 50.2。LoRA r=8 把可训练参数砍到 31.2M（0.39%），实际占用约 25.4GB，差 3 倍——这就是「为什么大家都用 LoRA 不用全参」的算术答案。

第三，小数据上 LoRA 反而比全参收敛得干净：同一个 4 层玩具 GPT、同 500 step，全参 loss 停在 3.3 震荡，LoRA r=4 降到 0.056。参数被低秩约束住了，小数据不容易跑飞。这是现象记录，不是「LoRA 效果一定好」的结论。

教程讲的那套，先按它的逻辑过一遍#

教程的脉络很标准。SFT 数据就是 {X, Y} 对，X 是指令，Y 是答案，CE Loss 不变，唯一的新东西是 Loss Mask：loss 只监督答案段，prompt 段的 label 全填 -100。

# Prompt 和正确答案的 Token IDs
input_ids = prompt_ids + answer_ids

# 只监督答案，不监督 Prompt
labels = [-100] * len(prompt_ids) + answer_ids

这段我不改一字，后面实验直接复用。

然后是 LoRA 的核心假设：模型适应下游任务时，权重更新集中在相对低秩的方向上，所以不必改 W 本身，冻结 W、只学一个增量 ΔW，把 ΔW 分解成 B·A（B 是 H×r，A 是 r×W，r 取 8 这种小数）。完整分解就是：

Y = XWᵀ + α/r · (XAᵀ)Bᵀ

两个细节教程点到了，但没验。一是初始化：必须 B = 0、A 随机，两个都为 0 梯度传不上来；二是缩放系数 α/r：换了 rank 之后 LoRA 分支的数值尺度会变，除以 r 让 8 和 64 两种配置共用一套超参。这两个细节恰好都能一行代码验掉，下面就是。

实验 A：教程那段 LoRA 代码，逐行跑掉#

教程尾部给了一段 LoRALinear（nn.Module 包一层，base 冻结、A/B 两个 Parameter、forward 是 base 加低秩分支）。我原样照抄进 2 核 EPYC，torch 2.14.1+cpu，seed=42，跑了三个断言：

$ python3 exp_a_lora.py
[A-1] 初始化 LoRA 输出 vs 原模型输出 最大diff = 0.0
[A-2] merged_weight forward vs 分离 forward 最大diff = 0.0
[A-3] 7B 结构可训练参数实算（68 层 x 7 Linear(4096) x r=8）：
      base=7,985,954,816（7986M），lora(r=8)=31,195,136（31.2M），占比 0.39%
      Full FT 可训练 7986M vs LoRA 31.2M，缩小 256 倍

A-1 是这篇里我最想钉的一个数。 B 零初始化意味着 delta 分支在 step 0 输出恒 0，所以「挂上 LoRA 的模型」和「原模型」在初始化瞬间是同一个函数——diff 不是接近 0，是逐位 0.0。教程里「初始化不破坏原矩阵的性质」这句，落到代码就是这一条断言。

A-2 解释了推理侧为什么「白嫖」。 merged_weight 把 LoRA 分支合并回 W（W + s·BA），单次 matmul 和「双分支」数值等价。也就是说训练完可以把 LoRA 权重烘进主权重，线上推理零额外延迟——LoRA 的成本全压在训练期，这条工程收益教程提了但没给等式。

A-3 是参数账。 按 68 层 × 7 个 4096² Linear × r=8 的结构实算：全参 7986M，LoRA 31.2M，占比 0.39%，缩小 256 倍。注意这个 7986M 是结构估算（68×7×4096²），比 Qwen2-7B 官方的 6.7B 略高，下一节的显存账我用官方参数量重算。

实验 C：7B 全参显存账，把「14+14+56」钉死#

教程的口算是 7B × 2B（BF16 权重 14G）+ 14G（梯度）+ 56G（AdamW 两个 FP32 动量），84G 级。它没说是哪个 7B。我按 Qwen2-7B 官方参数量 6,738,032,384 实算一遍：

$ python3 exp_c_memory.py
模型：Qwen2-7B，参数量 6,738,032,384
  权重 (BF16)                 12.6 GB
  梯度 (BF16)                 12.6 GB
  AdamW 一阶动量 (FP32)       25.1 GB
  AdamW 二阶动量 (FP32)       25.1 GB
  合计（不含激活）              75.3 GB
  LoRA r=8 可训练参数：31,195,136（0.46%）
  LoRA 优化器状态：0.23 GB vs Full 50.2 GB

75.3GB 是地板，不是预算。 这四个项只算参数、梯度、优化器状态，一个 token 的激活都没算。batch 上去、序列长了，激活再叠一层，实际占用只会更高。结论可以钉死：80G 单卡（A100/H100）跑 7B 全参，地板之上已经没有余裕；48G 双卡（2×48）刚好够放参数侧，激活还得靠 gradient checkpointing 和短序列挤。

LoRA r=8 那行账：冻结权重 12.6 + 12.6 照占（存着就要占），但可训练 31.2M 的优化器状态只有 0.23GB，合计约 25.4GB——全参的三分之一。这是「LoRA 为什么是默认选项」的算术答案，不是玄学。

教程里 84G 和我这边 75.3G 的差就是 7e9 整数近似（70 亿）对 6.738B 的取整，公式两边一致，它没错，只是没标型号。

QLoRA 那部分教程接得很顺：LoRA 只省了可训练参数，冻结的 7B 权重还在显存里，下一步把 W₀ 量化到 4-bit。NF4 的思路按权重分布分配量化格点（正态分布假设，中心密、尾部疏），双量化再把 scale 本身压一档，论文配到 0.13 bit/param。这块我本机没跑——无 GPU，4-bit 的 kernel 和 dequant 行为在 CPU 上测了也没法外推——只引机制，不给实测数字。

实验 B：小模型 SFT 冒烟，LoRA vs 全参同场#

教程说「手撕 LoRA + 简单 SFT 训练流程」。我把「简单 SFT」落地成一个最小可跑的对照：纯 torch 4 层 GPT（vocab 512、dim 128、4 头，939,008 参数），玩具指令数据 20 条（确定性伪 token，prompt 3 token + answer 5 token），loss mask 用教程原样的 labels = [-100]*len(prompt) + answer，AdamW lr=3e-3，各跑 500 step。

$ python3 exp_b_sft.py
[B-0] 模型总参数 939,008；Full FT 可训练 939,008 (100%)
[B-1] Full FT 500 steps:
      step  50 loss=3.6247   step 300 loss=3.3700   step 500 loss=3.2999
      最终 loss 3.2999，总耗时 3.8s，单步 8ms
[B-2] LoRA r=4 可训练 32,768 (3.5% of 总参数)
[B-3] LoRA 500 steps:
      step 150 loss=1.0383   step 300 loss=0.5956   step 500 loss=0.0559
      最终 loss 0.0559，总耗时 3.1s，单步 6ms
[B-4] Full vs LoRA：参数 28 倍差；单步 1.21 倍（LoRA 省掉 906,240 个参数的优化器状态）

三个观察，都是本机直接看出来的。

全参没收敛，LoRA 收敛了。 同样 20 条数据、500 step，全参 loss 在 3.0~4.0 之间震荡（step 50 的 3.62 → step 100 的 4.00，还往上走了），LoRA 从 1.0 一路压到 0.056。939K 参数对 20 条样本是过参数化的，全参更新把噪声也学进去了；LoRA 的低秩约束等价于给更新加了一个强正则，小数据下反而稳。这条只作现象记录——玩具模型、20 条数据，不能外推成「LoRA 效果一定比全参好」，大任务上结论可能反过来，教程也没承诺这个。

单步 8ms vs 6ms，1.21 倍。 小模型 + CPU 下，训练慢不慢主要看反向图的规模，全参和 LoRA 的前向反向路径几乎一样长，差距主要在优化器状态更新（939K vs 32,768 个参数的 AdamW 状态读写）。真正拉开倍数的是 C 节的显存账：到 7B 级，全参 75.3GB vs LoRA 25.4GB，3 倍且全参根本上不了多数卡。

参数 28 倍差 vs 7B 级 256 倍差。 玩具模型 939K 参数、LoRA r=4 挂了 28 个 Linear 槽位，可训练占比 3.5%；7B 结构 r=8 占比 0.39%。占比随模型变大越压越低，LoRA 的相对收益在 7B 以上才真正打开。

教程没写的一行：坑在哪#

教程那段「手撕 LoRA」代码直接照抄是能跑的，但有两处它没写、跑之前要自己会。

一处是原文代码块里 B 矩阵的初始化：它写的是 nn.Parameter(torch.zeros(d_out, r)) 然后 kaiming 初始化 A——顺序无所谓，但两个都随机初始化就会在 step 0 破坏原模型输出（delta 不再是 0），A-1 那条 diff=0 的断言立刻挂。这是「B=0」这条规则的全部意义，教程一句话带过，代码里一行定生死。

另一处是 merge 的时机。A-2 验的是「分离 forward 和 merged weight 等价」，前提是推理期才 merge。训练中途就 merge 会把 A/B 的梯度路径切掉，等于训练完才 merge 和训练中 merge 是两回事——很多「省显存技巧」把 merge 塞进 step 里，省了显存也省掉了训练本身。

诚实声明#

本机 2 核 EPYC 8GB，torch 2.14.1+cpu，无 GPU，2026-10-19 实测。脚本与输出全在 projects/ocr-finetune-1019-batch/src 与 results，可复现。

教程原文（linux.do，topic/3041329，10-18 发布）的 NF4 双量化 0.13 bit/param、Paged Optimizer、灾难性遗忘三招、多模态三方案（A/B/C 表）全部引用未复跑，本文不为其数字背书。

实验 B 是 939K 参数玩具模型 + 20 条数据，loss 曲线只证「流程能跑通 + 现象可观察」，不构成任何 7B 级训练效果的证据；Full FT 未收敛是学习率与数据量共同作用，未做超参搜索。

7B 显存账按 Qwen2-7B 官方 6,738,032,384 参数算；教程的 84G 是 7e9 取整版，两边公式一致，差异全在参数量取整。

常见问题

LoRA 挂上去之后，模型输出会变吗？

初始化瞬间不变。B 矩阵零初始化让 LoRA 分支 delta 恒为 0，实测 LoRA 输出与原模型输出最大 diff = 0.0，逐位严格相等。这是「BA=0 不破坏原矩阵」的可验证含义，不是说法。

7B 模型全参微调要多少显存？

按 Qwen2-7B 官方 6.7B 参数实算：BF16 权重 12.6GB + BF16 梯度 12.6GB + AdamW 两个 FP32 动量 25.1GB×2，合计 75.3GB，还不含激活。一张 80G 卡在地板之上吃紧。LoRA r=8 只维护 31.2M 可训练参数，优化器状态 0.23GB，实际占用约 25.4GB。

LoRA 到底省在哪？训练会快吗？

省在可训练参数与它的优化器状态。玩具 4 层 GPT（939K 参数）上 LoRA r=4 可训练 32,768（3.5%），单步 6ms vs 全参 8ms（1.21 倍）——小模型 CPU 上差距不大，真正的大头在 7B 级：全参 75.3GB vs LoRA 约 25.4GB，3 倍。

QLoRA 的 NF4 双量化我也能跑吗？

本篇没跑。本机 2 核 EPYC 无 GPU，NF4 的 4-bit 权重分组量化、0.13 bit/param 的双量化、Paged Optimizer 的显存-CPU 页迁移都是引用原文，没在本机复现，文里只讲机制不给实测数字。
