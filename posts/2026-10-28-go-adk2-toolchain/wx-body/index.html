Google 10-22 官宣了 ADK 的 Go 版，但真正先撞上来的不是 API，是工具链。ADK Go v2.4.0 的 go.mod 写死 go 1.26.6，而 go.dev/dl 主区早就没有 1.25 的位置了。这篇把版本门槛的机制讲透：1.25 用户会被哪条报错拦住、GOTOOLCHAIN 三个取值各自落到哪、以及 1.26/1.27 里对写 Agent 代码真正有用的变化。

网上两类说法，都不准#

一类是「ADK Go 需要 Go 1.24+」——那是 v0.2.0 时代的说法，现在依赖编译都过不了。另一类是「按 Go 1.26.0 的新特性写」——1.26.0 早不是当前版本了。Go 官方同时只维护两个次版本，09-26 快照的实际窗口是 go1.27.1（stable）加 go1.26.8（LTS），1.25 已掉出窗口。

正确的说法只有一句：最低要求由 ADK 的 go.mod 决定，go 1.26.6；实操基线直接用 go1.27.1。带 patch 的 go 指令是 Go 1.21 之后引入的，用途是精确表达「我需要这个 patch 才有的行为或修复」。ADK 从 v1.5/v1.6 一线把要求从 1.25.0 抬到 1.26.6，跟随的是 Go 支持窗口上移——框架作者不想为一个已经不发安全更新的 Go 版本兜底。

强制关系：工具链硬拦，不是文档建议#

在新模块里 go get google.golang.org/adk/v2，本地 go 还是 1.25 的话，报的就是这个：

go: google.golang.org/adk/v2@v2.4.0 requires go >= 1.26.6 (running go 1.25.6; GOTOOLCHAIN=local)

这不是提示，是硬拦。行为由 GOTOOLCHAIN 决定：

取值行为适用
auto（默认）自动下载满足 go 指令的新工具链，落到 GOMODCACHE/golang.org/toolchain@…本地开发
path / local只用当前 go，绝不下载，直接报错内网 / 离线 CI
go1.27.1+auto显式钉住一个工具链，缺了才下载CI 推荐，行为可预测

三条命令摸清现状：go env GOTOOLCHAIN 看当前取值，go env -w GOTOOLCHAIN=auto 放行自动下发，go list -m -f '{{.Path}} {{.Version}} {{.GoVersion}}' google.golang.org/adk/v2 看依赖到底要哪个版本。

国内环境还有两个坑。工具链下发走模块代理：GOPROXY=https://goproxy.cn 这类公共代理一般同步了 golang.org/toolchain，但自建 athens/goproxy 经常没同步这条路径——表现就是「拉普通包正常，拉 ADK 卡在 toolchain」。解法二选一：代理侧给 golang.org/toolchain 加白，或者 CI 镜像直接用 golang:1.27.1。另一个是别在 Dockerfile 里 go env -w GOTOOLCHAIN=local 之后又指望自动升级，钉镜像版本和放行下发两头都要占不住。

go mod init 故意写低：脚手架陷阱#

Go 1.26 改了 go mod init 的默认值：用 1.N.X 的工具链初始化，写进 go.mod 的是 go 1.(N-1).0（预发布写 N-2），目的是让新模块默认兼容仍在支持窗口的旧版本。

后果很直接：用 go1.27.1 新建项目，go mod init 之后 go.mod 里是 go 1.26.0——1.26.0 < 1.26.6，go get google.golang.org/adk/v2 立刻报错。两条命令补上：

go get go@1.27.1
go mod edit -go=1.27.1

新项目我推荐 go.mod 直接钉死 go 1.27.1，写进团队模板里，别每次靠记忆。

1.26/1.27 里对 Agent 代码真正有用的变化#

只列 ADK 代码里实际用到的，不凑数。

new(expr) 是三态指针的一行写法。Go 1.26 允许 new 带表达式初值，落到 ADK 上直接对应 v2.4.0 workflow/config.go 的 NodeConfig：RerunOnResume *bool 是 &true（显式重入）、&false（显式 handoff）、nil（没配，交给引擎）三个状态。源码注释写得很清楚：指针就是为了区分「用户显式关掉」和「用户没配」。以前要自己造 func ptr[T any](v T) *T { return &v } 这种样板，1.26 之后 new(false) 一行顶掉，genai.Schema 的 temperature、topP 那些 *float32 可选参数也是同一个模式。

goroutineleak profile 是我推荐基线用 1.27 而不是 1.26 的核心原因。它在 1.26 是实验特性（GOEXPERIMENT=goroutineleakprofile），1.27 转正：/debug/pprof/goroutineleak 直接可用，traceback 头部还带 goroutine label。2.x 图引擎的 ParallelWorker 每个输入项起一个 worker、JoinNode 屏障等全部分支，泄漏面比 1.x 大得多，以前只能靠 runtime.NumGoroutine() 猜，现在能直接看是谁泄漏。

asynctimerchan 在 1.27 永久移除：time 包造的 channel 从此恒为无缓冲。靠「上一轮 Stop 后残留值」侥幸跑对的老写法会翻车，节点级超时应该交给引擎的 NodeConfig.Timeout（context.WithTimeout 兜单次激活），而不是自己写 select。

另外三条也看得到：Green Tea GC 在 1.26 默认启用，事件流海量小对象正好命中它的优化路径，GOEXPERIMENT=nogreenteagc 开关 1.27 会移除；泛型可以自引用约束，workflow.NewDynamicNode[I, O] 这类双类型参数想封类型安全的节点链就是正解；go test 默认多了 stdversion 检查，go.mod 的 go 指令比实际编译版本低时会报「用了更新的库 API」，修法是抬 go 指令不是改回代码。

RetryConfig 的默认值陷阱，顺手交代一个#

官方推荐 rc := workflow.DefaultRetryConfig() 再改字段；明确不推荐 struct literal 直接构造。区别在：literal 构造时未设字段是零值而不是默认值——零值 RetryConfig 是合法的「不重试、不退避、不加抖动」策略。少写一个 InitialDelay，得到的不是 1 秒是 0 秒，立刻打满下游。默认策略本身：MaxAttempts 5 · InitialDelay 1s · MaxDelay 60s · BackoffFactor 2.0 · Jitter 1.0，且输入校验错误（ErrInputValidation）不重试，其余错误一律重试。

版本策略一句话#

基线 ADK Go v2.4.0 + Go 1.27.1（下限 1.26.6）；go.mod 写 go 1.27.1；CI 镜像 golang:1.27.1 配 GOTOOLCHAIN=go1.27.1+auto；生产构建加 -trimpath，用 go version -m 把实际 ADK 版本记进制品。上游发 v2.5/v2.6 时出增补篇，不悄悄改旧文。

你的 CI 钉的是哪个 Go 版本？GOTOOLCHAIN 用的 auto 还是 local？评论区说说。

诚实声明：以上基于 google.golang.org/adk（v2.4.0 与 v1.7.0 的 go.mod）、go.dev/dl 版本窗口（09-26 快照）及 Go 1.26/1.27 release notes 整理；GOTOOLCHAIN、go mod init 默认值与 RetryConfig 默认策略均出自官方文档与 ADK 源码注释，行为以官方为准。
