DeepSeek Harness 的输入框开始猜你想发：512 个 token 换掉你每次的起手式

dsh（DeepSeek Harness）的社区插件把输入框从哑的变成会猜你想发的：AI 答完一轮，浅色幽灵文字替你写好下一句，Tab 填入草稿。512 token 预算 + 本地 zsh-autosuggestions 双轨，凭据脱敏，官方核心一行没动。

October 20, 2026 · 2 min · 371 words · 梦兽编程 -  |  English

Claude Code、Codex、Cursor，这帮每天替你写代码的 agent 有一个共同点：输入框全是哑的。你打，它等，它不猜。DeepSeek Harness（dsh）这边的社区把这层皮掀开了——AI 答完一轮，输入框里浮出灰色幽灵文字，把你下一句可能想发的话摆在那，按 Tab 直接填进草稿。功能叫"猜你想发"，实现全部是社区 Web 插件，一行官方代码没动。

这篇说三件事。第一，这个功能到底是什么、怎么做到的：一次有界的辅助 LLM 调用加一套本地历史补全，成本 512 token 起步。第二，为什么值得看：它暴露了 agent harness 正在往"全栈接管人机对话"的方向走，输入框是最后一块没人接管的界面。第三，为什么这事发生在 dsh 而不是别的框架上：everything-is-a-plugin 的架构让第三方能用纯 JS 浮层做掉，官方只提供钩子。

先看它长什么样#

dsh-suggest-prompt 的效果是这样的：每个 agent 回合以 completed 结束，插件在 turn/end 事件上挂了一次辅助 LLM 调用，把最近一轮的用户输入和助手最终回答打标签丢进去，模型按"以用户口吻预测下一条提示词"的系统指令返回一句话，Web 端把它渲染成输入框内的浅色幽灵占位文字，光标后面淡灰色，按 Tab（可改成 Alt+Slash 等任意录制键）填入草稿。回复语言跟随会话——最后一条用户消息含 CJK 就预测简体中文，否则 English。

没被采纳也不亏。删回空草稿时已持久化的建议直接重新显示，不发新请求；输入任何字符幽灵文字立刻让位，不会跟你抢键；输入法组字期间整个拦截机制静默。模型回复为空或被判为"元文本、评价套话、助手口吻"时静默跳过，不报错、不写事件。

dsh-prompt-history 在同一批需求上做了更完整的一层：↑/↓ 历史走 bash 的 history-search-backward 语义（前缀搜索、pending-line 还原），Ctrl+R 反向搜索，选区上方浮"复制/引用/侧聊追问"工具条，右键直接粘贴，还能在右栏并行开第二条 agent 线程。12KB 的客户端 bundle，全走浏览器本地，纯 UI 行为不产生会话事件。

成本账：512 token 买什么#

把这笔账拆开看，这是整件事最有意思的地方。

默认不开思考。辅助请求带 reasoningEffort: off（DeepSeek 序列化为 thinking: disabled），不为"猜一句话"烧推理预算；模型不支持该参数就自动去掉字段重试一次，拒绝发生在任何网络 IO 之前，几乎零额外开销。

只喂最后一轮。maxRecentTurns 默认 1，中间的工具调用和推理过程一律不进建议模型。转录有 maxTranscriptChars 预算约束，建议本身有可见字符上限，整个调用有字节/令牌/超时三道闸。

不占主请求。主 agent 的 token 消耗一分不变，预测是每回合至多一次的并行辅助调用，且缓存命中（同一段上下文）时不重复请求。

我的判断：这 512 token 买的不是"帮你打字"，是把"你想问什么"这个决策成本压到接近零。agent 工作流里最贵的从来不是 token 是意图切换——AI 刚跑完一个重构，你要想起"哦对了还要跑一遍测试"，这个起手的心理成本比敲那行字的键盘成本高三百倍。幽灵文字替你记着，Tab 一下，意图不落地就走不了。

本地那半：没网也能猜#

别把"猜你想发"等同于"每回都调模型"。dsh-suggest-ghost 的设计是双轨：草稿为空时走 LLM 整句预测；一旦你开始打字，立刻切换成 zsh-autosuggestions 风格的前缀补全，纯本地，按对话历史排序——最近程度第一、会话内频次第二、跨会话热度第三，匹配时忽略大小写、空白和全角半角标点差异。

这就是 zsh 那个"灰字补全"在 agent 输入框里的移植。你的提示词历史里有过"修复那个 500"，这次再打"修复那个"，灰色部分自动续上。历史源是会话自身消息记录（user/steering 节点），刷新后还在，跨会话记忆默认关（开了上限 200 条存浏览器本地）。

双轨的价值在成本曲线：高频重复场景（“跑一遍测试"之类）靠本地历史命中，零 token；真正的新意图才落到 LLM 预测。设计是对的。还有一层容易被忽略：前缀补全的排序权重是"最近程度>会话内频次>跨会话热度”，这三档的优先级就是使用习惯的数学表达——你上周反复打的那句排在三天前偶尔用过的上面，比简单按总次数排序更贴实际。

为什么是插件，不是官方功能#

dsh 本体的输入框是 Lexical 的 contenteditable 宿主，官方提供 conversation.input.overlay 槽位和 inputActions.setDraft API，不提供预测逻辑。插件全在 DOM 浮层上做完，不碰核心。

这不是 dsh 独有的取舍，是它的架构立场：everything-is-a-plugin。官方赌对了钩子的粒度——turn/end、input.overlay、appendPluginRecord，刚好够第三方把"输入层"整层拿走重写，而核心 agent 循环一行不动。dsh-suggest-prompt 写日志用的是 ignorable 插件记录（plugin:suggest-prompt/suggested），不认识的读者保留并跳过，会话永远可冷读——在缺这个 API 的老版本上插件干脆保持完全休眠，宁可空着不写私有事件，因为私有事件写进日志会让整个会话冷读时直接被拒。

这个细节比功能本身更能说明问题：社区插件的纪律性已经高到要兼容会话格式的兼容性约束了。

TypeScript 之争：生态赢了性能#

dsh 从 8 月 13 日开源起，HN 上最常见的吐槽是"为什么是 TypeScript"。约 219 个包、45 万行 TS、pnpm monorepo——在讲究性的 agent harness 里确实扎眼。

官方社区给出的回答我认为是站得住的：这不是运行时选择，是分发选择。dsh 的整个论点是"一切皆插件"，插件必须能轻松安装、解析依赖、即时发布。npm 在"运行时装随机包"这件事上没有任何对手——Rust 有 crates.io，Go 有 modules，Python 有 PyPI，但没有一个具备 JS 生态那种零配置发布+庞大存量+热装习惯的组合。101 个社区插件的实测分割说明问题：11 个 npm 干净直装，81 个以裸 GitHub 仓库形式存在（dsh plugin add github:owner/repo 直接装），4 个需要 Web/TUI 运行时，3 个装不上。81/10 的裸 GitHub 占比之所以能跑，就因为 dsh add 是 Node 安装机制上的一层薄封装——你在 Rust 或 Go 里复现不了这一点，除非先造一个 npm 的等价物。

性能反驳忽略了一件事：agent 里主导成本是模型推理的跨网络往返，“决定下一步"发生在模型内部，不在 Node 进程里。Node 更慢的那部分（冷启动、JSON 解析、字符串处理）相对秒级模型往返是可忽略项。选 Rust 加速那 1%，却给 99% 的插件分发加摩擦——对一个赌社区生态的框架，这是错的取舍。

我同意这个判断。唯一要留个心眼的是 81 个裸 GitHub 仓库的质量下限：没有 npm 的发布流程约束，插件坏在 ERR_PNPM_FETCH_404 或 CJS/ESM 不匹配上是常态，官方排错指南把这些都收录了，但用户侧的脏活还是用户自己的。

四行总结#

场景 做法 成本 判定
重复提示词 本地前缀补全（zsh-autosuggestions 移植） 0 token 高频场景主力，正确
新意图 每回合一次 LLM 整句预测，512 token 预算 每回合 ≤1 次 买的是意图切换成本，值
凭据安全 转录发送前脱敏，只喂最近 1 轮 — 默认关 LLM 即零网络，边界清晰
采纳 Tab 填草稿，Enter 才发出 — 不打扰，不对，Esc 即弃

FAQ#

这是 dsh 官方功能吗？ 不是，全是社区 Web 插件（suggest-ghost / prompt-history / suggest-prompt / input-assist 这批）。官方提供插件装载点、turn/end 钩子和输入框 overlay API，功能逻辑一行没写。

预测会不会把我 API key 发给模型？ 按 suggest-prompt 的实现，转录在发送前做凭据形状脱敏，且只喂最近一轮的用户输入+助手最终回答，工具调用中间态不进。想彻底零网络，插件设置里把 LLM 建议关掉，只留本地前缀补全。

和 Claude Code 的补全比呢？ 方向一致（灰字 + Tab 采纳就是直接对齐 Claude Code 行为），但 Claude Code 是官方内置，dsh 这版是插件层。差别在装载方式：dsh 一行 dsh plugin add 装好，不用等官方排期，也不受官方版本节奏约束——代价是质量下限靠社区自律。

装不上怎么办？ 前置是 dsh ≥ 0.2.0-rc.2（0.2.0 改了会话投影和 Web 客户端模块表契约，老版插件按休眠处理）。安装 dsh plugin --profile web add dsh-suggest-ghost 之后重启 dsh web，Ctrl+Shift+R 强刷页面，无需配置即生效。

值得为这个专门用 dsh 吗？ 如果你已经在跑 dsh 工作流，装一个插件的事，白捡。如果没在用 dsh，单独为输入预测迁移不值得——它解决的是"高频 agent 对话"场景的效率，不是通用工具需求。

结尾#

输入框是 agent 工具的最后一块界面。模型能写代码、能跑测试、能连 MCP，唯独"你下一句想发什么"一直是纯靠人。dsh 社区用一批 12KB 的 Web 插件把这层堵上了，而且没碰官方核心一行代码——钩子给得够细，第三方就能把整个输入体验重写。

512 个 token 的预算买的是意图不落地就走不了，这笔账我认为是划算的。

你是哪种用法：纯本地补全够用，还是 LLM 整句预测离不开？dsh 之外你给哪个 agent 开过这类"猜你想发”？评论区聊，攒够一批实测我出续篇。转给那个还在给 agent 手动打起手式指令的同事。

常见问题

这功能是 dsh 官方的吗？

不是。dsh 本体（deepseek-ai/deepseek-harness）不带输入预测，功能全部来自社区 Web 插件：dsh-suggest-ghost、dsh-prompt-history、dsh-suggest-prompt、dsh-input-assist 这批。官方提供的是插件装载点和 turn/end 事件钩子。

预测会不会把我的凭据发给模型？

按 dsh-suggest-prompt 的实现，转录在发送前做凭据形状脱敏；默认只喂最近 1 轮的用户输入 + 助手最终回答，中间工具调用一律不发，预算约 512 token。

不开 LLM 有没有用？

有。前缀补全走纯本地历史（zsh-autosuggestions 风格：最近度>会话内频次>跨会话热度），零网络请求。LLM 那半是「下一句整句预测」，可以单独在插件设置里关掉。

Tab 采纳之后会不会直接发出去？

不会。采纳只填入输入框草稿，可改可弃（Esc），Enter 才真正作为你的消息发出。

为什么 dsh 用 TypeScript 写？

官方赌的是插件分发而不是运行时性能：npm 的零配置发布+依赖解析，101 个社区插件实测 11 个 npm 直装、81 个 GitHub 源码装、4 个需额外运行时、3 个装不上。Agent 的主成本在模型推理往返，不在 harness 语言。
