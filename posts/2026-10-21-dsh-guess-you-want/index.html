DeepSeek Harness 的输入框开始猜你想发：512 个 token 换掉你每次的起手式

dsh（DeepSeek Harness）的社区插件把输入框从哑的变成会猜你想发的：AI 答完一轮，浅色幽灵文字替你写好下一句，Tab 填入草稿。512 token 预算 + 本地 zsh-autosuggestions 双轨，凭据脱敏，官方核心一行没动。

核心结论：dsh（DeepSeek Harness）的社区插件把输入框从哑的变成会猜你想发的：AI 答完一轮，浅色幽灵文字替你写好下一句，Tab 填入草稿。512 token 预算 + 本地 zsh-autosuggestions 双轨，凭据脱敏，官方核心一行没动。

细节、可复现的数字与后续讨论，一律以 BBS 那篇为准。

常见问题

这功能是 dsh 官方的吗？

不是。dsh 本体（deepseek-ai/deepseek-harness）不带输入预测，功能全部来自社区 Web 插件：dsh-suggest-ghost、dsh-prompt-history、dsh-suggest-prompt、dsh-input-assist 这批。官方提供的是插件装载点和 turn/end 事件钩子。

预测会不会把我的凭据发给模型？

按 dsh-suggest-prompt 的实现，转录在发送前做凭据形状脱敏；默认只喂最近 1 轮的用户输入 + 助手最终回答，中间工具调用一律不发，预算约 512 token。

不开 LLM 有没有用？

有。前缀补全走纯本地历史（zsh-autosuggestions 风格：最近度>会话内频次>跨会话热度），零网络请求。LLM 那半是「下一句整句预测」，可以单独在插件设置里关掉。

Tab 采纳之后会不会直接发出去？

不会。采纳只填入输入框草稿，可改可弃（Esc），Enter 才真正作为你的消息发出。

为什么 dsh 用 TypeScript 写？

官方赌的是插件分发而不是运行时性能：npm 的零配置发布+依赖解析，101 个社区插件实测 11 个 npm 直装、81 个 GitHub 源码装、4 个需额外运行时、3 个装不上。Agent 的主成本在模型推理往返，不在 harness 语言。
