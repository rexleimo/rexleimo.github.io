Rust 的 SIMD 在 2026 年到底能不能写了：我在 Zen4 上把 4 条路线全跑了一遍

shnatsel 断言 Zen4 把 512 映射到 256-bit 执行。我这台 EPYC 9354P 就是 Zen4——写 4 路线吞吐基准（自动向量化/wide/pulp/3 档 target-cpu）亲手戳一遍：汇编 0 条 512-bit 实锤假 512，DCE 让循环凭空消失的坑也写在里面。

October 4, 2026 · 3 min · 586 words · 梦兽编程 -  |  English

shnatsel《The state of SIMD in Rust in 2026》断言：“Zen4 没有原生 512-bit，把 512 映射到 256-bit 执行，benchmark 却打过了 Intel 原生 512。“这句话正好落在我这台机器上——AMD EPYC 9354P 就是 Zen4。我写了个 4 路线吞吐基准（自动向量化 / wide / pulp / 3 档 target-cpu）亲手戳了一遍。

先给结论#

  1. stable Rust 手写 SIMD 已经能用，不必 nightly：std::simd 还锁在 nightly，但 wide + pulp 两个 stable crate 就能拿到 256-bit 满宽，实测稳过自动向量化。
  2. 自动向量化是薛定谔的快：同一份 chunks 代码，target-cpu=x86-64-v2 跑出 37.8 GB/s，换 v3/zen4 档循环被编译器整个消除（0.0000ms，物理不可能）。吞吐取决于你编译时选哪档 target-cpu，不是取决于代码。
  3. Zen4 假 512 实锤：target-cpu=zen4 档下 objdump 统计整机 0 条 512-bit ZMM 指令、512 条 256-bit YMM 指令——写 512 API，编译器给你 256-bit 指令；跑出来 43.2 GB/s，比 v2 档快 16%。

我做了什么#

基准在 bench/simd-bench（stable rustc 1.99.0），同一批 4M f32（16MB×2），4 条路线：

fn auto_sum(a: &[f32]) -> f32 { a.iter().sum() }        // 朴素标量
fn auto_sum_chunks(a: &[f32]) -> f32 {                  // 4 路累加器，让编译器自动向量化
    [0f32;4].iter().zip(a.chunks(4))
        .map(|(acc,ch)| ch.iter().fold(*acc, |s,x| s+x)).sum()
}
fn wide_dot(a,b: &[f32]) -> f32 { /* wide::f32x8 手写 */ }
fn pulp_dot_v3(a,b: &[f32]) -> f32 { /* pulp V3 256-bit 手写 */ }

每档 target-cpu 单独编译再测（RUSTFLAGS="-C target-cpu=..." cargo build --release），才能看清自动向量化被哪档解锁。

核心数据（GB/s effective，越高越快）#

路线x86-64-v2x86-64-v3zen4
auto_sum(iter.sum) 标量9.49.49.7
auto_sum(chunks) 自动向量化37.80.0000*0.0000*
wide f32x8 手写28.335.338.1
pulp V3 256-bit 手写37.142.943.2

* = 循环被编译器整个消除（死代码消除）。读 32MB 不可能 2µs 读完，这是吞吐基准的第一坑：black_box 没包住的地方，高 target-cpu 档下编译器会把"算完只读一次"的循环连根删掉。修法（打印结果 + black_box）有时也压不住，测前 objdump 确认 vaddps 还在转，再信墙钟。

汇编实锤：Zen4 的"假 512”#

$ RUSTFLAGS="-C target-cpu=zen4" cargo build --release
$ objdump -d target/release/simd-bench | grep -c "vaddps.*%zmm"   # 512-bit
0
$ objdump -d target/release/simd-bench | grep -c "vaddps.*%ymm"   # 256-bit
512

c5 前缀是 256-bit VEX 指令，真 AVX-512 要 62 EVEX 前缀。整机 0 条 ZMM——原文那句"Zen4 把 512 映射到 256-bit 执行"字面坐实（“比 Intel 原生 512 快"那半句我没那台机器，只坐实到"比 v2 档快 16%"）。

什么时候别写 SIMD#

跑完最想说的是这条：纯规约（sum/dot/min/max）且数据吃满内存带宽时，瓶颈在内存不在 CPU——我本机 43 GB/s 是 16MB 被 L3 反复读的"有效带宽”，真实 1GB 数据集一上立刻打回 DDR4/5 天花板（40-50 / 80-90 GB/s），SIMD 和标量的差距被内存瓶颈压平。判据一句话：每字节 <2 FLOP 的热点函数，先做缓存分块/预取，别先写 SIMD。

wide 还是 pulp#

  • wide 0.7 天花板是 f32x8（256-bit 当半宽用），没有 f32x16，本机 38.1
  • pulp 的 V3 是 256-bit 满宽（AVX2），本机 43.2，稳定最快
  • 两个都 stable。“手写 SIMD 得上 nightly"这个 2025 年的认知 2026 年已经过时

一段能直接编译过的 pulp 点积（stable，本机实跑通过）：

use pulp::{cast, f32x8, Simd};
use pulp::x86::V3;

fn dot_f32_v3(a: &[f32], b: &[f32]) -> Option<f32> {
    let simd = V3::try_new()?;             // 无 AVX2 的机器返回 None，必须 fallback 标量
    struct Impl<'a> { simd: V3, x: &'a [f32], y: &'a [f32] }
    impl pulp::NullaryFnOnce for Impl<'_> {
        type Output = f32;
        #[inline(always)]
        fn call(self) -> f32 {
            let Self { simd, x, y } = self;
            let (x8, x1) = pulp::as_arrays::<8, _>(x);
            let (y8, y1) = pulp::as_arrays::<8, _>(y);
            let mut acc = simd.splat_f32x8(0.0);
            for (x, y) in x8.iter().zip(y8.iter()) {
                let x: f32x8 = cast(*x);
                let y: f32x8 = cast(*y);
                acc = simd.add_f32x8(acc, simd.mul_f32x8(x, y));
            }
            let mut acc = simd.reduce_sum_f32s(acc);
            for (x, y) in x1.iter().zip(y1.iter()) { acc += x * y; }  // 余数必须标量
            Some(acc)
        }
    }
    simd.vectorize(Impl { simd, x: a, y: b }).map(|r| r)
}

两个必踩坑：f32x8/Simd 不在 pulp:: 根下（要 use pulp::x86::V3 + use pulp::{cast, f32x8, Simd}）；V3::try_new() 返回 Option 不 panic，ARM/老机器必须处理 fallback。

部署时 target-cpu 怎么选#

  • 自部署服务器/容器：直接 -C target-cpu=zen4 吃满本机，别上 multiversioning 给自己加复杂度
  • 分发给别人：函数够长 + 异构机器才值得 multiversioning（多份二进制 + CPUID 探测）；函数太短时探测/跳转固定开销占比太高，净收益为负，不如标量 + 自动向量化。multiversioning 的探测开销本机没测，标未验。

诚实声明#

  • 本机 2 核共享切片，看相对值不看绝对值；GB/s 是有效读带宽非真实内存带宽。
  • 已验：4 路线吞吐、3 档 target-cpu、DCE 陷阱、Zen4 512 映射（汇编 0 ZMM / 512 YMM）、stable wide/pulp。
  • 未验（转述原文）：老 Intel Skylake AVX-512 全核降频、三角函数 + multiversioning 小函数开销、“比 Intel 原生 512 快"那半句。
  • 复现：RUSTFLAGS="-C target-cpu=zen4" cargo build --release && ./target/release/simd-bench（bench/simd-bench）。

FAQ#

Q：stable Rust 能写 SIMD 吗？ A：能。std::simd 还 nightly，但 wide + pulp 都在 stable，本机实测吞吐稳过自动向量化。

Q：自动向量化为什么不可信？ A：吃两个变量：写成几路累加器（chunks(4) 翻 4 倍，朴素 sum 不翻）+ 编译时 target-cpu（v2 档 37.8，v3/zen4 档被 DCE 到 0）。同一份代码两档编译，吞吐能从 37.8 到"没有”。

Q：wide 还是 pulp？ A：pulp V3 满 256-bit（43.2）> wide f32x8（38.1，天花板）。API 简单选 wide，要满带宽选 pulp。

常见问题

stable Rust 能写 SIMD 吗？

能。std::simd 还 nightly，但 wide（f32x8）+ pulp（V3 256-bit）都在 stable，本机实测稳过自动向量化。

自动向量化为什么不可信？

吃两个变量：写成几路累加器（chunks(4) 翻 4 倍）+ 编译时 target-cpu（v2 档 37.8，v3/zen4 档被 DCE 到 0）。同一份代码两档编译，吞吐能从 37.8 到没有。

Zen4 没真 512 为什么还能写 AVX-512？

Zen4 把 512 指令映射到 256-bit 执行单元（一条 512 拆两条 256 跑），假 512。本机 zen4 档比 v2 快 16%，汇编实锤 0 条 ZMM、512 条 YMM。
