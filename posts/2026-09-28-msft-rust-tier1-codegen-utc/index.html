微软把 Rust 提为 Tier-1 语言：100+ 个仓库共用一个编译器后端，但它不开源

9 月 10 日 Rust Foundation 官网客文正式宣布：Rust 在微软内部拿到 Tier-1 语言地位，与 C++/C#/TypeScript 并列。真正的干货是 rustc_codegen_utc——把 rustc 焊进 MSVC 自家 UTC 代码生成管线，Rust 和 C++ 共用一个优化器。但我核了一圈流传的说法，三个都站不住：不是全面换 Rust、不是 Visual Studio 出了一等工具、这个后端目前闭源且没有开源计划。

September 28, 2026 · 2 min · 360 words · 梦兽编程 -  |  English

先说结论#

9 月 10 日，Rust Foundation 官网挂了一篇微软 Rust 工具链团队首席工程师 Victor Ciura 的客文，只有一句话是新闻本体：Rust 在微软内部正式拿到 Tier-1 语言地位，和 C++、C#、TypeScript 并列。同一周 RustConf 2026（蒙特利尔）的 keynote 上官宣，HN 首页跟了一天。

但这条新闻被转述得最烂。我拿官方原文、The Register 报道和 HN 讨论对了一遍，流传最广的三个说法全都站不住。这篇把该修正的修正掉，把真正值得看的工程细节——rustc_codegen_utc——讲透。三个结论前置：

  1. “微软全面 Rust 化"是误读。 原文原话：C++ 经过几十年积累仍然主导，“很多系统未来多年会同时用两种语言”。Tier-1 是给双语言混编铺路，不是替换。
  2. 真正的工程内容是 UTC 后端：把 rustc 直接接到 MSVC 的 UTC 代码生成器上，Rust 和 C++ 第一次共用一个优化器。这是 100+ 个微软仓库已经在跑的东西。
  3. 它不开源，且微软没有开源计划。 这是目前社区最大的摩擦点，也是这条新闻里最被省略的一句。

Tier-1 到底买了什么#

先拆"Tier-1"这个词。它不是营销头衔，是内部工程承诺，原文列了五样：

Tier-1 内容落到头上是什么
安全工具链构建rustc/标准库/工具链全走供应链加固构建
开发者工具达到 C++/C# 档位的工具质量
质量工作流与现有发布管线对齐
深度平台集成Windows 平台能力对 Rust 直接开放
SDL 合规微软软件必须过的安全开发流程，Rust 项目原样进

背景数字要放一起看：Azure CTO Mark Russinovich 在 RustConf 2025 给过那个数据——微软约 70% 的 Windows CVE 是内存安全类问题，他的原话大意是"再怎么改 C/C++，也改不到 Rust 出生就有的那个保证”。微软往 Rust 项目投了"数百万美元"（原文用词），Windows 内核里 win32kbase_rs.sys 这个 Rust 组件已经在线上——研究员在它身上挖的 bug 只会崩系统，不会给提权。Tier-1 就是给这条线正式盖章。

rustc_codegen_utc：和 LLVM/GCC/Cranelift 同族#

技术上这篇的价值全在 rustc_codegen_utc。它是 rustc 的第四个代码生成后端，和 rustc_codegen_llvm、rustc_codegen_gcc、rustc_codegen_cranelift 同一架构家族，插的是同一个 backend interface——差别在于它把 rustc 的共享编译机接到的不是 LLVM，而是 MSVC 内部那个代号 UTC 的代码生成器。

打个比方：以前你在 Windows 上写 Rust，编译链路是 rustc → LLVM → 生成目标文件，然后目标文件作为"外人"进入 MSVC 的世界——ABI 约定上兼容，但 MSVC 那套攒了几十年的全程序能力（内联、PGO、加固、热补丁）看不见它。现在 UTC 后端把 rustc 直接焊进 MSVC 自家管线，Rust 目标文件和 C++ 目标文件走同一个优化器。

原文列了这份"继承清单"：

  • 与 Windows 工具生态和 ABI 的高兼容
  • 二进制加固与代码安全特性
  • 链接后合规、分析与服务（含 Hotpatch）
  • 混编项目的无缝 Rust/C++ 互操作
  • 跨语言内联、优化与 SPGO（采样式 PGO）
  • 调试与崩溃转储分析
  • 剖析、诊断、覆盖率

其中"跨语言内联"是最实际的一条：混编项目里 Rust 函数和 C++ 调用方终于能被同一个优化器看到、内联、做 profile 引导优化——以前两套优化器各算各的。

时间线记三个点：2026 年初 production-ready，Rust 1.90 起 self-hosting（后端自己用自己编译），今天 100+ 个微软项目仓库在构建，且"每周还有新仓库接入"。

三个流传说法，逐一核掉#

这是这篇的主体。三个说法都转述得很多，我拿原文出处一条条对：

说法 1：“微软要用 Rust 全面替换 C/C++。” 站不住。原文自己划了界：“C++ 在几十年开发后仍然主导”，共享后端的意义正是"让两种语言未来多年平等地参与所有开发工作流"。2030 年前消灭存量 C/C++ 的目标（Galen Hunt 提的）是清理内存安全风险，手段是 Rust 和 C++ 混编迁移，不是整体重写。

说法 2：“Tier-1 意味着 Visual Studio 里有一等 Rust 工具了。” 站不住。这条 HN 评论里有人当面指出，The Register 也确认了：这个宣布是内部工程分级，Visual Studio 本体没有任何第一方 Rust 工具。今天包括微软内部开发者在内，主路线还是 VS Code + 社区版 rust-analyzer。“Tier-1"买的是工具链构建、质量管线和平台集成，不是 IDE 体验。

说法 3：“UTC 后端开源，Rust 生态多了一个公开后端。” 站不住，而且是三个里面最要命的。它目前闭源，Rust Project 维护者转述的口径是微软没有开源计划。对一个习惯"自己的工具链必须可查可改"的社区，这是实打实的摩擦。我在正文的 FAQ 里保留了这个问题的直接答案。

诚实声明#

三条边界，不吹满：

  1. UTC 后端我一行代码都没见过——它闭源，我无从验证"继承清单"里任何一条的实际生成质量，上面那些能力全部是转述微软官方口径。
  2. 跨语言内联/SPGO 没有性能数字。官方没给，The Register 没给，HN 也没人贴过跑分。“统一优化器"是架构事实，收益是推断。
  3. 70% CVE 是内存安全这个数是 2019 年 MSRC 分析的老底，近十年没变过——它说明问题量级，不代表 Rust 部署后 CVE 数会同比下降 70%。

常见问题#

Q：我项目里有 Rust + C++ 混编，这个后端跟我有什么关系？

直接关系：没有，你用不上（内部闭源）。间接关系：第二个生产级后端会在真实 Windows 负载上暴露 rustc 对 LLVM 行为的隐含假设，这些修正会回流上游——Rust 生产代码生成器一辈子只有一个（LLVM），这是它历史上少见的压力源。如果你 ship Windows 库，盯紧混编兼容问题就行。

Q：为什么微软做这个，而不是继续用 Clang/LLVM 链路？

非 Windows 平台上混编项目确实已经可以共用 LLVM（C++ 用 Clang 编译即可）。Windows 上 MSVC 是平台原生编译器，几十年平台能力长在里面，走 LLVM 等于让 Rust 在平台边界外。UTC 后端是 Windows 平台的等价方案。

Q：“Tier-1"会不会变成其他厂跟进的模板？

目前只是微软的内部分级，没有任何跨公司标准成分。但"内存安全 70% CVE"这条论证线，加上 Rust 进 Windows 内核既成事实，已经是操作系统厂商的公开叙事。跟进不跟进看各自的 CVE 账单，不看你这篇。

你是哪一派#

评论区报个立场：

  • 等上游派：UTC 闭源，等它修出的兼容性问题回流 rustc，自己继续 LLVM；
  • Windows 混编派：Rust/C++ 双语言项目，最在意的就是跨语言内联，盯这条线；
  • 安全叙事派：70% CVE 是内存问题，Rust 进内核是方向，Tier-1 只是盖章。

报个你项目里 Rust 占比和平台目标，攒够一批我出续篇：把 rustc_codegen_utc 的接口设计跟 Cranelift/GCC 后端做一个逐层对照（基于已公开的 backend interface，不用 UTC 源码也能写）。

转给那个还在 Windows 上抱怨"Rust 工具链不如 C++ 顺手"的同事——微软已经把后端的活干了，你抱怨的缺口正在被一个 100+ 仓库的流水线填上。

常见问题

Tier-1 语言是什么概念？是不是官方支持标准？

不是。这是微软内部的工程分级，不是任何行业标准。Tier-1 意味着微软给内部 Rust 团队一条从本地开发到生产的完整 paved path：安全工具链构建、开发者工具、质量工作流、深度平台集成、SDL 安全开发流程合规。和 C++、C#、TypeScript 一个档位。

rustc_codegen_utc 我能用上吗？

目前不能。它是微软 DevDiv 内部后端，Rust 1.90 起 self-hosting，100+ 个微软内部仓库在用，但没有公开发布，也没有上游进 rustc 的计划。它的价值对你来说主要在于：第二个生产级后端压出的一系列兼容性问题会修回上游。

UTC 后端开源吗？

目前不开源。Rust Project 维护者在 Zulip 上的口径是微软没有开源计划。它和 rustc_codegen_llvm/gcc/cranelift 同架构家族，但源码不公开——这是社区目前最大的摩擦点。

和 LLVM 后端比，UTC 的优势在哪？

不是生成质量的优势，是平台能力继承：Windows ABI 约定、二进制加固、Hotpatch 热补丁、崩溃转储分析、SPGO（采样式 PGO）、跨语言内联。这些是 MSVC 和 Windows 共进化几十年攒下的，LLVM 后端的 Rust 目标文件在 ABI 层兼容，但不参与这套全程序优化。
