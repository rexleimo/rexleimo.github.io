systemd 官方支持 Rust：5,144 行不动老 C，先塞一个 32KB 的叶子模块

systemd 把 Rust 支持合进主干，改动 5,144 行跨 54 文件。它不是重写，是「只准塞新叶子」：Rust 只做新增组件、老 C 一行不动，构建仍走 Meson、Cargo 彻底不进。

October 26, 2026 · 2 min · 256 words · 梦兽编程 -  |  English

systemd 这次把 Rust 支持合进了主干。

提 patch 的是 Linux 内核开发者 Christian Brauner（PR #44324，10-20 提交），改动 5,144 行、跨 54 个文件，落到将成 systemd 263 的版本。但把它的做法读一遍你会发现，这是个极其克制的加法：Rust 只做新增的叶子组件，老 C 一行没动。

它不是重写，是「只准塞新叶子」

systemd 明确写了：Rust 只用在「新的、其他组件不依赖它的独立部分」。现有 C 代码不 port，任何被别处依赖的东西都不许用 Rust 写。这一条是 Lennart Poettering 在柏林 hackfest 上定的调，所以整个改动被拆成了四个小 PR 的栈，而不是一口吞：

  1. #44323 keyring-util / voa-util 的 C 辅助（已合）
  2. #44324 Rust 支持本体（本 PR，已合）
  3. #44325 给 systemd-keyring-setup 包 libsystemd-shared 的辅助（还开着）
  4. #44114 systemd-keyring-setup 本体（还开着）

只有第 2 个合进去了，第 1 个已合、第 3/4 在等。

构建还是 Meson，Cargo 彻底不进

最反直觉的一条：不是把 Rust 工具链塞进 C 工程，而是让 Rust 代码「穿 C 的外衣」。新 Rust 代码只用 core、alloc、libc 三个 crate，no_std，连 alloc 都禁用（Rust 的 alloc 集合在内存耗尽时会直接 abort）。systemd 自己实现了一套 Box/Vec，跟 Linux 内核那套逻辑一样：所有分配失败都返回 error，没有全局分配器。C linkage 只保留一条路：Rust 程序像 C 程序一样动态链接 libsystemd-shared，crates 静态链进去。

32KB vs 20KB，官方 PR 自己报的

HACKING.md 写的：test-cli-rust 开 LTO、stripped 之后是 32KB，对应的 C 版本 20KB。Rust 比 C 大 60%。原因不神秘：panic 处理、栈保护、define_main! 生成的 CLI 框架、Vec<u8, Erasing>（分配时像 malloc、释放时 erase_and_free）这些运行时支撑，no_std 也省不掉。官方写得很诚实——「这是早期信号，样本只是个小测试程序」。

版本下限：rustc 1.85+ / bindgen 0.71.1+ / Meson 1.4.0+

这三个下限跟 Debian 13 的发行版工具链保持一致。-Drust=auto 是默认，老 Meson 上会自动关掉 Rust 支持。distro 打包者要注意：Arch 和 openSUSE OBS 的 --auto-features=enabled 构建会失败，因为没把 rustc 和 bindgen 拉进 build deps——要么改 -Drust=disabled，要么补上两个工具。

keyring-setup 是第一个真正落地的程序

它是给内核 keyring 登记 X.509 证书的（dm-verity、fs-verity、BPF keyring，启动期）。它用的是 Vec<u8, Erasing>：C 里「读完密文要清零」是每个调用方自己记得做的约定，Rust 版本把这个约定写进了类型——erase_and_free 是类型系统保证的，不靠人记。

本机 2 核 EPYC 能验到哪一层

rustc 1.99.0 够编译这个量级。但 32KB 那个数是官方在 LTO + stripped 前提下量的，本机全量 build systemd（54 文件 5,144 行 + 依赖 libsystemd-shared）跑不完。所以正文不写「我复现出 32KB」——只钉住官方 PR 自报 32/20KB，本机 C 同款 hello 是 glibc 链接 9KB 量级（无 LTO、无 stripped，跟官方自报值不可比）。要 32KB 精确复现得拉 systemd 仓库 + bindgen 跑 test-cli-rust，那活儿 2 核上没意义。

这个合并不是「Rust 接管 Linux」

systemd 选的是风险最低的那条：C 不动、Rust 插件化、可选构建、体积代价自己扛。对比 10-10 发过的「Linux 内核里有 Rust」，这是往用户态再推一层——内核模块要等大版本，systemd 每个发行版都有，落地路径短得多。

对三种角色的分量

distro 打包者：确认 Rust 工具链进 base 还是 extra，Arch/openSUSE 要补 build deps。普通用户：什么都不用做，-Drust=auto 缺工具链自动跳。Rust 开发者：这是个「no_std + 无 alloc + 无外部 crate + C linkage」的样本约束，比 toy 项目参考价值高——它告诉你「在不能 link 外部世界的系统服务里写 Rust」到底长什么样。
