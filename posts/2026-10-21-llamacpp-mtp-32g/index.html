AutoDL 32G + 你现有的 C++ llama.cpp，就能部署 DSpark：一条命令挂 1.5G 侧车

AutoDL 上只有 C++ llama.cpp 的 32G 主机，不用装 vLLM、不用 Python：llama.cpp 现在原生带 DSpark 推测解码（PR #25173），挂个 1.5G 的 Q8 侧车就开，一条命令；DSpark 赌得比内置 MTP 更深，短代码/短问答提速最猛。FP16 满血 54G 单卡放不下，走 Q4 档。

October 20, 2026 · 3 min · 464 words · Dreambeast -  |  English

先给结论#

能。你机器上那个 C++ 的 llama.cpp，恰好就能原生跑 DSpark，不用换 vLLM、不用装 Python、不用下 54G 的 FP16。

我上一轮写的那篇（A800 双卡 + vLLM）里，DSpark 走的是 vLLM 的 --speculative-config。但你要在你那台 AutoDL 主机上部署，它跑的是 llama.cpp（C++ 那个，二进制叫 llama-server / llama-cli），不是 vLLM。很多人一听 DSpark 就以为得整套 Python 环境重来——不用。llama.cpp 从 2026 年 7 月底起原生带 draft-dspark 推测解码（PR #25173），配一个 DSpark 侧车 GGUF，你现在那个 C++ 程序就能跑。

下面把"怎么部署、32G 够不够、有哪些坑"一次讲清，小白能照着敲。

先把三个名词讲明白（后面全靠它们）#

  • 量化：把模型权重从高精度压成更省的位宽。Q4 ≈ 一个词 4 个 bit，省一半多空间，速度几乎不掉。好比把高清照片压成手机尺寸，细节损失很小。
  • 推测解码：派个小"草稿员"先猜一串词，主模型一次性验收，猜对收下、猜错重来。猜的最后还是主模型说了算，输出无损（不是拿质量换速度）。DSpark 就是 DeepSeek 开源的一种草稿员——比主模型内置的小脑袋赌得更深（一次赌 7 个）。
  • DSpark 侧车：一个单独下载的小草稿模型（GGUF 格式），Q8 精度才 1.5–2GB，挂在主模型后面当草稿员。这就是"部署 DSpark"要下和要挂的唯一东西。

三个关键点：

  1. DSpark 有 C++ 原生路，不用 vLLM。llama.cpp 用 --spec-type draft-dspark + 一个 -md 侧车就能跑，我 t/47 那篇里 A800 走的是 vLLM，但你这台单卡 C++ 主机走 llama.cpp 这条就够，反而更轻。
  2. 32G 单卡显存放得下。主模型 Q4_K_M 约 17.2G + DSpark 侧车 Q8_0 约 1.5G（erlidev 版）≈ 18.7G，剩下 ~13G 给上下文（KV cache），一个人用绰绰有余。FP16 满血 54G 才是要双卡的，走 Q4 档就不用。（按体积算的账，没在你机器上实测，见文末声明。）
  3. DSpark 比 MTP 赌得更深，提速更猛——但只在你的活是"短代码 / 短问答"时。 侧车一次最多猜 7 个词，结构化的活（写代码、算数）接受长度能到 4 左右；开放式长文写得最差（接受长度掉到 2.7）。你跑什么活决定它值不值（详见"说点大实话"）。

三步部署 DSpark#

第一步：下两样东西——主模型 + DSpark 侧车。

主模型用 unsloth 的 GGUF（32G 卡选 Q4_K_M 或 UD-Q4_K_XL，约 16–17GB，留足上下文）：

# 主模型
hf download unsloth/Qwen3.8-27B-GGUF \
  --include "*UD-Q4_K_XL*" \
  --local-dir ./Qwen3.8-27B

# DSpark 侧车（Q8，约 1.5G，erlidev 版）
hf download erlidev/Qwen3.8-27B-DSpark-GGUF \
  --include "*Q8_0*" \
  --local-dir ./Qwen3.8-27B-DSpark

国内下不动就设镜像：export HF_ENDPOINT=https://hf-mirror.com。

第二步：确认你的 C++ llama.cpp 够新。 DSpark 是 2026-07-28 合进主线的（PR #25173），老编译的二进制不认。敲一句看：

./llama-server --help 2>&1 | grep -i "spec-type\|draft-dspark"
  • 认得（列出 draft-dspark）：直接走第三步。
  • 不认：你那个是旧编译，重新编译带 CUDA 的版本（AutoDL 的 conda 镜像自带 CUDA 头文件，见文末"重新编译"）。

第三步：起服务，挂上侧车开 DSpark。 这是全文最核心的一条命令——比默认多了 -md 侧车 + 三个 --spec-* 参数：

./llama-server \
  -m ./Qwen3.8-27B/Qwen3.8-27B-UD-Q4_K_XL.gguf \
  -md ./Qwen3.8-27B-DSpark/Qwen3.8-27B-DSpark-Q8_0.gguf \
  --spec-type draft-dspark --spec-draft-n-max 4 \
  -ngl 99 -ngld 99 -fa on -c 32768 \
  --host 0.0.0.0 --port 8080

逐句翻成人话：

  • -m ... 指主模型文件
  • -md ... 指 DSpark 侧车（草稿员），这就是"部署 DSpark"挂进去的那个
  • --spec-type draft-dspark：开推测解码，用 DSpark 这套草稿
  • --spec-draft-n-max 4：每轮最多一次猜 4 个词。4 是社区实测的吞吐峰值（猜得越多理论上越快，但草稿员自己的开销涨得更快，4 之后反而掉），别手滑设 7——那是在 vLLM 那边的数，C++ 这边 4 最稳
  • -ngl 99：主模型所有层甩给显卡
  • -ngld 99：侧车也要甩给显卡（这是最容易翻车的坑，见下）
  • -fa on：开 flash attention，省显存
  • -c 32768：上下文 32K 字，按需调
  • --host 0.0.0.0 --port 8080：开放访问，本地任何 OpenAI 兼容客户端指向 http://机器IP:8080/v1 就能用

DSpark 全程无损，输出跟不开时一模一样，只是出字快。

两个必踩的坑（别省事）#

  • -ngld 99 漏了就白跑。侧车默认可能留在 CPU 上，草稿员在 CPU 上猜、主模型在 GPU 上验，速度直接被拖没。主模型 -ngl 99 和侧车 -ngld 99 两个都要写，一条都不能省。
  • --spec-draft-n-max 别照搬 vLLM 的 7。vLLM 那边 A800 用的是 7（num_speculative_tokens:7），但 C++ llama.cpp 社区实测峰值在 4（8 就明显掉了）。你这套是 C++，用 4。

三条路线怎么选（同一台机器，看你要什么）#

  • A · DSpark 侧车（本篇主角）：挂 1.5G 侧车，短代码 / 短问答 / 算数这类"结构化、短平快"的活提速最猛（单卡实测 1.7–2.5 倍区间，接受长度能到 4）。你的主要活是这个，就走这条。
  • B · 内置 MTP（零下载的对照项）：主模型自带的多 token 头，--spec-type draft-mtp，零下载、零侧车。活是"写长文 / 聊天"（接受长度短），MTP 更划算，它还有个额外好处——高并发下比侧车更扛得住。
  • C · 双卡 80G 才上 FP16 / vLLM 版 DSpark：满血 54G 单张 32G 装不下，得双卡。单卡就用不上，别折腾。

旧版 C++ 没 draft-dspark 怎么办：重新编译一下#

AutoDL 的 conda 镜像自带 CUDA（带 .h 头文件），重新编译 llama.cpp 基本一条命令：

# 开 conda 环境后
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA=ON
cmake --build build -j --target llama-server
# 编好后用 build/bin/llama-server，就是上面第三步的命令

要 draft-dspark 支持，得用含 PR #25173 的编译版（2026-07 之后的主线）。嫌编译麻烦，就先用零下载的 MTP 路线（--spec-type draft-mtp，主线编译就有），DSpark 侧车等编译好了再加。

说点大实话#

  • 能部署，走的就是你手上那个 C++：32G 单卡 + llama.cpp，Q4 主模型 + 1.5G DSpark 侧车，基本就是"下两个文件 + 敲一条命令"，不用碰 vLLM、不用下 54G FP16。
  • DSpark 值不值，看你的活。它是"赌得深"的草稿员，短、结构化的活（代码、算数、问答）接受长度能到 4、提速最猛；长、开放式的活（写长文、闲聊）接受长度掉到 2.7，不如免费的 MTP 划算。所以下载侧车之前先想清楚你主要让它干嘛。
  • 单卡 32G 是"一条请求慢慢出字"的场景。我 t/47 那篇在双卡上压过几十路并发——并发一起来，DSpark 的草稿员自己抢算力抢显存，加速被吃回去（64 路甚至倒亏）。你要的是"自己一个人用、别等那么久"，DSpark 单卡单流刚好；要的是"一台机器扛几十个用户同时压"，那是另一套账，得双卡 + vLLM，别再单卡上堆侧车了。

本文面向"AutoDL 单机 32G、已有 C++ llama.cpp"的场景，主角是 DSpark 的 C++ 部署路径（llama.cpp draft-dspark，PR #25173）。显存数字（Q4 主模型≈17.2G、DSpark Q8 侧车≈1.5G、Q8 主模型≈24.5G、FP16≈54G）为按权重体积估算，未在你的机器上实测；侧车文件体积取自 erlidev / DimInfer 的 HF 仓库（1.46G / 1.98G Q8），加速倍数为社区单卡自报（DimInfer：1.69–2.51x），我未独立复现。Qwen3.8-27B、DSpark、llama.cpp 均为开源项目，能力随版本变化，以官方为准。

你那台 32G 的卡是 4090 还是 4080 Super Ultra？主要让它跑短代码 / 短问答（DSpark 最划算），还是写长文 / 聊天（免费的 MTP 更省）？告诉我，我帮你把上面那条命令按你的活把 --spec-draft-n-max 和侧车精度定到最合适。

常见问题

我机器上只有 C++ 的 llama.cpp，能部署 DSpark 吗？

能。llama.cpp 从 2026-07 起原生带 draft-dspark 推测解码（PR #25173），配一个 1.5G 的 DSpark Q8 侧车 GGUF，一条 --spec-type draft-dspark 命令就开。不用碰 vLLM、不用装 Python。

32G 单卡显存放得下吗？

放得下。主模型 Q4_K_M 约 17.2G + DSpark Q8 侧车约 1.5G，合计约 18.7G，剩 13G 给上下文。FP16 满血 54G 单卡装不下，走 Q4 档就够。以上为按体积估算，非本机实测。

DSpark 和内置 MTP 怎么选？

DSpark 赌得深（一次最多猜 7 个），短代码/短问答/算数这类结构化活提速最猛（单卡自报 1.7-2.5 倍）；内置 MTP 零下载、开放式长文更划算，高并发也更扛得住。看你主要干什么活来选。

有什么坑？

两个：1) -ngl 99 和 -ngld 99 都要写，侧车甩 CPU 上就白跑；2) --spec-draft-n-max 用 4（C++ 社区实测峰值），别照搬 vLLM 的 7。
