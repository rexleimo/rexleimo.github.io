Discord 客户端整体 Rust 化：290MB 内存，不选 Tauri 选 GPUI

Discord CTO 官宣：Electron 撤掉、React Native 撤掉，整个客户端用 Rust 重写。新客户端 Discord Phoenix 双账号 290.2MB 内存，渲染引擎选的是 Zed 家的 GPUI 不是 Tauri，Web 端逻辑换成 WASM。数字、机制、边界一次讲清。

November 7, 2026 · 3 min · 538 words · 梦兽编程 -  | 

11 月 4 日，Discord 联合创始人兼 CTO Stanislav Vishnevskiy 在 X 上发了几条短消息：Electron 撤掉，React Native 也撤掉，整个客户端用 Rust 重写。他的原话是「2018 年起 Rust 早期采用者，基础设施、语音技术、现有客户端的一部分都已经是 Rust，圣杯就是把整个客户端搬过去」。

这条消息里最硬的数字是一张 Windows 任务管理器截图。截图里新客户端代号 Discord Phoenix，内存占用 290.2MB，旁边 Google Chrome 是 1568.6MB，Steam 的 Web helper 是 856MB。现在还没有发布日期，Discord 市场负责人 Rigney 的说法是：很快进私有测试，「先保证稳定和安全」。

290.2MB 是怎么截出来的#

这张截图的条件不苛刻。Vishnevskiy 后来解释：当时那个构建同时挂着两个账号，新客户端原生支持多账号并发，两个号一起在线不用互相切换。现在的官方客户端用 Account Switcher 最多挂 5 个账号，但一次只能切到其中一个。

旧客户端这边有完整数字可查。2025 年 12 月 Discord 确认：Windows 客户端常规使用不到 1GB，最坏情况能到 4GB。当时的应对实验是内存超过 4GB 时自动重启客户端，触发条件卡得很死——应用运行超 1 小时、用户闲置满 30 分钟、不在通话中、24 小时最多一次，重启保留草稿和打开的频道。实验是止血，病根在 Electron 的多进程结构：每个服务器、每条消息流都是一个 tab，内存只增不减。

图源：CTO X 帖任务管理器截图，Windows Latest 报道采用

启动速度是 11 月 5 日放出来的。Vishnevskiy 发了一段 15 秒并排视频：两台 ThinkPad 同时冷启动，旧版 Electron 客户端和新版 Rust 客户端。新版大约 1 秒内出窗口，旧版还在「Starting」加载画面；旧版到主界面要 5 秒左右，此时新版好友列表已经加载完毕。两台都是冷启动这一点，是 Discord 音视频负责人 Coral 在视频下确认的。

图源：Windows Latest（视频截帧）

旧版那个「Starting」加载画面，在新版里直接没了。有人问新客户端为什么没有启动弹窗，Coral 的回答是：bootstrap 够快，加上是新架构，那个弹窗根本不需要了，更新改在后台自动完成。更新不走 Microsoft Store，也不走 Windows 的更新编排平台，Rigney 确认「目前不是」。

渲染引擎：GPUI，Zed 写的那个#

Rust 做桌面应用，主流答案通常是 Tauri。Discord 没选。他们选的是 GPUI，Zed 编辑器团队出品的 GPU 加速 UI 框架。

GPUI 的官方定位是「混合即时模式和保留模式、GPU 加速的 Rust UI 框架」。它不嵌入浏览器，也不用系统原生控件，界面直接画到 GPU 上：macOS 走 Metal，Windows 走 DirectX 11，Linux 走 wgpu，窗口层在 Linux 上是 X11 或 Wayland。Zed 自己的编辑器就跑在这套框架上，官方自报 120fps。

Zed 的来历值得说一句。做 Zed 的团队就是 Atom 的几位共同作者，2023 年 3 月 Zed 进公开 beta，定位就是一个不吃 Electron 亏的编辑器。GPUI 是它为了绕开 Electron 的资源开销写的渲染层，先服务 Zed，再开放给社区。现在 Discord 把它搬来渲染聊天界面，这个框架的大规模应用场景从编辑器扩到了聊天软件。

没有 GC 这一层，是内存数字能压到 300MB 以内的根源。Electron 的渲染器跑 JS，内存归 V8 垃圾回收管；Rust 的 ownership 系统在编译期定死内存归属，运行时没有回收器兜底，也没有回收器留下的堆碎片。GPUI 的样式 API 故意做得像 CSS，div()、flex()、grid、container_query 都是 Rust 方法调用，底下没有任何 HTML。

UI 代码长什么样，GPUI 官方示例可以直接看。一个能点的计数器，状态是一个结构体字段，点击事件是 Rust 闭包直调，没有浏览器到 Rust 之间的 RPC 边界：

// GPUI 官方示例（gpui.rs/examples），计数器
struct Counter {
    count: i32,
}

impl Render for Counter {
    fn render(&mut self, _window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        div()
            .child(format!("Count: {}", self.count))
            .child(
                div()
                    .on_click(cx.listener(|this, _, _, cx| {
                        this.count += 1;
                        cx.notify();
                    }))
                    .child("Add"),
            )
    }
}

对照 React 的写法，状态和事件处理全是一等 Rust 值，点击闭包在编译期就绑死了。样式那套 Tailwind 味的工具类换成了方法链，能用的属性是 GPUI 自己定义的，不是整个 CSS 子集。这套 API 对老前端不陌生：div、flex、grid 那套布局思维平移过来，只是从声明式 CSS 变成了命令式方法调用。

框架本身还是 pre-1.0，版本之间会有 breaking change，Zed 团队的说法是贡献目前先进 Zed 仓库。Discord 在 GPUI 上打了自己的补丁，Vishnevskiy 的原话是「我们看看哪些对社区有用就上游」。

图源：zed.dev 官方博客（Zed 公开 beta 发布稿配图）

为什么不是 Tauri#

Tauri 是另一条主流路线：Rust 写应用逻辑，界面继续用 HTML、CSS、JS，跑在系统 WebView 里，Windows 上是 WebView2。内存比 Electron 省一截，但整个 web 栈还在，渲染链路还是浏览器那一套。

GPUI 把 UI 渲染也做成纯 Rust，代价是需要真 webview 的地方做不了。Discord 的取舍划得清楚：YouTube 嵌入和视频、应用内游戏（Activities）这类内容，走系统原生 webview 渲染。Vishnevskiy 的原话是「我们用类似 Tauri 的原生 webview」。

两边放一起看，路线差在哪一目了然。旧栈每个 Electron 应用自带一份 Chromium，进程树里渲染器成排地生；新栈只有一个 Rust 进程，GPU 直接画 UI，webview 只留给嵌入内容。

图源：自绘架构图（依据 GPUI 官方文档与 Windows Latest 报道）

移动端和 Web：共享同一个 Rust 内核#

移动端撤掉 React Native。Vishnevskiy 补了背景：iOS 应用从立项就是 React Native，Android 是几年前才移植过来追功能对齐。新架构下移动端保留原生 UI，应用逻辑通过 Rust 和桌面端共享。也就是说同一个 Rust 内核，桌面端套 GPUI，移动端套原生控件，Web 端套浏览器，逻辑只写一遍。

Web 版不消失。浏览器里继续渲染 HTML，逻辑层从 JS 换成 WebAssembly，Rust 代码编译成 WASM 在浏览器里跑。Rust 编译到 WASM 是成熟链路，Discord 服务端和语音栈本来就是 Rust，等于客户端逻辑和 Web 端逻辑共用同一份源码。

Vishnevskiy 关于外观的说法就一句：「应用看起来、用起来和现在完全一样」。这句话的实际含义是：这次重写不动产品形态，服务器、频道、语音、Nitro 那一套全保留，动的只是底下那层壳。

安全侧，工程副总裁 Mark Smith 的表态是「可访问性和安全和性能一样重要」。登录 token 不落明文，走系统 keyring，Windows 10 和 11 上就是 Credential Manager。

Rust 在 Discord 不是新词#

2018 这个数字有出处。当年 Discord 开始用 Rust 写基础设施和语音技术栈，游戏 SDK、Go Live 的视频采集和编码也是 Rust。现有客户端里早就混着 Rust 模块，这次是把最后一块搬完。从局部到整体，隔了 8 年。

语音这条线反而最容易，因为 Discord 的卖点从来不只是打字，低延迟语音通话才是招牌，而它已经在 Rust 上了。真正难啃的是聊天界面：把每个服务器一个 tab 的多进程结构，换成单个 Rust 进程加 GPU 渲染。

为什么是现在#

内存价格在推。数据中心吃掉 DRAM 产能，DRAM 价格上行，微软公开表态 Windows 11 要降低自身内存占用。与此同时 Discord 在 Electron 内部的止血效果有限：2026 年 9 月的补丁说明写着，Electron 42 升级让中位 CPU 用量降了约 17%，代价是 p50 内存回涨约 4%。2025 年 10 月启动的内存治理修了 9 个问题，p95 内存降了 5%。

把这两组数放在一起看，结论很直白：打补丁的边际收益已经低于架构成本。17% 的 CPU 是省了，p50 内存反而涨了；4GB 自动重启是兜底，不是治理。架构级的账，只有换架构才付得掉。

同期还上了一个 Game Mode：检测到用户在打游戏就自动压低动画和视觉特效，把 CPU、GPU 让给游戏。方向是对的，但它管的是算力，不管内存。Electron 那套壳还在，内存的根就没动。

边界：哪些数字还不能下结论#

290.2MB 是早期构建的快照，不是官方逐一对标的基准。Discord 没有放出可安装的版本，独立测试要等。新客户端「点起来像即时响应」的说法全部出自 CTO 自己的帖子。4GB 是旧版最坏情况的实验阈值，不是典型值：The Verge 的测试里，只挂几个服务器，现版就能过 1GB。

GPUI 还有两处要盯住。框架 pre-1.0，Discord 的自定义补丁意味着上游合并进度不由社区节奏决定；除 Zed 外，目前公开的大规模生产应用还不多，聊天软件这种交互密度（列表滚动、消息高亮、实时音视频叠加）GPUI 扛不扛得住，要看真实用户的崩溃率数据。这些在私有测试期才会暴露。

FAQ#

问：什么时候能用上？

答：没有日期。市场负责人 Rigney 的原话：很快进私有测试，「先保证稳定和安全，不会太久」。

问：功能会砍吗？

答：官方说法是外观和操作和现版完全一样。YouTube 嵌入和 Activities 走系统 webview，不是 Rust 重写的。多账号并发反而是新客户端带出来的能力，现版切 5 个账号得逐个切，新版一起挂。

问：内存能一直这么低吗？

答：不确定。290.2MB 是早期构建快照，没有官方同条件对标数据，结论要等公开版本出来再验。

问：Linux 和 Mac 呢？

答：Linux 支持，Rigney 直接答了「yes」；Mac 方面 Coral 说内部大量人跑 Mac 版。三个平台共用 Rust 内核加 GPUI 渲染，移动和 Web 端共享同一份逻辑。

问：为什么不修好 Electron 版？

答：修了，效果有限。2025 年 10 月起治理内存，修 9 个问题换 p95 降 5%；止血靠 4GB 自动重启实验；Electron 42 升级 CPU 降 17%，p50 内存反涨 4%。结构没变：每个服务器一个 tab。
