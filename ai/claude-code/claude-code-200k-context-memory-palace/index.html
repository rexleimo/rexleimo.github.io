200K上下文窗口——AI的"记忆宫殿"管理术

深入解析Claude Code的上下文管理机制：200K token不是'无限内存'，如何自动压缩、精准修剪、预算分配。揭秘AI如何在有限的上下文窗口中管理海量代码信息。

May 16, 2026 · 1 min · 118 words · 梦兽编程 -

你有没有想过，当你跟Claude Code聊了很久之后，它怎么记住之前说的话？

Claude Code支持200K的上下文窗口，听起来很大——能装下15万字的文本。但放在大型代码库面前，这不算什么。一个中型项目的代码轻松超过这个数。

这就好比给你一间200平米的书房，但要装下整个图书馆的书。怎么办？答案是"记忆宫殿"管理术——该扔的扔，该留的留，该装箱的装箱。

图：200K上下文像记忆宫殿，需要精心整理和取舍

200K不是"无限内存"#

首先要明确：200K token是上限，不是"无限内存"。

Token是什么？简单说，是AI处理文本的基本单位。英文单词大约占1-2个token，中文字符大约占1-3个token。200K token大约能装：

  • 15万英文单词
  • 30万中文字符
  • 或者几百个中等长度的代码文件

放在实际开发中：

  • 一个React项目可能几千个文件
  • 一个大型开源项目可能几十万行代码
  • 200K根本装不下

所以Claude Code不能"记住"整个代码库，它只能"记住"当前对话中处理的部分。这就引出了上下文管理的核心问题：在有限的窗口里，装什么、扔什么、怎么组织。

自动压缩：当记忆不够时#

当上下文接近上限时，Claude Code会自动启动压缩（Compaction）。这个过程就像搬家时的收纳：把不常用的东西装箱，只在外面留标签。

压缩的流程：

检测上下文大小 → 超过阈值 → 识别可压缩内容 → 执行压缩 → 更新上下文

什么东西会被压缩？

旧的工具结果：早期对话中工具返回的结果，如果后续没再引用，会被压缩成摘要。

历史消息中的代码块：已经处理完的代码，只保留关键部分。

冗余信息：重复的内容、过时的状态。

压缩后，模型看到的不是完整内容，而是"摘要+引用"。如果需要详细内容，可以重新读取（通过引用）。

图：自动压缩流程，把旧内容装箱留标签

微压缩：更精细的修剪#

除了大块的自动压缩，Claude Code还支持微压缩（Microcompact）——更精细粒度的上下文修剪。

打个比方：

  • 自动压缩像把整本书装箱
  • 微压缩像把书中的某些章节抽出来

微压缩的应用场景：

单个文件内容过大：一个日志文件几万行，但模型只需要其中几行相关的。

工具结果冗余：Grep返回1000个匹配，但模型只关注前50个。

历史消息中的长代码块：保留函数签名，压缩实现细节。

微压缩的决策由模型自己参与——它决定"什么是重要的"。这符合"on distribution"的理念：模型不只是被动接收信息，还主动管理自己的上下文。

Token预算策略：钱该怎么花#

200K token就像一笔预算，要花得值。

Claude Code的预算分配策略：

系统提示词：约占总token的10-20%。这是"固定开销"，包含工具定义、行为规范等。

当前对话：约占总token的30-40%。最近的几轮对话，保持完整。

历史上下文：约占总token的20-30%。较早的对话，可能被压缩。

预留缓冲：约占总token的10-20%。给新消息、工具结果留出空间。

图：Token预算分配策略

这种分配不是固定的，而是动态调整：

  • 如果工具结果很大，压缩历史上下文
  • 如果对话很短，保留更多历史
  • 如果接近上限，激进压缩

文件状态保留：压缩后还记得什么#

一个关键问题：内容被压缩后，模型还"记得"什么？

Claude Code的做法是"有损压缩"——保留关键信息，丢弃细节。

具体来说，压缩后的内容会保留：

存在性：“这个文件我读过”

关键元数据：文件路径、大概内容类型、处理时间

相关性标记：哪些内容与当前任务相关

引用链接：如果需要详细内容，从哪里恢复

压缩掉的是：

完整内容：文件的具体内容、工具返回的完整结果

过时信息：已经被后续操作覆盖的内容

冗余数据：重复或无关的内容

这就像你的记忆：你可能记得"昨天看了一篇关于Rust的文章"，但不一定记得每句话——如果需要，你可以回去再读。

上下文折叠：最后的防线#

当即使压缩后上下文还是装不下时，Claude Code会启动最后一招：上下文折叠（Context Collapse）。

这就像搬家时实在装不下了——只能扔掉一些箱子，只留最重要的。

折叠策略：

保留最近的对话：最近的N轮对话保持完整。

保留系统提示词：这是AI的"身份"，不能丢。

压缩或丢弃早期内容：最早的几轮可能被完全移除。

关键决策点保留：重要的分支点、用户明确的要求保留摘要。

折叠后，模型可能"忘记"早期的细节。这就是为什么长对话中，AI有时候会问"你刚才说的那个是什么"——它可能已经被折叠掉了。

实战：如何管理上下文#

理解上下文管理，对你使用Claude Code有什么帮助？

理解"遗忘"是正常的。如果对话很长，AI"忘记"早期内容不是bug，是机制。

主动提供上下文。如果AI似乎忘了之前的内容，主动提醒它：“我们之前说过要用React，记得吗？”

使用CLAUDE.md存储关键信息。项目级的关键信息放在CLAUDE.md，它会被优先保留。

拆分长任务。如果任务很复杂，分成多个子任务，避免上下文爆炸。

利用工具重新加载。如果AI需要"回忆"被压缩的内容，它会用工具重新读取文件。

这对构建AI Agent的启示#

如果你想构建自己的AI Agent，上下文管理是关键：

设置token上限：不要假设模型能记住一切，明确上下文窗口大小。

实现压缩机制：当接近上限时，识别可压缩内容并生成摘要。

保留关键元数据：即使压缩内容，也要保留"存在性"和"引用"。

让用户参与决策：对于重要内容，询问用户"这个要保留吗？"

监控上下文使用：提供上下文使用情况的可见性，帮助用户理解。

总结#

200K上下文窗口不是"无限内存"，而是需要精心管理的"记忆宫殿"。通过自动压缩、微压缩、Token预算策略和上下文折叠，Claude Code在有限的窗口中装下了尽可能多的有用信息。

理解这一点，能让你：

  • 理解AI的"遗忘"行为
  • 更有效地管理长对话
  • 设计自己的AI Agent时借鉴这些模式

常见问题

Claude Code的200K上下文窗口到底能装下多少内容？

大约能装下15万英文单词、30万中文字符，或者几百个中等长度的代码文件；但大型项目的代码量远超这个范围，所以它并不能“记住”整个代码库。

上下文快满的时候，Claude Code会自动做什么？

会启动自动压缩：把早期未再引用的工具结果、处理过的代码块和冗余信息压缩成摘要，保留引用链接；模型看到的是“摘要+引用”，需要细节时可重新读取。

内容被压缩后，模型还“记得”这个文件吗？

记得。压缩是有损的，会保留“这个文件我读过”的存在性、文件路径等关键元数据、相关性标记和引用链接，但会丢失文件完整内容、过时信息和冗余数据。

为什么Claude Code在特别长的对话里会忘记我早先说过的内容？

因为当压缩也无法解决问题时，会触发上下文折叠：保留最近的对话和系统提示词，早期对话可能被完全移除；这是上下文管理机制，不是故障。

我该怎么避免Claude Code遗忘重要信息？

主动提醒它之前说过的关键内容；把项目级关键信息写在CLAUDE.md里，因为它会被优先保留；拆分复杂长任务；如果AI忘了被压缩的内容，可以引导它用工具重新读取原始文件。
